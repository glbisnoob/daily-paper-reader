## Abstract 

Small graphical user interface (GUI) agents can execute desktop workflows, but repeated local errors and fragile procedural decisions limit their reliability. We present GUI-WEdit-4B and GUI-SkillEvo-2B, two gradient-free adaptations of GUI-Owl-1.5 backbones. For the 4B model, we use trajectory feedback to construct guarded, closed-form updates to a late multilayer perceptron (MLP), retaining successful states as protection constraints. The final checkpoint changes 23,739,095 parameter values, or 0.535% of the 4,437,815,808-parameter backbone, within one weight tensor. For the 2B model, an assistant iteratively proposes and refines procedural skills while the model weights remain fixed. On the 361-task OSWorld subset excluding Google Drive tasks, the frozen systems obtain final aggregate scores of 48.02% and 45.47%, respectively.

## 1 Introduction 

OSWorld evaluates agents through executable desktop tasks and task-specific evaluators, requiring a model to translate visual observations into actions across applications [1]. A small model may locate the correct interface element yet fail by selecting an inappropriate mode, repeating a completed operation, or terminating at the wrong time. These failures motivate adaptation at two different points: the policy weights that produce actions and the procedural context supplied to the policy. We investigate these routes using GUI-Owl-1.5-4B-Instruct and GUI-Owl-1.5-2B-Instruct [2]. We call the resulting systems GUI-WEdit-4B (weight editing) and GUI-SkillEvo-2B (skill evolution). The 4B route edits a small fraction of the existing parameters without backpropagation or an optimizer. The 2B route keeps the backbone fixed and refines skills through execution feedback. Both retain the OSWorld task definitions and scoring criteria. Our contribution is an engineering study of a feedback-driven adaptation workflow, an audited 4B checkpoint with localized weight changes, and a frozen 2B skill harness with documented execution settings. Weight-space programming motivates using a language-model assistant to inspect failures and implement targeted changes to model parameters [3, 4]. Our implementation uses supervised state–action evidence and a constrained closed-form solve. Related visual modeling. In remote sensing, methods incorporate task-specific structure through three-dimensional wavelet textures with Markov random fields or through unsupervised polarimetric image factor-ization with convolutional networks [7, 8]. More recent work uses adaptive graph relations for multilabel scene classification, local enhancement and cross-modal state-space fusion for land-cover classification, and multiscale contrastive pretraining for polarimetric image classification [9–11]. In a different domain, Transformers have been applied to the inverse design of terahertz polarization converters [12]. These studies adapt representations or architectures to their domains. Here, we instead start with existing GUI policies and adapt their behavior through localized weight edits or procedural guidance, without retraining their visual backbones. 

## 2 Feedback-Driven Adaptation 

Development uses feedback from public OSWorld tasks. We inspect recorded screenshots, action sequences, and evaluator outputs to identify actionable failures. Candidate changes are checked against successful reference states and then evaluated in closed-loop desktop interaction. The research assistant operates offline during development. Figure 1 summarizes the two routes. 

2.1 GUI-WEdit-4B: Guarded Weight-Space Editing 

Edit location. The selected matrix is model.language_model.layers.35.mlp.down_proj.weight , using zero-based layer numbering. It maps a 9,728-dimensional MLP activation to the 2,560-dimensional residual stream. Let this matrix be W ∈ R2560 ×9728 . We save a separate checkpoint with W ′ = W + ∆ W . Vision parameters, token embeddings, attention weights, other MLP layers, and model configuration are unchanged.

With the instruction, screenshots, history, and preceding response tokens fixed, we capture MLP inputs and residual activations using the serving implementation. Final artifact. The final construction stage used one target input and 812 guard inputs, yielding 34,707 protected token states, including already-correct positions from the target response. It applied one corrective target position and one hard zero-change anchor. Earlier accepted edits are retained in the final checkpoint. An elementwise audit against the original backbone found 23,739,095 changed values in this single tensor out of 4,437,815,808 total parameter values (0.5349%). The other 712 serialized tensors are identical. No skill text is injected in the 4B evaluation. 

2.2 GUI-SkillEvo-2B: Iterative Skill Refinement 

The second route iteratively refines procedural skills while keeping the 2B backbone fixed. A development assistant inspects recorded screenshots and actions to diagnose a failed execution, then drafts a skill containing action guidance and stopping conditions. The skill is evaluated through the normal agent interface. The assistant uses the resulting trajectory and task score to revise the procedure or retain it in the skill library. The accepted library is fixed during evaluation. The wrapper uses exact instruction matching to select a procedure and append it to the instruction-side context; unmatched instructions retain the original prompt. At each step, the agent observes the current screenshot and generates a computer-use action. This separates offline skill refinement from online action generation, with the model weights remaining bitwise unchanged. 

## 3 Evaluation Setup 

Task scope and metric. We use the same fixed 361 tasks in ten domains, excluding the eight Google Drive tasks from the 369-task OSWorld suite. This subset is supported by the OSWorld setup guide [13]. The task scope follows OSWorld 1.0. We preserve raw finite scores from result.txt , including partial credit. A full-score task has score exactly one; the headline metric is the arithmetic mean of task scores, multiplied by 100. 

Execution parameters. Table 1 records the actual settings of the frozen systems. The history parameter retains up to five image observations under the native agent’s message construction. Both systems use screenshot observations and the original GUI-Owl action parser connected to OSWorld’s parallel runner. The 4B route changes model weights, and the 2B route adds skill context; neither changes evaluator functions, scoring thresholds, or task objectives. 

Score aggregation. We report the arithmetic mean of the valid score for each of the 361 tasks. We document two practical routes to adapting small desktop agents without conventional gradient-based model training. Guarded weight-space editing concentrates the 4B changes in one late MLP tensor, while iterative skill refinement adapts the 2B harness with fixed model weights. The frozen systems reach final 361-task aggregates of 48.02% and 45.47%.
