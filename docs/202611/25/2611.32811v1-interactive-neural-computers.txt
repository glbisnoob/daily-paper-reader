Abstract
Computers and their interfaces are usually treated as fixed,
so a person, or increasingly an AI agent, must adapt to
whatever the operating system presents. This is limiting
when someone needs a different workflow, or an interface
suited to hands-free use or a disability. We explore an over-
looked alternative. Rather than training an agent to operate
an existing computer, we train a generative model to be the
computer, predicting each next screen from past screens and
the user’s mouse and keyboard actions. Treating a desktop
as an interactive world model raises problems that natural-
video world models largely avoid. Without a camera pose
to index memory, the model must remember content that has
left the screen without any geometric cues. Arithmetic in a
terminal has to be exactly right, not merely plausible. Small
interface text must also stay legible at interactive frame
rates. Our Interactive Neural Computer is structured like
a Neural Turing Machine and starts to address these prob-
lems with three modules trained end to end from pixels and
actions. A surprise-gated slot memory, supervised by latent
next-frame prediction (MEMORY-JEPA), stores what is off
screen. An exploratory query bridge brings in the reason-
ing of a pretrained VLM, and a residual renderer predicts
only the latent changes between frames. In long closed-loop
rollouts, our model recalls occluded files in 64.2% of trials
(chance is 33.3%), compared with at most 56.0% for recur-
rent and sliding-window baselines. It also raises terminal-
text OCR accuracy from 1.3% to 50.1%. Finally, because
the memory is explicit, it can be transplanted at test time to
causally change what the model renders.
1. Introduction
Much recent work on computer use aims to build agents
that operate a computer in the way a person does, reading
the screen, moving a cursor, and selecting from menus, to
complete tasks on users’ behalf [3, 45, 61]. This setting has
three fundamental issues. First, the user is removed from
the loop, which serves to replace human capabilities rather
than augment them. Second, removing the user makes exe-
cution hard to supervise, which is risky, given documented
deceptive and alignment-faking behavior in frontier mod-
els [20, 30, 37]. Third, this setting treats computer inter-
faces as fixed environments to be ‘completed’. In reality,
an interface is an arbitrary construct, so we should care less
about whether an agent can ‘solve’ it `a la MiniGrid [15],
and more about whether an AI can generate a useful inter-
face that augments human capabilities. Ultimately, if the AI
is the computer, human-AI collaboration can move toward
open-ended interfaces. Following Hughes et al. [31], we
call a system open-ended with respect to an observer when it
keeps producing artifacts that the observer finds both novel
and learnable. Here the observer is the user, and the artifacts
are interfaces that adapt to their evolving workflow while

We therefore set out to build a generative interactive neu-
ral computer (Figure 1) that learns, directly from pixel and
action trajectories, to remember abstract concepts, execute
symbolic operations, and render crisp updates, all with-
out a hand-crafted symbolic memory state. Each of these
three requirements is an open problem for world models at
large, and each takes a specific form on a computer. The
first is long-horizon object permanence. World models of
3D scenes can use camera pose and scene geometry to de-
cide where to store an observation and when to retrieve
it [35, 60], but a desktop offers no such index. A file opened
in a pane overwrites exactly the pixels of the file that was
there before, so the model must learn for itself what to store,
when, and where. The second is symbolic reasoning inside
a generated world. Approximate dynamics look convincing
in natural video, but a terminal that receives 3+3 must print
6 every time. The third is rendering. Most of the screen
is static from one frame to the next, which tempts a model
to simply copy the previous frame, yet the regions that do
change include 10–12 px text that must stay legible at inter-
active frame rates.
To address these three problems, we introduce the Inter-
active Neural Computer (Figure 2), an end-to-end architec-
ture analogous to a Neural Turing Machine [18, 19] orga-
nized into three core modules:
• Memory (surprise-gated concept slots):

Standard perceptual metrics cannot tell whether a world
model remembers what is off screen, because a frame can
look plausible while its content is wrong. We therefore eval-
uate memory directly (Section 5.2). In our hidden-shape re-
call task, a file containing a shape is closed, the user works
elsewhere, and the file is later reopened, so the correct shape
can only come from memory. A harder variant first over-
writes the same pane with a competing file. Because our
memory is an explicit bank rather than part of an entangled
hidden state, we can also transplant or erase it at test time
and check that what the model renders changes accordingly
(Section 5.3).
Public GUI corpora rarely revisit occluded content or test
symbolic execution after the screen is cleared, so we built
two controlled datasets, Desktop and Maths, that do (Sec-
tion 4). We will release the full five-source aligned cor-
pus, including both controlled datasets and our conversion
and alignment pipelines, together with all training code and
model weights.
2. Related Work
World models of computers.
Modeling the machine
rather than the agent has begun to be explored in recent
work. Neural Computers [76] models the desktop as an
open-loop generated video of a user interacting with a
computer, which generates compelling open-loop videos,
but does not support closed-loop user interaction. State-
Craft [55] similarly uses video diffusion as its substrate,
but augments its model with an explicit symbolic mem-
ory. This helps recall (object permanence), but its design
requires access to hand-crafted symbolic accessibility-tree
state graphs. Other concurrent GUI world models rely on
external scaffolds or omit persistent memory: Solaris [1]
stores state in text prompts, while CUWM [23] and Yu et al.
[67] pair VLM or latent predictors with separate decoders
without a persistent learned memory bank. NeuralOS [46],
the precursor to these approaches, is the only open-weight,
interactive, pixel-to-pixel desktop world model, available
for direct closed-loop rollouts, without privileged symbolic
state requirements. NeuralOS requires only pixel supervi-
sion, but compressing observation history into a single re-
current LSTM state degrades performance over long roll-
outs. Our model differs from all of the above in that we
learn an addressable external memory end-to-end from pix-
els and actions without hand-crafted state schemas.
Generative interactive world models and memory.
More broadly, action-conditioned world models have pro-
gressed from single-vector recurrent state spaces [24, 25]
to large-scale video generation for driving [28], 2D and
3D worlds [12, 40, 41], and games [2, 53].
Across all

of these domains, world models face a trade-off between
storing raw history frames, which scales poorly with roll-
out length, and compressing history into a fixed-size state,
which risks overwriting older information [18, 19, 42, 69].
Fixed-size memory is much easier to manage when the en-
vironment provides an external index for reads and writes.
In 3D physical environments, geometry provides that index
‘for free’ via camera pose, field-of-view overlap [60, 66],
3D surfels [35], or raymaps [13, 59]. A 2D interface of-
fers no such index (Section 1), so the model must learn
what, where, and when to write. Existing 2D world mod-
els avoid this indexing problem by keeping a short slid-
ing window of frames [2, 53, 69] or compressing his-
tory into a single recurrent vector [24, 25, 46], both of
which lose occluded state over long rollouts.
To build
an indexed, fixed-capacity memory without 3D geometry,
we instead draw on three complementary ideas from the
representation-learning and sequence-modeling literature.
First, to decide where and when to write without spatial
coordinates, sequence models such as Differentiable Neu-
ral Computers [18, 19], slot attention [36, 72], and gated
delta networks [22, 33, 48, 63, 64] address discrete slots
by content similarity and free capacity (where). Predictive-
coding models [10, 17, 43, 51] and CAMBRIAN-S [65] gate
memory writes by whether a new observation is surprising
(when). However, content addressing and surprise gating
only work if the underlying representations capture high-
level semantics rather than static background pixels. For
what to store, we therefore draw on Joint-Embedding Pre-
dictive Architectures [4, 5, 9, 71, 74], self-supervising our
concept slots via latent next-state prediction (MEMORY-
JEPA) rather than pixel reconstruction alone.
Symbolic reasoning in generated worlds.
Learning
symbolic rules and multi-digit arithmetic purely through
pixel diffusion [12, 40, 41] is sample-inefficient.
Pre-
trained vision–language models (VLMs) [6, 7] already pos-
sess strong symbolic reasoning, though in computer use re-
search they are typically trained as external agents operat-
ing existing interfaces [3, 16, 34, 44, 45, 49, 52, 61, 75].
We instead bootstrap symbolic execution inside the world
model from a pretrained VLM, supervising its query to-
kens [14, 38, 39] with the outcome text rather than only the
diffusion loss (Section 3.2).

3.2. Compute
We bootstrap symbolic execution capabilities from a pre-
trained vision–language model. Learning exact arithmetic
purely from pixels is prohibitively slow, and hand-crafted
state graphs [55] do not scale across open-ended applica-
tions or general world models. However, pretrained VLMs
already have symbolic reasoning capabilities. Given this,
we asked whether a VLM backbone could guide our inter-
face diffusion module directly.
The problem is that a VLM cannot be plugged into a
diffusion model out of the box. Attending over prompt-
prefix states [xt; ˜Rt; at] ( ˜Rt: Rt projected into the VLM’s
embedding space) without explicit symbolic supervision
(Lexe = 0), yields 0.0% arithmetic accuracy (Section S4.3).
Another alternative, conditioning on decoded text yt, made
each state-generation step of the outer world model very
slow, as we had to wait for slow test-time autoregressive
decoding from the VLM.

paying the test-time decoding penalty, we build on recent
methods that connect autoregressive VLMs to diffusion de-
coders using learnable query tokens [14, 38, 39] (Figure S2
in Section S1). We insert Nout = 16 learnable query to-

VL model with a frozen vision tower and LoRA-adapted
language backbone (Qwen3-VL-2B-Instruct [6] /
Qwen2.5-VL-3B-Instruct [7, 29]) strictly between
the multimodal prefix and the training target yt, the text of

4. Training Corpus and Data Mixture
Training a world model to function as a usable computer
requires training examples of both (a) open-world GUI di-
versity (cursor dynamics, window management, and varied
typography), and (b) controlled multi-step workflows where
off-screen files or cleared variables uniquely determine fu-
ture frames. Public GUI corpora alone rarely revisit oc-
cluded state or test symbolic execution after screen clears.
Due to this, we chose to curate five separate datasets, which
we group into three regimes (Figures S5–S7 and Table S2
in Section S3):
1. Three open-world GUI corpora (AgentNet, ProCUA-
SFT, and CUA-Gym, with > 2.1 TB raw, 173,975
trajectories / 8.83 M steps):
Human recordings on
Windows, macOS, and Ubuntu from (1) AgentNet [56]
(21,957 cleaned episodes), plus Ubuntu rollouts from
(2) ProCUA-SFT [32] (92,964 Kimi-K2.5 episodes) and
(3) CUA-Gym (55,139 Qwen3.5 VM episodes).
2. Controlled XFCE file persistence (Desktop, source 4):
Hand-collected VS Code sessions (768 train, 96 eval
episodes in 32 matched triplets) where a geometric dia-
gram (triangle, circle, or star) is edited, occluded for 13–
256 steps while competing files are edited in the same
pane, and reopened from pixel-identical frames.
3. Controlled XFCE cleared-screen CLI (Maths, source
5): Interactive Python REPL sessions (4,000 train, 300
eval episodes, four task families) where variables (q =
854) are cleared via Ctrl+L before evaluating queries
(q * 738).
Synthesis of sources.
All 16:9 recordings are letterboxed
onto a 4:3 canvas, and pyautogui scripts are parsed into
abstract syntax trees without being executed, which lets us
filter 194 corrupted gap/scroll records and fix an undocu-
mented post-action frame offset in ProCUA-SFT so every
step obeys (xt, at) →xt+1 (Section S3). Each step emits
a verbatim keystroke string (preserving character order and
Ctrl+L) for Compute, plus (y, x) cursor heat maps, click
flags, and held-key vectors for Memory and Interface.
Data mixtures, training windows, and public release.
Three of our five sources are already public. Upon publica-
tion, we will release the full aligned corpus, including Desk-
top and Maths, along with our alignment pipelines, mixture
manifests, training code, and model weights.
To fully evaluate all of our architectural mechanisms un-
der academic compute budgets, our multi-seed ablations
and long-horizon rollouts train on 128-step windows (64-
frame warm-up + 64-frame BPTT) for 3,000–9,000 steps
(48,000–144,000 128-step trajectories) on the Dense In-
teractive Mixture (50% Desktop, 50% Maths), comple-
mented by a high-resolution 1024×768 transfer run on
the Broad Mixture (75.0% equally stratified AgentNet,
ProCUA-SFT, and CUA-Gym, 12.5% Desktop, and 12.5%
Maths, comprising 12,268 FLUX.1-schnell episodes
/ 325,573 transitions resampled to 694,266 windows (for
more details see Table S2 and Sections S4, S6, and S7 in
the Supplementary Material)).

5.3. Memory is Causal and Editable
High recall does not by itself show that the learned mem-
ory module is responsible. For example, abstract concepts
such as shapes could have been carried by the LSTM, or
by the renderer. However, because our memory is an ex-
plicit bank Mt, rather than part of an entangled latent state,
we can test this directly. We hold the screen xt, the ac-
tion at, and the LSTM (hidden-state) fixed, and change
only Mt (Figure 4). With Mt intact, the model recalls the
true shape (a triangle). When we transplant the memory
with a donor Mt ←M donor
t
from an episode in which a
circle was drawn, the model renders the donor’s circle on
64.7±1.1% of trials (Table 2), and when we block memory
reads, the stored file is erased. What the model draws on re-
opening a file is therefore determined by the contents of its
slots, which a supervisor can inspect, replace, or potentially
even wipe without resetting the rest of the latent state of our
model.
Ablations.
In ablations at 3,000 steps (Section S4), re-
moving MEMORY-JEPA (LJEPA=0) drops edited-file re-
call to chance (32.1%), and removing residual prediction
drops terminal OCR from 43.5% to 0.2% (p=0.0007). For
full ablations of every component of our model, see the Sup-
plementary Material.
6. Conclusion
We introduce a world model of a computer, with a novel
surprise-gated memory component. Our model improves
on the baselines in edited-region fidelity, text legibility, and
resistance to overwriting. It learns how to interact with a
modular and detachable memory state, and is significantly
more functional (useful) than the learned alternatives.
Due to academic compute limits, we trained on only a
small portion of our full data mixture, and performance has
not yet saturated, so scaling up training is a clear next step.
Another exciting angle for future work is to explore
open-ended interface generation, where applications which
augment human capabilities are generated in real time
around a user depending on their goals, abilities, and en-
vironment.

S1. Method Equations, Diagrams, and Evalua-
tion Protocols
The main paper asks whether a generative world model can
be a usable computer rather than merely render plausible
frames. In order to achieve this goal, we first needed to
overcome three critical problems:
1. Given the lack of 3D camera pose to rely on, world mod-
els of computers forget off-screen state, even over short
time-horizons.
2. World models in general tend to struggle with explicit
symbolic reasoning, but nowhere is this more apparent
than in a world model of a computer. Baseline mod-
els often generate plausible-looking but patently illogi-
cal text on screen.
3. As ∼95% of a desktop can remain static from one frame
to the next (think of a terminal shell), diffusing the next
screen state without weighting the rendering loss can
cause the model to collapse into simply copying the pre-
vious frame.
Our Interactive Neural Computer (Main Figure 2) ad-
dresses these three failures in turn by separating the system
into three modules, trained end-to-end: Memory, Com-
pute, and Interface. We give each module targeted super-
vision rather than asking pixel diffusion alone to teach all
three.
This section ‘opens the hood’ of the main paper’s Fig-
ure 2, and provides the intuition, exact equations, and eval-
uation protocols behind the architecture introduced in the
main paper’s Sections 3 and 5.
We organize the details into four parts: why each training
objective and addressing rule takes the form it does (Sec-
tion S1.1), how the architecture stays compact and scales
to 1024×768 (Section S1.2), how we test functional useful-
ness beyond single-step image metrics (Section S1.3), and
how we train long-horizon memory under bounded GPU
memory (Section S1.4).

How does the memory decide whether to update an ex-
isting slot or claim a free one?
Unlike 3D physical world
models, a computer interface has no camera pose for mem-
ory addressing. Screen coordinates are not a viable replace-
ment either, because a new application window routinely
opens over the exact coordinates of a closed one—which
would simply overwrite old files. The third alternative, a
fixed-length queue, eventually fills up and evicts long-lived
state.
We confront these issues by following the Differentiable
Neural Computer (DNC) [19]. A write chooses between
two destinations (Figure S1, Step 3): it either updates the
occupied slot whose stored content best matches the current
screen, or claims the first empty slot.
Each slot m ∈{1, . . . , M} stores a key Kt−1,m ∈
R64 and an occupancy ut−1,m ∈[0, 1], both initialized
to zero.
A gate γt ∈(0, 1) (Main Section 3.1) mea-
sures how strongly the current write key kt matches the
best occupied slot and blends a content distribution ac,m
with an allocation distribution aa,m as wt,m = γtac,m +
(1 −γt)aa,m—updating an existing slot when re-editing a
known file (γt ≈1), and claiming a free slot for a new
file (γt ≈0). For content matching, we score each slot by
its similarity to kt and add a log-occupancy bias so empty
slots receive negligible weight once any slot is occupied.
For allocation, rather than maintaining the DNC’s discrete
usage-sorted free list, we claim free slots from left to right
differentiably: we favor low-occupancy slots and penalize
every slot m by how many earlier slots j < m are still be-

Why does standard diffusion loss fail on a mostly static
desktop?
Most desktop pixels do not move much be-
tween state transitions. Re-synthesizing the entire frame
at every step wastes capacity redrawing static backgrounds,
and tends to blur small interface text. Predicting only the
frame-to-frame change, then, seems like a good idea. It
would avoid touching static text, by only predicting the
delta in the state on each timestep. However, this format
introduces another trap: an unweighted loss is dominated
by the unchanged patches, tempting the renderer to predict
zero change everywhere and freeze the screen.

Approximate

A practical neural computer must keep memory overhead
constant as sessions grow long and scale to high-resolution
typography without blowing up parameter count or latency.

how are user actions encoded?

growing frame buffer or KV cache, memory cost is inde-

state per episode. In summary, the fixed memory compo-
nent adds very little overhead, leaving substantial room to
scale it up.

S1.4. Training and Optimization
How do we train a memory to survive long occlusions un-
der bounded GPU memory? Every model trains on win-
dows of 128 consecutive frames (Figure S10).
The first
64 frames are a warm-up: the model runs forward on them
without gradients, so that by frame 65 its memory already
holds what the episode showed earlier, such as a file that
was edited and then closed. The remaining 64 frames are
trained with truncated BPTT, with a loss on 8 of them. We
use AdamW (β1=0.9, β2=0.999, weight decay 0.01), a lin-
ear learning-rate warm-up to a constant rate (200 steps at
512×384; 150 to 300 at 1024×768), global gradient-norm
clipping at 1.0, and a T=1,000 diffusion schedule. Table S3
gives the training budget and sampling settings of every
model, and Table S1 the remaining settings of the 512×384
model. All 512×384 models are initialized from NEURA-
LOS’s joint-272k checkpoint; the baseline is fine-tuned
with the published NEURALOS recipe. The 1024×768 runs
of Ours stop at a wall-clock limit, so their step counts are
means over seeds (867, 834 and 826 steps on the Dense
Interactive Mixture; 1,510, 2,105 and 2,069 on the Broad
Mixture). Notably, every budget difference favors the base-
lines rather than Ours: fine-tuned NEURALOS sees three
times as many windows as our 512×384 model, and COPY-
ONLY sees about four times as many as ours on the Dense
Interactive Mixture. The 1024×768 models use the mem-
ory and loss settings of Table S1 with a learning rate of 10−5
for pretrained weights and 10−4 (1.5×10−4 on the Dense
Interactive Mixture) for new modules.

S4. Four Ablations at 3,000 Steps
The ablations are separate, shorter experiments. Every arm,
including the full model, was trained for only 3,000 steps
(Section S1.4), so the numbers in Sections S4.1 to S4.4
should be compared with each other and not with the main
tables, which report longer training.
In this setting, the full model reaches 40.3±0.7% edited-
file recall, 28.2 ± 2.1% cleared-screen answers and 43.5 ±
2.2% Terminal OCR. Each ablation removes one compo-
nent from the full model2. Answer accuracy is counted over
124 transitions, so it moves in steps of 0.8 points; several
arms that keep the execution loss average to the same value,
28.2% (35 of 124).
S4.1. Memory Supervision (MEMORY-JEPA)
The memory objective is intended to supply a learning sig-
nal across an occlusion, where a hidden file affects only a
small patch of the single reopen frame. Without the mem-
ory objective (LJEPA=0), edited-file recall is 32.1% (seeds
25.9% and 38.3%), against 40.3±0.7% for the full model of
the same experiment; cleared-screen answers (28.2%) and
Terminal OCR (45.2%) are unchanged.
S4.2. Surprise Gating
Writing on every frame (ηt ≡1) gives 35.8% edited-file
recall (seeds 33.3% and 38.3%), against 40.3±0.7% for the
full model of the same experiment, which uses the surprise
gate [17, 43, 65].
S4.3. Symbolic Compute Supervision
Cleared-screen answer accuracy scores the VLM’s decoded
text, not the rendered screen. With the execution losses, the
full model answers 28.2 ± 2.1% of the 124 cleared-screen
queries (15.5% of arithmetic queries and 38.7% of number-
recall queries), against 65.5 ± 0.5% of the 200 queries
whose operands are still on screen. Without them (Lexe=0,
Lprobe=0), cleared-screen answer accuracy is 0.0% in all
three seeds, and Hout

to 0.0%. The answer does not arise from rendering supervi-
sion alone.

S9. Generalization to Unseen Desktops
Ours generalizes to unseen desktops better than NEURA-
LOS [46]: trained on the same recordings, the two models
render VS Code with similar fidelity, but on Windows, ma-
cOS and Ubuntu desktops NEURALOS loses 20.0 dB PSNR
and ours 11.1 dB (Figure S15).
Setup.
We compare the two 512×384 models of Table S3.
Both start from the NEURALOS joint-272k checkpoint
and are trained only on the Dense Interactive Mixture, our
recordings of VS Code in an XFCE desktop (Desktop) and
of a Python REPL (Maths); NEURALOS is fine-tuned for
9,000 steps and ours for 3,000. Neither model has seen
an AgentNet frame. The seen-app set is 30 held-out VS
Code episodes from Desktop. The unseen-desktop set is 30
AgentNet [56] dev episodes: 16 from Windows, 9 from ma-
cOS and 5 from Ubuntu, covering browsers, office and pre-
sentation software, a terminal, system settings and maps; 4
of them show VS Code under another operating system and
theme. Each frame is predicted teacher-forced, that is, from
the true preceding frames and actions, so both models al-
ways receive the real current screen. We score the first 12
transitions of each episode, sampled with 32 DDIM steps,
for one training seed and one sampling seed per model. We
report PSNR and LPIPS [70], a learned perceptual distance
computed on AlexNet features (lower is better), averaged
within each episode and then over episodes, with 95% boot-
strap intervals over episodes.
Result.
On VS Code the two models are close: 26.2
against 25.8 dB PSNR and 0.097 against 0.120 LPIPS for
ours and NEURALOS. On unseen desktops NEURALOS
falls to 5.8 dB and 0.86 LPIPS and ours to 15.1 dB and 0.34;
the intervals do not overlap (Figure S15). In the generated
screens of Figure S16, NEURALOS replaces a Windows or
macOS screen with a dark screen, with illegible text in the
Windows example, while ours keeps the screen it is given.
When an action opens a new page or a dialog on these
desktops, ours keeps the old screen, with artifacts.
Our
1024×768 model, trained on the same mixture and scored
on the same episodes after downsampling to 512×384, falls
from 30.4 to 19.2 dB.
Why NEURALOS fails.
In NEURALOS the UNet that
draws the next screen never sees the current one: the latent
zt of the current screen (16×48×64 = 49,152 numbers)
enters the lower of two stacked LSTMs only as one atten-
tion read-out of 1,024 numbers, and the UNet is conditioned
only on an MLP projection of the upper LSTM’s 4,096-
number output. Whatever this state does not encode about
the current screen must come from the UNet’s weights,
which have learned the screens of the training data. The
zero-shot result of Table S4 shows the same failure without
our fine-tuning: the public NEURALOS release, shown our
XFCE desktop, renders its own training desktop (9.84 dB).
S10. Broader Impact and Ethics
Off-screen state lives in an explicit memory bank, so it can
be inspected, replaced, or wiped without resetting the rest
of the model (Main Section 5.3). The main misuse risk
is the generation of deceptive screenshots or ‘spoofed’ ap-
plication sessions, which motivates provenance watermark-
ing for generative interface systems. Our in-house data are
XFCE virtual-machine recordings and contain no personal
data. The AgentNet examples in Figures S5 and S6 are
screenshots distributed with that corpus; we show none that
contain photographs of people or account details. The pub-
lic corpora are used under their licenses (AgentNet under
MIT, ProCUA-SFT under CC BY 4.0, and CUA-Gym un-
der CC0). On publication, we will release the aligned five-
source corpus, our conversion and alignment pipelines, and
our training code.
