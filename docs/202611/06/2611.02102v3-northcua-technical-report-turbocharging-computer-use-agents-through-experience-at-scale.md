## 摘要
将计算机使用智能体从单个动作扩展到复杂软件工作，需要能够把决策与完整结果联系起来的经验。我们提出 NorthCUA，一个通过规模化经验加速计算机使用智能体的集成系统。其 Experience Flywheel 向 NorthCUA Harness 提供多样化的可执行任务，后者维持长时交互、记录决策并检查任务结果。Experience Flywheel 利用这些记录来筛选经过验证的轨迹。对于未解决的任务，递归自我改进会演化可复用技能并保留已验证的里程碑，使后续尝试能够建立在先前进展之上。Staged Learning 将这些经验与来自 Experience Flywheel 的 grounding 数据相结合，通过中期训练和长时程监督微调来发展 GUI 能力。随后，策略通过桌面-Web 联合强化学习，在同一 Harness 中从新的尝试中学习，从而闭合经验生产与策略改进之间的循环。由此得到的 Nano、Mini 和 Pro 系列在报告所述评测设置下，在 GUI grounding、桌面执行和 Web 交互方面取得开源模型中的最先进结果。为获得响应更迅速的 Web 工作流，NorthCUA-Ultrafast 在预 RL 的 Nano 上将直接动作选择与开放式生成配对，提供可衡量的质量与延迟权衡。这些进展共同确立了 NorthCUA 作为一个高性能模型系列，以及作为使智能体将复杂软件工作从意图推进到完成的可复用基础。

## Abstract
Scaling computer-use agents from individual actions to complex software work requires experience that connects decisions to complete outcomes. We present NorthCUA, an integrated system for turbocharging computer-use agents through experience at scale. Its Experience Flywheel supplies diverse executable tasks to the NorthCUA Harness, which sustains long interactions, records decisions, and checks task outcomes. The Flywheel uses these records to curate verified trajectories. For unsolved tasks, recursive self-improvement evolves reusable skills and preserves verified milestones so later attempts build on earlier progress. Staged Learning combines this experience with grounding data from the Flywheel to develop GUI competence through mid-training and long-horizon supervised fine-tuning. The policy then learns from fresh attempts in the same Harness through joint desktop-web reinforcement learning, closing the loop between experience production and policy improvement. The resulting Nano, Mini, and Pro family achieves state-of-the-art results among open-source models across GUI grounding, desktop execution, and Web interaction under the reported evaluation settings. For more responsive Web workflows, NorthCUA-Ultrafast pairs direct action selection with open-ended generation on pre-RL Nano, offering a measured quality-latency tradeoff. Together, these advances establish NorthCUA as a high-performing model family and a reusable foundation for agents that carry complex software work from intent to completion.

- **三级执行作用域**：Session（跨请求的执行状态与资源）→ Round（单次用户请求的处理、预算、终止）→ Step（一次策略决策 + 工具执行与反馈，可含多次工具调用）。
- **长时程支持（三个互补机制）**：
  - *动作感知视觉上下文*：滑动窗口保留最近 k 帧，历史帧叠加动作标记（点击点、拖拽路径、滚动方向、文本/按键徽章），最新帧保持干净；
  - *任务保持的上下文压缩*：保护当前交互、摘要任务进展（目标、约束、事实、决策、已完成/失败、待办、产物引用）、过滤易失效的 GUI 定位符（坐标/元素引用）；
  - *结构化工作记忆*：提供 note 工具，让智能体主动记录事实、纠正、预防、约束、决策、检查点，并支持替换过期条目。
- **Agent-as-a-Judge 评估器**：复用 Agent Kit 工具，先检索录制证据（轨迹、截图、DOM/无障碍快照、产物），再对**仍存活的原始工作区**做实时检查（只读 shell、GUI、浏览器探针）；输出多维报告（任务完成、过程质量、效率、安全与副作用、失败诊断、判断不确定性），且每条判断必须绑定证据与不确定性。
- **Batch Rollout Service**：集中式控制器 + 独立 E2B 沙箱设备 worker（长连接 WebSocket）；流水线式预准备队列；分阶段并发限制 + 控制器压力反馈；断连后先判定"可续评/需重跑"；交付前校验轨迹、观察、评估是否完整且同源。

**(B) Experience Flywheel：规模化经验与 grounding 生产**
- **单步 UI grounding 两条路线**：
  - *广覆盖视觉/结构路线*：公共 UI 数据集 + 网页采集 + 智能体轨迹截图 → OmniParser 检测控件 + 无障碍元数据 → 合并为控件记录（裁剪、原图坐标、名称、角色、颜色、上下文）→ LLM 生成名称/位置/操作三类查询变体，共享同一坐标；
  - *文档驱动功能定位路线*：识别应用与版本 → 检索在线手册中的图示控件与功能描述 → 图像嵌入取 top-k → 结合面板与选中上下文消歧（如"对齐对象左边缘"vs"段落左对齐"）→ 生成功能化查询。
  - 质检：几何正确性 + 多模态复核 + 去重与覆盖检查。
- **任务构造三条互补路线**：
  - *Scaling Intents*：从软件支持的操作 + 文件/网站内容反推请求；桌面基础任务按"选功能→配文件→写请求→组装 CaseSpec"；长流程任务用场景蓝图 + DAG 规划（阶段、前置依赖、内容依赖、执行顺序）后落地材料与请求；Web 任务从站点内容与控制推导目标、初始记录与判定；
  - *Scaling Environments*：用 EnvAgent 为来源请求补齐输入文件与启动计划（检索、读文件、缺则生成、检查一致性）；Web 侧从开源前端或公开 URL 重建本地站点（观察→本地实现→浏览器测试→修复→重置初始数据→打包），并支持"仓库 issue 驱动的浏览器前端测试"闭环（Coding Agent 改码 → Web Test Agent 复现测试 → 报告回传）；
  - *Scaling Verifiers*：以带可执行验证器的种子任务为起点，做**分解 / 变化 / 组合**，请求、初始状态、验证器同步改写；再用 GUI 执行试验 + 验证器探针（正控、负控、近似错、等价替代）双重检验后入池。
- **递归自我改进（RSI）两条管线**（针对普通收集失败但构造有效的难题）：
  - *技能引导的递归探索*：探索→固化候选技能（何时用、步骤、如何自检、应避免的坑）→独立 agent 冻结验证→带技能重试原任务→新发现回流再固化；
  - *里程碑引导的轨迹搜索*：规划 agent 依据请求与验证器代码拆出"子任务—检查"对；通过检查即保存 E2B 工作区快照 + agent 上下文作为检查点；以检查点为节点、动作序列为分支构成搜索树；最终由**原始验证器**做全任务验收；未完成尝试中通过里程碑的片段可作为子任务级示范保留。

**(C) Staged Learning：从经验到能力**
1. **Broad GUI Mid-training**：约 10 万+ 轨迹、400 万+ GUI 交互步、约 4 万 grounding 样本；覆盖办公、视觉媒体、文件管理、CAD/3D、医学影像可视化、Web 检索/表单/人机验证/前端测试等；用评估器做结果导向筛选；同时把评估器自身轨迹作为独立"判断任务"训练样本。
2. **Verified Long-horizon SFT**：约 3,000 条轨迹、31 万步；要求**原始验证器全任务通过** + 依赖关系检查 + 执行质量与清洗（拒绝畸形工具调用、无效循环，保留"出错—纠正—完成"的连贯恢复）；优先长依赖、难工作流，同时保持应用多样性。
3. **Joint Desktop–Web Agentic RL**：
   - 任务筛选：在 SFT 检查点上每例至少 5 次 rollout，**只保留有效验证器分数存在差异**的任务（全同分则组内优势为零）；
   - 分组执行：同一任务组成员共享请求、初始状态、验证器、预算，但各自独立沙箱；
   - **GRPO** 组内相对优势：$A_i = \dfrac{R_i - \bar R}{s_R + \epsilon}$，$\bar R$ 与 $s_R$ 均在任务组内计算；
   - **决策时输入保留**：记录每次模型调用的输入、响应、生成对数概率、行为策略版本；仅当文本与有序图像历史构成"同版本下的前缀扩展"才拼接，图像替换（干净帧→动作叠加）、图像驱逐、摘要改写、版本变化都会**开启新训练段**；重复出现的历史响应只作上下文、被 mask 掉；
   - **完整尝试加权**：优势按"完整尝试"计算一次并共享给其所有段；损失按尝试内全部目标 token 归一后再对尝试平均，避免"被切得越碎权重越大"；
   - 工程优化：未变图像复用 CPU 预处理张量；Zstandard 无损压缩图像张量（实测载荷降至 2.8%，即缩小 97.2%）；异步模式下"暂停新调用→等待在途→提交权重→恢复"。

**(D) NorthCUA-Ultrafast（附录 E.7）**
- 在预 RL 的 Nano 上加入**choice head**：对 CLICK/HOVER/CHECK/UNCHECK/FILL/NATIVE/RESPOND 七类路由与候选目标做有限选择，直接构造工具调用，绕过逐 token 解码；开放式输出（填文本、最终回复）仍走原生生成。
- 两变体：Head-only（4.21M 参数，约 0.045%）与 Head + LoRA（47.49M，约 0.505%，LoRA 仅分类时启用、生成时关闭）。
- 置信度阈值 0.8，低置信/引用失效/不支持的观察面回退到原生生成。
