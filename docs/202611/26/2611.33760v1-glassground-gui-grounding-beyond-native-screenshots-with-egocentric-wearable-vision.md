## 摘要
可穿戴助手在无法直接访问截图时，必须从相机观测中定位界面元素，然而现有的 GUI 定位基准主要评估原生截图。我们提出 GlassGround，一个新基准，它在保持 GUI 状态、指令和目标固定的同时，将原生截图与可穿戴相机观测配对。GlassGround 包含 Android 和 iOS 上的 3,250 个任务，使用四种可穿戴设备在四种观看条件下采集。在十个开源模型上，平均定位准确率从截图上的 94.8% 下降到相机图像上的 48.5%。进一步分析表明，目标尺度、屏幕几何形状和背景的变化不能完全解释这种性能下降。随后我们研究两种缩小该差距的方法。在推理时，局部缩放和屏幕矫正有帮助，但仍留下大部分差距。对于训练时适配，我们基于 GlassGround 的配对视图设计，引入 PairDistill，一个在坐标监督之外对齐跨视图目标表示的基线。它在独立收集的数据上训练，且在推理时不使用截图，在两个骨干网络上将相机图像准确率分别提高 9.4 和 12.2 个百分点，并可迁移到未见过的设备和操作系统。结合局部缩放，它达到 69.6% 和 64.4%，但并未弥合差距。GlassGround 数据集和代码可在 https://github.com/yunnw/GlassGround 获取。

## Abstract
Wearable assistants must localize interface elements from camera observations when direct screenshot access is unavailable, yet existing GUI grounding benchmarks primarily evaluate native screenshots. We introduce GlassGround, a new benchmark that pairs native screenshots with wearable camera observations while holding GUI states, instructions, and targets fixed. GlassGround contains 3,250 tasks across Android and iOS, captured using four wearable devices under four viewing conditions. Across ten open-source models, mean grounding accuracy drops from 94.8% on screenshots to 48.5% on camera images. Further analysis reveals that changes in target scale, screen geometry, and background cannot fully explain this performance degradation. We then study two ways to narrow this gap. At inference time, local zooming and screen rectification help but leave most of the gap. For training-time adaptation, we build on GlassGround's paired-view design and introduce PairDistill, a baseline that aligns target representations across views alongside coordinate supervision. Trained on independently collected data and using no screenshots at inference, it improves camera-image accuracy by 9.4 and 12.2 points on two backbones and transfers to unseen devices and operating systems. Combined with local zooming, it reaches 69.6% and 64.4%, but does not close the gap. The GlassGround dataset and code are available at https://github.com/yunnw/GlassGround.

## 1. 核心问题与研究动机

- **现实背景**：智能眼镜等可穿戴 AI 助手需要通过第一人称（egocentric）摄像头观察用户手机屏幕，进而给出分步操作指导；这类助手往往**无法直接获取手机截图或底层界面状态**，只能依赖相机画面完成 GUI 元素定位（GUI grounding）。
- **核心矛盾**：现有 GUI grounding 基准（ScreenSpot、ScreenSpot-Pro、OSWorld-G 等）几乎全部基于**原生数字截图**评估；而相机拍摄的屏幕数据集（如 PC-Restore、ScreenShotMatcher）主要面向**图像修复或截图检索**，并非指令条件下的定位任务。
- **物理观测带来的挑战**：在可穿戴相机视角下，屏幕只占画面一小部分，存在透视畸变、光照变化、屏幕反射、摩尔纹、显示-相机成像效应等，可能使模型在截图上能定位的目标在相机图像上失败。
- **研究问题**：物理观测（相机视图）相比原生截图会造成多大的 grounding 性能损失？这种损失能否由目标尺度、屏幕几何、背景变化解释？推理时处理与训练时适配能在多大程度上弥补？

## 2. 方法论

### 2.1 GlassGround 基准：配对视图设计

- **任务形式化**：任务定义为三元组 $(s, q, e)$，即 GUI 状态、指令、目标元素。对同一任务，clean 观测 $I_c = O_c(s)$ 为原生截图；physical 观测 $I_p^{(k)} = O_p(s;\phi_k)$ 为同一状态在物理屏幕上被可穿戴设备拍摄的图像。
- **配对关系**：每个 GUI 状态产生 1 个 clean 实例与 $K=16$ 个 physical 实例，共享同一指令与目标：
  $(I_c, q, y_c) \leftrightarrow \{(I_p^{(k)}, q, y_p^{(k)})\}_{k=1}^{K}$
- **观测偏移（observation shift）**：仅改变观测过程而固定任务内容，从而将性能差异归因于物理观测本身。

### 2.2 物理采集协议

- **保持 GUI 内容一致**：将每张原生截图**全屏显示在原手机上**再拍摄，避免动态界面内容变化。
- **设备维度（4 种）**：Meta Project Aria Gen 1、Aria Gen 2（研究型第一人称眼镜），Meta Quest 3、Samsung Galaxy XR（消费级 XR 头显）。
- **光照维度（4 种）**：Indoor-Dark、Indoor-Lamp、Outdoor-Shade、Outdoor-Sun，共 $4\times4=16$ 种采集设置。
- **手持采集**：操作者自然握持手机，保留轻微模糊、反射、局部遮挡等自然伪影；若目标部分出界则重拍。

### 2.3 任务构建（Clean 侧）

- 用 OmniParser + OCR 发现候选元素区域，赋予 Set-of-Mark 编号；
- 用 VLM（Claude Fable 5.1）**逐候选**判断是否适合作为目标，并生成指令、分类为 text/visual/functional/positional 四类（VLM 不预测目标区域）；
- **100% 人工审核**：核验目标有效性、可点击性、指令清晰度与类型、边界框准确性，可保留/改写/拒绝，并可补充遗漏目标。

### 2.4 物理真值迁移

- 用 YOLO11n-pose 检测 physical 图像中的屏幕四角，**人工逐图校正**；
- 由四角对应关系计算单应矩阵 $H_k$，满足 $c_j^{(k)} = \pi(H_k \tilde{c}_j)$；
- 将 clean 目标区域投影到 physical 图像，得到**多边形**真值（保留透视几何）；
- 对局部错位可选 **TPS 网格细化**：$T_k(x) = \pi(H_k \tilde{x}) + f_k(x)$。

### 2.5 中间观测分解（分析用）

- **Resized**：将截图缩放至与 physical 中目标面积一致；
- **Warped**：用单应性把截图投影到 physical 的屏幕区域并保留真实背景；
- **Rectified**：用逆单应性把 physical 图像矫正为正视图（保留相机像素内容）；
- 通过 Clean → Resized → Warped → Physical 的逐级对比定位损失来源。

### 2.6 PairDistill：跨视图目标表示对齐

- **核心思想**：利用配对的原生截图作为“教师”，在训练时监督相机图像“学生”对同一目标的表示，同时保留坐标监督；**推理时只用相机图像与指令，不用截图**。
- **教师/学生**：同源初始化，教师冻结处理 clean 截图；学生对 physical 图像 + 指令做 LoRA 适配；从 patch merger 输出提取视觉 token 特征 $F_c, F_p$。
- **目标池化**：按 token 与目标区域的重叠面积加权：
  $\text{Pool}_R(F) = \sum_j w_j f_j,\quad w_j = \frac{|R \cap \Omega_j|}{\sum_k |R \cap \Omega_k|}$
- 减去各图全部视觉 token 均值得到目标表示 $z_c, z_p$。
- **训练目标**：
  $\mathcal{L}_{PD} = \mathbb{E}_D[\mathcal{L}_{SFT}(I_p, q, a) + \lambda \mathcal{L}_{align}],\quad \mathcal{L}_{align} = 1 - \cos(z_p, z_c)$，取 $\lambda = 1$。
- **训练数据**：独立于 GlassGround，从 AMEX 的 Android 截图在固定支架上拍摄采集，共 4,636 图像对、76,224 个目标，覆盖 4 种设备-光照组合；LoRA rank 16、scaling 32，AdamW、lr $10^{-4}$、3 epoch、共 3,477 次更新，采用 WiSE-FT 权重插值（$\alpha=0.5$，推理时 LoRA scaling 降为 16），并加入尺度增强（0.2 不变 / 0.4 放大 / 0.4 缩小）。

- **充分性评价**：整体实验设计**较为充分且客观**——配对设计消除了任务内容混杂，匹配子集保证闭源/开源可比，多种子 + bootstrap 增强统计可信度，泛化实验覆盖未见设备/光照/OS。但闭源模型仅在 500 任务子集评估，且未报告训练算力成本。

## 6. 主要结论与发现

- **显著物理 grounding 鸿沟**：10 个开源模型平均准确率从 **94.8%（Clean）降至 48.5%（Physical）**，个体下降 36.1–56.2 pp；闭源模型同样下降 26.9–67.1 pp。

- **鸿沟无法被单一因素解释**：逐级分解（Clean → Resized → Warped → Physical）显示，把截图缩放到与物理目标同等像素面积只能挽回一小部分损失，说明**目标尺度并非主因**；用单应性把截图投影到真实屏幕位置并保留真实背景（Warped）能进一步恢复，说明**屏幕几何与背景上下文确有贡献**；但 Warped 仍明显低于 Clean，剩余差距只能归因于相机成像本身——摩尔纹、屏幕反射、色偏/亮度、轻微模糊与压缩噪声等显示—相机效应。换言之，物理鸿沟是**尺度、几何、背景、成像四类因素的叠加**，且成像因素是其中最难通过简单预处理消除的部分。
- **几何矫正收益有限但稳定**：Oracle 矫正（人工四角）与 Auto 矫正（检测器四角）均能缩小差距，且两者差距很小，说明自动四角检测已足够可靠，工程上不必依赖人工标注；但矫正只是把物理图像“拉回正视图”，并未消除反射与摩尔纹，因此**无法闭合鸿沟**。
- **推理时补救的天花板较低**：ReGround（局部裁剪后二次定位）在多数模型上带来正增益，但增益幅度远小于训练时适配，且额外增加一次模型调用，属于“性价比有限”的补救手段。
- **训练时适配更有效且不牺牲原生性能**：PairDistill 在两个骨干上均显著提升 Physical 准确率，同时借助 WiSE-FT 权重插值把 Clean 性能基本保持在原水平，说明跨视图表示对齐可以在**不引入推理开销、不使用截图**的前提下获得物理鲁棒性；叠加尺度增强（PD+Aug）后增益进一步提升，且三个随机种子的标准差较小，结果稳定。
- **泛化性成立**：在未见设备（Aria Gen 2、Galaxy XR）、未见光照（Outdoor-Shade/Sun）、跨操作系统（Android 训练 → iOS 测试）以及剔除与训练集重叠应用后的子集上，PairDistill 的增益均保持为正，说明其学到的是**视图层面的不变性**而非对特定设备、光照或应用界面的记忆。
- **模型间差异的结构性观察**：GUI 专用模型在 Clean 上普遍更强，但物理条件下的绝对跌幅也往往更大，呈现“**原生越强、跌落越狠**”的倾向；通用 VLM 的物理鲁棒性略好，但 Clean 与 Physical 的绝对水平都偏低。闭源模型整体领先，然而 26.9–67.1 pp 的下降说明**鸿沟是普遍现象而非开源模型特有缺陷**。物理条件下的排序与 Clean 条件下的排序并不完全一致，提示仅用截图基准选型可能误导可穿戴场景的模型选择。

## 7. 局限性

- **观测形式受限**：物理侧采用“把静态截图全屏显示在手机上再拍摄”的方式以保证内容一致，因而**未覆盖动态 UI**（滚动、动画、加载态、通知弹窗、视频播放）与连续视频流下的时序定位。
- **采集姿态理想化**：手持采集保留自然伪影，但仍是**站立/坐姿下的相对稳定握持**，未覆盖真实佩戴行走、运动中模糊、手指遮挡、镜片反光叠加等更严苛情形。
- **设备与屏幕形态有限**：仅涉及手机屏幕 + 4 种头戴/眼镜设备，未覆盖平板、桌面显示器、多窗口、曲面屏或折叠屏，单应性假设（平面屏幕）在这些场景下会退化。
- **真值精度依赖投影**：物理真值由单应性投影得到，屏幕反光、边框遮挡或轻微弯曲会引入多边形偏差；TPS 网格细化是可选步骤，论文未系统报告其对最终指标的影响幅度。
- **适配验证范围窄**：PairDistill 只在 2 个骨干上验证，未覆盖更大规模模型或闭源模型，也未探索全参数微调与 LoRA 之外的适配方式。
- **算力与成本透明度不足**：未报告训练 GPU 数量、总 GPU 小时与能耗，也未量化 4 种设备 × 4 种光照的采集人力与时间成本，复现与成本评估受限。
- **语言与地域覆盖未说明**：102 个应用的语言分布、地区性应用占比未明确，跨语言界面的泛化性无法判断。

## 8. 意义与启发

- **对基准建设的意义**：GlassGround 通过“同一 GUI 状态、配对 clean/physical 观测”的设计，把“观测条件”从“任务内容”中剥离出来，为**观测偏移（observation shift）**这一此前缺乏受控测量的维度提供了可复用的实验范式；其真值迁移流程（检测四角 → 单应性 → 多边形真值 → 可选细化）也可迁移到其他“屏幕被相机拍摄”的定位任务。
- **对系统设计的启示**：既然几何矫正只能挽回有限损失、而表示层对齐收益更大，可穿戴 GUI 助手的鲁棒性应更多投入在**训练阶段的跨视图对齐**，而非推理阶段的图像预处理流水线；同时 Auto 矫正接近 Oracle 的结果说明轻量检测器即可承担几何归一化。
- **对评测实践的提醒**：截图基准上的高分**不能直接外推**到相机视图，且模型排序会随观测条件改变；面向真实可穿戴部署的选型应包含物理观测条件下的评测。
- **开放问题**：动态界面与视频流下的物理 grounding、多屏幕/非平面场景的单应性失效、以及反射与摩尔纹的显式建模或数据增广，仍是该方向尚未解决的核心挑战。
