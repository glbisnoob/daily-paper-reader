Abstract
GUI agents can formulate a correct immediate plan in their
reasoning yet emit an action that fails to execute it, creat-
ing an execution gap. This recurring mismatch undermines
reliable task completion, as a single execution error can
derail a multi-step workflow. In outcome-supervised rein-
forcement learning, broadcasting a negative response-level
advantage across all generated tokens risks penalizing valid
planning together with erroneous execution. To address this
credit-assignment conflict, we introduce PACT (Plan–Action
Consistency Training), a training framework that combines
reference-aligned plan protection and plan-aligned action
repair without altering the original scalar action reward.
Using annotated reference actions to identify execution gaps,
PACT protects the verified plan by masking negative policy-
gradient contributions across its token span. Keeping the
generated reasoning unchanged as context, it then favors the
reference action over the emitted erroneous action through a
preference surrogate with stop-gradient pair weights. Com-
pared with the outcome-only baseline, PACT raises Android-
World task success from 60.34% to 68.97% (+8.63 pp), while
improving rule-based plan–action consistency on Android-
Control High from 83.71% to 89.74% (+6.03 pp). Adapting
PACT to desktop agents also improves task success from
40.92% to 44.17% (+3.25 pp) on the full 369-task OSWorld
benchmark. Together, these results establish PACT as an
effective credit-assignment framework for bridging execu-
tion gaps and improving task completion across mobile and
desktop GUI environments.
1. Introduction
GUI agents must translate visual interfaces and user goals
into executable interactions. Yet formulating a correct imme-
diate plan in generated reasoning does not guarantee that the
emitted action executes it. For example, an agent may state
that it will tap a visible + button, yet emit an application-
launch command instead (Figure 1). This execution gap is
distinct from a planning error: the response already contains
a valid immediate plan, but the final action fails to realize it.
Building on prior diagnostic studies of reasoning–execution
gaps in mobile agents [5], we investigate how training can
preserve valid plans within failed responses while repairing
their execution.
In reinforcement learning (RL), such execution gaps cre-
ate a credit-assignment problem. Several GUI-agent meth-
ods use Group Relative Policy Optimization (GRPO) or its
variants to learn from action feedback [7, 9]. In implemen-
tations that broadcast one response-level advantage across
reasoning and action tokens [17], a negative advantage penal-
izes valid planning alongside erroneous execution. A scalar
thought–action consistency reward [9] does not determine
the direction of correction: higher agreement can result from
adapting a plan to justify an incorrect action, and a flawed
plan can be executed consistently. Effective correction there-
fore requires identifying which component the annotated
reference action supports preserving.
Our central principle is to preserve a reference-
supported plan and repair the action that fails to im-
plement it. Here, a plan denotes the intended next GUI in-
teraction expressed in the generated reasoning, and the plan
span denotes the tokens expressing it. Verifying reference
support for parameterized GUI actions requires checking
spatial or textual arguments beyond action type alone, en-
abling selective credit assignment that shields valid plans
while repairing failed actions.
We present PACT, which instantiates this principle within
a group-relative RL pipeline while leaving the original scalar
action reward intact. First, a conservative rule-based selector

• Reference-aligned plan protection and plan-aligned
action repair. PACT uses reference-supported plans to
decouple plan preservation from action correction without
altering the scalar action reward.
• Task improvements across mobile and desktop environ-
ments. Comparisons against outcome-only and two repair
baselines demonstrate consistent gains in dynamic task
completion on AndroidWorld and OSWorld, supported by
consistency and grounding evaluations on AndroidControl
and ScreenSpot-v2 Mobile.
• Mechanistic evidence on repair and retention. Through

2. Related Work
Reasoning–execution alignment in GUI agents. Reliable
GUI interaction demands both sound planning and faithful
execution, motivating fine-grained evaluation beyond ag-
gregate task success. VenusBench-Mobile [6] decomposes
user-centric agent evaluation across perception, understand-
ing, decision, action, and memory capabilities, while Dong
et al. [5] specifically diagnose reasoning–execution gaps by
separating the correctness of stated plans from that of emitted
actions. On the training side, Faithful-Agent [9] combines
evidence-grounded supervision, thought–action consistency
rewards, and a guided advantage estimator, whereas Mo-
bileIPL [10] derives thinking-level preferences by propa-
gating action feedback through reasoning trees to improve
planning. In contrast, PACT uses reference-supported plans
within unsuccessful responses to determine the direction of
correction—preserving valid plans while repairing only their
failed execution.
Fine-grained preference learning and action correc-
tion. Building on the pairwise objective of DPO [15], Step-
DPO [11] targets individual reasoning steps conditioned on
a correct prefix, whereas Agentic-DPO [2] contrasts expert
actions against sampled mistakes at expert states. From a
rollout-augmentation perspective, Octopus [4] recombines
sampled trajectories and masks specific segments to separate
self-correction from direct reasoning. PACT instead retains
the model’s own decoded reasoning trace as the shared con-
ditioning context to contrast the reference-derived action
suffix against the emitted erroneous suffix.
Credit assignment within failed responses. Localized
supervision also raises a credit-assignment question: which
parts of an unsuccessful response should be penalized? In
standard GRPO [17], a single group-relative advantage is
broadcast across every token of a sampled response. Re-
cent methods refine this assignment based on intermediate
correctness, ranging from retrieval-calibrated negative advan-
tages in CalibAdv [19] to teacher-identified first-error bound-
aries in Cliff [8]. In GUI agent training, UI-Venus-2 [18]
introduces structured action-aware distillation to condition
token-level supervision on action correctness and distinguish
action-type errors from parameter errors. Within outcome-
supervised GRPO, PACT masks negative policy-gradient
contributions on reference-supported GUI plan spans and
repairs failed action suffixes under the same plan, while
keeping the scalar action reward intact.

4.2. Reference-verified execution-gap selection
The selector evaluates the eligibility flag Ei in Eq. (2). In
the mobile implementation, it scans the final four sentences
of zi in reverse order for an explicit immediate plan, reject-
ing negation, multi-step ambiguity, and conflicting action
types. Candidate plans are extracted solely from the rea-
soning text zi prior to reference comparison, never inferred
retrospectively from the emitted action ai.
Judgeability (Ji = 1) requires a parseable reference, a
unique emitted action block, comparison metadata, and a
non-terminal plan with checkable parameters: pointing ac-
tions require a unique explicit coordinate; scrolling actions
require a single direction; text-entry and app-launch actions
require a unique quoted argument; and supported parameter-
free system actions require a valid action type. Grounding-
only examples, terminal references, and unverifiable plans
(Ji = 0) remain active in the base RL objective but are
excluded from auxiliary selection.
For judgeable responses, bTi checks the plan parameters
against a⋆

5. Experimental Setup
Training. In our primary mobile study, O, OA, OAR, and
PACT share the same Qwen3.5-9B vision–language model
SFT initialization, whose frozen copy serves as the refer-
ence policy πref, along with 10,000 mobile GUI state–action
training examples with pixel-space reference coordinates.
Each variant is trained for 1,250 training iterations over
two epochs, sampling 16 prompts and K = 8 responses
per prompt at each step to yield B0 = 128 original rollout
responses before auxiliary rows are added. Optimization
uses one PPO epoch per rollout batch, a learning rate of
10−6, rollout temperature 1.0, KL coefficient η = 0.01,
and 32 accelerators with FSDP2; repair-enabled variants set
λ = β = 0.1 and retain at most 64 repair pairs per itera-
tion. To evaluate cross-platform generality, we also train
desktop-adapted counterparts of O, OA, OAR, and PACT.

Benchmarks and roles. Our evaluation separates inter-
active task completion, plan–action consistency, and visual
grounding. On AndroidWorld [16], we report the task suc-
cess rate across its 116 interactive tasks for each checkpoint.
On AndroidControl [12], we evaluate 8,444 states from
1,543 episodes in each of the High and Low settings: along
with the current screenshot and available history, High pro-
vides only the task goal, whereas Low additionally supplies
the step instruction. In both settings, we measure rule-based
plan–action consistency and reference-action matching for
retention and mechanism diagnostics. ScreenSpot-v2 Mo-
bile [20] measures point-in-target hit rate across 501 exam-
ples (290 text and 211 icon targets). For desktop interaction,
we report task success for each desktop checkpoint on the
full 369-task OSWorld benchmark [21], counting a task as
successful strictly when its native score equals 1.0.
Generation and measurement. Mobile evaluation uses
greedy decoding (temperature 0), a 4,096-token output limit,
and up to ten prior interaction steps. On AndroidControl,
models observe recorded screenshots, with non-initial states
conditioned on each model’s own generated history. OS-
World uses the same environment configuration, greedy de-
coding (temperature 0), a 100-step limit, and the official
native evaluator. Distinct from the training-time selector, our
AndroidControl consistency evaluator extracts a function-
style or keyword-based action intent from the reasoning
trace and compares the inferred action type and recover-
able parameters with those of the emitted action. We report
Crule = Nconsistent/Njudgeable with consistent and judge-
able counts provided in the supplementary material. For
action retention, we measure the proportion of O’s reference-
matched states on which a compared variant also matches
the reference.
In mechanism diagnostics, fixed-plan continuation con-
ditions each model on the same input and the exact valid
reasoning prefix generated by O to isolate action generation,
whereas free generation requires each model to produce
both reasoning and action from scratch. On these subsets,
screenshot-based semantic assessments use language-model
assistance and human verification to separately evaluate
plan correctness (T), action validity (A), and semantic plan–
action consistency (C), complementing benchmark-wide
rule-based scores; the supplementary material details sample
selection, annotation protocols, and execution.

7. Discussion and Limitations
Why plan protection complements action repair. Across
multi-step benchmarks, the complete PACT framework
achieves substantially higher task success on AndroidWorld
and the highest task success on OSWorld within the matched
comparisons of Table 3(B), while preserving more baseline-
correct actions across aligned states in Table 4, even though
OAR and OA match or approach PACT on isolated single-
step grounding in Table 3(B) and fixed-plan continuation in
Table 5. These results clarify the complementary roles of our
two mechanisms: plan-aligned action repair teaches the pol-
icy to translate a valid plan into the intended action, whereas
reference-aligned plan protection shields that plan from neg-
ative policy-gradient updates on failed rollouts. Because
each action in closed-loop interaction alters the context for
subsequent turns, retaining mastered behaviors is as critical
as recovering from errors, enabling PACT to drive stronger
end-to-end task completion across mobile and desktop envi-
ronments.
Limitations and future directions. First, our training-
time selector requires explicit plans whose parameters can
be verified against a single annotated reference. Conse-
quently, valid but implicit plans or semantically equivalent
alternative actions may fall outside the eligible set; incor-
porating semantic plan verifiers or multi-reference super-
vision could broaden the coverage of repairable failures.
Second, whereas our OSWorld experiments establish task-
level gains on desktop workflows, our fine-grained plan and
fixed-plan continuation diagnostics focus on mobile states.
Extending these mechanistic analyses to richer desktop ac-
tion spaces—such as keyboard shortcuts, composite opera-
tions, and long-horizon workflows—will clarify how both
mechanisms interact in complex environments.
8. Conclusion
We presented PACT, a training framework that couples
reference-aligned plan protection with plan-aligned action
repair to resolve GUI execution gaps without altering the
original scalar action reward. It shields reference-supported
plan spans from negative policy-gradient updates while
optimizing corrected action suffixes under the same de-
coded reasoning trace. Compared with outcome-only RL,
8


PACT substantially improves AndroidWorld task success
and achieves higher task success on OSWorld, alongside mo-
bile plan–action consistency and visual grounding. Aligned-
state retention analyses further show that PACT preserves
a higher proportion of baseline-correct actions than unpro-
tected repair variants. Moreover, fixed-plan continuation
and free-generation diagnostics confirm the complementary
roles of both mechanisms while distinguishing true action
correctness from surface-level plan–action agreement. To-
gether, these findings establish a correctness-guided credit-
assignment principle for GUI agents: preserve valid plans
and selectively repair their execution, rather than optimizing
consistency alone.
