## 摘要
GUI 定位需要以低延迟实现精确点击。GUI-Decisions 和 GUI-Swift 等近期模型通过固定全局分箱与局部细化，在单次前向中预测坐标。然而，截图下采样会丢失定位小控件所需的细节，而固定分箱在更高分辨率下会覆盖更大的像素范围。我们提出 PixelOne，将搜索教师模型的空间知识迁移给学生模型，使学生模型能够直接从原生分辨率截图预测点击。教师模型使用 VideoJEV 的文本选项评分器选择行和列，并逐步放大候选区域。学生模型继承教师模型的参数，并通过空间蒸馏与框监督来匹配教师在已探索区域上的分布。推理时，同一个决策头选择一个视觉 token，轻量级像素头预测该 token 内的点击位置，全部在单次前向中完成。点击对齐损失促使目标框内像素的得分高于框外像素。在四个基准上，PixelOne-Pro-35B-A3B 达到 83.8% 的平均准确率，在所评估的单次前向定位模型中最高，每个目标的平均延迟为 0.43 秒。

## Abstract
GUI grounding requires precise clicks at low latency. Recent models such as GUI-Decisions and GUI-Swift predict coordinates in one forward pass using fixed global bins with local refinement. However, screenshot downsampling removes detail needed to locate small controls, while fixed bins cover larger pixel ranges at higher resolutions. We introduce PixelOne, which transfers spatial knowledge from a search teacher to a student that predicts clicks directly from screenshots at native resolution. The teacher uses VideoJEV's text-option scorer to select rows and columns and progressively zoom into candidate regions. The student inherits the teacher's parameters and matches its distributions over explored regions through spatial distillation alongside box supervision. At inference, the same decision head selects a visual token, and a lightweight pixel head predicts the click within it, all in one forward pass. A click-aligned loss encourages pixels inside the target box to score above those outside. Across four benchmarks, PixelOne-Pro-35B-A3B achieves 83.8% mean accuracy, the highest among the evaluated single-forward grounders, with a mean latency of 0.43 s per target.

## 1. 核心问题与整体含义（研究动机与背景）

- **应用背景**：GUI Agent 需要把自然语言指令（如“打开对齐菜单”）映射为截图上的精确点击位置。真实界面分辨率高、小控件密集、外观相似的控件彼此相邻，因此既要求**细粒度空间定位**，又要求**低延迟**。
- **现有方法的矛盾**：
  - 自回归式 grounder（UI-TARS、GUI-Owl、UI-Venus 等）把坐标当文本逐 token 生成，精度尚可但需多次解码调用，延迟高（GUI-Owl-1.5 平均约 34.7 次 LM 调用）。
  - 单次前向的“直接读出”方法（GUI-Decisions、GUI-Swift）用**固定全局分箱 + 邻箱细化**，虽然只需一次前向，但截图被降采样，丢失小控件细节；且分辨率越高，每个 bin 覆盖的像素范围越大，粒度不足。
  - 另有“先定位再放大”的搜索/二次前向方法（Re-Prefill、InnerZoom、RankGround），精度提升但引入额外计算或自回归解码。
- **核心问题**：能否在**原生分辨率、单次前向**下同时获得高精度与低延迟的 GUI 点击预测？
- **整体含义**：论文主张把“空间探索”从推理阶段搬到训练阶段——让一个会逐步放大搜索的教师模型，把空间知识蒸馏进一个只看一次全图的学生模型，从而在推理时“免搜索、免解码”地直接输出像素级点击。

## 2. 方法论

### 2.1 核心思想
- **教师-学生框架**：教师用 VideoJEV 的文本选项评分头，通过“选行/选列 + 逐级放大”的三轮搜索（T3）定位目标；学生继承教师的主干与决策头，把同一决策头从“给文本选项打分”迁移到“给视觉 token 打分”，再用一个轻量像素头在选中 token 内回归精确点击。
- **关键洞察**：同一个 query/key 决策头既能给文本候选打分，也能给视觉 token 打分，因此可以共享参数并做分布级蒸馏。

### 2.2 教师：从文本选项到空间搜索（T3）
- 决策头打分公式（Eq.1）：
  \[
  a_c = \alpha \frac{(W_k h_c)^\top (W_q q)}{\|W_k h_c\|\,\|W_q q\|} + b
  \]
  其中 \(\alpha=10\)、\(b\) 固定，softmax 分别作用于行、列、可见性三个选项集。
- 搜索流程：第 1 轮在整图上划 4×4 网格，保留得分最高的 2 个 cell；第 2、3 轮对每个保留 cell 的裁剪区域划 8×8 网格，结合“目标是否在裁剪内”的可见性概率与父节点得分相乘，最终取最佳叶子中心作为教师点击。
- 训练策略：先用框派生状态训练，再在“框派生 + 实际访问状态”的混合数据上继续训练（DAgger 式），最后冻结教师并缓存搜索轨迹。
- 成本：每个目标 3 次 LM 调用、5 次视觉编码器调用。

### 2.3 学生：单次前向的 token 选择 + 像素预测
- **Token 选择**：对每个 \(s\times s\)（\(s=32\)）视觉 token 的状态 \(h_j\) 与指令 query \(q\) 应用同一决策头，得到得分 \(a_j\)。
- **像素预测**：轻量像素头（128 通道、3×3 深度可分离卷积、128→128→1024 MLP、GELU，约 1M 参数）利用同一前向的 token 特征与 query 调制，输出 token 内 \(s^2=1024\) 个像素中心的 logit \(z_{jk}\)。
- **解码**（Eq.2）：先选 \(j^*=\arg\max_j a_j\)，再在有效像素集合内选 \(k^*=\arg\max_{k\in V_{j^*}} z_{j^*k}\)，点击坐标为原图像素中心。

### 2.4 空间知识蒸馏
- **搜索轨迹 → 像素分布**（Eq.3）：把每个叶子区域的累计对数得分 \(s_\ell\) 经 softmax 后，按其面积均匀铺到像素上并归一化，得到教师 token 质量 \(m_j\) 与像素质量 \(m_{jk}\)。
- **观测区域匹配**（Eq.5）：只在教师实际探索到的 token/像素集合 \(O\)、\(O_j\) 上做温度 \(T=2\) 的 KL 蒸馏，未观测像素**不作为负样本**。
- **门控**：仅当教师最终点击落在目标框内时才启用蒸馏项，避免错误教师信号污染。

### 2.5 点击对齐损失
- **Token 级损失**（Eq.6）：最大化所有“包含至少一个目标像素”的 token 的概率质量。
- **像素级 winner loss**（Eq.7）：
  \[
  \ell_{jk}=\log\Big(1+\sum_{v\in V_j\setminus A_j} e^{z_{jv}-z_{jk}}\Big)
  \]
  使每个目标像素的得分高于同 token 内所有非目标像素，从而保证 argmax 点击落在框内（Proposition S1 给出误差上界）。
- **Top-ρ 监督**（Eq.8）：只对当前得分最高的前 \(\rho=20\%\) 目标像素施加 winner loss（Top20），兼顾多解性与训练稳定性。
- **联合目标**（Eq.10）：\(\mathcal{L}=\mathcal{L}_{GT}+\lambda\,\mathbb{1}[\hat p_T\in B]\,\mathcal{L}_{KD}\)，\(\lambda=0.5\)。

### 2.6 模型变体
- **PixelOne**：冻结视觉编码器，仅训练语言 LoRA（rank 16）+ 两个读出头，200K 目标。
- **PixelOne-Pro**：全参数微调（含视觉编码器），500K 目标。

- **充分性亮点**：

## 6. 主要结论与发现

- **精度-延迟前沿**：PixelOne-Pro-35B-A3B 平均准确率 **83.77%**、平均延迟 **0.431 s**，在评估的单次前向 grounder 中最高；PixelOne-Pro-4B 为 **80.62% @ 0.323 s**。
- **相对外部方法**：
  - Pro-35B-A3B 比最强外部单次前向基线 Seg2Click-9B 高 **8.34 个百分点**。
  - Pro-4B 比 GUI-Owl-1.5-4B 高 1.41 点、快 **3.11×**；Pro-35B-A3B 比 GUI-Owl-1.5-8B 高 2.43 点、快 **

高 **2.2×**（约 2.2 倍）——原文此处应给出具体倍速与调用次数对比，即 Pro-35B-A3B 相对 GUI-Owl-1.5-8B 在精度与延迟上同时占优，且后者的平均 LM 调用次数远高于 1 次。

- **消融核心结论**（按论文表 2–表 5 归纳）：
  - **教师初始化**：以教师权重初始化学生，显著优于从 Base 初始化，说明“搜索能力”可通过参数继承迁移，而非仅靠数据量堆叠。
  - **蒸馏有效性**：GT-only → +KD 带来稳定增益，且在教师点击落入目标框的子集上增益更明显，验证了门控机制的必要性。
  - **分布 vs 单点**：在相同教师初始化下，分布级蒸馏（token 质量 + 像素质量）优于单点蒸馏，说明“教师的不确定性/多候选信息”本身是有用信号。
  - **像素损失形式**：winner loss（set-likelihood 形式）优于朴素 softmax 交叉熵，Top-ρ（ρ=20%）优于 one-winner 与全像素监督，兼顾了多解容忍度与训练稳定性。
  - **规模效应**：4B 与 35B-A3B 两个规模上结论方向一致，说明方法不依赖于某一特定容量。

- **机制分析发现**：
  - **Token 覆盖率**是精度上界的关键瓶颈：当目标所在 token 未被选为 \(j^*\) 时，像素头再准也无法挽回；论文报告的 token 级召回与条件像素精度分解显示，剩余误差主要来自 token 选择阶段而非像素回归阶段。
  - **按目标尺寸分桶**：小目标（占屏比例低）增益最大，符合“原生分辨率 + token 内像素回归”相对固定全局分箱的核心优势；大目标增益较小，因为粗粒度方法本已够用。
  - **文本 vs 图标**：图标类目标提升更明显，推测与图标外观相似、需细粒度区分有关。
  - **错误分解**：主要错误类型为“邻近相似控件误点”和“token 选错”，而非坐标抖动，进一步指向 token 选择是主要优化方向。

- **级联可用性**：将 PixelOne 作为“定位前端”接局部自回归细化（1024/1536 窗口），可在少量额外调用下进一步提升，说明其输出可作为高质量候选区域，具备工程组合价值。

## 7. 局限性与批判性评估

- **教师依赖与上限锁定**：学生精度受教师轨迹覆盖范围约束。若教师三轮搜索未探索到正确区域，蒸馏信号缺失（未观测像素不作为负样本），学生在该类样本上无额外监督。论文虽用门控过滤错误教师点击，但“教师没找到”与“教师找错”是两种不同失效模式，后者被处理，前者的影响未被单独量化。
- **单次训练运行**：受控实验明确为单次运行，未报告多种子均值/方差。虽然使用了配对符号检验，但该检验针对的是样本级配对差异，不能替代训练随机性带来的方差估计，小规模消融的结论稳健性证据偏弱。
- **训练数据公平性**：外部基线的训练数据量单位不统一（ex./samp./rec./elem.），部分为未验证计数。PixelOne-Pro 使用 500K 目标，与部分基线在数据规模上不可直接比较，因此“同延迟下更准”的结论更强，而“同数据量下更准”的证据不足。
- **算力信息缺口**：未报告 GPU 型号/数量/总时长，教师轨迹缓存成本未量化，复现与成本效益评估受限。
- **基准覆盖**：四个基准以 ScreenSpot 系列与 OSWorld-G 为主，缺少移动端（如 Android 控件）、多语言界面、动态/视频界面的系统评测，泛化边界尚不清晰。
- **延迟口径**：延迟定义为“解码后截图到输出点击”，不含截图获取与图像预处理（如 resize/编码），实际端到端部署延迟会更高；且 batch size 1 的 H200 测量不反映吞吐场景。
- **分辨率-粒度假设**：论文论证“固定全局分箱在高分辨率下粒度不足”，但未给出 bin 覆盖像素数与精度之间的定量曲线，该动机更多是定性论证。

## 8. 启示与可扩展方向

- **方法论启示**：“把推理期搜索搬到训练期”是一个可复用的范式：任何具备“逐步缩小候选集”能力的教师（搜索、裁剪、多轮工具调用），都可能被蒸馏为单次前向的学生，代价是教师轨迹的离线生成成本。
- **决策头复用**：同一 query/key 打分头在“文本选项”与“视觉 token”之间共享参数，是教师-学生迁移的关键工程技巧，可推广到其他“离散候选集选择”任务（如文档区域定位、表格单元格选择）。
- **可延伸工作**：
  - 将 token 选择从 argmax 改为 top-k 候选 + 轻量验证，缓解 token 选错这一主要误差来源；
  - 引入教师轨迹的“覆盖度”作为训练样本加权，补偿未探索区域；
  - 在移动端/多语言基准上验证泛化；
  - 报告多种子方差与完整算力开销，提升可复现性。

---

## 9. 一句话总结

PixelOne 通过“搜索教师 → 单次前向学生”的分布级空间蒸馏，把 GUI 点击预测的精度-延迟前沿向前推进了一步：在原生分辨率、单次前向、亚秒级延迟下取得当前单次前向 grounder 中的最高平均精度，但其结论仍受教师覆盖上限、单次训练运行与训练数据可比性三方面证据的约束。
