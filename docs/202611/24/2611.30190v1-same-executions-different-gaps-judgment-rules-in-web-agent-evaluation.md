## 摘要
成功率提升引导着 Web 智能体的发展。然而，知道哪个智能体排名第一，并不能告诉我们应在其报告的领先幅度上赋予多少置信度。我们研究比较本身：成功如何定义、何种证据支持判断，以及智能体之间的差异如何估计。在固定的 Web 智能体执行结果上，将评判器从预测可能完成改为要求有记录支持，可以在不改变排名的情况下消除大部分已报告的领先优势。当未解决的完成与有支持的失败被区分开时，这一效应仍然存在。受控的来源添加解释了任务要求、对象和观察之间缺失的关系如何掩盖差异或制造表面优势。我们还发现，使两个智能体的分数估计更准确，反而可能使其差异估计更不准确，因为它们原本的误差部分相互抵消。为了估计选定的结果差异，我们将评判器预测与抽样任务对的参考标签相结合。在四个已发布的执行系统上，基于同样 50 个标注对拟合的回归相对于直接配对抽样降低了估计误差。这些结果为智能体研究者评估所声称的改进提供了实用依据：明确比较目标，保留检验该目标所需的证据，并使用配对标签直接估计差异。

## Abstract
Success-rate gains guide the development of web agents. Yet knowing which agent ranks first does not tell us how much confidence to place in its reported advantage. We study the comparison itself: how success is defined, what evidence supports the judgments, and how the difference between agents is estimated. On fixed web-agent executions, changing a judge from predicting likely completion to requiring recorded support can remove most of a reported lead without changing the ranking. This effect persists when unresolved completion is distinguished from supported failure. Controlled source additions explain how missing relations between task requirements, objects and observations can conceal a difference or create an apparent advantage. We also find that making both agents' score estimates more accurate can make their difference less accurate, because their original errors partly canceled. To estimate a chosen outcome difference, we combine judge predictions with reference labels for sampled task pairs. Across four released execution systems, regression fitted on the same 50 labeled pairs reduces estimation error relative to direct paired sampling. The results give agent researchers a practical basis for assessing claimed improvements: make the comparison target explicit, retain the evidence needed to check it, and use paired labels to estimate the difference directly.

## 1. 核心问题与研究动机

- **背景**：Web 智能体的研发通常以“相对基线的成功率提升”作为进展信号；LLM 评审器（model judge）通过检查保存的执行轨迹来打分，使这种比较可以规模化。
- **问题**：知道“谁排第一”并不等于知道“领先幅度有多可信”。论文把**比较本身**作为研究对象，拆成三个可检验的环节：
  1. **成功如何定义**（预测可能完成 vs. 要求记录支持完成）；
  2. **什么证据支持判断**（记录中是否保留了任务条件、对象与观察之间的必要关系）；
  3. **智能体差值如何估计**（两个分数之差是否需要独立于单个分数来校准与估计）。
- **关键洞察**：两个分数之差的行为可能与任一分数单独的行为不同——规则若不等地压低双方分数，排名可以不变而报告的领先幅度大幅缩水；反之，让两个分数各自更准，也可能因原本误差相互抵消被破坏而使**差值更不准**。
- **整体含义**：对“某智能体提升了 X 个百分点”这类主张，需要单独的评估与证据支撑，而不能由排名或单体分数精度替代。

## 2. 方法论

### 2.1 核心思想

在**完全固定的执行记录**上，只改变评审器的“判断目标”和“可用证据”，观察同一批执行下智能体间报告差距如何变化；再用配对参考标签直接估计目标差值，而不是分别校准两个分数后相减。

### 2.2 判断规则的操纵（Prediction vs. Certification）

- 两种规则共享相同的任务成功标准、证据输入和二元回答格式，**唯一差别是不确定性下的决策指令**：
  - **Prediction**：预测该执行的实际结果；记录不足以判定时须选择更可能的结果。
  - **Certification**：判断所给记录是否**支持**任务完成；不支持的记为 0，涵盖“观察到失败”与“确认不足”两种情况。
- 每个执行在每种规则、每种视图下做**两次独立调用**并取平均，以抑制采样噪声。
- 领先幅度定义为 Claude 比率减 Qwen 比率；**规则效应**定义为 Prediction 领先减 Certification 领先，正值表示 Claude 领先缩小。
- 置信区间用**按 benchmark 内任务对重采样**的 bootstrap，把同一任务的多规则、多重复绑定在一起。

### 2.3 三状态判定

- 将二元判定扩展为三态：**有支持的成功 / 有支持的失败 / 未解决（unresolved）**，用以检验领先缩小是否只是因为“不确定”被塞进“非成功”这一类。

### 2.4 证据关系干预（source intervention）

- 在保留目标、动作与推理轨迹、错误信息、原始媒体的前提下，**追加存档观察**，使任务条件与对象、观察之间的关系变得可核查。
- 设置**重复呈现（re-presentation）**与**部分来源（partial-source）**控制，检验增益是否仅来自“信息变多”而非“关系被补全”。

### 2.5 差值估计：配对标签 + 全队列评审输出

- 设任务 $i$ 上两智能体的参考结果差为 $Y_i$，评审器认可差为 $Z_i$；对随机抽样的任务对集合 $S$：
  $$\hat{\mu} = \bar{Y}_S + \hat{\beta}\,(\bar{Z} - \bar{Z}_S)$$
  其中 $\bar{Y}_S$ 为标注样本上的参考差，$\bar{Z}$ 为全队列评审差，$\bar{Z}_S$ 为样本内评审差；第二项用“全队列与样本的评审差偏离”校正抽样不均衡。
- **基线**：$\beta=0$ 即直接配对抽样；$\beta=1$ 即等权校正。
- **本文做法**：$\hat{\beta}$ 由**同一批 50 个标注对**内 $Y_i$ 对 $Z_i$ 的回归学习得到，无需额外开发集，标签被复用而非重复购买。
- 原理：评审器的系统性偏移在 $\bar{Z}-\bar{Z}_S$ 中抵消，真正有用的是 $Z_i$ 与 $Y_i$ 的**跨任务关联**，因此评审器“原始差距不准”或“对规则敏感”都不妨碍它作为辅助信息。
- 区间：近似 95% 区间程序，用于判断参考下的领先方向。

## 3. 实验设计

- **数据与 benchmark**：AgentRewardBench 的固定发布版本；主实验使用 Qwen2.5-VL-72B 与 Claude 3.7 Sonnet 的**全部 300 个共享测试任务**，任务来自 AssistantBench、WebArena、VisualWebArena、WorkArena；任务对共享任务 ID，但生成实体与数值实例可不同，各自对照自己的记录目标评分。
- **评审器**：Astra、Sonnet 4.5、Kimi K2.5，均与执行智能体不同；输入含任务目标、完整动作与推理轨迹、URL、错误、目标图像；**final 视图**含终端截图，**expanded 视图**另加最多两张早期截图；Astra 与 Sonnet 用两种视图，Kimi 仅 final。输入不含参考标签与环境奖励。
- **参考标准（两套，差异极大）**：
  - Human reference：发布版专家评估，隐含 Claude–Qwen 领先 **10.67 pp**；
  - Functional reference：benchmark 奖励转二元结果，隐含领先 **0.67 pp**。
- **扩展执行系统**：Qwen、Claude、GPT-4o 共享 300 任务；加入 Llama 3.3-70B 后为 **206 个共同任务**（Llama 无 VisualWebArena 执行、缺两个 WebArena 任务，且用文本观察，其余为视觉配置）。
- **对比方法**：Prediction vs. Certification；二元 vs. 三状态；直接配对抽样（$\beta=0$）、等权校正（$\beta=1$）、回归学习 $\hat{\beta}$；另设分别对每个智能体做二元误差校正的对照（Lee et al. 的方法）。
- **估计实验流程**：从固定队列中**无放回重复抽样 50 个任务对**（即 100 条执行需标注），每次回归只用样本内标签，用已知全队列参考衡量误差；报告 MSE、参考领先者识别率、区间覆盖率。
- **源干预案例**：VisualWebArena 任务 756（要求选择第 2 行第 2 列商品）与一个笔记本购买任务（要求 Development Laptop (PC)，确认为 Dell XPS 13），每条件两次重复。
