## Abstract 

Graphical user interface (GUI) agents enable automated interactions with mobile, web, and desktop interfaces. How-ever, their large memory footprint and repeated model calls hinder deployment on resource-constrained devices, moti-vating post-training quantization (PTQ) without full retrain-ing. Quantization can degrade GUI response accuracy and distort the instruction–vision affinities and local spatial re-lations needed for GUI target selection. Small coordinate errors can cause missed clicks, while early action errors can alter subsequent interface states and disrupt task execution. Local reconstruction error alone does not directly assess whether these responses and relations are preserved. We propose GUI-Q , a PTQ framework that targets response and relation preservation with 4-bit weights and 16-bit ac-tivations (W4A16). Task-Sensitive Granularity Allocation (TSGA) allocates finer groups under a scale-byte budget by combining response sensitivity with the measured reduc-tion in activation-weighted distortion. Relation-Preserving Symmetry Selection (RPSS) then selects symmetric or asym-metric grids to preserve instruction–vision affinities and local spatial relations in GUIs. Across three GUI-capable models, GUI-Q improves mean grounding TargetHit by 8.04– 12.55 points over the strongest evaluated 4-bit configurations, while reducing static peak graphics processing unit (GPU) memory by 49.9–56.2% relative to bfloat16 (BF16). Fixed-output replay with packed 4-bit execution provides 1.7–2.8 ×

model-call speedups. The code will be released. 

## 1. Introduction 

GUI agents translate instructions and screenshots into actions on mobile, web, and desktop interfaces. Beyond understand-ing images and language [8, 24, 25], they must localize tar-gets precisely and specify action arguments correctly. Small coordinate errors can cause missed clicks, and early mistakes can alter the interface state in later steps. Recent GUI agents [21, 26, 35] rely on large vision-language models and repeated model calls, creating sub-stantial memory and inference costs. For 7–8B models, FP32 weights require approximately 26–30 GiB of mem-ory. Even in bfloat16 (BF16), peak GPU memory allocation reaches 15.75–16.67 GiB in our static evaluation (Sec. 4.6). These resource demands complicate local deployment on smartphones and other edge devices with limited memory and compute resources. Post-training quantization (PTQ) of-fers a practical route to reduce weight storage while reusing pretrained models without full retraining. We focus on four-bit weight quantization (W4) to reduce model cost while preserving accurate target selection and action generation. This motivates examining how quantization affects GUI re-sponses, instruction–target associations, and spatial relations among neighboring GUI elements within the interface. Existing PTQ methods use reconstruction and activation-aware scaling [12, 19]. Recent methods incorporate end-loss guidance, modality or token sensitivity, and action fidelity [1, 13, 16, 27, 30]. These advances provide useful task-aware signals, but identifying sensitive modules does not establish where finer grouping is most beneficial. For GUI agents, a sequence-averaged objective alone does not explicitly bal-ance numerical content against the rest of the response, while local reconstruction error does not directly measure whether instruction–target and spatial relations are preserved. Groups of 64 weights (G64) adapt ranges more locally than groups of 128 (G128) but double scale metadata. Finer groups should therefore be assigned where they best pre-serve GUI responses. Task-Sensitive Granularity Al-location ( TSGA ) estimates module sensitivity from full re-sponses, digit-bearing tokens, and remaining tokens. It combines this sensitivity with the measured reduction in activation-weighted distortion from G128 to G64 to allocate finer groups on a per-module basis under a scale-byte budget. These label-free calibration signals use the frozen model’s own responses. Across UI-TARS-1.5-7B, OS-Atlas-Base-7B, and InternVL3.5-8B, GUI-Q improves mean grounding Tar-getHit (TH) over the strongest evaluated W4 configurations by 12.55, 9.62, and 8.04 points, respectively, while reducing static peak GPU memory by 49.9–56.2% relative to BF16. A separate AgentCPM-GUI evaluation on AndroidWorld [22] improves strict success by 7.2 points. Packed four-bit model calls run 1.7–2.8 × faster in our fixed-output replay. Our work makes the following three main contributions: • A W4A16 PTQ framework for GUI agents that combines granularity allocation and symmetry selection under a scale-byte budget and a cap on asymmetric modules. • TSGA, which allocates finer groups based on response sen-sitivity and distortion reduction to preserve GUI responses under a shared budget for storing quantization scales. • RPSS, which selects symmetric or asymmetric grids to preserve instruction–vision affinities and local spatial rela-tions needed to select the correct GUI target. 

## 2. Related Work 

GUI understanding and agents. GUI systems have pro-gressed from visual templates and interface encoders to screenshot grounding and general interaction [2, 3, 5, 31]. Web, mobile, and desktop benchmarks now evaluate both iso-lated grounding and multi-step execution [9, 14, 15, 18, 28, 29, 36]. UI-TARS and OS-Atlas provide representative GUI-oriented checkpoints for grounding and action generation, while InternVL3.5 provides a general multimodal check-point with GUI interaction capabilities. Static grounding assesses target localization, whereas closed-loop evaluation captures how action errors change later observations and task outcomes. These requirements motivate preserving target selection and action generation when quantizing GUI agents. 

Post-training quantization. PTQ methods optimize weight rounding [12, 20], rescale weights using activations [19], or learn calibration transformations [23]. Related work also studies token-group constraints for activation quantization [17]. Sensitivity-based methods use gradients, curvature, per-turbations, and end-loss signals [4, 10, 11, 13]. AutoRound is represented by the SignRound formulation and imple-mentation family [6]. SignRoundV2 combines gradient-informed allocation with scale initialization and tuning that also apply at fixed bit width [7]. Sensitivity alone does not indicate how much a module benefits from finer grouping, while distortion reduction alone does not measure its effect on GUI responses. GUI-Q combines response sensitivity with the measured G128-to-G64 distortion reduction to allo-cate finer groups under a shared scale-byte budget. 

Multimodal and action-aware quantization. Multimodal PTQ studies dependencies across layers, modality balance, compensation for asymmetry, bit-width allocation, and token sensitivity [16, 27, 32, 34]. In embodied control, QVLA and Figure 2. ActQuant use sensitivity to action spaces or predicted actions [1, 30], while QuantVLA studies scale-calibrated PTQ for vision-language-action models [33]. Task sensitivity and full-precision self-generated action references also appear in prior PTQ. For GUI target selection, local reconstruction error does not directly assess changes in instruction–vision affinities or local spatial relations. RPSS evaluates the preser-vation of these relations to select symmetric or asymmetric grids at the group sizes allocated by TSGA.

A symmetric grid ties its range to the largest absolute weight; an asymmetric grid adds a zero point for an offset range. Either can alter relative affinities between instruc-tions and competing targets. 3.3. Relation-Preserving Symmetry Selection 

RPSS selects grids using relations needed for target selection. Instruction–vision affinities link screenshot features to the request; spatially weighted visual similarities describe local feature relations. Preserving both complements response-sensitive allocation. After TSGA fixes {gl}, RPSS evaluates a frozen 16-module attention pool spanning early q pro-jections and k/v/o projections at three depths. Attention projections directly affect these relations, while the frozen pool bounds profiling cost. Supplementary Sec. S2.8 details pools, tie orders, and how visual tokens map to screenshots. For candidate a = ( b, p ) ∈ C , RPSS quantizes only 

a at ga and retains BF16 elsewhere. This estimates the grid’s marginal gain in relation preservation at its assigned granularity. It omits interactions among jointly quantized projections. Preserving relative affinities cannot guarantee unchanged downstream actions, because they do not con-strain every feature direction used by the final readout. ## 4. Experiments 

4.1. Experimental Setup 

Models and evaluation metrics. We evaluate UI-TARS-1.5-7B, OS-Atlas-Base-7B, and InternVL3.5-8B on ScreenSpot-Pro (SS-Pro), ScreenSpot-v2 (SS-v2), Android-Control (AC), and OSWorld-G (OSW-G), where their output formats are supported. We use official TH, Grounding Ac-curacy (GA), and StepSuccess (SS). Mean TH averages the three shared grounding benchmarks; AndroidControl end-points are reported separately. Closed-loop AndroidWorld uses 250 frozen task–reset pairs. Strict success requires both a reward above 0.5 and an explicit termination action. 

PTQ protocol and baselines. All methods quantize decoder q/k/v/o and gate/up/down projections to W4, retain BF16 elsewhere, and share the evaluation interface. We compare AWQ, GPTQ, AutoRound, VLM-PTQ, MABA, COD-TDQ, MBQ, QIG, Q-VLM, and allocation/action-aware transfers. Ground Truth BF16 GUI -Q(Ours) GPTQ QVLA AWQ ActQuant VLM -PTQ Figure 3. Qualitative comparison on GUI tasks. GUI-Q correctly localizes the requested control in all three cases. 

Transfers share calibration data, 384 backward passes, the rounding backend, and the asymmetry cap. GUI-Q uses 128 unlabeled calibration examples, a 256-token response cap, and 50 rounding iterations. Calibration, development, static tests, and AndroidWorld are disjoint. Lexical weights are selected on a separate annotated 512-example OS-Atlas de-velopment split and frozen before testing. Only calibration is label-free. Static W4 results average five paired seeds on fixed test examples; BF16 is deterministic. Each com-parison fixes prompts, image processing, parsers, stopping rules, and official evaluators. GuidedQuant-, QVLA-, and ActQuant-inspired transfers implement allocation or action signals in this W4 scope, rather than reproducing every up-stream recipe. A separate retained-objective cohort helps separate criterion gains from adaptation effects. Supple-mentary Secs. S2.2–S2.9 specify seeds, baseline settings, hyperparameters, manifests, data splits, and the hardware. Configuration and retained-objective controls use a sepa-rate cohort: 128 cases for each of 12 static model–workload pairs and 250 AndroidWorld cases, with five paired seed slots per case. Here G3 averages TH on SS-Pro, SS-v2, and OSW-G (Supplementary Secs. S12–S13). In the primary static models, TSGA assigns G64 to 56/196, 20/196, and 81/252 targets; RPSS selects 5, 5, and 6 asymmetric projections, respectively. Remaining target modules retain symmetric grids or G128 as assigned. Supplementary Secs. S2.6 and S6.2 give each model’s byte ceilings and group assignments.

4.3. Ablation Study 

Tables 3 and 4 compare component removal and criterion replacement with identical calibration data, decoder targets, W4 payload, scale-byte ceilings, asymmetry caps, rounding backend, and evaluation protocol. 4.5. Cross-Model Generalization 

Across the three shared grounding benchmarks, UI-TARS achieves 53.47 Mean TH in BF16, 33.21 with the ActQuant-inspired transfer, and 45.76 with GUI-Q. OS-Atlas scores 39.22, 25.74, and 35.36 under the same settings. InternVL scores 50.21 in BF16, 41.41 with its strongest baseline AWQ, and 49.45 with GUI-Q. The gains over W4 baselines are 12.55, 9.62, and 8.04 points, with respective gaps to BF16 of 7.71, 3.86, and 0.76 points. GUI-Q improves all three checkpoints, but recovery of full-precision accuracy varies. GUI-Q’s SS-Pro/SS-v2/OSW-G TH is 11.76/74.03/20.28 on OS-Atlas and 22.45/87.74/38.16 on InternVL. On OS-Atlas, it exceeds the best tested PTQ baseline on each bench-mark. InternVL AndroidControl SS is 69.77 versus 62.89 for BF16 and 56.99 for AWQ. Supplementary Sec. S3 provides per-dataset rates and hit totals. Dynamic-resolution checks retain these gains (Supplementary Sec. S2.8): Mean TH is 51.72/41.02 on UI-TARS and 37.93/29.88 on OS-Atlas for GUI-Q and the listed comparator, in that order. On the separate retained-objective cohort, GUI-Q exceeds Action-Mixed-Fisher by 3.28 G3 points on OS-Atlas and 4.06 on InternVL. The respective 95% case-cluster intervals are [2 .40 , 4.22] and [3 .13 , 5.05] (Supplementary Sec. S12). This comparison tests whether the gains persist when the baseline objective is retained. These gains are measured within this cohort and should therefore be read separately from those on the main static tests. 

4.6. Efficiency Analysis 

We report one-time configuration cost, static peak alloca-tion, and packed-W4 model-call latency. With 128 calibra-tion examples, UI-TARS configuration takes 29.80 minutes for TSGA and 24.63 for RPSS, peaking at 15.43 GiB; DP takes 0.138 seconds. Static exports use 4.166 bits per tar-geted weight on UI-TARS, 4.145 on OS-Atlas, and 4.172 on InternVL, including quantizer metadata. Supplementary Sec. S7 lists scale, zero-point, descriptor, BF16-rest, and serialization bytes. The AgentCPM-GUI export is audited separately in the same section as the static exports. GUI-Q lowers peak allocation from 16.62 to 8.32 GiB on UI-TARS, 15.75 to 6.93 GiB on OS-Atlas, and 16.67 to 7.29 GiB on InternVL: reductions of 49.9%, 56.0%, and 56.2%. Fixed-BF16-output replay from vision encoding through decoding gives respective speedups of 1.92–2.80 ×, 1.70– 2.80 ×, and 1.70–2.24 ×. AndroidWorld first-decision replay over 250 inputs falls from 792.04 to 597.08 ms (1.33 ×), with 56.67% less peak memory. These W4-versus-BF16 gains concern packed model calls; within-W4 configura-tion controls show much smaller timing differences. Fixing BF16-reference output lengths separates execution speed from action changes and early stopping. Logical dispatch coverage and reduced-dimensional numerical checks val-idate execution for tested operator shapes and numerical tolerances. Supplementary Secs. S7.6 and S14 report work-load timings, paired-bootstrap intervals, dispatch coverage, and numerical checks of the execution path. The Android-World replay speedup has a paired-bootstrap 95% interval of [1 .29 , 1.36] ×; the 2.80 × UI-TARS OSWorld-G speedup has a 95% interval of [2 .67 , 2.92] ×. These intervals support faster model calls under fixed output lengths. Environment execution is excluded. The measured speedup therefore con-cerns model calls and does not describe how long an agent takes to complete a GUI task in real environments. 

## 5. Conclusion 

GUI-Q combines TSGA and RPSS for decoder-only W4A16 quantization. TSGA allocates finer groups using response sensitivity and distortion reduction to preserve GUI responses under a scale-byte budget. RPSS selects symmetric or asymmetric grids to preserve instruction– vision affinities and local spatial relations needed for target selection. Calibration uses the frozen model’s own responses without task labels. GUI-Q improves grounding over the evaluated W4 baselines and increases task success in a separate closed-loop evaluation. Static peak GPU memory falls by 49.9–56.2% relative to BF16. Packed model calls run 1.7–2.8 × faster when replaying the same fixed outputs.
