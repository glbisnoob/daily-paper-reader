## 摘要
近期，大型（视觉）语言模型的进展使计算机使用智能体能够通过细粒度键盘和鼠标操作自动化数字工作流。然而，这类智能体在长时程场景中仍然脆弱：错误会累积，已执行动作会留下非预期副作用，因此从失败中恢复的能力至关重要。然而，现有补救措施仍不充分：在专有环境中重置环境不可行，动作回放在长时程上代价过高，而基于 API 的回滚仅限于 Web 环境，使得基于模型的恢复在很大程度上仍未被探索。为填补这一空白，我们提出 ReTrace，一个可扩展的评估框架，用于系统研究计算机使用智能体的恢复行为。我们形式化定义了转移一致性恢复（Transition-Consistent Recovery）：从恢复状态和目标状态执行相同的下游动作必须产生相同结果。我们通过在受控错误注入后执行目标导向动作回放来落实这一准则。借助 ReTrace，我们首次对自主的、基于模型的恢复进行系统研究，揭示出：(i) 理想恢复能够释放模型潜在的任务完成能力；(ii) 当前计算机使用智能体未能利用其潜在恢复能力；(iii) 准确的基于模型恢复可带来可测量的端到端增益。总之，这些发现确立了恢复作为构建可靠计算机使用智能体的基础能力。我们的代码与数据集见 https://github.com/BangProx/ReTRACE。

## Abstract
Recent advances in large (vision) language models have enabled computer-use agents that automate digital workflows via fine-grained keyboard and mouse operations. However, such agents remain fragile in long-horizon settings, where errors accumulate and executed actions leave unintended side effects, making the ability to recover from failures critical. Yet, existing remedies remain inadequate: environment resets are infeasible in proprietary settings, action replay is prohibitively expensive over long horizons, and API-based rollback is limited to web environments, leaving model-based recovery largely unexplored. To address this gap, we present ReTrace, a scalable evaluation framework for systematically studying recovery behavior in computer-use agents. We formalize Transition-Consistent Recovery: identical downstream actions from the recovered and target states must yield identical outcomes. We operationalize this criterion through goal-oriented action replay following controlled error injection. Using ReTrace, we present the first systematic study of autonomous, model-based recovery, revealing that (i) ideal recovery can unlock model's latent task completion capabilities, (ii) current computer-use agents fail to exploit their latent recovery capabilities, and (iii) accurate model-based recovery yields measurable end-to-end gains. Together, these findings establish recovery as a fundamental capability for building reliable computer-use agents. Our code and dataset is available at https://github.com/BangProx/ReTRACE.

- **现有方案不足**：
  - **环境重置**：在专有网站、生产系统等场景中往往不可行。

  - **基于模型的自主恢复**：即由智能体自身恢复先前状态，仍缺乏系统研究。
- **研究问题**：
  - RQ1：恢复是否是释放模型潜在任务完成能力的必要条件？
  - RQ2：当前 CUA 是否具备恢复能力？该能力是潜在的还是完全缺失的？
  - RQ3：准确的模型级恢复是否能转化为可测量的任务完成率提升？

## 2. 方法论

### 2.1 核心思想

- 提出 **ReTrace**：一个可扩展的恢复行为评估框架，通过“受控错误注入 + 目标导向动作回放”系统评估 CUA 的恢复能力。
- 形式化 **Transition-Consistent Recovery（转移一致性恢复）**：恢复状态与目标状态是否一致，不应仅看截图相似度，而应看从二者执行相同下游动作是否产生相同结果。
- 理论依据：借鉴预测状态表示理论，用“预测的未来转移行为”定义状态等价，以捕捉截图不可见的潜在状态差异（如隐藏配置文件被修改）。

### 2.2 关键技术细节

- **状态与恢复任务定义**：
  - 将 CUA 任务建模为部分可观测马尔可夫决策过程：状态 \(s_t=(h_t,o_t)\)，其中 \(h_t\) 为隐藏状态，\(o_t\) 为可观测截图。
  - 恢复任务：将当前错误状态 \(s_t\) 映射回过去的目标状态 \(s_{target}=s_{t-d}\)，其中 \(d\) 为恢复距离。
- **恢复判定 Oracle**：
  - **转移一致性判定 \(R_{TC}\)**：从恢复状态执行原轨迹中的下游动作，若递归执行后能复现原轨迹状态或最终完成任务，则视为恢复成功。
  - **观测一致性判定 \(R_O\)**：恢复状态截图与目标状态截图需在观测层面一致。
  - 最终判定：\(R=R_{TC}\land R_O\)，同时检查隐藏状态行为等价与可见界面一致。
  - 实际实现中，观测一致性使用 SSIM，阈值设为 0.99。
- **ReTrace 三阶段流程**：
  1. **On-Policy Trajectory Rollout**：
     - 对每个策略 \(\pi_\theta\) 在任务集上收集成功轨迹。
     - 将同一动作序列回放 \(N=3\) 次，仅保留连续成功者，构建“转移一致”数据集，以近似确定性转移函数 \(\hat{T}\)。
  2. **Trajectory Drift via Perturbation**：
     - 从成功轨迹中采样中间状态作为恢复目标 \(s_{target}\)。
     - 使用扰动策略 \(\pi^p_\theta\) 从该状态故意执行偏离任务的动作，直到基准 Oracle 判定任务失败，得到错误状态 \(s_{error}\)。
  3. **Goal-Oriented Action Replay**：
     - 从 \(s_{error}\) 启动恢复策略 \(\pi^R_\theta\)，允许最多 \(r\) 步恢复动作。
     - 恢复后，回放原成功轨迹中剩余的下游动作，检查是否能复现原任务结果。
- **恢复策略类型**：
  - **隐式恢复（Implicit Recovery）**：直接复用前向策略 \(\pi^R_\theta=\pi_\theta\)，不提供恢复专用指令，测试智能体是否自发恢复。
  - **显式恢复（Explicit Recovery）**：使用专门恢复策略 \(\pi^R_\theta(a_t\mid o_{target},C,(o_0,a_0,\dots,o_t))\)，其中 \(C\) 为恢复上下文，用于表示目标状态的隐藏信息。
  - 显式恢复上下文变体包括：0-E（错误步前历史）、0-R（目标恢复步前历史）、w/o History（无历史）、Recovery Target Contextualization（用 LLM 总结目标状态及转移历史）。

## 6. 主要结论与发现

- **Finding 1：准确恢复具有显著价值**。在相同重试预算下，从错误前状态恢复比从初始状态完全重置更高效，尤其在低重试次数下提升明显。
- **Finding 2：当前 CUA 很少自发恢复**。隐式恢复成功率普遍很低，EvoCUA-32B 平均恢复率不足 1%；智能体既缺乏恢复倾向，也缺乏稳定恢复能力。
- **Finding 3：恢复能力是潜在的而非完全缺失**。显式模型级恢复相比隐式恢复平均提升约 17.86%，说明当前模型具备一定潜在恢复能力，但标准前向执行不会有效激发它。
- **Finding 4：后训练可能削弱恢复能力**。通用模型（Claude-Sonnet-4.6、GPT-5.4-CUA、Qwen3.5-9B）从显式恢复中获益更大；经过单向任务完成轨迹后训练的专业模型（如 EvoCUA-32B）恢复能力较弱。
- **Finding 5：即使不完美恢复也能带来端到端收益**。Qwen3.5-9B 在多种恢复设置下平均端到端成功率提升约 2.12%，说明恢复可开始释放潜在任务完成能力。
- **Finding 6：恢复质量直接影响任务完成，弱恢复可能反噬**。恢复能力弱的模型在端到端推理中可能性能下降；更多恢复尝试对恢复能力较好的模型有益，但对弱恢复模型可能造成进一步轨迹漂移。
- **定性失败模式**：
  - **Spurious Perception（虚假感知）**：智能体关注恢复状态中偶然出现的 UI 元素，偏离正确操作。
  - **State Tracking Failure（状态跟踪失败）**：智能体错误假设恢复状态与目标状态一致，产生幻觉动作。

## 7. 优点

- **问题定位新颖且重要**：首次系统研究 CUA 的自主模型级恢复行为，将恢复从推理启发式提升为独立研究问题。
- **恢复定义严谨**：提出转移一致性恢复，用行为等价而非单纯视觉相似判断恢复成功，能捕捉隐藏状态差异。
- **评估流程可扩展**：通过受控错误注入与目标导向动作回放，将恢复评估操作化，适用于不同策略与基准。
- **实验覆盖较广**：跨 OSWorld 与 WindowsAgentArena、闭源与开源模型、短/长时程设置，结论具有较好外部参考价值。
- **重视评估可靠性**：引入人类评估验证 Oracle，并分析环境随机性、SSIM 阈值及双 Oracle 互补性。
- **发现具有实践启示**：揭示“恢复能力潜在但未被利用”，并指出后训练可能损害恢复能力，为后续恢复感知训练提供方向。

## 8. 不足与局限

- **只测量不改进**：ReTrace 是评估框架，显式恢复只能激发模型已有能力，无法弥补 GUI 理解、状态跟踪或动作规划的根本缺陷。
- **恢复成功率仍不理想**：即使最强模型结合显式恢复，也未达到完整恢复，说明实际恢复机制仍需研究。
- **样本规模有限**：最终评估集每个模型仅数十至百余条，且经过多轮过滤，可能影响统计稳定性与任务多样性。
- **基准覆盖有限**：仅覆盖 OSWorld 与 WindowsAgentArena，未覆盖移动端、更多专有桌面应用或真实生产环境。
- **依赖自动评估组件**：LLM 错误检测器、恢复步检测器、状态验证器与基准 Oracle 可能引入偏差；人类评估 kappa 仅 0.45，标注一致性中等。
- **环境随机性风险**：弹窗、渲染变化、时间戳等动态因素可能影响恢复判定，虽然论文报告 86.0% 的判定不受影响，但仍非完全消除。
- **API 成本限制采样**：GPT-5.4-CUA 在部分设置中仅采样 600 条，可能限制覆盖度。
- **专业模型恢复能力弱**：EvoCUA-32B 等后训练模型恢复能力极低，弱恢复可能造成额外轨迹漂移，限制实际部署。
- **缺乏训练方法验证**：论文提出恢复感知后训练、潜在状态跟踪等方向，但未实际设计或验证这些改进方法。
