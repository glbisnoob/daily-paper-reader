## 摘要
潜在记忆正逐渐成为 GUI 智能体的一种轻量级历史补充。它通过使用逐步交叉熵（CE）训练的 prefix 向量，为冻结的视觉-语言模型提供历史信息。尽管由此获得的增益通常被归因于所编码的历史，我们的控制实验表明，这些增益主要源于动作修正。该 prefix 学会改变模型的默认动作。然而，这种修正是无范围约束的，因为逐步 CE 在每一步都将输出推向参考动作，而没有显式保留正确决策。因此，它修复了错误，却也破坏了 8–13% 最初正确的答案。总体准确率指标掩盖了这些损失。为此，我们提出 ScopeMem，一种用于有范围修正的潜在记忆方法。其编码器以模型的初始答案为条件生成 prefix，并被训练为在保留正确决策的同时修正错误。在受控消融集上，ScopeMem 将正确决策被破坏的比例降至 5.6%，同时修复的错误多于任何所评估的 CE 训练 prefix。在 AndroidControl、GUI-Odyssey 和零样本 AITW 上，ScopeMem 优于所有所评估的提示方法与潜在记忆基线，使冻结的 Qwen3-VL-8B 能够匹配或超越 GUI 专用智能体以及 Qwen3-VL-32B。

## Abstract
Latent memory is gaining ground as a lightweight history supplement for GUI agents. It supplies history to a frozen vision-language model via prefix vectors trained with step-wise cross-entropy (CE). While resulting gains are naturally attributed to encoded history, our controlled experiments show they primarily stem from action revision. The prefix learns to alter the model's default actions. However, this revision is unscoped because step-wise CE pushes outputs toward reference actions at every step without explicitly preserving correct decisions. Consequently, it repairs errors but also breaks 8-13% of initially correct answers. Overall accuracy metrics hide these losses. We therefore propose ScopeMem, a latent-memory method for scoped revision. Its encoder conditions prefix generation on the model's initial answer and is trained to correct errors while preserving correct decisions. On the controlled ablation set, ScopeMem reduces the share of broken correct decisions to 5.6% while repairing more errors than any evaluated CE-trained prefix. On AndroidControl, GUI-Odyssey, and zero-shot AITW, ScopeMem outperforms all evaluated prompting and latent-memory baselines, enabling a frozen Qwen3-VL-8B to match or surpass GUI-specialized agents and Qwen3-VL-32B.

# ScopeMem 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：潜在记忆（latent memory）被视为冻结视觉-语言 GUI 智能体的轻量历史补充手段：一个可训练编码器把历史压缩成少量连续 prefix 向量，拼接在冻结 actor（决策模型）的输入前，仅用逐步交叉熵（CE）在参考动作上训练该编码器。
- **常见归因**：以往工作把性能增益归因于“编码了历史信息”。
- **本文的反直觉发现**：控制实验显示，当 actor 的上下文中**已经包含最近历史**时，prefix 的增益主要来自**动作修正（action revision）**，而非补充历史——仅看任务的编码器提升 12.0 pp，加上历史也只提升 11.8 pp（差值上界仅 1.6 pp）。
- **关键缺陷（无范围修正）**：逐步 CE 在每一步都把输出推向参考动作，却不要求“原本正确的决策保持不变”，因此 prefix 在修复错误的同时会**破坏 8–13% 原本正确的决策**（称为 harm）。
- **评测盲区**：总体准确率只反映“修复 − 破坏”的净值（ΔAcc =(R−H)/N），掩盖了大量相互抵消的损失。
- **研究含义**：需要把潜在记忆重新定义为“**有范围的修正**”——只改错、不改对；并主张同时报告 repairs 与 harms。

## 2. 方法论：ScopeMem

### 核心思想
让 prefix 编码器**先看到 actor 的初始答案**（first opinion），再学习“在何处修正”，即只修正错误决策、保留正确决策。

### 两遍推理流程（two-pass）
1. 冻结 actor 在无 prefix 条件下对上下文 $c_t$ 作答，得到初始动作 $a_0$ 及其动作类型概率 $p_0$、熵 $H_0$。
2. 编码器 $E_\phi$（10.5M 参数、cross-attention 网络）读取 $a_0$、置信信号、任务描述、滚动摘要与最近动作，生成 $K=16$ 个 prefix 向量 $z_t$。
3. 将 $z_t$ 拼接到**同一上下文**前，actor 再作答一次，得到“第二意见” $a_t$，即最终动作。
4. 两遍均用贪心解码。

### 训练目标：有范围保留（scoped preservation）
- 定义 keep 指示 $k_t$：初始答案与参考动作匹配则为 1，否则为 0（仅训练时可得）。
- 损失函数：$\mathcal{L} = \mathrm{CE} + k_t\, w_t\, P_t$
  - $k_t=0$（初始错误，即“修正范围”内）：仅 CE 推动模型输出参考动作。
  - $k_t=1$（初始正确）：额外加入基于 KL 散度的保留项 $P_t$，惩罚加 prefix 前后 token 分布沿参考动作方向的偏移。
- **理想目标分布**：初始错误时逼近参考动作的 one-hot 分布 $\delta_{y^*}$，初始正确时保持原分布 $\pi_0$ 不变。

### 三个关键设计
- **token 类型加权**：决定动作类型的 decision token 获得 10 倍于参数 token（如坐标）的保留权重，因为 benchmark 对动作类型要求严格匹配、对坐标有容差。
- **置信度加权**：$w_t$ 随置信度上升，越自信的正确回答保留越强。
- **两阶段训练**：第一轮仅用 CE 教会 prefix “会改”，第二轮才加入保留项教会它“该保留什么”；否则保留项会奖励“什么都不改”的平凡解。

### 与相关工作的定位
只有 ScopeMem 同时具备：冻结 actor、读取第一意见、可学习修正、以训练目标形式防止破坏、并报告 repairs/harms（对比表 1）。

## 6. 主要结论与发现

- **增益来自修正而非记忆**：task-only 与 history 编码器增益几乎相同（11.96 vs 11.76 pp），说明 prefix 主要改变 actor 对已有上下文的使用方式。
- **CE 训练必然带来破坏**：所有 CE prefix 都改变约 71–74% 的原本正确动作，8–13% 的正确决策被破坏；fixed-query prefix 的破坏甚至抵消其修复量的一半以上。
- **置信度不足以做门控**：actor 置信度检测自身错误 AUC≈0.72，但区分“修复 vs 破坏”仅 AUC≈0.53，故需**学习**修正范围而非事后门控。
- **ScopeMem 效果最佳**：消融集上修复 254 / 破坏 49，破坏率降至 5.6%，增益 +14.01 pp；优于所有 CE 训练 prefix。
- **主结果**：AndroidControl EM 67.91 / TM 82.98；GUI-Odyssey 72.90 / 86.33；AITW Macro 66.69，全面超过所有提示与潜在记忆基线；是唯一在三个 benchmark 上都能匹配或超过 GUI 专用模型的冻结 actor 方法（AndroidControl 上以 67.91 略超 GUI-Owl-1.5-8B 的 67.55）。
- **小模块胜过大规模**：10.5M 参数模块带来 5.5–14.2 pp 提升，而 4 倍大的 Qwen3-VL-32B 仅提升 3.1–3.7 pp，且在 AndroidControl 上反而下降 0.7 pp。
- **破坏主要发生在动作类型层**：scoped 保留把动作类型 harm 从 35 降到 19（坐标类几乎不变），并显著减少“过早 COMPLETE”（Mem-W 15 次 vs ScopeMem 6 次）。
- **第一意见必不可少**：扰动或替换第一意见显著降分（−1.03 / −1.64 pp），而移除历史影响不显著（−0.89 pp，CI 含 0）。

## 7. 优点

- **问题重构有洞察力**：把“记忆是否记住”转化为“记忆在哪里修正”，并用可控变量（是否让编码器读历史）干净地分离两种解释。
- **提出更有信息量的评测口径**：repair / harm 分解与 ΔAcc=(R−H)/N，揭示聚合准确率的掩盖效应，具有方法论推广价值。
- **方法对症**：两遍“第二意见”结构直接对应“需要看到被修正的对象”；scoped preservation 把 focal distillation / 负翻转抑制的思想迁移到 prefix 训练。
- **工程细节考究**：decision token 10× 权重、置信度加权、先 CE 后保留的两阶段课程，均有明确动机与消融支撑。
- **实验规范**：统一 actor 上下文与训练预算、配对 bootstrap 置信区间、3 种子重复、对不显著结果如实报告、案例研究直观展示“同一条回忆既修复又破坏”。

## 8. 不足与局限

- **仅离线、步级评测**：未在 AndroidWorld 等在线环境验证真实任务成功率；步级匹配可能惩罚合法替代动作。
- **参考动作噪声**：错误标注会污染训练时的 $k_t$，把正确首答误标为错误，从而错误地进入“修正范围”。
- **泛化范围窄**：只测一个 actor（Qwen3-VL-8B）、仅移动端 benchmark；其他模型、平台、历史预算下行为未知。
- **延迟翻倍**：每步两次 actor 前向，实际部署成本明显上升，论文未给出延迟/吞吐量化数据。
- **算力信息缺失**：未报告 GPU 型号、数量与训练时长，可复现性与成本评估受限。
- **统计稳健性有限**：细粒度分析来自单次运行；主运行中“第一意见 × scoping”交互 CI 含零，需跨种子平均才显著；baseline（尤其 Mem-W）为自行复现。
- **记忆范围受限**：只讨论“actor 已能看到最近步骤”的情形，未涉及超出近期窗口的长期记忆。
