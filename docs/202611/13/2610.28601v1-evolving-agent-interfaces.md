## 摘要
计算机使用智能体受限于人类为其提供的接口。智能体可能会逐单元格地输入电子表格，而一行代码即可完成；或者通过 shell 打印一个文件的全部两千行来查找一个函数。这些接口以及何时使用各接口的知识都是手工构建的，无法跟上新应用、新工作流和新模型的发展。我们认为，接口设计本身应成为智能体的一项能力。我们提出 Agent S4，一个自主的计算机使用科学家，它从任务经验中构建演化式智能体接口。一个元智能体在无成功标签的合成训练任务上检查任务智能体的轨迹，并在一个仓库中构建和修订接口及使用知识。随后，基于种群的演化根据各仓库在元智能体从未见过的验证任务上的表现，选择进一步开发哪些仓库，从而偏好能够泛化到已见任务之外的改动。在 OSWorld V2 上，Agent S4 搭配 Qwen3.8-27B 和演化得到的接口仓库，在开源计算机使用智能体中创下新的最先进水平，达到 21.3% 的二值得分，是同一模型使用固定接口时的 3.8 倍。这高于 GPT-5.5（13.0%）和 Claude Opus 4.8（20.6%），而成本分别约为它们的 4.3% 和 1.5%。在 ScienceBoard 上，演化得到的接口在相同模型下将成功率从 41.4% 提升至 58.6%。这些结果表明，有用的接口可以从经验中演化而来，使自主接口设计成为与模型和执行框架进步互补的一种改进来源。我们在 https://github.com/simular-ai/agent-s 开源了代码。

## Abstract
Computer-use agents are limited by the interfaces humans give them. An agent may type a spreadsheet cell by cell when a single line of code would do, or print all two thousand lines of a file through a shell to find one function. Both the interfaces and the knowledge of when to use each are built by hand, which cannot keep pace with new applications, workflows, and models. We argue that interface design should itself be an agent capability. We introduce Agent S4, an autonomous computer-use scientist that builds Evolving Agent Interfaces from task experience. A meta-agent examines task agents' trajectories on synthetic training tasks, without success labels, and constructs and revises interfaces and usage knowledge in a repository. Population-based evolution then selects which repositories to develop further by their performance on validation tasks the meta-agent never sees, favoring changes that generalize beyond the seen tasks. On OSWorld V2, Agent S4, with Qwen3.8-27B and the evolved repository of interfaces, sets a new state of the art in open-source computer-use agents, reaching 21.3% binary score, 3.8 times the same model with fixed interfaces. This is above both GPT-5.5 (13.0%) and Claude Opus 4.8 (20.6%), at about 4.3% and 1.5% of their respective costs. On ScienceBoard, the evolved interfaces improve the success rate from 41.4% to 58.6% with the same model. These results suggest that useful interfaces can be evolved from experience, making autonomous interface design a source of improvement complementary to advances in models and harnesses. We open-source our code at https://github.com/simular-ai/agent-s.

## 2. 方法论

### 2.1 形式化框架

- **计算机与任务**：计算机状态 $s\in S$；任务 $x=(g,s_0,V_x,B_x)$，即指令、初始状态、评估器、预算。
- **接口**：$I=\langle c_I, A_I, O_I\rangle$，连接计算机的某个部分 $c_I$，请求语言 $A_I$，观察语言 $O_I$；执行 $(s',o)\sim T_I(\cdot\mid s,a)$。GUI 接口接受点击/按键并返回截图；shell 接口接受 bash 命令并返回字符串。
- **模型 / harness / 智能体**：$A=(M,H)$，harness 负责模型调用、请求执行、预算、权限 $P_H$、上下文准备与压缩。
- **仓库**：$R=(I(R), K(R))$，含可执行接口与支撑知识（能力描述、可复用工作流、配置、使用笔记）。智能体在 $I_R=I\cup I(R)$ 与 $K(R)$ 下选择接口与请求。
- **优化目标**：$R^\star\in\arg\max_R \mathbb{E}_{x\sim D}[J(A,R,x)]$，即在**构造经验之外**的任务分布上最大化期望得分。
- **接口演化算子**：$R_{k+1}=E(R_k,T_k)$，$T_k$ 为使用 $R_k$ 产生的轨迹。

### 2.2 Agent S4 的种群式演化流程（Algorithm 1）

1. **初始化**：从种子仓库 $R_0$ 出发，种群 $\mathcal{R}_0=\{R_0\}$，在训练集与验证集上各跑一次。
2. **循环 $k=1..N$**：
   - 算子调度 $\sigma(k)$ 决定 **mutation（1 个父代）** 或 **crossover（2 个不同父代）**，交替进行，从 mutation 开始。
   - **二元锦标赛选择**：均匀抽两个合格变体，取验证分数更高者；crossover 时第二个父代排除第一个。
   - **元智能体构造后代**：$A_{meta}=(M_{meta},H_{meta})$ 在其虚拟机 $C_{meta}$ 中持有父代仓库、训练轨迹、lineage notebook，通过文件/shell/代码接口诊断失败与低效、形成假设并直接改代码。
     - Mutation：增加、修订或删除接口与知识（操作、返回观察、可复用工作流）。
     - Crossover：在重叠接口间取舍、移植互补能力、合并为新代码与知识；**后代不必是父代并集**。
   - **冻结与评估**：$R'$ 固定后，任务智能体在合成训练任务 $T_{train}$ 与不相交验证任务 $T_{val}$ 上各跑一遍；仓库置于文件系统固定路径，通过既有代码执行工具调用（`capabilities` / `doc` / `call` 三个子命令）。
   - **入种群**：无论验证分数高低，$R'$ 与父代并存，保留替代设计；父代链接构成 DAG；可选剪枝仅移除父代资格、保留谱系。
3. **输出**：按验证准则从 $\mathcal{R}_N$ 选出 $\hat R$，冻结后在完整基准上评估。

### 2.3 关键设计：非对称评估（Asymmetric Evaluation）

- **元智能体只能看到训练轨迹**（合成任务、**无成功标签**、评估器恒返回 0 的占位符），验证任务、轨迹、诊断与分数**全部不可见**。
- 验证只通过**父代选择**间接影响构造，不提供直接编辑反馈，从而抑制对已见任务的过拟合。
- 训练轨迹被缓存复用：后代若成为父代，其历史轨迹继续作为证据。

### 2.4 具体实现细节

- 种子仓库约 550 行 Python/shell，含 4 个模块 15 个基础接口：`gui`（截图/点击/按键/活动窗口/grounding 模型）、`atree`（可访问性树/窗口列表/焦点元素）、`browser`（Chrome targets/活动标签/新标签）、`cli_ops`（gsettings、OOXML 结构/文本），外加 `cli.py`、`setup.sh`、`context_compaction.json`。
- 约束：仅 Python 标准库（VM 上禁用 pip）、VM 每次全新、禁止改 `shadow_interface/` 与 `notebook.jsonl` 之外的文件、禁止访问验证数据。
- 提示词要求接口具备**通用性**（"只解决单个任务说明抽象停得太早"）与**可发现性**（清晰签名与 docstring）。
