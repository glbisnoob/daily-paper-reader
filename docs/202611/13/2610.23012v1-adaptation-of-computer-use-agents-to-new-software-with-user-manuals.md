## 摘要
近期多模态基础模型的进展显著提升了通过图形用户界面（GUI）利用视觉观察和自然语言指令操作真实软件的能力。然而，在未见过的应用上保持强劲性能仍具挑战，因为实际任务通常需要长时程的程序性知识和应用特定的操作模式。此外，构建可执行任务并收集相应轨迹用于训练仍严重依赖人工标注数据，成本高昂。本文提出 MAGE（Manual-augmented computer use AGent Execution and learning，手册增强的计算机使用智能体执行与学习），一个利用用户手册作为可扩展程序性知识来源以同时改进推理和训练的框架。在执行阶段，MAGE 检索与任务相关的手册内容，并使用规划器为计算机使用智能体生成显式的程序性指导。为进一步应对手册与实际 GUI 环境之间的差异（如版本差异或用户设置），MAGE 还通过环境交互自适应调整智能体策略。在训练阶段，MAGE 将手册转换为可执行的任务-计划对，并利用计划引导环境 rollout 朝向任务相关状态；所得轨迹随后用于优化策略，无需人工编写的演示。这一统一设计使手册能够有效用于任务执行和训练，减少对人工编写训练数据的依赖。在六个应用上的实验结果表明，任务成功率相较强基线有所提升，凸显了手册引导的规划与策略自适应在新软件环境中的有效性。代码与复现脚本见 https://github.com/ku-autoai/MAGE。

## Abstract
Recent advances in multimodal foundation models have significantly improved the ability to operate real-world software through graphical user interfaces (GUIs) using visual observations and natural language instructions. However, maintaining strong performance on unseen applications remains challenging, as practical tasks often require long-horizon procedural knowledge and application-specific operation patterns. In addition, constructing executable tasks and collecting corresponding trajectories for training still heavily rely on human-annotated data, incurring substantial cost. In this paper, we propose MAGE (Manual-augmented computer use AGent Execution and learning), a framework that leverages user manuals as a scalable source of procedural knowledge to improve both inference and training. During execution, MAGE retrieves task-relevant manual content and uses a planner to generate explicit procedural guidance for CUAs. To further account for the discrepancies between manuals and actual GUI environments, such as version differences or user settings, MAGE also adapts the agent policy through environment interaction. During training, MAGE converts manuals into executable task-plan pairs and uses the plans to guide environment rollouts toward task-relevant states; the resulting trajectories are then used to optimize the policy without human-authored demonstrations. This unified design enables effective utilization of manuals for both task execution and training, reducing reliance on human-authored training data. Experimental results across six applications demonstrate improvements in task success rates over strong baselines, highlighting the effectiveness of manual-guided planning and policy adaptation in new software environments. We provide the code and reproduction scripts at https://github.com/ku-autoai/MAGE.

## 1. 核心问题与整体含义

- **研究背景**：多模态视觉语言模型（VLM）驱动的计算机使用智能体（CUA，如 UI-TARS、OpenCUA）已能仅凭屏幕截图和自然语言指令操作真实软件 GUI，不再依赖 API 或 HTML 结构。
- **核心痛点一：新软件适应难**。每个应用都有独立界面与功能布局，关键功能常隐藏在菜单、对话框、工具栏或快捷键之后，任务具有长时程（long-horizon）特性，导致智能体在未见应用上性能显著下降。
- **核心痛点二：训练数据昂贵**。现有适配方法（如 UI-TARS 的人工修正轨迹、OpenCUA 的大规模标注）依赖人工定义可执行任务并逐步采集动作轨迹，成本极高、难以规模化。
- **核心痛点三：强化学习信号稀疏**。GUI 任务需要逐步探索才能暴露可用选项，成功轨迹稀少，仅靠 RL 难以获得足够训练信号。
- **整体含义**：论文主张将**用户手册**视为一种可扩展的“程序性监督”（procedural supervision）来源——手册天然描述了功能入口、菜单路径与操作流程，可同时服务于**推理阶段的规划**与**训练阶段的策略优化**，从而在无人工演示的条件下实现新软件适配。

## 2. 方法论（MAGE 框架）

### 2.1 核心思想
- 统一框架 **MAGE**（Manual-augmented computer use AGent Execution and learning）：同一份用户手册既用于执行时的检索增强规划（RAP），也用于训练时的任务-计划对构造与策略优化（PO），形成“手册 → 规划 → 交互 → 评估 → 策略更新”的闭环。

### 2.2 执行阶段：检索增强规划（RAP）
- **手册索引**：将手册按文档结构切分为 section 级 chunk（LibreOffice 按目录切分，网页文档按 HTML 标题切分），用嵌入模型（Qwen3-Embedding-0.6B）编码为向量并存入向量数据库。
- **检索**：将任务指令编码为查询向量，按余弦相似度取 Top-K（默认 K=5）手册片段。
- **规划**：多模态 LLM 规划器（Qwen3.6 27B）以「任务指令 + 初始截图 + 检索片段」为输入，生成含具体按钮名、快捷键的逐步计划 P。
- **执行**：CUA 在整条 episode 中以固定计划 P 为条件选择动作：
  - \(a_t \sim \pi_\theta(\cdot \mid o_t, \tau_{<t}, P, I)\)
  - 计划在整个 episode 中保持不变，智能体仍依据当前观测与交互历史决策。

### 2.3 训练阶段：手册派生任务与策略优化
- **阶段一：任务生成**（训练前一次性完成）
  - 对每个手册 section，用多模态 LLM（GPT-5.4）同时生成 **setup 任务/计划**（可选，用于构造初始 GUI 状态）与 **main 任务/计划**（使用该 section 描述的功能）。
  - 通过显式分离 setup 任务，无需人工准备初始环境即可生成多样化可执行任务。
- **阶段二：Episode 生成**
  - 当前策略在真实 GUI 中执行任务-计划对；setup 成功后才执行 main 任务。
  - **评估器**：采用 VLM-as-a-judge，仅依据「任务指令 + 轨迹最后 5 张截图」判定二值成功奖励 \(R_{success} \in \{0,1\}\)，以降低幻觉与评估成本。
  - setup 与 main 作为**独立训练实例**，每条执行产生一个四元组 \((I, P, \tau, R_{success})\)。
- **阶段三：GRPO 策略优化**
  - **奖励设计**：总奖励 \(R_i = R^{success}_i + \lambda R^{step}_i\)，其中步数效率奖励仅在成功时生效：
    - \(R^{step}_i = (T_{max}-T_i)/(T_{max}-T_{min})\)，若 \(T_{max}=T_{min}\) 则为 0；权重 \(\lambda=0.1\)。
  - **优势估计**：按同一任务内的 episode 组做标准化 \(A_{i,k} = (R_{i,k}-\text{mean}(R_i))/\text{std}(R_i)\)；奖励方差为零的组被剔除。
  - **目标函数**：带裁剪的 GRPO 目标 + 对初始策略 \(\pi_{ref}\) 的 KL 惩罚：
    - 概率比 \(r_t(\theta)=\pi_\theta(a_t|\cdot)/\pi_{\theta_{old}}(a_t|\cdot)\)
    - \(J(\theta)=\frac{1}{|\tau|}\sum_t[\min(r_t A_t,\ \text{clip}(r_t,1-\epsilon,1+\epsilon)A_t)-\beta D_{KL}(\pi_\theta\|\pi_{ref})]\)
    - 超参：\(\epsilon=0.2\)，\(\beta=0.1\)，KL 参照为冻结的初始 CUA 策略。
  - **Round-based 训练**：将“episode 生成 + GRPO 训练”定义为一轮，新 episode 增量加入已有数据集反复训练，避免每步重采样，逐步提高成功轨迹比例。
  - **Episode 采样**：每个任务随机采样 1 条 episode 参与训练，但优势用该任务全部 episode 计算；setup 与 main 分别独立采样。
  - **微调方式**：LoRA（UI-TARS-1.5：rank 16、α=32、lr=1e-5、2 轮；EvoCUA：rank 8、α=16、lr=1e-6、1 轮），作用于 query/value/output 投影层。

## 3. 实验设计

### 3.1 数据集 / 场景与 Benchmark
- **OSWorld benchmark**：覆盖 5 个应用——LibreOffice Calc、Impress、Writer、GIMP、VSCode，涉及表格编辑、幻灯片修改、文档编辑、图像编辑、代码操作等多步 GUI 交互。
- **自建 Slack 评测集**：因 Slack 在主流 CUA benchmark 中覆盖有限，作者独立于训练手册构造 30 个任务（15 个功能主题），含 18 个仅 main 任务与 12 个 setup–main 任务对；用 Gemini 3.1 Pro Preview 判定成功。
- **手册来源**：LibreOffice 官方指南（Calc 7.1、Impress 7.6、Writer 7.3）、GIMP 3.2 官方文档、VSCode 官方文档、Slack Help Center。

### 3.2 对比方法
- **闭源强模型**：o3、Claude-Sonnet-4.5。
- **开源 CUA**：UI-TARS-DPO (72B)、OpenCUA (7B/32B/72B)、GUI-Owl-1.5 (32B)、TianXi-Action (7B)、EvoCUA (8B/32B)。
- **MAGE 变体**：以 UI-TARS-1.5 (7B) 与 EvoCUA (8B) 为骨干，分别与对应基座对比。

### 3.3 评估协议
- 每模型 5 次独立运行，报告均值 ± 标准差；OSWorld 总体成功率按任务数微平均。
- 50 步交互预算；使用 OSWorld 官方配置以保证公平。
- 统计显著性用双侧 Welch's t 检验。

### 3.4 消融与分析实验
- **消融**：RAP（执行期规划）与 PO（策略优化）的四组合对比（Calc）。
- **手册质量敏感性**：用 2010 旧版手册、以及保留 75%/50%/25% 的 2021 手册片段。
- **检索敏感性**：Top-5 vs 随机 5 段 vs 排名 6–10 的低相关段 vs 无 RAP；Top-K = 1/3/5/10。
- **人工验证**：150 个生成任务（有用性/可行性/视觉可验证性）、47 个生成计划（需求覆盖、流程正确性、可执行性、范围安全）、VLM 评估器与 OSWorld 规则评估器的一致性（114 例）。
- **成本分析**：各应用 API 费用、episode 生成与策略优化耗时。
