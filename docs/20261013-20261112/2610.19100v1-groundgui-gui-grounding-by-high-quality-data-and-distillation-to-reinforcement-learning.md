## 摘要
构建稳健的 GUI 智能体依赖于多模态视觉定位：即将自然语言意图精确映射到屏幕上的可操作组件的能力。尽管桌面端、网页端和移动端基准已十分丰富，但面向多样环境的高保真资源却出奇稀缺。为弥合这一差距，我们提出了屏幕指代定位数据集（ScreenRef），这是一个全面的 GUI 定位数据集，由 GUI 截图及与之配对的自然语言指代表达和框或点标注组成。ScreenRef 覆盖桌面端、网页端和移动端领域，包含 586K 张截图和超过 633K 个指代表达实例，涵盖文本识别、视觉匹配、空间理解和拒答场景等任务。为提升模型的定位性能，我们提出了蒸馏到强化学习（D2RL）方法，以解决监督微调泛化能力有限以及强化学习中奖励稀疏的问题。利用 ScreenRef，我们通过依次进行 SFT 和 D2RL 训练来训练 Qwen3-VL-8B-Instruct，得到 GroundGUI-8B。GroundGUI-8B 在 ScreenSpot-V2 上达到 95.2%，在 ScreenSpot-Pro 上达到 63.9%，在 OSWorld-G 上达到 65.4%，在 MMBench-GUI L2 上达到 86.8%，在 UI-Vision 上达到 38.3%。在 8B 规模模型中，相较于在开源数据集上训练的模型，它取得了显著提升，性能与在闭源数据上训练的模型相当甚至更优。代码、模型和数据集见 https://github.com/PrentisAI/GroundGUI。

## Abstract
Constructing robust GUI agents relies on multimodal visual grounding: the ability to precisely map natural language intents to actionable on-screen components. Despite abundant desktop, web, and mobile benchmarks, high-fidelity resources tailored for diverse environments are surprisingly scarce. To bridge this gap, we introduce the Screen Referring Grounding Dataset (ScreenRef), a comprehensive GUI grounding dataset consisting of GUI screenshots paired with natural language referring expressions and box or point annotations. Spanning desktop, web, and mobile domains, ScreenRef comprises 586K screenshots and over 633K referring expression instances, covering tasks such as text recognition, visual matching, spatial understanding, and refusal scenarios. To boost the model's grounding performance, we propose the Distillation-to-Reinforcement Learning (D2RL) method to address the limited generalization of supervised fine-tuning and the sparse reward problem in reinforcement learning. Utilizing ScreenRef, we train Qwen3-VL-8B-Instruct via sequential SFT and D2RL training, yielding GroundGUI-8B. GroundGUI-8B achieves 95.2% on ScreenSpot-V2, 63.9% on ScreenSpot-Pro, 65.4% on OSWorld-G, 86.8% on MMBench-GUI L2, and 38.3% on UI-Vision. Among 8B-scale models, it produces substantial gains over models trained on open-source datasets, with performance comparable or even superior to models trained on closed-source data. Code, models, and datasets are available at https://github.com/PrentisAI/GroundGUI.

# GroundGUI 论文结构化总结

## 1. 核心问题与研究动机

- **任务背景**：GUI 智能体的基础能力是**多模态视觉定位（GUI grounding）**——把自然语言意图精确映射为屏幕上的可点击坐标（框或点）。桌面、网页、移动端的界面复杂度高、分辨率大、图标语义专业且视觉高度相似，跨平台定位仍很困难。
- **数据瓶颈**：表现最好的 GUI 智能体（Mobile-Agent-v3.5、UI-Venus-1.5、UI-TARS-2、MAI-UI 等）依赖**闭源大规模数据**；已开源的数据集（GroundCUA、ScaleCUA）虽公开，但**多样性不足、标注噪声较大**，在其上训练的模型效果次优。现有移动端数据集布局标准化、网页数据集偏重可读文本元素、桌面数据集受无障碍树 API 不一致影响而标签噪声大。
- **训练瓶颈**：SFT 容易**过拟合特定领域**；GRPO 类 RL 方法在困难样本（小图标、空间关系查询）上**所有 rollout 都得零奖励**，奖励信号稀疏，难以学习。
- **整体含义**：作者试图同时从“**高质量、多平台、带拒答监督的数据**”和“**更稳健的后训练范式**”两条线解决 GUI 定位问题，并在 8B 规模上验证其可与闭源数据训练的模型竞争。

## 2. 方法论

### 2.1 ScreenRef 数据集构建（双路径）

- **Path 1：真实截图爬取**
  - 桌面用 Accessibility Tree、网页用 DOM、Android 用 XML 布局文件提取元素框、类别与文本。
  - 用 **OmniParser V2** 对元数据框去噪：与检测结果 **IoU < 0.5** 的框被移除。
  - **Qwen3-VL-235B-A22B-Instruct** 基于框、类别和上下文生成定位指令；**Qwen3.8-27B** 结合原图与框裁剪图判断“答案是否匹配指令”，做二次验证。
  - 指令分三类：**文本识别**（靠可读文字唯一指定）、**视觉匹配**（靠图标语义/形状/颜色）、**空间理解**（靠与锚点元素的相对关系或容器边界）。
- **Path 2：教程视频挖掘**
  - 自动生成搜索词爬取 YouTube 元数据，**Qwen3.6-27B** 过滤非教程视频；无字幕视频用 FFmpeg 抽音频生成转写。
  - 三阶段流水线：
    1. **关键帧候选提取**：基于块级帧差定位局部屏幕更新，降权全帧变化（切镜、滚动、视频播放），结合转写中的动作动词与 **YOLOv8** 光标检测重排，每视频最多 60 个候选；在时间戳前后搜索最近静态帧，构造干净的“变化前/后”帧对。
    2. **联合指令与动作标注**：帧对、时间戳、转写片段和视频元数据一起送入 **GPT-5.5**，同时完成任务分割与动作标注，输出含交互类型、参数和**严格基于可见屏幕证据**的元素级指代表达。
    3. **事后视觉定位**：以动作前帧为观测，**Qwen3.7-Plus** 预测目标是否存在、框/坐标与置信度；置信度低于 **τ = 0.95** 时升级到 **Claude Opus 5** 重定位，二次置信度仍低于阈值则丢弃。
  - **拒答样本**：将指令与帧随机配对，再用 Qwen3.8-27B 识别并验证“确实不可定位”的实例，填补现有数据集缺少不可行查询监督的空白。

### 2.2 D2RL：蒸馏到强化学习

- **总体思路**：SFT → **Stage I OPSD（在线策略自蒸馏）** → **Stage II RLOO**。OPSD 用稠密 token 级监督塑造更好的初始策略，缓解 RL 稀疏奖励；RLOO 再在原图观测下直接优化任务级点击奖励。
- **Stage I：On-Policy Self-Distillation**
  - 学生策略 πθ 仅接收原图 I 与指令 q，自行采样坐标响应 s。
  - 教师是**冻结的 SFT 策略副本**，仅在 OPSD 阶段接收“高亮 GT 目标框的截图 + 文本定位提示（目标名与框）”，推理时不使用。
  - 教师与学生在同一学生采样前缀上计算 **reverse KL**，实现沿学生自身轨迹的稠密监督。
  - **位置感知加权**：坐标数字 token 权重为 \(w_{pos}(t)=\beta\cdot k_t\)，\(k_t\) 表示数位重要性（个位 1、十位 2、百位 3），其他 token 权重为 1；理由是高位数字错误造成的空间偏差远大于低位。
  - 目标函数：\(L_{OPSD}=\frac{1}{T}\sum_t w_{pos}(t)\,D_{KL}(P^t_\theta \,\|\, P^t_{teacher})\)。
- **Stage II：REINFORCE Leave-One-Out（RLOO）**
  - **point-in-box 二值奖励**：响应无法解析为点击点时奖励为 0（格式检查是**门控**而非加分项）；否则在归一化坐标空间判断点 \((\hat x,\hat y)\) 是否落在目标框 \(B=(x_1,y_1,x_2,y_2)\) 内，是则 1，否则 0。
  - 每个样本采样 \(G\) 个响应，用组内**留一法均值**作为基线，无需 critic：
    \[
    \nabla_\theta J=\frac{1}{G}\sum_{i=1}^{G}\left(R_i-\frac{1}{G-1}\sum_{j\ne i}R_j\right)\nabla_\theta\log\pi_\theta(s_i\mid I,q)
    \]
  - 不使用 KL 惩罚。

  - **开源数据训练模型**：在 GroundCUA、ScaleCUA 上复现或直接采用的同规模（8B 级）模型，作为数据质量对照。
  - **通用多模态大模型**：Qwen3-VL 系列、GPT 系列视觉模型等零样本/少样本结果，作为能力下界参考。
  - **消融基线**：纯 SFT、SFT+GRPO、SFT+OPSD、SFT+RLOO 等组合，用于分离“数据”与“后训练范式”的贡献。

- **训练与实现细节**：
  - 基座模型为 8B 级多模态模型，统一采用“原图 + 指令 → 坐标点”的输出格式，坐标归一化到 [0,1] 区间。
  - SFT 阶段使用 ScreenRef 全量数据（含拒答样本）；OPSD 阶段教师为冻结的 SFT 副本，仅训练时接收高亮 GT 框；RLOO 阶段每样本采样 \(G\) 个响应，point-in-box 二值奖励，无 KL 惩罚。
  - 数据划分上，教程视频路径与真实截图路径分别统计规模、平台分布与指令类型占比，并做去重与泄漏检查（与评测集做元素/截图级相似度过滤）。

## 4. 主要实验结果

- **整体定位精度**：GroundGUI 在 ScreenSpot-V2、ScreenSpot-Pro、MMBench-GUI L2 上均取得 8B 规模下的领先或可比成绩，尤其在 ScreenSpot-Pro 这类高分辨率、小目标密集场景上相对开源数据基线提升明显，缩小了与闭源数据训练模型的差距。
- **跨平台一致性**：在 web/桌面/移动三类平台上表现更均衡，说明 ScreenRef 的多平台采集与去噪流程有效缓解了单一平台偏置；而仅用移动端或网页数据训练的基线在桌面专业软件上掉点显著。
- **拒答能力**：在 OSWorld-G 的拒答子集上，包含拒答监督的 GroundGUI 明显优于不含该监督的对照模型，误点率下降，表明“不可定位查询”的显式监督对实际部署安全性有实质价值。
- **真实 computer-use 场景**：OSWorld-G 上文本匹配、元素识别、布局理解、细粒度操作各子项均有提升，说明数据多样性带来的收益可迁移到端到端智能体任务。
- **RL 训练动态**：RLOO 在困难样本上的零奖励比例较 GRPO 明显降低（得益于 OPSD 提供的更好初始策略），训练曲线更平稳，验证了“先稠密蒸馏、再稀疏任务奖励”的两阶段设计。

## 5. 消融与分析

- **数据来源消融**：分别去掉教程视频路径、去掉拒答样本、去掉 OmniParser 去噪或去掉二次验证，均导致性能下降；其中去噪与二次验证对 ScreenSpot-Pro 的小目标定位影响最大，拒答样本主要影响 OSWorld-G。
- **指令类型消融**：文本识别、视觉匹配、空间理解三类指令混合训练优于单一类型，空间理解类样本对密集布局场景贡献突出。
- **后训练范式消融**：
  - 纯 SFT 易在特定平台过拟合，跨平台泛化差；
  - SFT+GRPO 在困难样本上奖励稀疏，提升有限；
  - SFT+OPSD 显著改善初始化，但缺少任务级奖励的直接优化；
  - SFT+OPSD+RLOO 取得最佳综合效果，验证两阶段互补性。
- **位置感知加权分析**：对坐标数字 token 按数位加权（个位 1、十位 2、百位 3）优于均匀加权，说明高位数字误差对空间偏差的影响更大，加权能更有效地约束粗粒度定位。
- **教师输入消融**：教师仅在高亮 GT 框条件下提供监督、推理时不使用该信息，保证学生部署时无泄漏；去掉高亮提示后 OPSD 收益明显衰减。

## 6. 贡献与意义

- **数据层面**：提出 ScreenRef，通过“真实截图爬取 + 教程视频挖掘”双路径构建多平台、多指令类型、带拒答监督的高质量 GUI 定位数据集，并提供可复现的去噪与验证流水线。
- **方法层面**：提出 D2RL（OPSD + RLOO），用在线策略自蒸馏缓解 RL 稀疏奖励，再用无 critic 的 RLOO 直接优化点击奖励，为 GUI 定位的后训练提供了一套稳健范式。
- **实证层面**：在 8B 规模上证明公开数据 + 合理后训练可逼近闭源数据训练模型，为社区提供了可复现的强基线。

## 7. 局限性

- 教程视频路径依赖外部模型（GPT-5.5、Claude Opus 5 等）做标注与重定位，成本与可复现性受第三方 API 影响。
- 奖励仅为 point-in-box 二值信号，未显式建模框级精度、交互类型（点击/拖拽/输入）或多步任务依赖。
- 评测集中于静态截图定位，端到端智能体长程任务中的累积误差与状态变化尚未充分评估。
- 拒答监督基于模型判断“不可定位”，仍可能存在与人类标注不一致的边界样本。
