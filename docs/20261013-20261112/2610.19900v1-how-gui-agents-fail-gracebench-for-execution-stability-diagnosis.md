## 摘要
随着 GUI 智能体越来越多地部署于移动任务自动化，其可靠性不仅取决于最终任务结果，还取决于它们是否通过稳定的交互轨迹达成这些结果。在自动化工作流中，不必要的动作、绕行和执行错误会给采集数据引入噪声、造成不可逆的副作用或削弱信任，即使智能体最终完成了任务。因此，系统性地诊断执行稳定性十分重要，包括智能体是否偏离可行路径、进入循环、陷入停滞，或能否从不稳定动作中恢复。然而，现有基准主要评估最终任务成功或少量中间里程碑，导致步骤级执行行为仍不清晰。为弥补这一空白，我们提出 GraceBench，一个在线评估框架，将移动应用的可达交互空间表示为 UI 转换图（UTGs），为步骤级执行诊断提供结构化参考。为支持动态 UI 观测与图状态之间的可靠对齐，GraceBench 在此图对齐表示上使用基于视频的轨迹评估，通过偏离率、循环负担率和恢复能力等指标评估最终成功之外的过程稳定性。GraceBench 包含跨越 10 个应用的 169 个任务，并构建了 10 个 UTG，包含 2,909 个规范 GUI 状态和 3,116 个观测到的转换。在 3,718 条轨迹上，GraceBench 表明结果分数掩盖了执行不稳定性：GPT-5.6 Sol 取得最高成功率（SR），但恢复能力最低，51.24% 的成功运行仍包含偏离或循环，且具有相同成功率（SR）和完成率（CR）的轨迹在恢复行为上可能差异显著。代码和数据将在 https://iaie-physicalai.github.io/GraceBench 发布。

## Abstract
As GUI agents are increasingly deployed for mobile task automation, their reliability depends not only on final task outcomes, but also on whether they reach these outcomes through stable interaction trajectories. In automation workflows, unnecessary actions, detours, and execution errors can add noise to collected data, introduce irreversible side effects, or undermine trust, even when the agent eventually completes the task. It is therefore important to systematically diagnose the execution stability, including whether an agent deviates from a feasible path, enters a loop, becomes stagnant, or recovers from unstable actions. Existing benchmarks, however, primarily assess final task success or a small set of intermediate milestones, leaving step-level execution behavior unclear. To bridge this gap, we introduce GraceBench, an online evaluation framework that represents the reachable interaction space of mobile applications as UI Transition Graphs (UTGs), providing a structural reference for step-level execution diagnosis. To support reliable alignment between dynamic UI observations and graph states, GraceBench uses video-grounded trajectory evaluation over this graph-aligned representation, assessing process stability beyond final success with metrics such as deviation rate, loop burden rate, and recovery ability. GraceBench contains 169 tasks spanning 10 applications and constructs 10 UTGs with 2,909 canonical GUI states and 3,116 observed transitions. Across 3,718 trajectories, GraceBench shows that outcome scores hide execution instability: GPT-5.6 Sol achieves the highest success rate (SR) but the lowest recovery ability, 51.24% of successful runs still contain a deviation or loop, and trajectories with the same success rate (SR) and completion rate (CR) can differ substantially in recovery behavior. Code and data will be released on https://iaie-physicalai.github.io/GraceBench.

## 1. 核心问题与研究动机

- **背景**：GUI 智能体正被广泛用于移动任务自动化（如日常操作、软件测试数据采集）。其可靠性不仅取决于“是否最终完成任务”，还取决于“是否通过稳定的交互轨迹完成”。
- **核心痛点**：不必要的动作、绕路、循环和执行错误会给采集数据引入噪声、造成不可逆副作用或削弱信任，即使任务最终成功。
- **现有基准不足**：
  - 多数基准（如 AndroidWorld）只评估最终任务成功，无法反映过程稳定性。
  - 里程碑式基准（如 A3、SPA-Bench、ProBench）虽引入中间语义检查点，但仍属粗粒度，无法区分“干净成功”与“带循环/偏离后成功”。
  - 离线评估依赖单一黄金轨迹，忽略多路径与恢复能力。
- **研究目标**：系统诊断 GUI 智能体的**步骤级执行稳定性**，包括是否偏离可行路径、进入循环、停滞，以及能否从错误中恢复。

## 2. 方法论

### 2.1 核心思想

- 将移动应用的**可达交互空间**建模为 **UI Transition Graph（UTG）**：
  - 节点 = 可视觉验证的 GUI 状态；
  - 边 = 可执行动作导致的状态转移。
- 每个任务定义为 UTG 的**任务子图**，包含多条合法路径；将智能体实际执行轨迹映射回该图，进行步骤级诊断。
- 由于移动 UI 动态变化（加载、弹窗、动画、内容更新），采用**同步视频证据**对齐观测与图状态。

### 2.2 关键技术流程

**（A）UTG 构建（Agent-driven Exploration）**
- 通过 ADB 观测当前屏幕（截图 + UI hierarchy），智能体选择候选动作并执行。
- 记录 `state-action-state` 转移；支付、下单、授权等高风险操作设为**边界状态**，不执行。
- 探索后人工审查、去重、归一化，得到规范 UTG。
- 规模：10 个应用 UTG，3,265 次状态观测归一化为 **2,909 个规范状态**，**3,116 条观测转移**。

**（B）任务策展**
- 选择具有稳定完成语义的终端状态作为任务目标，提取任务子图（含替代合法路径）。
- 每个任务生成两种指令：
  - **简洁指令**：仅描述用户目标；
  - **详细指令**：沿一条人工验证的可行路径给出步骤级操作。
- 对查询词、类别、实体、选择器进行参数化，降低对固定表面形式的过拟合。

**（C）在线执行环境**
- 在物理 Android 设备上在线循环执行，动作空间：`CLICK / SWIPE / TYPE / ENTER / BACK / COMPLETE / WAIT`（排除 `HOME`）。
- 每步记录 `(o_t, a_t, o_{t+1})`，并用 scrcpy 全程录屏，动作时间戳与视频同步。

**（D）视频对齐的轨迹评估**
- 将 episode 视频按动作时间戳切分为步骤级片段。
- 将动作前后观测映射到图状态：
  - 若匹配某状态 `v_i` 则记为 `v_i`，否则记为图外状态 `v_out`；
  - 局部转移转化为图对齐转移 `(v̂_t, a_t, v̂_{t+1})`。
- 为每步分配四类标签之一：
  - **on path**：沿任务子图合法转移；
  - **stagnation**：无有意义状态变化；
  - **deviation**：离开任务子图或进入 `v_out`；
  - **recovery**：从偏离状态返回合法状态/转移。
- 标签先由专家智能体生成，再在**预注册分层 10% 样本**上与盲审人类专家比对（Cohen's κ：状态匹配 0.798、偏离 0.795、恢复 0.766、循环 0.866）。

### 2.3 评估指标

- **SR（成功率）**：评估摘要中标记成功的轨迹比例。
- **CR（完成率）**：已完成的任务必需转移数 / 必需转移总数。
- **DR（偏离率）**：偏离标签步骤数 / 可评分步骤数（排除 WAIT、COMPLETE）。
- **LBR（循环负担率）**：循环覆盖步骤数 / 决策步骤数（仅在发生循环的轨迹上聚合）。
- **RSR（恢复成功率）**：成功返回任务子图的偏离事件数 / 偏离事件总数。
- **ARL（平均恢复延迟）**：从首次偏离到返回任务子图的步数均值。
- **RA（恢复能力）**：每次恢复机会贡献 `c_i = 1/max(1, latency_i)`（恢复时），否则为 0；对恢复机会取平均。

## 6. 主要结论与发现

- **失败由不稳定

- **失败由不稳定执行主导，而非单纯的“能力不足”**：失败轨迹中偏离、循环与停滞的比例显著更高；不少失败并非完全没有接近目标，而是在接近后因一次错误转移进入循环或 `v_out`，最终耗尽 15 步预算。过程指标能揭示“结果相同、过程质量不同”的失败模式。
- **成功轨迹并不等于“干净执行”**：即使最终成功，仍有相当比例轨迹包含偏离或循环，只是通过后续恢复回到任务子图。这说明仅以 SR 评价会系统性高估智能体的可靠性，也会掩盖采集数据中的噪声与潜在副作用。
- **结果控制后过程差异仍存在**：在相同 SR、精确 CR 的匹配对中，模型间在 DR、LBR、RA 上仍出现显著差异；且该结论在 CR 容差与过程差距阈值的 54 种设置下方向一致，说明过程指标提供了独立于结果的信息，而非成功率的代理变量。
- **指令粒度是一把“双刃剑”**：详细指令通常提升完成率、降低偏离，但也可能带来更机械的步骤跟随；简洁指令更接近真实用户使用，却更易触发探索性偏离。配对分析显示指令效应具有任务/场景异质性，不能简单认定“越详细越好”。
- **模型排名具有较好的跨任务一致性**：在 1,000 次分层任务划分下，模型的过程指标排名与总体排名呈稳定正相关（Spearman ρ 显著），说明 GraceBench 的评估并非由少数任务驱动，排名结论具有一定泛化性。
- **及时恢复与任务成功显著关联**：在匹配与回归调整后，较短的恢复延迟、较高的恢复成功率与最终成功相关；但作者将其定位为关联性证据而非因果结论。
- **过程指标具有增量预测价值**：在结果变量之外加入 DR/LBR/RA 等过程特征，可提升对任务成功的预测；消融显示增益主要来自偏离与恢复类指标，而非单纯的轨迹长度。
- **基准层面具备区分度**：与 AndroidWorld、SPA-Bench、A3 等相比，GraceBench 能区分“干净成功”“带恢复成功”“循环后失败”等结果相同但过程不同的情形，弥补了里程碑式检查点粗粒度与离线单黄金路径评估的不足。

## 7. 局限与可改进方向

- **UTG 构建成本高且依赖人工审查**：图构建需要智能体探索加人工去重、归一化，扩展到大量应用时成本较高；图的完备性受探索覆盖度限制，未观测到的合法路径可能被误判为偏离。
- **状态匹配受 UI 动态性影响**：加载、弹窗、动画、推荐内容刷新等会造成同一语义状态的外观差异；虽有视频对齐与状态归一化，仍存在 `v_out` 误判风险，人工审计 κ 值虽较高但非完美。
- **任务子图与“合法路径”的定义带有策展者视角**：多路径建模缓解了单黄金轨迹问题，但任务边界、终端状态与替代路径的选择仍可能引入主观性。
- **恢复指标的机会结构未完全可控**：RSR/ARL/RA 依赖自然发生的偏离与恢复机会，机会难度、剩余预算、错误类型难以完全匹配；作者也将其部分分析标为探索性。
- **成功标签未重新审核**：沿用已有评估摘要的成功判定，可能与视频证据存在细微不一致；两个 GUI 专用模型的视觉材料未纳入分析包，影响完全复现与再裁定。
- **场景样本不均衡**：抖音 63 个任务而直播仅 8 个，细粒度场景结论的估计精度有限；10 个应用、169 个任务的规模仍小于大规模众包基准。
- **未报告推理算力与设备细节**：物理设备型号、并发规模、推理硬件等未披露，复现成本和吞吐难以估计。
- **可改进方向**：引入自动化图增量维护与状态匹配学习；报告按场景/任务长度的分层置信区间；预注册恢复机会的匹配策略；公开视频与标注以支持独立复核；将过程指标扩展到副作用与不可逆操作风险度量。

## 8. 对领域的启示

- **评估范式**：从“结果导向”转向“过程—结果联合评估”，是 GUI 智能体走向可靠部署的必要条件；UTG + 视频对齐提供了可操作的步骤级诊断框架。
- **数据采集**：对于以智能体采集训练数据的场景，过程指标可直接用于过滤“带循环/绕路”的脏轨迹，降低噪声与不可逆副作用风险。
- **模型选择**：相同成功率下应优先选择偏离率低、恢复快的模型；过程指标可作为部署前的稳定性门槛。
- **指令设计**：简洁/详细指令应作为评估维度而非单一设定，以反映真实用户分布与模型鲁棒性。
- **可复现性**：视频证据与预注册人工审计提升了评估可信度，但仍需更完整的材料公开与算力披露。

## 9. 总体评价

GraceBench 的核心贡献不在于提出新模型，而在于把 GUI 智能体评估从“是否完成”推进到“如何完成”。其 UTG 建模、多路径任务子图、视频对齐的步骤级标注与一组互补的稳定性指标，构成了较完整的诊断工具；实验覆盖 11 个模型、3,718 条轨迹，配合匹配分析、置换检验与人工盲审，统计严谨性在同类基准中较为突出。主要不足在于图构建与状态匹配的成本和误差、恢复机会的不可控性、场景样本不均衡以及算力与部分材料披露不足。总体而言，该工作为 GUI 智能体的可靠性评估提供了有价值的范式与可复用的度量体系，但其结论更适合作为“过程稳定性重要且可测”的强证据，而非对具体模型能力的最终定论。
