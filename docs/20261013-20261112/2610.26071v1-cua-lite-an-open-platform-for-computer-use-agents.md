## 摘要
计算机使用智能体（CUA）的开放资源——环境、数据集和模型——仍然分散：缺乏标准时，这些资源无法集成和扩展；此外，评估、强化学习（RL）和监督微调（SFT）无法共享同一套基础设施。我们提出 CUA-Lite，一个用于开发 CUA 的开放平台，围绕三个标准化抽象构建：（1）统一环境接口，在该接口下我们集成了涵盖桌面、浏览器和移动端的 12 个基准，以及以更低成本复现 OSWorld 桌面环境的轻量级无虚拟机沙箱，提供超过 30,000 个可验证任务。（2）统一监督数据格式，我们将主要的公开 CUA 数据集转换为该格式，涵盖从 GUI 定位与理解到完整 rollout 的数据，并记录前沿 CUA 在这些可验证环境中的新采集 rollout。（3）跨评估、RL 和 SFT 共享的模型 harness，每个模型一个，并为 14 个模型系列实现。每个 harness 在这些计算机环境中运行其模型，生成供评估和 RL 使用的 rollout，或将存储的监督数据转换为该模型自身的 SFT 训练格式。我们发布了集成基准上的参考分数，并表明通过同一 harness 进行 RL 和 SFT 可以提升开放权重模型。我们发布数据集、代码和模型，平台开放接受贡献。

## Abstract
Open resources for computer use agents (CUAs) -- environments, datasets, and models -- remain scattered: without a standard, these resources cannot be integrated and scaled; additionally, evaluation, RL, and SFT cannot share one infrastructure. We present CUA-Lite, an open platform for developing CUAs, built around three standardized abstractions: (1) Unified environment interface, under which we integrate 12 benchmarks across desktop, browser, and mobile, plus lightweight VM-free sandboxes that replicate OSWorld's desktop at much lower cost, providing over 30,000 verifiable tasks. (2) Unified supervised data format, into which we convert the major public CUA datasets, from GUI grounding and understanding to full rollouts, and record our fresh rollouts from frontier CUAs on these verifiable environments. (3) Model harnesses shared across evaluation, RL, and SFT, one per model and implemented for 14 model families. Each harness runs its model in these computer environments, producing the rollouts that evaluation and RL consume, or renders stored supervised data into the model's own training format for SFT. We release reference scores across the integrated benchmarks, and show that RL and SFT through the same harness improve open-weight models. We release our dataset, code, and models, and the platform is open to contributions.

## 1. 核心问题与研究动机

- **背景**：计算机使用智能体（Computer Use Agent, CUA）需要在桌面、浏览器、移动端等真实计算机环境中操作应用。构建这类智能体需要三类开放资源：可验证任务的环境、监督数据、模型及其运行脚手架（harness）。
- **核心问题：资源高度碎片化**：
  - 每个环境都有自己的接口与运行时（VM、浏览器、移动模拟器），多数桌面基准以虚拟机形式发布，需要 KVM 与完整客户机操作系统，部署重、启动慢。
  - 每个监督数据集有自己的格式（GUI 定位标签、理解问答、完整 rollout）。
  - 每个模型有自己的动作空间、提示格式和 rollout 代码。
- **后果**：把模型接到环境上必须反复重写同样的代码（动作映射、上下文管理、rollout 循环），开放资源无法集成与规模化；更关键的是，**评估、强化学习（RL）、监督微调（SFT）无法共享同一套基础设施**。
- **整体含义**：论文试图为 CUA 开发建立"一个标准"，用三项标准化抽象把环境、数据、模型解耦并统一，使同一份 rollout 代码同时服务评测、RL 与 SFT，从而降低 CUA 研究与训练的门槛。

## 2. 方法论

### 2.1 核心思想
以三个标准化抽象为骨架，各资源只需向标准对齐一次，即可与所有其他资源互操作：

1. **Lite.Gym**：统一环境接口。
2. **Lite.Sample**：统一监督数据格式。
3. **每模型一个 harness**：把模型同时适配到上述接口与数据格式，评测、RL、SFT 复用同一份代码。

### 2.2 关键技术细节

- **统一环境接口（Lite.Gym）**
  - Gym 风格循环：`reset / step / close`；`gym.make("osworld@chrome_030", max_steps=30)`。
  - 统一观测格式：截图、文本或二者兼有。
  - **GUI 动作即工具调用**，按平台各一个工具：
    - 桌面/浏览器：`computer`（click, mouse_move, drag, scroll, type, key, hold_key, wait, screenshot, cursor_position 等）。
    - 移动端：`mobile`（tap, long_press, swipe, drag, pinch, type, system_button）。
    - 定位任务：`point` / `bbox`。
    - 坐标在所有平台上归一化到 `[0, 1000]`。
  - **动作批处理**：一次工具调用可携带多个 GUI 动作，每个 `call_id` 返回一个结果，多步动作只需一次往返。
  - **环境可附加额外工具**：桌面 `bash`，浏览器 `goto/back/forward/new_tab/switch_tab/close_tab`，移动端 `open_app`、`ask_user`；所有平台通用 `response`、`terminate`。
  - 接口包裹环境原有运行时（VM / 浏览器 / 模拟器），不改变上游任务与评测器。

- **无虚拟机桌面沙箱（Lite.\*）**
  - 官方 OSWorld VM 只有磁盘镜像、无构建配方，作者**逆向工程**出其中安装的应用与配置，用 Dockerfile 重建为容器化 Linux 桌面。
  - Lite.OSWorld 保留 OSWorld 的 369 个评测任务、初始设置与验证器不变。
  - 收益：内存约为 VM 的 1/6（0.6 GB vs 3.8 GB）、冷启动约 3/4（21.3 s vs 29.3 s）、磁盘 6.8 GB vs 31 GB、空闲 CPU 1.4% vs 5.7%。
  - 保真度：13 个模型在 332 个相同任务上，与 OSWorld 平均差 2.7 分、最差 5.0 分（EvoCUA-8B），Spearman 相关 0.98。

- **统一监督数据格式（Lite.Sample）**
  - 数据结构：`images`（去重后的图像）+ `messages`（user / assistant / tool 多轮）+ `metadata`（`dims = (Platform, TaskType)`，TaskType 含 grounding.action/point/bbox、understanding、use）。
  - 消息内容按类型打标签：`text`、`image`、`action_description`（一步动作的一行自然语言描述）、`inline_reasoning`、`history_summary`；推理单独放在 `reasoning_content` 字段。
  - 好处：harness 可按类型（而非解析文本）选择丢弃推理、只保留最近若干截图、或用动作描述替代历史步骤。
  - 转换规则：坐标重缩放到 [0,1000]、动作重建到 Lite.Gym 动作集、图像按内容去重；图像缺失或坐标越界的样本**直接丢弃而非修复**（rollout 则整条丢弃）。

- **每模型 harness**
  - 核心是一个 adapter：在 Lite.Sample 与模型自身输入/输出格式之间转换。
  - SFT 时：把存储的 Lite.Sample 渲染成该模型的训练格式。
  - 评测/RL 时：随 rollout 增长逐步渲染，并把模型回复转回 Lite.Gym 动作。
  - 内部两模块：`action_space`（原始动作 ↔ 标准 GUI 动作映射）、`protocol`（跨轮上下文管理）。
  - 模块可继承（Qwen3.5、Qwen3.8、EvoCUA 均基于 Qwen3-VL），新 harness 只实现差异部分；已覆盖 **14 个模型家族**，含开源权重模型（UI-TARS、Qwen 等）与 API 模型（GPT、Claude、Gemini）。

- **训练实验**：SFT 3 个平台 + 4 类消融（教师、推理有无、截图数量 1/4、有无 SFT 对照），表 G.1 给出全部 12 种设置；GRPO 3 个平台 × 5 个随机种子，报告均值与标准误。
- **充分性评价**：
  - **较强之处**：训练实验有 5 个种子并报告标准误；SFT 评测在 temperature 0 下重复 3 次取均值；消融设计有针对性（教师强弱、推理是否为关键、图像历史是否必要）；运行时对照严格控制了内存/核数分配与交替测量以抵消主机漂移。
  - **客观性**：作者明确声明多数已有分数**没有可运行脚本，因此不声称复现**，只把自己的分数作为"可重跑的参考分"；WebVoyager 跑在离线镜像上并明确说明"测的是镜像不是真实站点"。
  - **不足之处**：主评测每任务仅 1 次 rollout、单一种子，缺少方差报告；部分基准只评子集（WebArena 241/812、MobileWorld 117/201 等），跨模型比较受子集选择影响；RL 的桌面与移动在**训练用过的应用**上评测，未测跨应用迁移；移动端仅 1 个训练环境，泛化证据薄弱。

## 6. 主要结论与发现

- **平台可行且成本显著降低**：容器化 Lite.OSWorld 在保持任务、设置、验证器不变的前提下，与 OSWorld 分数平均差 2.7 分、排序 Spearman 0.98，但内存降至约 1/6
