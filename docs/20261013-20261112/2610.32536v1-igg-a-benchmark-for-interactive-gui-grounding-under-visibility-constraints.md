## 摘要
GUI 定位基准考察智能体能否定位静态截图中已经可见的目标。真实界面往往违背这一假设：目标可能位于屏幕之外，仅在状态变化或悬停后出现，持续被遮挡，或在延迟后才可操作。这使得恢复目标可见性的能力未被评估。为衡量这一“显现”步骤，我们提出交互式 GUI 定位（IGG）基准，其中智能体必须首先通过交互使目标可见，然后点击它。IGG 包含 601 个任务，覆盖 16 个可控 GUI 环境和七种可见性约束子类型，动作空间紧凑，包括滚动、移动、拖拽、等待和点击。在人类研究中，参与者达到 94.6% 的准确率，而 GPT-5.5 达到 79.4%，评估中最强的开源 VLM 仅达到 31.6%。为找出这一差距的来源，我们进行了两项受控干预。告诉 Qwen3-VL 应执行哪种交互仅将其准确率从 30.8% 提升到 33.9%，而替模型执行该交互则将其提升到 81.9%。瓶颈在于执行“显现”交互，而非在目标暴露后识别它。我们进一步表明这种能力是可学习的，证明可见性恢复能力可以在不同模型系列中一致地得到增强。

## Abstract
GUI grounding benchmarks ask whether an agent can localize a target that is already visible in a static screenshot. Real interfaces often violate this assumption: a target may be off-screen, appear only after a state change or hover, remain occluded, or become actionable after a delay. This leaves the ability to recover target visibility unevaluated. To measure this reveal step, we introduce Interactive GUI Grounding (IGG), a benchmark in which an agent must first make the target visible through interaction and then click it. IGG contains 601 tasks across 16 controllable GUI environments and seven visibility-constraint sub-types, with a compact action space of scrolling, moving, dragging, waiting, and clicking. In our human study, participants achieve 94.6% accuracy, while GPT-5.5 reaches 79.4% and the strongest evaluated open-source VLM reaches only 31.6%. To identify the source of this gap, we conduct two controlled interventions. Telling Qwen3-VL which interaction to perform raises its accuracy only from 30.8% to 33.9%, whereas performing the interaction for the model raises it to 81.9%. The bottleneck is executing the reveal interaction, not recognizing the target once it is exposed. We further show that this capability is learnable, demonstrating that visibility recovery can be strengthened consistently across model families.

## 1. 核心问题与研究动机

- **背景假设的缺陷**：现有 GUI grounding（界面定位）基准（ScreenSpot、ScreenSpot-Pro、OSWorld-G 等）都在**单张静态截图**内评估“指令→坐标”的映射，默认目标元素**已经可见**。
- **真实界面的反例**：目标常常位于视口之外、藏在折叠面板中、被弹窗遮挡、只有悬停才显示标签、或需要等待延迟加载后才可点击。此时**任何静态定位模型无论多准都无法在初始截图中定位目标**。
- **评测体系的空档**：
  - 静态 grounding 基准完全不测量“使目标显现”这一步；
  - GUI 导航基准（Mind2Web、WebArena、OSWorld）把这一步折叠进端到端任务成功率，导致规划、探索、定位失败混为一个信号，无法归因。
- **核心研究问题**：当前 GUI 智能体能否在定位之前**先让目标可见**？若不能，失败发生在哪个阶段？
- **整体含义**：论文把“可见性恢复（visibility recovery）”从导航任务中**剥离出来单独测量**，提出 IGG 基准，定位为静态 grounding 与端到端导航之间的一个**中间能力轴**，二者互补而非替代。

## 2. 方法论

### 2.1 任务形式化

- 一个 IGG 任务由四要素定义：**初始界面状态**（目标不可见/不可操作）、**仅含目标的指令 q**（只说明点哪个，不泄露操作流程）、**带稳定 ID 的目标元素**、**点击时刻判定器**（点击元素 ID 与目标 ID 匹配即成功）。
- 每步智能体接收：截图 $s_t$、指令 $q$、动作历史 $h_{t-1}$，从动作空间选一个动作，获得下一帧 $s_{t+1}$。
- 仅提供**截图级观测**；DOM、可访问性树、目标 ID、真值轨迹对模型全部隐藏。
- 动作预算 8 步；首次命中目标的点击即成功，预算耗尽即失败；点到别处会触发已定义的界面状态转移，回合继续。

### 2.2 四阶段分解（核心分析框架）

将成功分解为：① 选择正确的“显现”动作；② 在正确位置/以正确参数执行该动作；③ 目标出现后识别它；④ 定位最终点击。**①+② 定义为“可见性恢复”**，③+④ 等同于静态 grounding。这一分解是后续干预实验的理论基础。

### 2.3 紧凑动作空间（5 个动作）

| 动作 | 作用 |
|---|---|
| SCROLL(dir, Δpx) | 滚动以露出视口外区域 |
| MOVE(x, y) | 移动指针触发 hover 状态/消歧线索 |
| DRAG(startX, startY, endX, endY) | 拖拽元素（如移开遮挡物） |
| WAIT(Δt) | 等待延迟/异步 UI 更新 |
| CLICK(x, y) | 最终定位，评测在此步判定 |

### 2.4 可见性约束分类体系（3 大类 / 7 子类）

- **约束类型 1：视口约束（Viewport）**
  - CT1-1 滚动探索：目标在视口外，需 SCROLL。
- **约束类型 2：多状态约束（Multi-State）**——目标或被识别所需的线索被当前 UI 状态隐藏
  - CT2-1 视觉消歧：目标与邻近元素外观相似，需 MOVE 触发 tooltip/标签；
  - CT2-2 隐藏状态激活：目标在下拉框/标签页/侧栏中，需先展开；
  - CT2-3 可移除遮挡：弹窗/模态框挡住目标，需先关闭。
- **约束类型 3：时序与操作约束（Temporal & Manipulation）**
  - CT3-1 延迟状态激活：目标初始不可交互，需 WAIT；
  - CT3-2 动态目标交互：目标在轮播/滚动条中自动切换，需等待正确状态或用导航控件；
  - CT3-3 可移动遮挡：遮挡元素需 DRAG 移开/缩放。

### 2.5 环境与任务构建

- **16 个可控 Web 环境**，参照 Gmail、Google Calendar、GitHub、VS Code Web、Discord、Google Docs、Figma、Google Sheets、Notion、Netflix、Walmart、Spotify、Google Maps、YouTube、Twitter/X、Google 等真实应用构建（仅作规范参照，无隶属关系）。
- 环境特性：**确定性初始状态、可复现的状态转移、每个元素带稳定 ID**，因此点击时刻可**程序化判定**，无需启发式匹配；同时保留 hover 显现、折叠面板、弹窗、延迟激活、轮播、可拖拽遮挡等难点交互模式。
- 评测器：Playwright 驱动 Chromium，视口 1440×900。
- **三步任务构建流程**：
  1. 多模态智能体起草“仅目标”指令与参考轨迹；
  2. 人工改写**泄露流程**的指令（如把“悬停消息后点 Reply”改为“点 Minji 消息上的 Reply”），并在多个同名元素时补充自然消歧线索（作者、标题、上下文）；
  3. 人工重放每条轨迹，确认目标唯一且可达。

### 2.6 训练方法（两阶段：SFT → 在线 GRPO）

- **动机**：基础 VLM 几乎不采样 DRAG 等稀有揭示动作，若初始策略从不采样 DRAG，GRPO 就观察不到成功的 drag rollout 可供强化。
- **阶段一：SFT（行为克隆）**
  - 损失：$L_{\text{SFT}}(\theta) = -\,\mathbb{E}_{(x_t,a_t)\sim D}\,[\,w(a_t)\log \pi_\theta(a_t\mid x_t)\,]$
  - 标准 BC 取 $w=1$；**频率平衡变体**对稀有动作（MOVE、WAIT、DRAG）加权，把 CLICK/SCROLL/MOVE/WAIT/DRAG 的过采样比设为 1/1/2/2/4。
  - 训练数据仅来自人类验证的成功轨迹，**指令仍为 goal-only**，只改变训练分布。
- **阶段二：在线 GRPO（浏览器执行反馈）**
  - 奖励定义在**浏览器真实执行的轨迹**上而非文本：
    $R(\tau) = R_{\text{out}}(\tau) + R_{\text{proc}}(\tau) - \lambda_{\text{step}}|\tau| - R_{\text{err}}(\tau)$
  - $R_{\text{out}}$ 奖励点击时刻命中；$R_{\text{proc}}$ 对“可见性改变进展”给有界奖励（hover/move、隐藏状态展开、drag、wait 各有权重）；$R_{\text{err}}$ 惩罚错误点击、空点击、非法动作、重复无效动作；成功但含先前错点封顶 1.2，走捷径成功 0.8。
  - 关键设计：**SFT 负责扩展动作支撑集（support），GRPO 负责在这些动作中做选择与执行优化**。

## 3. 实验设计

### 3.1 基准与数据

- **IGG 基准**：601 个任务 / 16 个环境 / 7 个子类。分布：视口约束 27.8%（167）、多状态约束 40.9%（246，其中视觉消歧 89、隐藏状态 104、可移除遮挡 53）、时序与操作 31.3%（188，其中延迟 70、动态 58、可移动遮挡 60）。
- **训练/验证划分**：剔除 2 个无法可靠重放的轨迹后，599 个任务分为 **479 训练 / 120 验证**，验证集既不参与 SFT 也不参与 GRPO rollout。
- 人类研究：15 名被试，21 任务平衡套件（每子类 3 个），共 315 试次；另有 7 个环境的保真度评分。

### 3.2 对比方法

- 开源：**Qwen2.5-VL-7B-Instruct、Qwen3-VL-8B-Instruct、GUI-Owl-1.5-8B-Instruct**（训练部分另加 **InternVL3.5-8B**）。
- 商用：**GPT-5.5**（另有 GPT-5.4-mini 作为附加基线）。
- 人类表现作为上界参照。

### 3.3 指标

- **GA（Grounding Accuracy）**：预算内点中目标的任务比例（主指标）。
- **AC（Action Cost）**：成功或耗尽预算前的平均动作数。
- **RER（Reference Efficiency Ratio）**：成功任务上 $|g_i|/|a_i|$ 的均值，>1 表示比真值轨迹更短。
- **TT（Total Time）**：单任务墙钟时间（作者明确声明**未做硬件归一化**，仅作描述性报告）。

### 3.4 实验组构成（约 10 类）

1. **主实验**：4 个模型 × 3 大类 + 7 子类 + 总体（表 2）；
2. **按应用分解**：16 个环境 × 4 模型（表 3、表 A10）；
3. **受控干预（归因实验）**：告知交互类型 vs 代为执行揭示动作（表 4）；

6. **训练实验**：SFT、SFT+GRPO、跨 3 个架构（Qwen3-VL / InternVL3.5 / GUI-Owl-1.5）；

## 4. 资源与算力

- **论文未明确报告 GPU 型号、数量与训练总时长**，这是本文在可复现性披露上的一个明显缺口。
- 仅给出的训练超参：
  - **SFT**：LoRA rank 8、alpha 32、dropout 0.05、全线性语言模型目标模块、视觉塔与投影器冻结、bf16、学习率 $1\times10^{-4}$、有效 batch 8、最大长度 8192、最大图像像素 1,382,400、**500 步**、每 100 步存 checkpoint；数据 1,141 条动作级样本，频率平衡后扩至 1,460 条（drag 从 55 增至 220）。
  - **在线 GRPO**：group size 6、temperature 1.0、top-p 0.95、学习率 $2\times10^{-6}$、PPO 裁剪 $\epsilon=0.2$、最大梯度范数 1.0、**最多 20 个 update group**；rollout 来自 479 个训练任务的真实浏览器执行，预算同为 8 步。
- 推理侧成本有报告：GPT-5.5 跑完整 601 任务约 **$74.9**，平均 **66.5 s/任务**，而训练后的 Qwen3-VL 约 **14.2 s/任务**且无需付费 API。
