## 摘要
基于可验证奖励的在线强化学习（RL）推动了数学、编程和工具使用领域的快速进展，但要将这一成功扩展到 GUI 智能体仍面临挑战，原因是交互环境成本高昂且真实训练任务稀缺。我们提出 MAI-Gym，一个开源一体化平台，统一了跨移动、计算机和 Web 环境的 GUI 智能体评估、数据收集与在线 RL 训练。通过共享的 rollout 流水线，MAI-Gym 确保智能体在评估与训练中的行为一致，支持十个成熟基准，并可扩展到 20,000 个并行环境实例。除可扩展基础设施外，MAI-Gym 还能自动合成多样化的 GUI 应用与具有挑战性的任务，包括可重置的模拟应用，以及具有执行验证任务验证器的连贯跨应用世界。利用 MAI-Gym，我们训练了 MAI-Gym-9B，一个面向移动与计算机使用的统一 9B 智能体，在参数量低于 10B 的开源 GUI 智能体中取得最先进性能：MobileWorld 上为 78.4%，OSWorld-Verified 上为 76.2%。重要的是，在模拟火车票预订应用中的 RL 可迁移到其真实世界对应场景，将物理手机上的任务成功率从 28.8% 提升至 48.1%。我们发布该框架、合成技能、模拟应用、2,000 个已验证任务以及模型检查点，以支持可复现研究和可扩展 GUI 智能体训练的进一步进展。

## Abstract
Online reinforcement learning (RL) with verifiable rewards has driven rapid progress in mathematics, coding, and tool use, but scaling this success to GUI agents remains challenging due to the high cost of interactive environments and the scarcity of realistic training tasks. We introduce MAI-Gym, an open all-in-one platform that unifies GUI agent evaluation, data collection, and online RL training across mobile, computer, and web environments. Through a shared rollout pipeline, MAI-Gym ensures consistent agent behavior across evaluation and training, supports ten established benchmarks, and scales to 20,000 parallel environment instances. Beyond scalable infrastructure, MAI-Gym enables automated synthesis of diverse GUI applications and challenging tasks, including resettable mocked apps and coherent cross-app worlds with execution-validated task verifiers. Using MAI-Gym, we train MAI-Gym-9B, a unified 9B agent for mobile and computer use, achieving state-of-the-art performance among open GUI agents under 10B parameters: 78.4% on MobileWorld and 76.2% on OSWorld-Verified. Importantly, RL in a mocked train-ticketing app transfers to its real-world counterpart, improving task success on a phys- ical phone from 28.8% to 48.1%. We release the framework, synthesis skills, mocked apps, 2,000 verified tasks, and the model checkpoint to support repro- ducible research and further advances in scalable GUI agent training.

## 一、核心问题与研究动机

- **背景**：基于可验证奖励的在线强化学习（RL）已在数学、编程、工具使用等领域取得快速进展，其成功依赖“执行成本低、验证容易、任务丰富”的环境（如数学题自动判分、代码仓库自带测试）。
- **扩展到 GUI 智能体的两大瓶颈**：
  - **环境成本高且难以保持一致**：GUI 实例无法像代码沙箱那样被并发共享（智能体操作整个屏幕并改变设备状态），每次尝试都需要独立的手机/电脑/浏览器实例并重置到已知初始状态，大规模训练需数千实例；不同平台与基准各自维护智能体实现，导致评估与训练代码“漂移”，测得的分数可能取决于 harness 而非模型本身。
  - **真实训练任务稀缺**：真实 GUI 工作流常依赖跨应用、跨文件的一致信息（如回邮件需附件发票内容与环境一致），而现有任务合成多依赖孤立输入文件或共享样本数据，多样性与真实性不足；涉及交易的真实应用不安全/不可重复；研究“适应陌生界面”还需全新应用。
- **现有 GUI Gym 的不足**：基础设施型 Gym 仅覆盖单一平台、最多数百并行环境；数据型 Gym 提供新应用与任务，但不发布训练代码、也无法运行现有基准。二者割裂，缺少“可扩展执行 + 自动环境/任务合成”的统一平台。
- **论文定位**：提出 **MAI-Gym**，一个开源一体化平台，统一移动、电脑、Web 三类环境下的 GUI 智能体评估、数据收集与在线 RL 训练，并配套自动合成可重置模拟应用与带执行验证器的跨应用任务。

## 二、方法论

### 2.1 核心思想：共享 Rollout 路径

- 对给定智能体与环境，**评估、数据收集、训练复用同一条 rollout 路径与同一个 agent harness**（相同的观察处理、上下文构建、动作执行），修一处 harness 即同时惠及三者，从根本上消除“训练的是 A、评估的是 B”的漂移问题。
- 三类工作负载仅在轨迹使用方式上不同：评估做打分聚合、数据收集做存储（如 SFT 数据）、RL 训练用于策略更新并同步权重到推理引擎。

### 2.2 系统架构

- **Rollout 调度器 → Rollout Worker → Agent Harness → 推理引擎**，轨迹与验证器奖励写入 trajectory buffer。
- **环境管理器**暴露五个操作：申请实例、观察、重置到任务、执行动作、评估；统一负责实例供给与分配、会话生命周期（初始化/租约/重置/清理）、任务注册、奖励计算（代码验证器或 VLM judge）、轨迹持久化与状态上报。
- **环境适配器**将上述操作翻译为各平台原生 API，保留基准自身的任务初始化与验证逻辑，不涉及 RL。
- **部署后端**：Kubernetes、Docker 或接入既有真机/浏览器会话；配套 Dashboard 展示实例可用性、会话、吞吐与逐步轨迹回放。
- 四个扩展点：新增 Agent Harness、新增任务、集成新环境、定制环境（应用/服务/启动配置）。

### 2.3 可扩展且高效的 Rollout

- **可靠重置**：
  - 移动端用 ReDroid 将每个手机作为普通容器跑在宿主内核上（规避嵌套虚拟化），重置恢复 golden `/data` 快照。
  - 桌面端加严就绪检查、故障容器恢复、独立服务端口与 artifact 缓存、等待应用完成启动与保存。
  - Web 端用 headless Chromium 承载真实网站与本地模拟应用。
  - 重置中位数：Android 165 s、桌面 VM 37 s、浏览器 6 s。
- **大规模快速供给**：异步 provisioning、warm pools、截图经对象存储而非控制消息传输；实测 20,000 并行实例，1,000 个实例启动耗时移动 328.4 s、电脑 88.9 s。
- **故障隔离**：会话租约拒绝被替换 worker 的动作、动作 ID 保证重试幂等、每操作设 deadline、验证器在独立进程组运行；**环境故障与零奖励分开记录**，基础设施故障不进入训练信号。
- **高效多轮推理（window-wise history）**：将步数分组为长度 K、重叠 O 的窗口（K=10, O=2），窗口内只追加内容以复用 KV cache；窗口边界处旧截图折叠为占位符但保留文本。相比逐步骤保留最近 k 张截图的策略，前缀缓存命中率从 42.5% 提升到 85.9%，训练输入 token 降低 84.7%，训练更新耗时从 2166.4 s 降到 810.9 s。

### 2.4 评估与诊断

- **一条命令评估**：支持 10 个基准，保留各基准的步数上限、验证器与原生指标，额外报告 pass@n 与 pass^n；环境故障导致的中断自动重跑，不拉低分数。
- **Dashboard**：回答“集群是否健康 / 哪些任务解释了分数 / 某次尝试错在哪”，逐步对齐截图、模型输出、执行动作与验证结果，区分智能体失败与环境失败。
- **智能体驱动诊断**：向 coding agent（如 Claude Code、Codex）开放 diagnosis 端点，从单动作、整条轨迹、任务所需知识三个层级分析成功/失败轨迹，输出报告作为后续任务生成的输入。

### 2.5 环境与任务合成

- **环境合成（mocked apps）**：
  - **真实世界克隆**：7 个（12306、建设银行、滴滴、美团、大众点评、抖音、小红书），复现主流程、后端可重置，测试者用相同任务对照真机比对界面。
  - **全新应用**：42 个，基于 HTML5 模板的确定性状态机，在 Chromium 中运行，可无浏览器测试逻辑，并用参考解、重置测试、双端一致性校验。
- **跨应用世界构建**：由 persona（身份/角色/目标）与 scenario（时间线/事件/约束）生成共享人物、事件、事实的文件与应用记录（项目简报、预算表、邮件线程、日历等），任务要求跨应用检索、推理与整合，而非孤立导航指令；通过可复用初始化模板加载为可复现的初始状态 s0。
- **任务与验证器合成**：
  - **失败驱动生成**：从诊断报告出发，针对模型弱项生成“证据链 + 推理 + 动作”型任务，并做去重、消歧、可完成性审查。
  - **先定需求再写验证器**：任务规格含指令、所需资产、成功标准与内部答案上下文（策略不可见）；两次独立调用分别生成 golden code 与 verifier code，互不读取；再做 reward audit 对照规格。
  - **执行后才接受**：验证器须在“初始态 0 → golden 执行后 1 → 重置后 0”序列上通过；再用多个模型经 GUI 试做并审查轨迹（可执行性、难度、指令清晰度、reward hacking 风险）。最终发布 2,000 条任务（MobileWorld 与 OSWorld 各 1,000）。

### 2.6 在线 RL 训练

- 单条命令 `mai-gym train --config ...`；训练器基于 slime（Megatron-LM 训练 + SGLang 生成），支持 GRPO、DAPO、GSPO、REINFORCE++、SAO、PPO；主配方为 GRPO。
- **奖励与成功定义**：任务要求为二值判据 b_j 及权重 w_j，必选子集 C；奖励 r = Σw_j b_j / Σw_j ∈ [0,1]（部分分），成功 S = Π_{j∈C} b_j（须全部满足）。
- **GRPO 优势**：A_i = (r_i − mean(r_{1:G})) / (std(r_{1:G}) + δ)，组内奖励全同则优势为零、不贡献梯度。
- **策略自适应任务采样**：按历史成功率估计，未见过与“有时能解”的任务给满组 G=8 次；从未解出与已掌握（成功率 > η=0.8）的任务只给 4 与 2 次的小额预算，随策略变化复查；优势在该任务全部尝试结束后统一计算。
- **窗口化打包**：每个窗口作为一条因果训练序列，只对窗口内新增步计损失（K=10
