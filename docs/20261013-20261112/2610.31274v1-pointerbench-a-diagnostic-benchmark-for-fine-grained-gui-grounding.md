## 摘要
多模态大语言模型在计算机使用任务中展现出良好性能，从规划用户工作流到将自然语言动作定位到精确的 UI 目标。现有端到端基准主要强调长时程任务完成，而 GUI 定位基准仍聚焦于传统控件和有限的专业界面。我们提出 POINTERBENCH，一个包含 1,500 个截图-指令对的诊断套件，用于探测三种互补能力：电子表格中细小亚元素识别与几何定位（POINTERBENCH-Sheets）、长文本文档中的字符级定位（POINTERBENCH-Text），以及跨 100 个专业应用的混合 GUI 定位（POINTERBENCH-Pro）。我们精心构建每项任务，并提供像素级精确的目标几何标注，评估通用多模态模型和 39 种专用 GUI 定位配置。我们发现文本定位是最具挑战性的设置：Claude Fable 5、GPT-5.6 Sol 和领先的原生专用模型 UI-Venus-2-9B 在 POINTERBENCH-Text 上分别取得 69.6%、53.4% 和 25.8% 的成功率，而它们在 POINTERBENCH 上的平均成功率分别为 83.2%、77.7% 和 54.5%。这些结果表明，前沿模型和专用模型在细粒度 GUI 定位方面仍有显著提升空间。我们公开基准和评估代码：https://github.com/warmwindOS/pointerbench。

## Abstract
Multimodal Large Language Models have shown promising performance in computer-use tasks, from planning user workflows to grounding natural-language actions to precise UI targets. Existing end-to-end benchmarks primarily emphasize long-horizon task completion, while GUI grounding benchmarks remain focused on conventional controls and a limited set of professional interfaces. We introduce POINTERBENCH, a diagnostic suite of 1,500 screenshot-instruction pairs probing three complementary capabilities: thin sub-element identification and geometric grounding in spreadsheets (POINTERBENCH-Sheets), character-level grounding in long-text documents (POINTERBENCH-Text), and mixed GUI grounding across 100 professional applications (POINTERBENCH-Pro). We carefully curate each task with pixel-exact target geometry and evaluate both general-purpose multimodal models and 39 specialist GUI grounding configurations. We find text grounding to be the most challenging setting, with Claude Fable 5, GPT-5.6 Sol, and the leading native specialist UI-Venus-2-9B achieving 69.6%, 53.4%, and 25.8% success on POINTERBENCH-Text despite respective 83.2%, 77.7%, and 54.5% average success across POINTERBENCH. These results reveal substantial headroom in fine-grained GUI grounding across frontier and specialist models. We publicly release the benchmark and evaluation code at https://github.com/warmwindOS/pointerbench.

## 一、核心问题与研究动机

- **背景**：计算机使用智能体（computer-use agents）需要把自然语言指令定位到屏幕上的精确坐标或区域，即 GUI grounding。现代界面目标密集、视觉歧义大，专业软件还存在高分辨率小目标，定位本身仍是瓶颈。
- **现有评测的两类缺口**：
  - *交互式/端到端基准*（Mind2Web、WebArena、OSWorld、AndroidWorld）：衡量长时程任务完成，但端到端成功率把规划、定位、执行、环境控制失败混在一起，无法归因。
  - *静态 grounding 基准*（ScreenSpot、ScreenSpot-Pro）：隔离了定位能力，但集中于常规控件，缺少"电子表格列边界、两个字符之间的插入符、窄文本跨度"这类细粒度几何动作。
- **论文主张**：应构造一个**去除时间维度规划**、只考察"给定动作能否被精确定位"的诊断性基准，并按目标几何形态系统性地分离不同定位原语。
- **整体含义**：PointerBench 不是又一个"排行榜"，而是把 grounding 拆解为结构几何、字符级文本、专业界面三类可诊断能力的"显微镜"，用于暴露聚合分数掩盖的失败模式。

## 二、方法论

### 2.1 核心思想

- 构建 **1,500 个截图–指令对**，由三个互补的 500 例子集组成，每个样本包含：1024×768 截图、自然语言指令、像素级精确的目标几何（点或边界框）。
- 统一坐标系（固定 1024×768、绝对像素、原点左上），使不同模型、不同子集的误差可直接比较；官方分数要求模型**原样输出**，不做坐标后处理。
- 统一评分为三个子集的**非加权平均**，避免大子集主导。

### 2.2 三个子集的构建

- **PointerBench-Sheets（结构/几何定位）**：程序化生成，随机采样可见网格、行列表偏移、视觉样式与应用外框（chrome），防止语义位置与屏幕坐标形成固定映射。目标族包括：单元格/表头引用、相对引用与相对偏移、颜色指定区域、**细边界与 resize 手柄**、单元格四角。共 500 例（Cell 170、Edge 116、Relative 60、Header 59、Color 56、Corner 39）。
- **PointerBench-Text（字符级文本定位）**：由受控文档表面渲染，具有精确字形几何；包含 **366 个点任务 + 134 个框任务**。目标类型：词（112）、单字符（27）、标点（23）、**插入符位置（187）**、区域（词/行/字符/段落/发票字段，134）、界面控件文本（17）。语言固定为 50% 英语 + 德/法/西/意/荷各 10%；只保留目标唯一可判定的样本。
- **PointerBench-Pro（专业界面混合定位）**：从生成的专业应用界面中组装，**100 个应用各 5 例**，共 190 个图标目标、154 个文本目标、156 个其他控件（下拉、列表项、滑块、标签页、面板等）；图标指令显式要求"图标本身"以避免与相邻文字标签混淆。保留应用名、类别、平台与来源 ID 以便溯源。
- **可复现性**：Sheets/Text 生成过程确定性（deterministic），一个样本对应一份唯一截图与元数据；发布元数据 + 评分脚本。

### 2.3 评测协议与评分（文字化公式）

- **点预测**：预测坐标落在标注目标区域内即成功。
- **框预测**：设预测框 $B_p$、真值框 $B_g$，计算
  - 覆盖率 coverage = $|B_p \cap B_g| / |B_g|$
  - 精度 precision = $|B_p \cap B_g| / |B_p|$
  - 判定正确需 **coverage ≥ 0.90 且 precision ≥ 0.70**。
  - 该准则**非对称**：强烈惩罚裁切目标（覆盖不足），但允许目标外围有适度余量（精度要求较松）。
- 格式错误、无法解析的输出一律计为失败；每个子集报告二值成功率。

### 2.4 提示与推理设置

- **通用模型**：统一系统提示，要求使用绝对像素坐标、禁止归一化、禁止裁剪/缩放坐标系，点任务返回 `{"point":[x,y]}`，框任务返回 `{"bbox":[x0,y0,x1,y1]}`；通过 OpenRouter 调用，JSON schema 强制输出格式。
- **推理预算**：关闭推理时响应上限 512 token；low 为 2,048 token；medium 为 2,048 token + 1,024 推理预算。预算耗尽的响应不重试（计为失败）。
- **专用模型**：39 种配置（35 个 2B–32B checkpoint）各自使用**官方原生 grounding 提示、坐标归一化方式与解析器**（如 UI-Venus 的 [0,1000]、MAI-UI 的 [0,999]、UI-TARS 的 Doubao 格式、GTA1/OpenCUA 的 `pyautogui.click`），或推理时集成包装（MVP 多视图预测、GUI-RC 区域一致性）。

## 五、实验数量与充分性

**规模**
- 主实验：约 **76 个模型/配置 × 1,500 例 ≈ 11 万次单例评测**（37 通用 + 39 专用）。
- 消融/分析：6 模型 × 最多 3 档推理预算；3 组配对显著性检验；7 类分组细分分析；1 组坐标换算诊断。

**充分与客观之处**
- 同时覆盖**闭源前沿模型**与**开放权重专用模型**，并刻意让专用模型使用各自原生提示与解析器，避免"因格式不兼容而低估专用模型"，这是相对公平的设计。
- 使用配对 McNemar 检验而非只报均值差，对 Sonnet 的"轻微下降"也做了显著性判定，统计上较严谨。
- 失败模式被拆到"裁切 vs 过大 vs 区域错误"，并单独隔离**坐标框架不合规**这一混杂因素（Gemini 3.1%→78.1%、Qwen3.8 Max 2.8%→55.4%），避免把表示问题误读为定位能力问题。

**不足**
- 每个子集仅 500 例，细分后**部分类别样本极少**（如 caret 中 "Blank line" n=1、"Top-right corner" n=5、"Line start" n=10），这些格子的百分比波动很大，不宜做细粒度排名。
- 无真正意义上的"方法消融"（因为不训练模型），只有推理预算与输出表示两类可控变量。
- 专用模型用原生提示、通用模型用统一提示，**跨类别的绝对分数并非严格同条件对比**；作者也承认官方榜与诊断榜口径不同。
- 单一固定分辨率，未做分辨率/缩放策略的鲁棒性扫描。
- 闭源模型存在**预训练数据污染不可验证**的问题，作者在附录 H 中明确承认。

## 六、主要结论与发现

- **文本定位是全局瓶颈**：Claude Fable 5 在 Text 上 69.6%、GPT-5.6 Sol 53.4%、最强原生专用 UI-Venus-2-9B 仅 25.8%，而它们的总平均分别为 83.2%、77.7%、54.5%；**没有任何专用模型在 Text 上超过 34.0%**（MVP-32B 34.0%）。
- **粒度衰减规律清晰**：词级最强（Fable 90.2%、GTA1-32B 70.5%），字符级骤降（Opus 51.9%、Sol 48.1%、专用模型 11.1–18.5%），标点 39.1–56.5%，插入符 22.5–34.2%；**区域（bounding box）对前沿模型仍困难**（Fable 56.0%、Opus 50.7%），仅输出点的专用模型在 134 个区域任务上直接得 0。
