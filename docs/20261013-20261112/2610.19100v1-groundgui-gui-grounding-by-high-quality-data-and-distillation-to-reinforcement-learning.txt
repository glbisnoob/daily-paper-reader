## ABSTRACT 

Constructing robust GUI agents relies on multimodal visual grounding—the abil-ity to precisely map natural language intents to actionable on-screen components. Despite abundant desktop, web, and mobile benchmarks, high-fidelity resources tailored for diverse environments are surprisingly scarce. To bridge this gap, we introduce the Screen Referring Grounding Dataset (ScreenRef), a compre-hensive GUI grounding dataset consisting of GUI screenshots paired with natu-ral language referring expressions and box or point annotations. Spanning desk-top, web, and mobile domains, ScreenRef comprises 586K screenshots and over 633K referring expression instances, covering tasks such as text recognition, vi-sual matching, spatial understanding, and refusal scenarios. To boost the model’s grounding performance, we propose the Distillation-to-Reinforcement Learning (D2RL) method to address the limited generalization of supervised fine-tuning and the sparse reward problem in reinforcement learning. Utilizing ScreenRef, we train Qwen3-VL-8B-Instruct via sequential SFT and D2RL training, yielding GroundGUI-8B. GroundGUI-8B achieves 95.2% on ScreenSpot-V2, 63.9% on ScreenSpot-Pro, 65.4% on OSWorld-G, 86.8% on MMBench-GUI L2, and 38.3% on UI-Vision. Among 8B-scale models, it produces substantial gains over models trained on open-source datasets, with performance comparable or even superior to models trained on closed-source data. Code, models, and datasets are available at https://github.com/PrentisAI/GroundGUI. 

## 1 INTRODUCTION 

Graphical User Interfaces (GUIs) (Cheng et al., 2024) are ubiquitous in modern human-computer and mobile interactions. Visual GUI grounding (mapping language instructions to pixel coordinates of interactive elements) is a foundational capability. Robust cross-platform grounding is challenging due to interface complexity and contextual diversity. Modern applications often have high-resolution canvases with dense layouts and subtle visual disambiguations, complicating spatial localization. GUI agents degrade on domain-specific software due to limited grasp of specialized icon seman-tics. Data underpins model capability, but constructing high-quality grounding datasets with broad coverage is challenging (Xu et al., 2024; Xie et al., 2025). Mobile-Agent-v3.5 (Xu et al., 2026), UI-Venus-1.5 (Gao et al., 2026), UI-TARS-2 (Wang et al., 2025a), and MAI-UI (Zhou et al., 2025) perform well with proprietary large-scale data, unavailable to the community. GroundCUA (Feizi et al., 2026) and ScaleCUA (Liu et al., 2026b) release their data, but models trained on them are suboptimal due to limited diversity/accuracy. We introduce ScreenRef, a large-scale GUI grounding dataset (586K screenshots and 633K referring expressions), with text recognition, visual matching, spatial understanding, and refusal tasks. It covers desktop, web, and mobile platforms, with image resolutions ranging from 0.1 to 8.3M pixels. Multi-stage filtering/verification yield verified data for robust cross-platform grounding.

Reinforcement learning (RL) works (Tang et al., 2026; Li et al., 2026; Liu et al., 2026a; Lu et al., 2026) use Group Relative Policy Optimization (GRPO) (Shao et al., 2024) to improve generalization, but suffer from sparse signals on hard samples where all rollouts receive zero reward. Inspired by on-policy self-distillation (OPSD) (Zhao et al., 2026a) which provides dense token-level supervision, we propose Distillation-to-Reinforcement Learn-ing (D2RL) , a two-stage post-training framework: OPSD followed by REINFORCE Leave-One-Out (RLOO) (Ahmadian et al., 2024). OPSD tailored for GUI grounding delivers rich token-level supervision for precise coordinate generation from a teacher that sees the ground-truth bounding box, providing a stronger starting policy before RL. RLOO then enhances model generalization and localization accuracy. Through the proposed ScreenRef and D2RL method, we obtain GroundGUI for precise GUI grounding across desktop, web, and mobile. GroundGUI-8B achieves 95.2% on ScreenSpot-V2 (Wu et al., 2025b), 63.9% on ScreenSpot-Pro (Li et al., 2025), 65.4% on OSWorld-G (Xie et al., 2025), 86.8% on MMBench-GUI L2 (Wang et al., 2025d), and 38.3% on UI-Vision, remarkably outperforming the models trained on open-source datasets. GroundGUI-8B also sur-passes Holo2-8B (H Company, 2025) and Step-GUI-8B (Yan et al., 2025) by a large margin, both of which are trained on closed-source data. 

Core contributions. (1) ScreenRef , a high-quality GUI grounding dataset with 586K screenshots and 633K referring expressions, providing text recognition, visual matching, spatial understanding, and refusal supervision for robust GUI agents. (2) D2RL , which proposes OPSD before RL to shape a better initial policy, unleashing the potential of RL for GUI grounding, enhancing model generalization and grounding accuracy. (3) GroundGUI-8B , trained on our proposed data and approach. GroundGUI-8B achieves state-of-the-art or competitive performance among models with 8B parameters or fewer, surpassing several 32B-scale models, e.g., ScaleCUA-32B, OpenCUA-32B and GTA1-32B. We release the data, code, and model to the community to facilitate future research. 

## 2 RELATED WORKS 

GUI Agent. Computer-use agents interact with interfaces, from simple commands to multi-step tasks. CogAgent (Hong et al., 2024), ShowUI (Lin et al., 2025), Ferret-UI (You et al., 2024), OS-Genesis (Sun et al., 2025), GUI-Actor (Wu et al., 2025a), and UI-TARS (Qin et al., 2025) improve interaction via SFT. OS-ATLAS (Wu et al., 2025b) and UGround (Gou et al., 2025) scale data to map language to UI components. These methods are data inefficient, particularly in complex desk-top and web environments. RL approaches, inspired by GRPO (Shao et al., 2024) (GUI-R1 (Luo et al., 2025), GUI-G 2 (Tang et al., 2026), GUI-C 2 (Li et al., 2026), InfiGUI-G1 (Liu et al., 2026a)), improve grounding. Still, reliably grounding instructions to hard on-screen elements remains a bot-tleneck due to sparse signals on difficult samples where all rollouts generate erroneous responses. Motivated by OPSD, an approach that provides online token-level supervision via a single roll-out, we introduce D2RL, a two-stage training framework. In the preparatory phase, the framework performs OPSD tailored for GUI grounding to bootstrap subsequent reinforcement-learning opti-mization. 

GUI Grounding Datasets. GUI grounding datasets span mobile, web, and desktop environments. Mobile datasets (e.g., RICO (Deka et al., 2017), UIBert (Bai et al., 2021), AITW (Rawles et al., 2023), AITZ (Zhang et al., 2024), AMEX (Chai et al., 2025)) provide element-level supervision in standardized layouts, which simplifies extraction but offers limited layout density and visual variation vs. desktop software. Web-focused datasets (e.g., SeeClick (Cheng et al., 2024), We-bUI (Wu et al., 2023), UGround, and AGUVIS-G (Xu et al., 2024)) scale collection by harvesting HTML/DOM structures. These favor text-bearing elements over icon-only controls. High-quality desktop datasets remain scarce and hard to curate. OS-ATLAS (Wu et al., 2025b) extracts desktop elements from accessibility trees; inconsistent accessibility APIs introduce label noise. JEDI (Xie et al., 2025) scales dataset size via synthetic interface generation, but its simplified screens fail to capture desktop complexity. Recent efforts such as GroundCUA (Feizi et al., 2026), ScaleCUA (Liu et al., 2026b), and Wild2GUI (Xiong et al., 2026) offer dense annotations, cross-platform coverage, or video-synthesized data, but annotation inaccuracies or sparse diversity constrain performance. ## 3 SCREEN REF DATASET 

3.1 SCREENSHOT CRAWLING 

We use platform-specific approaches for GUI metadata extraction (Figure 1, Path 1). For desktop, Accessibility Trees (A11y Trees) provide interface layouts and UI element coordinates. Document Object Model (DOM) structures offer element information for web browsers. Parsed XML layout files provide UI element locations for Android applications. Metadata contains bounding boxes, cat-egories, and text. However, some metadata contains noisy bounding box attributes. For these cases, we adopt OmniParser V2 (Yu et al., 2026) to reduce noise by comparing the metadata bounding boxes with the detection results of OmniParser. The bounding boxes with an IoU lower than 0.5 are removed. Figure 6 in Appendix D shows the annotation for the screenshot. Qwen3-VL-235B-A22B-Instruct (Bai et al., 2025) is then employed to produce grounding instructions with annotated 3bounding boxes, categories, and surrounding context. To further verify the correctness of the gen-erated grounding pairs, we adopt Qwen3.8-27B (Qwen Team, 2026c) to judge whether the answer matches the instruction given the raw image and the bounding box crop. Through this pipeline, we generate three primary types of instructions, including text recognition, visual matching, and spatial understanding. Text recognition denotes grounding a target element uniquely designated by readable on-screen text. Visual matching refers to identifying the target element by its visual attributes (icon noun, shape, or color). Spatial understanding represents identifying a target element purely through its spatial relationship, whether relative to an anchor element or bounded within a named container. Qualitative examples are provided in Appendix A. 3.2 TUTORIAL VIDEO CRAWLING 

To collect real-world interfaces, we complement screenshots with interaction frames from public tutorial videos. To this end, search queries are automatically generated to crawl video metadata on YouTube. Qwen3.6-27B (Qwen Team, 2026a) is then used to filter out non-tutorial video metadata, followed by video downloading based on the preserved metadata. For subtitle-free videos, FFmpeg is exploited to extract audio for transcript generation. To produce grounding samples, we design a pipeline converting tutorial videos into trainable (instruction , observation , action , coordinate ) tu-ples via 3 sequential stages: (i) Keyframe Candidate Extraction. It computes block-level frame differences to pinpoint timestamps of local screen updates. To prevent global screen transitions (shot cuts, page scrolling, video playback) from dominating, we down-weight full-frame edits, letting fine-grained interactions compete. Candidates are re-ranked using action verbs extracted from the transcript alongside cursor coordinates detected via YOLOv8 (Reis et al., 2023) as cheap priors, yielding at most 60 filtered candidates/video. Instead of capturing the immediate moment of change (often with motion blur or mid-animation states), we perform a forward-and-backward search around each timestamp to identify the nearest static frames, constructing a clean pre-/post-change frame pair. (ii) Joint Instruction and Action Annotation. Each candidate frame pair, with absolute timestamps, is concatenated with its transcript segment and video metadata into a single GPT-5.5 API prompt. This pass performs both task segmentation and action annotation, outputting a sequence of temporal actions. Each action includes its interaction type, parameter values, and an element-level referring expression grounded strictly in visible screen evidence (referencing UI controls solely by their visible text labels, icon shapes, or explicit functional descriptions). (iii) 

Post-Hoc Visual Grounding. Taking the pre-action frame as the visual observation, the target coor-dinate is resolved via action-type-conditioned routing. A single call to Qwen3.7-Plus (Qwen Team, 2026b) predicts target presence, a bounding box/coordinate, and a confidence score. If confidence falls below a threshold τ = 0 .95 , the proposal is escalated to Claude Opus 5 for re-grounding. Sam-ples with secondary confidence below τ are discarded. To fill the critical gap of handling infeasible grounding queries in existing datasets, we construct refusal samples via strategically random-pairing instructions and frames. We then employ the Qwen3.8-27B model to identify and verify genuinely infeasible grounding instances. 3.3 DATASET STATISTICS 

Through dual-mode pipelines, we obtain ScreenRef, comprising 585,981 screenshots and 633,369 instructions (Instr), with 284,531 grounding samples from pathway 1 and the remaining from path-way 2. As listed in Table 1, ScreenRef features multiple platforms and a wider resolution range (Res Range) than the existing datasets. Stage I: On-Policy Self-Distillation. SFT learns from labeled responses, while RL samples from the model’s own policy. OPSD bridges the two by matching the teacher’s token distribution on student-generated prefixes via reverse KL divergence, providing guidance on the responses the model currently explores. Specifically, given a screenshot I and an instruction q, the student policy 

πθ samples a coordinate response s from the original screenshot. Inspired by GUI-SD (Zhang et al., 2026), the teacher is a frozen copy of the SFT policy; during OPSD only, it receives the screen-shot with the ground-truth target box highlighted together with a textual localization hint (the target name and its box), whereas the student receives only the original screenshot and the instruction. The teacher is not used at inference. Both models score the same student-sampled prefix, so the teacher provides dense token-level guidance along the student’s rollout. Since errors in higher-order coordinate digits induce much larger spatial deviations than errors in lower-order digits, we apply position-aware weighting during distillation: we set wpos (t) = β · kt for coordinate-digit tokens and 

wpos (t) = 1 otherwise; kt denotes the significance of the digit (e.g., 1 for units, 2 for tens, and 3 for hundreds), and β controls the weighting strength. The OPSD objective is then

## 5 EXPERIMENTAL RESULTS 

5.1 IMPLEMENTATION DETAILS 

SFT is performed on 4 B300 GPUs, using a global batch size of 32 and a learning rate of 1 × 10 −6.The model is trained for 2 epochs using the AdamW (Loshchilov & Hutter, 2019) optimizer. In the second epoch, the loss weights for text recognition and refusal samples are reduced to 0.2. Starting from the SFT model, we post-train with D2RL on 12K grounding samples derived from GroundCUA, excluding screenshots identical to those in the UI-Vision benchmark. Training runs for 2 epochs (one for OPSD and one for RLOO) on 8 B300 GPUs. Both stages use AdamW with a learning rate of 1 × 10 −6, a cosine schedule, and a batch size of 42, without a KL penalty. OPSD matches a frozen teacher’s token distributions on the policy’s own rollouts, followed by RLOO with 8 rollouts per prompt and a binary point-in-box reward. 5.2 EVALUATION BENCHMARKS 

We evaluate GroundGUI on 5 representative GUI grounding benchmarks: ScreenSpot-V2 (SS-V2) (Wu et al., 2025b), MMBench-GUI L2 (MMB-GUI L2) (Wang et al., 2025d), ScreenSpot-Pro (SS-Pro) (Li et al., 2025), OSWorld-G (OSW-G) (Xie et al., 2025), and UI-Vision (Nayak et al., 2025). ScreenSpot-V2 evaluates general-purpose GUI grounding across web, desktop, and mo-bile, covering text, icons, and interactive elements. ## 6 CONCLUSION 

We introduce ScreenRef, a large-scale, high-quality GUI grounding dataset of 586K screenshots and 633K referring expressions across desktop, web, and mobile environments. Using ScreenRef, we construct a suite of real-world instruction tasks for multimodal grounding. We also present GroundGUI-8B, trained via SFT followed by D2RL, which sequentially applies OPSD and RLOO. Across 5 benchmarks, GroundGUI substantially outperforms models trained on existing open-source datasets, while achieving performance competitive with or superior to leading models trained on closed-source data. AI USE STATEMENT 

In this work, we used generative AI models to generate synthetic datasets and to clean and reformat dataset content, as described in Section 3: Qwen3-VL-235B-A22B-Instruct generated grounding in-structions from denoised metadata; Qwen3.8-27B verified instruction–target consistency; Qwen3.6-27B filtered non-tutorial video metadata; GPT-5.5 produced task segmentation, action annotations, and referring expressions from video frame pairs and transcripts; and Qwen3.7-Plus and Claude 9Opus 5 produced target coordinates with confidence gating. OmniParser V2 and YOLOv8 were used as non-generative detectors. We did not use generative AI tools to develop theoretical models or conceptual frameworks, formulate mathematical claims, write proofs, propose or refine hypothe-ses, design or evaluate the research methodology, translate, perform qualitative analysis, or interpret results. Additionally, we used generative AI tools to aid and polish the writing of this manuscript. All AI-generated data passed the automated verification stages described in Section 3, and all AI-assisted text was reviewed by the authors. We take responsibility for the final content of this work, including text, claims, and artifacts produced with the aid of generative AI. ETHICS STATEMENT 

ScreenRef is built from screenshots of live GUI environments and from frames of publicly available tutorial videos; no human subjects were recruited. The dataset used for D2RL post-training consists of samples from GroundCUA, excluding screenshots identical to those in the UI-Vision benchmark, and follows GroundCUA’s MIT license. Screenshots of real interfaces may incidentally contain per-sonal or account information, and we have not yet performed a systematic human privacy audit; the dataset documentation asks users to report any such content, and removal requests are actioned with a corrected revision. The code and model checkpoints are released under the Apache 2.0 license, and ScreenRef is released under a gated, non-commercial research-only license that prohibits redistribu-tion, subject to source-platform terms. Improved GUI grounding can enable automated interaction with software, including unapproved automation on sensitive services; the released artifacts are in-tended for research on grounding, and their documentation states this intended use. ## C ADDITIONAL SCREEN REF STATISTICS 

We provide additional statistics on the distribution of grounding capabilities in ScreenRef. ## D ELEMENT METADATA FROM LIVE SCREENSHOT CRAWLING 

Part of ScreenRef is built from live screenshot crawling, where we capture screenshots from real web pages, desktop applications, and Android applications. Alongside each screenshot, we record element metadata from the platform’s native interface: the DOM on web pages, the accessibility tree on desktop, and the XML layout on Android. Each element record contains a bounding box in the pixel coordinates of the screenshot, a text string, and a functional category such as Button, Input Elements, or Visual Elements. The text is the element’s visible text or, if the element displays none, its accessibility name; the category may be absent for some Android elements. Every record contains non-empty text, so the metadata covers the elements that the interface exposes with a text or an accessibility name, rather than every visual object on the screen. Before the metadata is used to generate grounding instructions, it is filtered to remove or refine unreliable screenshots and boxes.
