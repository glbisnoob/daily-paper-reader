## 摘要
高分辨率屏幕上的 GUI 定位大多在小目标上失败，而放大是一种常见的免训练补救手段。然而，现有大多数缩放流程并未根据目标尺寸调整缩放比例，会无条件接受缩放后的答案，且从不重新审视错误答案。为解决这些问题，我们提出 AdaGround，一个免训练框架，包含三个组件：（1）令牌归一化自适应缩放（Token-Normalized Adaptive Zooming），根据模型自身对目标尺寸的估计来设定每个样本的放大倍数、视野和缩放深度；（2）验证器在环精炼（Verifier-in-the-Loop Refinement），使用一个带标记点击的“是/否”验证器来决定保留或拒绝每次缩放、在不同缩放链之间进行选择、触发重新定位，并通过存在性查询决定何时弃权；（3）组合结构定位（Compositional Structure Grounding），根据表头组合出电子表格单元格。在 Qwen3-VL 模型上，AdaGround 超越了最先进的免训练缩放方法和许多经过训练的 GUI 模型，在 OSWorld-G 和 ScreenSpot-Pro 上相较主干模型将准确率提升 7.4 至 20.6 个百分点，且其增益可迁移到留出的 UI-Vision 上。代码见 https://github.com/bcwang-sjtu/AdaGround

## Abstract
GUI grounding on high-resolution screens fails mostly on small targets, and zooming in is a common training-free remedy. However, most existing zooming pipelines do not match the zoom to the target's size, accept the zoomed answer unconditionally and never revisit a wrong answer. To address these issues, we propose AdaGround, a training-free framework with three components: (1) Token-Normalized Adaptive Zooming, which sets the magnification, field of view and zoom depth of each sample from the model's own estimate of the target size; (2) Verifier-in-the-Loop Refinement, which uses one marked-click Yes/No verifier to keep or reject each zoom, choose between zoom chains, trigger re-grounding and, with an existence query, decide when to abstain; and (3) Compositional Structure Grounding, which composes spreadsheet cells from their headers. On Qwen3-VL models, AdaGround surpasses state-of-the-art training-free zooming methods and many trained GUI models, improving accuracy over the backbone by 7.4 to 20.6 points on OSWorld-G and ScreenSpot-Pro, and its gains carry over to held-out UI-Vision. Code is available at https://github.com/bcwang-sjtu/AdaGround

# AdaGround 论文中文总结

## 一、核心问题与整体含义

- **研究背景**：GUI 定位（GUI grounding）是 GUI 智能体的感知核心，要求根据指令与截图精确定位可点击元素。当前主流做法让视觉语言模型（VLM）直接生成坐标，但在高分辨率专业软件中，目标往往只有二十余像素，单次定位非常脆弱。
- **常见补救**：测试时放大（test-time zooming）无需训练，先粗定位，再裁剪局部并高分辨率重定位。但现有流程存在五类共性缺陷：
  1. **缩放几何与目标尺寸无关**：固定比例、固定窗口或候选分布决定裁剪，未考虑目标在渲染视图中占多少视觉 token。
  2. **开环接受**：缩放后的答案无条件替换粗答案，即使裁剪已丢失识别目标所需的上下文。
  3. **没有二次尝试**：无法判断哪些错误答案值得复查。
  4. **白盒或投票式聚合**：依赖注意力图或空间投票，无法判断两个冲突视图谁更可信。
  5. **总是缩放并回答**：对屏幕上不存在的目标无法弃答；对电子表格单元格这类由结构定义的目标，紧裁剪反而丢失表头证据。
- **核心观察**：不同缩放几何会在不同样本上失败。以 Qwen3-VL-8B 在 ScreenSpot-Pro 为例，固定裁剪与自适应裁剪分别正确 63.5% 和 59.6%，但至少一个正确达 68.9%。因此关键不是固定采用某一种缩放，而是**逐样本判断应信任哪个缩放答案**。
- **整体含义**：论文提出 AdaGround，一个**免训练、黑盒**框架，让现成 VLM 自己估计目标尺寸、自己验证候选点击，并在缩放链之间做选择、重定位与弃答。其目标是在不更新模型权重的前提下，显著提升高分辨率小目标定位的可靠性。

## 二、方法论

### 2.1 核心思想

- 将 GUI 定位视为对现成 VLM 的“查询编排”问题，而非训练更好的定位器。
- 仅访问模型输出的文本与首 token 概率，不读取注意力图、隐藏状态或梯度。
- 三个组件共享一套常量，同时服务 Qwen3-VL-8B 与 32B 及全部 benchmark。

### 2.2 Token 归一化自适应缩放（TNZ）

- **Token 跨度定义**：目标短边为 \(s\) 原始像素，视图线性缩放为 \(k\)，编码器 token pitch 为 \(\pi\)（Qwen3-VL 为 32 像素），则目标在视图中的 token 跨度  
  \[
  \sigma = \frac{s k}{\pi}
  \]
  该量在渲染后测量，因此可跨分辨率、裁剪与上采样比较。
- **尺度感知粗定位**：先将截图渲染到约 \(A_0=2.2\) MP 的粗视图，模型返回粗点和目标边界框；框短边映射回原图像素得到自报尺寸 \(\hat{s}\)。若无框返回，则不缩放。
- **足迹匹配放大与误差感知视野**：
  \[
  k = \mathrm{clip}(\tau\pi/\hat{s},\,1,\,k_{\max})
  \]
  \[
  d = \mathrm{clip}(\max(\gamma\hat{s},\,\varepsilon\pi/k_{\mathrm{prev}}),\,d_{\min},\,d_{\max})
  \]
  其中 \(\tau=3\) 为目标 token 跨度，\(\gamma=16\) 保持上下文比例，\(\varepsilon=4\) 为粗定位误差预留 token，\(k_{\max}=4\)。
- **性质 1**：若尺寸估计精确且目标尺寸在 24–96 像素范围内，缩放视图会把目标稳定渲染为 \(\tau=3\) 个 token，与屏幕分辨率无关；若当前点偏差不超过上一视图的 \(\varepsilon/2\) 个 token，目标中心仍在裁剪内。
- **自适应深度**：第 \(t\) 阶段在 \(\hat{\sigma}<\lambda_t\tau\) 时触发，首阶段 \(\lambda_1=\lambda=2\) 较宽松，后续 \(\lambda_t=1\)；最多 \(D=2\) 阶段。每阶段后重新查询框以更新尺寸估计。
- **门控接受**：缩放答案 \(p'\) 仅在验证器不偏好原答案时替换，即 \(v(p')\ge v(p)\)。

### 2.3 验证器在环精炼（VLR）

- **验证器定义**：在候选点 \(p\) 周围取边长 \(d_0(W,H)\) 的窗口，以 4 倍面积渲染并画红圈，询问“红圈是否位于指令所指 UI 元素上？是/否”。  
  \[
  v(p)=\frac{P(\text{YES}\mid x_p)}{P(\text{YES}\mid x_p)+P(\text{NO}\mid x_p)}
  \]
  首 token 概率按大小写变体求和。
- **四个决策**：
  1. **验证门控接受**：TNZ 每阶段答案仅在 \(v(p')\ge v(p)\) 时保留。
  2. **验证器仲裁的链组合**：固定运行两条链——TNZ 链与固定 4× 裁剪链。两答案按完全链接聚类（半径 14 像素），每组由最高优先级链代表；若多于一组，对最多 \(K=3\) 组代表分别验证，取最高 \(v\) 者。这替代了 MVP 的空间投票。
  3. **负反馈重定位**：当仲裁后答案未达 \(\theta_r=0.99\)，在整屏视图上把被拒位置画红叉，并在指令后附注“此前点击被判非目标”，再执行“整屏→原生分辨率裁剪→更紧裁剪”的三步重定位；仅当新答案验证分数更高时替换。
  4. **存在性门控弃答**：另问一次整屏“屏幕上是否存在可执行该指令的元素”，得到 \(e(S,I)\)。仅当  
     \[
     \frac{1}{2}\big(v(p)+e(S,I)\big)<\theta_e=0.03
     \]
     时弃答。验证器已确认的答案不会被撤回；弃答仅在允许拒答的 OSWorld-G 启用。

### 2.4 组合结构定位（CSG）

- 针对电子表格单元格：单元格由列头与行头定义，而紧裁剪会丢失表头。
- 先用纯文本查询把指令重写为程序：`GROUND` 或 `CELL(col,row)`；其他类型回退为 `GROUND`。
- 对列头和行头分别定位：先整屏，再在 \(d_0/2\) 裁剪上以 3 倍线性放大重定位，得到 \((x_{\text{col}},y_{\text{col}})\) 与 \((x_{\text{row}},y_{\text{row}})\)。
- 仅当列头位于行头右上方，即 \(x_{\text{col}}>x_{\text{row}}\) 且 \(y_{\text{col}}<y_{\text{row}}\) 时，组合点击 \((x_{\text{col}},y_{\text{row}})\)；否则回退到 VLR 答案。

### 2.5 整体流程

1. CSG 文本路由读取指令。
2. 两条缩放链分别产生候选点。
3. VLR 聚类并验证仲裁。
4. 未确认则负反馈重定位。
5. 若为单元格程序则组合表头。
6. 满足弃答条件则弃答，否则输出点击点。

## 三、实验设计

### 3.1 数据集与 Benchmark

- **OSWorld-G**：564 条指令，含 54 条目标不在屏幕上的指令；官方评分器，仅弃答才算正确解决缺失目标。
- **ScreenSpot-Pro**：1,581 条专业桌面软件指令，高分辨率屏幕，目标短边中位数约 24 像素。
- **ScreenSpot-v2**：1,272 条指令，目标较大，中位数约 85 像素，用于观察大目标场景。
- **UI-Vision**：留出测试，元素定位任务 5,479 条指令、1,181 张截图、83 个桌面应用，目标中位数约 26 像素。
- **评价协议**：预测点落入目标区域即正确；ScreenSpot-Pro/-v2/UI-Vision 为 point-in-box；OSWorld-G 使用官方评分并计入弃答。配对差异用 4,000 次截图级 bootstrap 重采样给出 95% 置信区间。

### 3.2 对比方法

- **同骨干单次 pass**：Qwen3-VL-8B-Instruct 与 Qwen3-VL-32B-Instruct（FP8）。
- **免训练测试时方法**：MVP（主要对比，注意力引导多视图+空间投票）、ZoomClick（32B ScreenSpot-Pro 已发表结果）。
- **固定 4× 裁剪链**：作为 AdaGround 的 \(c_{4\times}\) 链及消融基线。
- **训练型 GUI 专家与专有模型**：UI-TARS-72B、UI-Venus-Ground-72B、GTA1-72B、OS-Atlas-7B、UGround-V1-7B、GUI-G1-3B、InfiGUI-G1-7B、SE-GUI-7B、GUI-Spotlight 等，以及 GPT-4o、Claude Computer Use、Gemini-2.5-pro、Seed1.5-VL 等。
- **复现对比**：Qwen3-VL-8B 上用 MVP 官方代码与配置复现；32B 使用作者发布的 ScreenSpot-Pro 逐样本预测做配对检验。

### 3.3 主要结果概览

- **OSWorld-G**：8B 从 64.7% 提升到 76.1%（+11.3）；32B 从 71.8% 提升到 79.3%（+7.4）。相对 MVP 已发表结果分别高 3.4 与 7.3 点。
- **ScreenSpot-Pro**：8B 从 51.3% 提升到 66.2%（+14.9）；32B 从 55.3% 提升到 75.9%（+20.6）。相对 MVP 已发表结果高 0.9 与 1.9 点；32B 高于 ZoomClick 的 72.1%。
- **UI-Vision（留出）**：8B 从 23.7% 提升到 32.0%（+8.3），与 MVP 的 31.9% 基本持平；32B 从 36.7% 提升到 47.6%（+10.9），高于 MVP 的 44.1% 与 ZoomClick 的 39.2%。
- **ScreenSpot-v2**：8B 91.9% 对单次 92.1%，32B 95.4% 对 94.7%，无显著提升，说明大目标场景收益有限。
