## 摘要
GUI 定位使 Web 智能体能够将自然语言指令转换为可操作的界面位置。然而，密集的布局以及尺寸小且视觉相似的控件可能使模型倾向于看似合理但错误的元素，而围绕单一预测进行细化可能会使其他候选目标未被探索。我们提出多假设验证框架（MHVF），用于免训练的 GUI 定位。它使用单个预训练的视觉-语言模型，将多假设探索与局部视觉验证相结合。为探索其他目标，MHVF 从多个全屏预测中构建空间假设，并通过放大重定位来检查相应区域。为解决所得候选之间的歧义，它在标记的局部视图中验证这些候选与指令的一致性。验证分数随后指导第二轮局部搜索，并对两个搜索层级保留下来的候选进行排序以进行最终选择。在八种基准设置下，使用五个通用及 GUI 专用模型进行的实验表明，大多数设置下的定位准确率有所提升。MHVF 在 Mind2Web 和 VisualWebBench 上分别将 UI-Venus-Ground-7B 提升了 4.3 和 2.1 个百分点，并将 Qwen2.5-VL-7B 在 ScreenSpot-Pro 上的准确率从 23.6% 提高到 53.6%。

## Abstract
GUI grounding enables web agents to translate natural-language instructions into actionable interface locations. However, dense layouts and small, visually similar controls can lead models toward plausible but incorrect elements, while refinement around a single prediction may leave alternative targets unexplored. We propose the Multi-Hypothesis Verification Framework (MHVF) for training-free GUI grounding. It combines multi-hypothesis exploration with local visual verification using a single pretrained vision-language model. To explore alternative targets, MHVF constructs spatial hypotheses from multiple full-screen predictions and examines the corresponding regions through zoomed re-localization. To resolve ambiguity among the resulting candidates, it verifies their agreement with the instruction in marked local views. Verification scores then guide a second round of local search and rank candidates retained from both search levels for final selection. Experiments with five general-purpose and GUI-specific models across eight benchmark settings demonstrate improvements in grounding accuracy in most settings. MHVF improves UI-Venus-Ground-7B by 4.3 and 2.1 percentage points on Mind2Web and VisualWebBench, respectively, and raises Qwen2.5-VL-7B's accuracy on ScreenSpot-Pro from 23.6% to 53.6%.

## 1. 核心问题与研究背景

- **任务定位**：GUI grounding（界面定位）要求模型把自然语言指令映射为截图上的可点击坐标，是 Web/桌面智能体可靠执行动作的前提。
- **核心痛点**：
  - 界面布局密集、控件尺寸小、视觉上高度相似，模型在输入分辨率下容易丢失细节，从而选中“看似合理但错误”的元素（如图 1(a) 中本应点“对比复选框”却点了商品图片）。
  - 现有免训练方法（ZoomClick、MVP、AutoFocus 等）多围绕**单一初始预测**做放大或细化，一旦初始点偏离目标，替代目标就永远不会被检查。
- **研究含义**：作者主张把“多假设探索”和“局部视觉验证”结合起来——用多次全屏预测提出若干候选区域，用放大后的局部视图重定位并逐点验证，再让验证分数同时驱动**第二轮搜索**与**最终选择**，从而在**不训练、不微调**的前提下提升现成 VLM 的定位鲁棒性。

## 2. 方法论

### 2.1 核心思想

- 使用**同一个冻结的预训练 VLM** 承担三种角色：假设生成（P）、放大重定位（Z）、候选验证（V）；再用验证分数决定“重开哪个区域”（R）和“最终点哪个候选”。
- 采用**两级搜索**：第一级在全屏范围内生成多个空间假设；第二级只重开第一级得分最高的区域做局部再搜索；两级候选**全部保留**，统一按验证分数排序取最优。

### 2.2 关键技术细节（文字化描述）

- **问题形式化**：输入截图 \(I\) 与指令 \(q\)，输出归一化坐标 \(p\in[0,1]^2\)；视图 \(v\) 可为全屏或裁剪放大区域；候选点为局部视图预测映射回原图后的坐标。
- **第一级：空间假设生成**
  - 1 次贪心解码（确定性预测）+ \(n\) 次温度 \(T\) 随机采样；丢弃无效输出，按坐标去重并保留对数概率最高的序列。
  - 赋权：确定性预测权重固定为 1；采样样本按序列对数概率做 softmax 归一化，整体只占与确定性预测相当的总权重（式 1）。
  - 聚类：按权重降序处理，若与某簇种子在渲染视图的视觉 token 间距内（\(\delta=2\)）则并入，否则新建簇；簇权重为成员权重之和（式 2）。
  - 取权重最高的至多 \(k\) 个簇作为第一级假设集合（式 3），仅点预测会补一个小中心框以便裁剪。
- **缩放重定位与验证（Z–V）**
  - 以假设框为中心裁剪，宽高取 \(\max(\beta w_b,\ \rho W)\) 与 \(\max(\beta h_b,\ \rho H)\)，扩展至原图长宽比并做边界修正（式 4）；\(\beta\) 控制上下文，\(\rho\) 为最小裁剪比例。
  - 用像素预算 \(P(c)=(\kappa s_0)^2 w_c h_c\) 控制放大倍率（式 5），\(s_0\) 由 checkpoint 的全屏像素预算 \(P_{\max}\) 推出，\(\kappa\) 为目标放大系数。
  - 在放大视图上贪心解码得到框中心，按式 6 映射回原图归一化坐标，得到候选点 \(p_h\)。
  - 在局部视图上以红圈标记该点（借鉴 Set-of-Mark 视觉标记提示），提问“圈出的元素是否为指令描述的元素？Yes/No”，取 Yes 与 No 首 token 对数概率（各标签取单 token 变体最大值）之差作为**验证分数** \(m_h=\ell_{Yes}-\ell_{No}\)（式 7），分数越高越匹配。
- **第二级：验证引导的重开与最终选择**
  - 取第一级验证分数最高的候选所在视图作为重开视图（式 8）。
  - 在该视图内重新采样 \(n'\) 个预测、去重加权、以该视图的视觉 token 间距聚类，保留至多 \(k'\) 个假设；用更小的裁剪下限 \(\rho'<\rho\) 重新裁剪放大，重复 Z–V 流程得到第二级候选。
  - 最终在两级候选并集上取验证分数最高者（式 9）；**平分时保留第一级候选**，即第二级只有在分数更高时才替换。
  - 输出序列数上界为 \(N_{seq}\le 1+n+2k+n'+2k'\)（含至多 \(k+k'\) 个单 token 验证响应）；成本还取决于渲染视图尺寸与输出长度。
- **默认超参**：\(T=1.0\)；第一级采样 8 个、保留 ≤4 个假设；第二级采样 6 个、保留 ≤3 个；\(\kappa=3\)，\(\beta=3\)，\(\rho=0.25\)，\(\rho'=0.10\)；定位解码上限 32 token；验证请求 1 个输出 token 与 top-20 对数概率，缺失标签记 −30；所有模型与基准共用同一套搜索配置。

## 6. 主要结论与发现

- **总体有效**：在 8 个基准的多数设置中提升定位准确率；UI-Venus-Ground-7B 在 Mind2Web 75.7%→80.0%（+4.3）、VisualWebBench 90.7%→92.8%（+2.1）；Qwen2.5-VL-7B 在 ScreenSpot-Pro 23.6%→53.6%（+30.0），UI-Venus-Ground-7B 在 ScreenSpot-Pro 50.3%→66.6%、UI-Vision 26.7%→38.8%。
- **并非普适增益**：GTA1-7B 在 Mind2Web（−0.8）、VisualWebBench（−0.2）、MMBench-GUI L2（−3.0）下降，说明额外搜索对部分已强定位模型无益甚至有害。
- **组件贡献**：多假设与放大均有贡献；在 ScreenSpot-Pro 上，去掉放大（\(\kappa=1\)）损失最大（UI-Venus 5.0 点、Qwen2.5-VL-7B 12.5 点）；固定搜索深度下，验证优于按

按权重/对数概率排序的投票式选择——即“验证器打分”比“模型自身置信度”更能指示正确性；把验证改到全屏视图上做，增益明显下降，说明**局部放大视图上的验证**是必要的，验证器需要看清细节才能判断。

- **覆盖 vs 选择的分解**：第一级候选集合的“覆盖率”（正确点是否落在某个候选的裁剪区域内）显著高于单次预测的准确率，说明多假设采样确实能把正确目标“框进来”；但最终准确率仍低于覆盖率，表明瓶颈已从“生成”转移到“选择”，而 MHVF 的验证器缩小了这一差距但未完全消除——仍有一部分样本“候选里有正确答案却选错”。
- **目标尺寸分析**：增益随目标变小而增大，最小目标档（占屏面积很小）提升最明显，符合“放大重定位补偿分辨率损失”的设计动机；对本身就很大的目标，额外搜索几乎无收益，甚至因引入干扰候选而略有波动。
- **成本–精度权衡**：在相近的平均视觉 token 预算下，MHVF 优于“3×3 固定网格裁剪 + 同款验证器”的对照，说明**验证引导的选区**比**均匀铺网格**更省算力；但相对 Self-Zoom 与 Sample-and-vote，token 消耗约为其数倍，属于“以推理成本换准确率”的方法。
- **超参敏感性**：放大系数 \(\kappa\) 从 1 增至 3 收益最陡，继续增大收益递减并推高成本；假设数 \(k\) 增大同样呈边际递减，作者据此选择较小的默认值以控制开销。
- **定性表现**：成功案例多集中在“密集列表中的相邻项”“视觉相似的图标/按钮”“小尺寸文字链接”三类；失败案例主要是目标完全未被第一级任何假设覆盖、验证器被红圈附近的相似元素误导、以及模型输出的坐标本身存在系统性偏移。

## 7. 局限与作者未充分讨论之处

- **验证器与被定位模型同源**：生成、重定位、验证三种角色由同一个冻结 VLM 承担，存在**共模错误**风险——模型若对某类控件理解错误，验证阶段很可能给出同样错误的“Yes”，此时多假设搜索无法纠偏。
- **验证粒度粗**：仅用 Yes/No 首 token 的对数概率差作为分数，缺少“位置是否精确到可点击像素”的细粒度判断，对紧邻控件的区分能力有限。
- **搜索深度固定**：两级搜索、固定 \(k\)、\(k'\) 与采样数，未做自适应终止（如验证分数足够高即停），在简单样本上存在算力浪费。
- **成本报告不完整**：只给平均累计视觉 token，未给延迟、吞吐、显存峰值；对实际智能体部署而言，墙钟时间往往比 token 数更关键。
- **骨干覆盖窄**：五个模型全部为 Qwen2.5-VL 架构，未验证在 InternVL、Gemini/GPT 系列等其他视觉编码器与坐标表示方式上的可迁移性。
- **对比公平性受限**：与 25+ 已报方法的比较依赖各论文自报数字，配置与算力不一致，作者亦声明不作直接比较依据；缺少同算力下的训练型方法对照。
- **统计严谨性不足**：未报告多随机种子均值/方差与显著性检验，采样本身带随机性，单次结果的稳定性无法判断。
- **负增益未深究**：GTA1-7B 在三个设置上下降，作者仅归因于“已强定位模型”，未给出机制性解释（如验证器校准偏差、候选引入干扰）。

## 8. 总体评价与启示

- **定位清晰**：论文把问题准确地表述为“单点预测的局部性陷阱”，并用“多假设 + 局部验证 + 验证引导重开”给出一个结构简洁、无需训练的解法，动机与设计之间的对应关系紧密。
- **设计亮点**：让**同一个验证分数同时驱动搜索决策与最终选择**，是本文最具复用价值的思想；它把“验证”从后处理过滤器提升为搜索控制器，避免了生成与选择使用两套不一致准则。
- **工程价值**：作为即插即用模块，可直接套在现成 GUI 定位模型上，对中小规模、缺乏训练资源的团队尤其实用；代价是推理成本上升数倍，适合对准确率敏感、对延迟不敏感的离线或异步场景。
- **学术价值**：提供了“覆盖–选择”分解分析与同成本固定网格对照，这两点比单纯的准确率提升更有信息量，为后续工作指明了瓶颈所在（选择阶段与验证器质量）。
- **可延展方向**：①引入异构验证器或训练轻量 verifier 以缓解共模错误；②把 Yes/No 验证升级为带坐标的细粒度打分或成对比较；③自适应搜索深度与早停以压缩成本；④将验证分数回传为采样先验，形成迭代式搜索；⑤在更多骨干与真实智能体闭环任务（而非仅离线定位基准）上验证端到端收益。
