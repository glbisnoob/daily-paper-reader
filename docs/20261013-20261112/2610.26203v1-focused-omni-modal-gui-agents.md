## 摘要
图形用户界面（GUI）智能体越来越多地基于流式全模态观测采取行动，这些观测涵盖截图、音频、视频、交互历史和设备状态。然而，在每一步都统一暴露这一完整上下文，忽视了相关性是瞬态且稀疏的：决定某一动作的信号在下一步可能变成干扰。由于已执行动作会反馈到上下文中，这些错误会累积为顺序分心（Sequential Distraction），驱使智能体陷入不可逆的轨迹漂移。我们将这一底层需求表述为聚焦感知（Focused Perception）：一种步自适应、动作充分且非侵入式的表示。我们在 FocusGUI 中实现了这一点：这是一个轻量级适配器，能够针对特定步骤的决策参考动态地对多模态通道进行优先级排序。它并非统一处理所有输入，而是将最相关的证据压缩为紧凑的潜在表示，并微妙地注入冻结解码器的嵌入中，在不改变其原生参数空间的情况下引导模型注意力。FocusGUI 仅通过动作监督进行训练，既不需要模态相关性标签，也不需要骨干网络微调。在四个全模态骨干网络上，它相比冻结骨干网络平均将总体 Type Match 提升 +33.2，将 Exact Match 提升 3.0 倍，并相比最强现有增强方法将 Type Match 提升 +30.1。

## Abstract
Graphical User Interface (GUI) agents increasingly act over streaming omni-modal observations spanning screenshots, audio, video, interaction history, and device states. However, exposing this complete context uniformly at every step ignores that relevance is transient and sparse: the signal determining one action can become clutter at the next. Because executed actions feed back into the context, these errors compound into Sequential Distraction, driving the agent into irreversible trajectory drift. We formulate the underlying requirement as Focused Perception: a representation that is step-adaptive, action-sufficient, and non-intrusive. We realize this in FocusGUI, a lightweight adapter that dynamically prioritizes multimodal channels against a step-specific decision reference. Instead of uniformly processing all inputs, it compresses the most relevant evidence into a compact latent and subtly injects it into the frozen decoder's embeddings, guiding the model's attention without altering its native parameter space. FocusGUI trains from action supervision alone, requiring neither modality-relevance labels nor backbone fine-tuning. Across four omni-modal backbones, it raises overall Type Match by +33.2 and Exact Match by 3.0 times over the frozen backbone on average, and Type Match by +30.1 over the strongest existing enhancement method.

## 1. 核心问题与研究动机

- **背景**：GUI 智能体正从“解析静态截图”转向“基于流式全模态观测行动”，观测包含截图、音频、视频、交互历史与设备状态。现有主流范式是**每一步都把完整多模态观测暴露给模型**，让解码器自行隐式判断“什么重要”。
- **核心问题——相关性是“步级”属性，而非静态属性**：
  - **跨步瞬变**：消融实验显示，主导模态在 **45.3% 的相邻步**之间发生切换，**94.0% 的 episode** 至少出现一次切换。
  - **步内稀疏**：目标元素面积中位数仅占屏幕 **0.87%**，单步内视频内容变化中位数仅 **7.41%**。
  - **模态干扰**：**90.1% 的步骤**至少存在一个“干扰模态”（移除它反而提升正确动作似然）。
- **后果——顺序分心（Sequential Distraction）**：闭环智能体执行的动作会回灌到下一步观测与历史中，单步误读会**累积放大**，导致不可逆的轨迹漂移。
- **对现有方案的批判**：空间裁剪/缩放类方法（裁剪屏幕、解析元素、放大区域）本质是“做减法”，但①决定性信号可能来自音频、视频或设备状态，完全超出空间裁剪范围；②裁剪掉的背景往往包含坐标与文本参数所需的上下文。论文主张：**问题不是给得太多，而是缺少“如何优先阅读”的引导**——应改变解码器“怎么读”，而非“给什么”。

## 2. 方法论：Focused Perception 与 FocusGUI

### 2.1 核心思想
将需求形式化为**聚焦感知**：一种**步自适应（step-adaptive）、动作充分（action-sufficient）、非侵入（non-intrusive）** 的表示。实现为 **FocusGUI**——轻量适配器，冻结骨干与输入不变，仅额外提供“当前步什么重要”的信号。

### 2.2 关键技术流程（文字版算法）

1. **通道分解（CD）**：将同一观测拆为可分离的感知通道 \(X_t=\{x_t^{(m)}\}\)，包括文本/历史、屏幕、音频、视频、交互状态、全模态隐状态、屏幕空间通道等；各通道经**源特定投影器** \(P_m\) 映射到共享 128 维空间 \(e_t^{(m)}\)。
2. **决策参考**：由完整观测的整合表示生成步级参考 \(q_t = P_q(e_t^{(all)})\)。
3. **步自适应优先级（SP）**：对每个通道计算与参考的兼容性分数
   \(s_t^{(m)} = v^\top \tanh(W_e(e_t^{(m)}+r_m)+W_q q_t)\)，
   经 softmax（温度 \(\tau=1.0\)）归一化为优先级 \(\alpha_t^{(m)}\)，加权得到 \(c_t=\sum_m \alpha_t^{(m)} e_t^{(m)}\)。**每步重算、不跨步携带状态**，从源头阻断误差累积。
4. **动作充分压缩（AP）**：\(z_t = P_s(c_t)\in\mathbb{R}^{64}\)（\(d_z<d\)）。因完整观测仍走原通路，潜变量无需重建细节，只需承载“强调什么”。
5. **残差对齐（RA）**：将 \(z_t\) 经 \(W_p\) 展开为 \(K=4\) 个残差槽 \(R_t\)，**加性**注入动作边界前最后 4 个 prompt 嵌入位置：\(\tilde{E}_t = E_t + S_{J_t}(\gamma R_t)\)。\(W_p,b_p\) **零初始化**，训练起点等价于原模型，逐步学习观测条件化偏移。不追加文本提示、不删减任何输入、不新增预测头。
6. **训练目标**：仅对动作 token 的负对数似然做 teacher-forcing 优化，梯度穿过冻结解码器回传至适配器参数 \(\phi\)；骨干、解码器、LM head 全部冻结。**无需模态相关性标签**。

### 2.3 理论分析（附录 G）
- 残差经两条路径影响输出：**(V) 值路径**改变“读到什么内容”，足以切换动作原语；**(A) 注意力路径**（query steering + key displacement）重新分配注意力质量，是修正坐标/文本参数的**唯一途径**。
- 命题 G.1：第 1 层仅 key displacement 在 \(J_t\) 内重加权；第 2 层起 query steering 使残差可影响**整个观测**的注意力分布；且证据位置的内容 \(v_i\) 与 \(\gamma\) 严格无关——这解释了**为何注入必须是加性的**（替换会破坏最近、被关注最多的上下文位置）。

## 3. 实验设计

- **数据集/Benchmark**：**OmniGUI**（全模态智能手机 GUI 交互基准，29 个应用），708 个 episode、2,572 个动作步；每步配截图 + 同步音频/视频/动作历史。划分：训练 1,807 步（495 轨迹）/ 验证 257 步（71）/ 测试 508 步（142），episode 不相交。
- **指标**：Type Match（TM，动作原语匹配）、Exact Match（EM，原语+坐标落入目标框+文本匹配）、Goal Progress（GP，episode 内正确执行步占比）。
- **骨干（4 个开源全模态模型）**：Qwen2.5-Omni、VITA-1.5、MiniCPM-o 4.5、Baichuan-Omni-1.5，均冻结。
- **对比基线（4 个）**：DRS-GUI、OmniParser、RegionFocus（三者均为推理期空间区域精化）、GUI-Actor（可训练动作头，参数量与 FocusGUI 可比）。
- **任务类别（5 类）**：Localization、Semantic、Cross-modal、Temporal、Instant。
- **公平性控制**：所有方法共享同一系统提示、动作空间（13 种原语，坐标归一化 [0,1000]）、观测、解码配置（贪心，beam=1）；表 5 提供**参数量匹配（差 79 参数）的静态拼接对照**，以隔离“动态打分”本身的贡献。

## 6. 主要结论与发现

- **一致增益**：4 骨干平均 **TM +33.2、EM +22.3、GP +6.6**；较各骨干最强基线再高 **TM +30.1、EM +23.6、GP +8.0**；TM 从 31.0%→64.2%，EM 从 11.2%→33.5%（约 3.0×）。
- **空间精化反而有害**：三个区域裁剪类基线平均 TM 仅 +0.9，但 EM 相对下降 28%、GP 下降 35%（12/12 全负）——印证“原语更显著、但坐标/文本上下文被破坏”。
- **增益随交互深度扩大**：Qwen2.5-Omni 从首步 64.79 TM 跌至第 4 步起 32.79（保留一半），FocusGUI 保留 **86.8%**；EM 增益从 +22.54 单调增至 +35.25，所有区间不含 0。Temporal 类别上骨干第 3 步后 EM 为 0.00，FocusGUI 达 39.39。
- **Instant 类为负对照**：前两步与骨干无统计差异（区间含 0），深度 ≥2 后才出现 +28.57/+46.67 的增益——符合“针对累积误差”而非“普遍更强预测器”的预期。
- **学到的优先级会重排**：交互状态通道开局占 30.9%（均匀为 14.3%），收尾降至 7.7%；音频/视频从 13.4%/11.3% 升至 18.8%/18.3%；屏幕通道始终不占主导（10.9–12.8%），空间屏幕通道 ≤9.1%。**全程无相关性监督**。
- **容量不敏感**：\(K\) 在 16 倍范围内 TM 波动仅 2.6；\(d_z=32\) 过小（EM −6.9、GP −6.5），64 以上稳定，默认值无需逐骨干调参。

## 7. 优点

- **问题刻画扎实**：用模态消融的定量证据（切换率、干扰率、稀疏度）把“相关性瞬变稀疏”从直觉变成可测量事实，并命名“Sequential Distraction”，使动机与方法形成闭环。
- **设计原则清晰且自洽**：“改变怎么读而非给什么”直接推出**非侵入、加性、零初始化残差**三个设计约束，并有理论分析（V/A 双路径、命题 G.1）解释“为何必须加性”。
- **工程轻量、部署友好**：仅 0.0162% 可训练参数，骨干完全冻结，无额外预测头、不改词表、不追加文本提示，易于跨骨干迁移（4 个异构骨干均有效）。
- **监督极简**：仅用动作标签，不需要模态相关性标注，避免了昂贵的人工相关性标注。
- **实验对照严谨**：参数匹配对照（差 79 参数）排除了“容量红利”解释；Instant 类作为负对照验证机制特异性；提供 episode-clustered bootstrap 置信区间；附配对纠错统计而非只看均值。

## 8. 不足与局限

- **前瞻性缺失**：优先级仅由当前观测计算，无法预判“下一步会变重要”的证据；作者自述这是未来方向，也意味着对需要提前准备的时序任务仍有上限。
- **基准单一、规模偏小**：仅 OmniGUI（智能手机、29 应用、508 测试步），未覆盖桌面/Web 环境；小测试集使部分类别（每类 82–124 步）结论的统计稳健性受限。
- **骨干覆盖有限**：4 个开源全模态模型，未验证闭源商用模型或更大规模模型上的表现；EM 的骨干间差异被归因于“参数生成能力”，但未做进一步归因实验。
- **算力信息不完整**：仅说明 2×L20，缺少训练时长、推理开销、显存与延迟数据，不利于复现成本评估与实时场景可行性判断。
- **对比基线偏弱**：基线均为推理期空间精化或轻量动作头，缺少与全量微调、LoRA 微调、更大规模 GUI 专用 agent 训练的对比，“+30.1 TM”的强度需在此背景下谨慎解读。
- **潜在偏差风险**：通道集合（含“全模态隐状态”“屏幕空间”等人工定义的 7 个通道）本身是一种归纳偏置，其选择依据与缺失通道的影响未做系统消融；优先级权重 \(\alpha\) 被作者明确限定为“辅助通路内部的组织方式”，不能解释骨干内部真实模态使用，可解释性有限。
- **应用限制**：依赖骨干已能编码各通道特征（\(P_m\) 的输入来自冻结编码器），若骨干对某模态表征弱，适配器难以补偿；零初始化虽保证训练稳定，但也可能限制早期收敛速度（文中未报告收敛曲线）。
