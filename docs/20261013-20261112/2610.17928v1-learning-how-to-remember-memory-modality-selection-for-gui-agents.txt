# Learning How to Remember: Memory Modality Selection for GUI Agents

Abstract 

Recent advances in vision-language models (VLMs) have substantially improved the capa-bilities of GUI agents, while memory augmen-tation has emerged as a promising approach for reusing knowledge from past interactions. However, existing memory augmented GUI agents typically adopt a fixed representation strategy, providing retrieved experience as a static modality. It remains unclear whether a single memory modality is consistently optimal, or how modality preference changes across in-teraction steps. In this work, we conduct a systematic study of memory modality in VLM based GUI agents. Across GUI benchmarks, we find that the preferred memory represen-tation is strongly step dependent. Motivated by the finding, we introduce SwitchMem , a routing framework that dynamically selects be-tween textual and visual memory representa-tions at each step. Across three GUI bench-marks, SwitchMem outperforms memory aug-mented baselines that rely on static memory representations. Our findings validate our claim that memory modality is a step dependent de-cision rather than a fixed design choice. Code and project resources are available here .

1 Introduction 

Recent advances in vision-language models (VLMs) have substantially improved their ability to perceive, reason over, and act upon visual en-vironments (Xie et al., 2024; Gemini Robotics Team et al., 2025; Jung et al., 2026). Such progress has enabled graphical user interface (GUI) agents, where VLMs directly interpret screenshots, rea-son about user instructions, and execute actions across desktop and mobile environments (Xu et al., 2024; Zhang et al., 2025; Rawles et al., 2025; Qin et al., 2025). Despite these advances, GUI interac-tion remains challenging: tasks often require long-horizon decision making, and errors made at one step can propagate to subsequent decisions. To learn from prior interactions and reduce re-peated errors, recent GUI agents augment the actor with memories constructed from past trajectories, demonstrations, interaction knowledge, and visual observations (Li et al., 2026b; Qin et al., 2026; Choi et al., 2026; Liu et al., 2026; Zeng et al., 2026). Once cho-sen, this representation strategy typically remains unchanged across interaction steps. Conse-quently, it consistently outperforms all static memory baselines across evaluation tasks. 

2 Related Work 

Mobile GUI Agents. Mobile GUI agents exe-cute user instructions through repeated observation and interaction with mobile applications. At each step, the agent interprets the current screenshot in the context of the task instruction and interaction history, then predicts an action such as tapping, swiping, or entering text (Wang et al., 2024, 2025; Qin et al., 2025). The resulting interface state be-comes the observation for the next decision, and this process continues until the task is completed. Recent VLM based approaches integrate visual per-ception, action grounding, and sequential reasoning to support this interaction loop (Xu et al., 2024; Qin et al., 2025). Despite these advances, reliable mo-bile interaction remains challenging because each action changes the interface state, and errors in per-ception or action selection can propagate through subsequent decisions. 

Memory Systems for GUI Agents. Memory augmentation enables agents to extract and reuse actionable knowledge from prior interactions, sup-porting informed decisions and reducing the risk of repeated failures (Chhikara et al., 2025; Yeo et al., 2026; Xu et al., 2025b; Roh et al., 2026a). In GUI environments, existing approaches pre-serve episodic histories and retrieve relevant ex-periences as in-context examples (Agashe et al., 2025; Xu et al., 2025a; Zhang et al., 2025; Liu et al., 2026). Others transform interaction trajecto-ries into reusable textual traces, structured proce-dures, or executable knowledge that guides action generation (Li et al., 2026b; Qin et al., 2026; Xiao et al., 2026). Visual memory methods instead retain screenshots or action-relevant regions to ground de-cisions in prior interface states (Rawles et al., 2025; Choi et al., 2026; Zeng et al., 2026). While these methods differ in how memories are constructed and retrieved, they use a fixed modality after re-trieval. SwitchMem instead treats memory modal-ity as a step level decision, selecting between Text and Image based on the current interaction state.

Neither modality consistently dominates. As shown in Figure 2, both Text and Image memory are preferred for substantial subsets of interaction steps across AITW and LearnGUI. 4 SwitchMem 

SwitchMem is trained in two stages. First, a prefer-ence estimator processes Text and Image memory through separate actor forward passes and maps the resulting representation shift to a preference target. Second, a pairwise router is trained to predict the preference target from the current state and the re-trieved memory candidates. The router applies a shared MLP scorer to each state–memory pair and uses the difference between the Text and Image scores as its routing score.

5 Experiments 

Benchmarks. We evaluate SwitchMem on three GUI benchmarks: MobileMiniWob++ (Rawles et al., 2025), AITW (Rawles et al., 2023), and LearnGUI (Liu et al., 2026). Together, these bench-marks cover diverse mobile GUI interaction set-tings and allow us to examine whether adaptive memory modality selection generalizes across en-vironments. Because MobileMiniWoB++ does not provide official training or validation splits, we transfer the router trained on LearnGUI while keep-ing its weights fixed. Further details on the transfer and threshold-calibration protocol are provided in Section B.1. 

Models and Retrieval. All primary experiments use Qwen3.5-9B (Qwen Team, 2026) as the frozen actor and Qwen3-VL-Embedding-2B (Li et al., 2026a) for top-1 retrieval and memory embedding. Text and Image memories are instantiated from the same retrieved demonstration, isolating the effect of memory representation. 

Baselines. We compare SwitchMem with general-purpose VLMs (GPT-5.4-mini and Qwen3.5-9B), GUI specialized agents, such as Aguvis (Xu et al., 2024) and UI-TARS variants (Qin et al., 2025), and memory-augmented methods. The memory-augmented group uses the same frozen Qwen3.5-9B actor and includes RAG-GUI (Xu et al., 2025a), M3A (Rawles et al., 2025), AppAgent (Zhang et al., 2025), EchoTrail (Li et al., 2026b), AGMem (Choi et al., 2026), and fixed Text, Image, and Both baselines. 

5.1 Results Main results. Table 1 shows that augmenting the GUI agent with retrieved experience can improve action prediction, but its effectiveness depends on how the experience is represented. Image mem-ory tends to perform well on AITW and LearnGUI, whereas providing both modalities is more effective on MobileMiniWoB. Notably, advanced memory formulation strategies do not consistently outper-form raw context injection, suggesting that altering context representation without step-wise selectivity yields limited benefits. SwitchMem achieves the strongest performance across all three benchmarks. Rather than fixing one representation or always providing both, it selects a single memory modality at each interaction step. This allows the actor to exploit the complementary strengths of textual and visual memory across steps while avoiding the performance degradation that can arise from jointly providing both modalities. 

Modality preference changes within trajectories. 

Table 2 offers a quantitative analysis of Switch-Mem’s routing behavior across steps within a tra-jectory. Across all benchmarks, SwitchMem fre-quently utilizes both modalities within a single tra-jectory exhibiting moderate transition frequencies. Crucially, selected modalities are retained for con-secutive steps. This demonstrates that SwitchMem does not lock into a static task level modality, but exhibits state adaptive modality.

Empirical analy-sis shows that element density remains positively associated with the Image-over-Text utility gap. Im-age memory yields an advantage when decisions rely on fine-grained layouts containing dense UI elements that textual abstractions fail to convey. 

Image memory is more useful for function-oriented actions. Following standard GUI action taxonomies (Shi et al., 2025; Lu et al., 2025), we group interaction steps into Spatial and Function actions. Spatial actions comprise coordinate-based operations such as tapping, swiping, scrolling, and dragging, whereas Function actions govern inter-face functionality, task status, or system navigation. When shifting from Spatial to Function actions, the utility advantage of Image memory grows across benchmarks, showing that functional interface com-ponents rely on visual grounding. This suggests that visual memory is particularly valuable for deci-sions requiring an understanding of interface state and functionality, beyond simply locating interac-tion targets. 

Image memory becomes more useful after the in-terface evolves. Compared to initial states, post-initial states exhibit a wider Image-over-Text utility gap. This finding indicates that as a trajectory pro-gresses beyond initial states, evolving UI contexts generate complex visual nuances that text-based representations fail to preserve. 

6.1.2 Understanding SwitchMem’s Memory Modality Selection 

While Section 6.1.1 identified when visual context is useful, we now examine whether SwitchMem’s learned router dynamically aligns with these utility patterns. Furthermore, we evaluate how Switch-Mem’s adaptive routing translates into overall per-formance gains across benchmarks. 

SwitchMem follows modality-utility patterns. 

SwitchMem’s routing selections consistently align with the utility shifts identified across all three di-mensions (Figure 6). The router selects Image memory more frequently on visually dense screens, at steps whose reference actions are categorized as Function rather than Spatial, and in post-initial states. This alignment demonstrates that Switch-Mem’s router dynamically responds to systematic changes in modality utility across interaction steps. This behavior helps explain the performance im-provements in Table 1. By favoring Image in con-ditions where visual context is more useful while retaining Text in complementary states, Switch-Mem outperforms static memory strategies across all three benchmarks. 

6.2 Comparison with Alternative Routing Strategies 

To demonstrate the advantages of SwitchMem’s routing design, we analyze its performance against alternative routing baselines. 

Learned routing baselines. We compare Switch-Mem with three learned alternatives. Utility and Bi-nary utilize the same router architecture as Switch-Mem, constructed upon the actor’s current-state hidden representation and retrieved-memory em-beddings. However, both are trained directly from sampled action utilities, without D-CoE-based tar-get construction. Utility regresses the utility gap us-ing MSE, whereas Binary predicts only its sign us-ing binary cross-entropy. Basic routing also learns binary preferences, but uses embeddings of the cur-rent instruction, screenshot, and retrieved memo-ries rather than the actor’s hidden states. As shown in Figure 7a, conventional routing baselines offer minimal gains over a static Image Memory pol-icy, whereas SwitchMem delivers consistent per-formance improvements. These results validate the necessity of actor-derived preference targets for guiding memory selection.

7 Conclusion 

We study memory modality as a step-dependent de-cision for VLM-based GUI agents. Across bench-marks, neither Text nor Image memory consistently dominates, and their utility varies across interaction steps. We show that memory modality preference is reflected at internal state through D-CoE analysis. Based on the representation-level signal, we intro-duce SwitchMem which uses modality conditioned representation shifts to train a router that selects the suitable memory modality at each step. Switch-Mem improves over fixed modality and memory-augmentation baselines while providing only one memory modality to the actor. Together, these re-sults confirm that optimal memory selection is step-dependent, and that our SwitchMem approach can predict memory modality achieving performance gains over static alternatives. 8Limitations 

Our evaluation focuses on mobile GUI benchmarks centered on Android interfaces and controlled in-teraction settings. Generalization to iOS interfaces and newer Android versions, which may introduce different visual layouts and interaction conventions, remains unverified. Our online evaluation uses emulated environ-ments rather than physical devices. Although these environments support controlled and reproducible experiments, they do not fully capture device ren-dering differences, system interruptions, network variability, or hardware constraints. Evaluation on physical devices is an important direction for future work. SwitchMem requires access to the actor’s hid-den states for both preference target construction and routing at inference. It therefore cannot be directly applied to models accessed through APIs that do not expose these representations. Extending modality routing to such models remains an open direction.

10 A Dataset and Baseline Details 

A.1 Dataset Details 

We evaluate SwitchMem on three mobile GUI benchmarks that cover complementary interaction settings: Android in the Wild (AITW), LearnGUI, and MobileMiniWoB++. 

Android in the Wild (AITW). AITW (Rawles et al., 2023) contains human-demonstrated Android interaction trajectories spanning diverse applica-tions and user goals. Its heterogeneous interface states and multi-step trajectories make it suitable for studying whether the preferred memory repre-sentation changes across interaction steps. We eval-uate next-action prediction using the benchmark-specific action scorer. 

LearnGUI. LearnGUI (Liu et al., 2026) eval-uates mobile GUI agents in demonstration aug-mented interaction settings, requiring agents to ex-ecute complex navigation tasks by conditioning on retrieved historical execution traces. Because agent performance hinges on effectively leverag-ing retrieved multimodal experience for dynamic step-wise decisions, it serves as an ideal testbed for evaluating adaptive memory routing. Memory is retrieved only from demonstration trajectories distinct from the query trajectory. Following the benchmark’s standardized protocol, we report ac-tion level execution accuracy across its diverse mo-bile interaction tasks. 

MobileMiniWoB++. MobileMini-WoB++ (Rawles et al., 2025) provides pro-grammatically verifiable mobile GUI tasks in an online, closed-loop execution environment. While AITW and LearnGUI evaluate agents against het-erogeneous real-world traces, MobileMiniWoB++ offers deterministic state transitions and immediate environment feedback for step-wise actions. This setup serves as a controlled testbed, allowing us to isolate and evaluate SwitchMem’s dynamic memory routing without confounding noise from real-world OS rendering anomalies or ambiguous task rewards. Following standard protocol, we report task completion success rate. Together, the three benchmarks cover human-demonstrated trajectories, demonstration-based knowledge transfer, and controlled executable in-teraction. For all benchmarks, Text and Image memory conditions use the same actor, current ob-servation, retrieved demonstration, and decoding configuration; only the representation of the re-trieved memory differs. 

A.2 Baseline Details 

General-purpose and GUI specialized baselines are evaluated from their released models or APIs. For a fair comparison, we standardize the backbone actor across all memory-augmented methods. Specifi-cally, all methods use the same frozen Qwen3.5-9B actor, retrieval bank, and decoding protocol, differing only in how the retrieved experience is represented and provided to the actor. 

Fixed memory conditions. TEXT serializes the retrieved instruction, state description, and demon-strated action. I MAGE replaces the state description with its screenshot while retaining the same instruc-tion and action information. B OTH supplies both representations of the same retrieved step. 

RAG-GUI. RAG-GUI (Xu et al., 2025a) aug-ments the agent with external procedural knowl-edge retrieved from a corpus of GUI tutorials. Rather than appending raw retrieved documents, it filters and converts relevant content into concise, task- and progress-conditioned textual guidelines for the actor during action prediction. 

M3A. M3A (Rawles et al., 2025) enriches the current observation with structured interface infor-mation, including visible UI elements and recent interaction history. This structured context enables the actor to jointly reason about screen states and prior execution steps during action selection. 

AppAgent. APP AGENT (Zhang et al., 2025) con-structs an offline operation document by exploring target applications to detail interface elements, exe-cutable actions, and state transitions. At inference time, it retrieves documentation associated with the current screen’s UI elements and uses it to guide action generation. 

EchoTrail. ECHO TRAIL (Li et al., 2026b) builds reusable memory from collected GUI trajectories using self-exploration and critic-based filtering. Successful experiences are reformulated into com-pact textual traces highlighting interface states and transitions, enabling the retrieval and reuse of rele-vant interaction patterns for new tasks. 

AGMem. AGM EM (Choi et al., 2026) preserves action-relevant visual evidence from demonstra-tions by comparing consecutive frames to crop changed interaction regions. It provides these 11 cropped regions as visual memory, falling back to full demonstration frames when distinct regions cannot be reliably identified. To ensure fair comparison, all baselines are im-plemented as training-free, component-level mem-ory methods under the same retrieval bank, frozen actor, and decoding protocol as S WITCH MEM .Consequently, performance differences directly re-flect how each method formulates and delivers re-trieved experience to the agent. 

B SwitchMem Details 

B.1 SwitchMem Training and Evaluation Details 

For AITW and LearnGUI, we retrieve one memory step using the text-based retriever and represent the same retrieved ID as either Text or Image. At each training state, we sample seven actor actions per modality using temperature 0.7 and seeds 42–48, and score them with the benchmark specific action metric. Exact utility ties are excluded from pref-erence target construction. The routing threshold is selected by maximizing utility on the resulting training predictions and is frozen before test evalu-ation. The router is parameterized by a two-layer MLP (1024 → 256 → 1) with GELU activation and a 0.1 dropout rate, trained using AdamW with a learning rate of 0.001 .

AITW. We divide 20,000 steps from the official training split at the trajectory level into 10,019 preference-query steps and 9,981 memory steps, corresponding to 3,100 and 3,087 trajectories, re-spectively. The two subsets have no trajectory overlap. Each training query retrieves a demon-stration from the memory subset within the same AITW task category. For test evaluation, we use 5,000 steps from 759 held-out trajectories and al-low retrieval from the complete 20,000-step train-ing bank. 

LearnGUI. We use the 101 successful Online demonstration trajectories, comprising 1,500 in-teraction steps, as the source of both preference queries and candidate memories. Success is used to ensure that the memory bank contains validated experiences. We then construct preference supervi-sion by comparing the actor’s action quality under the Text and Image representations of the same re-trieved step. At evaluation, we follow LearnGUI’s offline one-shot setting and use the support demon-strations available as memory in that setting. The router and threshold remain fixed after Online train-ing, and no Offline-Test action, utility, or outcome is used for fitting or calibration. 

MobileMiniWoB++. MobileMiniWoB++ does not provide step level action utilities or an official training/validation split. We therefore transfer the LearnGUI router without updating its weights. The memory bank is constructed once using suite seed 1001 and contains 129 interaction steps from 50 successful trajectories. It is fixed before calibra-tion and evaluation. For threshold calibration, we use only the initial states of the 92 task templates instantiated with suite seed 43. Without observ-ing actions, rewards, or task success, we choose the cutoff whose Image-selection rate best matches the training-side routing rate on LearnGUI. The cutoff is then frozen and evaluated through full on-line rollouts on the same 92 templates instantiated with suite seed 42, yielding 63.043% task success (58/92). Suite seeds 1001, 43, and 42 share task templates but instantiate different task values, on-screen text, and target coordinates. Consequently, the memory bank, calibration set, and evaluation set contain no identical task instances. No observation from seed 42 is used to construct the memory bank, train the router, or select its threshold. Text memory is constructed without an addi-tional captioning model. For AITW, we serialize the dataset-provided UI text annotations together with the current Android activity. For LearnGUI, we use the provided element annotations, including page captions, element descriptions, and functional-ity labels. For MobileMiniWoB++, we determinis-tically serialize the Android accessibility hierarchy obtained through UIAutomator. Each textual GUI observation is paired with its task instruction and demonstrated action to form a Text memory entry.

B.6 Statistical significance. 

We assess whether the improvement over the strongest fixed memory baseline is statistically re-liable using paired tests. For AITW and Learn-GUI, we resample complete task trajectories rather than individual steps, thereby preserving within-trajectory dependence, and construct 95% con-fidence intervals using 20,000 paired cluster-bootstrap replicates. We additionally perform a two-sided cluster-level sign-flip randomization test. For MobileMiniWoB++, where each task produces a binary success outcome, we use a paired task bootstrap and an exact McNemar test. The improvements are statistically significant on AITW ( p < . 001 ) and LearnGUI ( p = .016 ), and remain significant after Holm correction across the three benchmarks. On MobileMiniWoB++, Switch-Mem exhibits a positive gain, but the difference is not statistically significant ( p = .688 ), reflect-ing the limited sample size of 92 evaluation tasks. Moreover, the router is transferred directly from LearnGUI without any MobileMiniWoB++ prefer-ence supervision or target-domain training. Within each example, Text and Image memory represent the same retrieved demonstration, and the current instruction and screenshot are identical across memory conditions. Only the representation of the past GUI observation differs. 

Sparse initial state: Text memory is more use-ful. At step 0 of “Go to the official website of bestbuy,” the current screen shows a Costco sign-in page (Figure 12). Its annotated element density is 177.25, below AITW’s lower-quartile cutoff of 310.00, placing it in the Sparse group. The gold action is a tap on the browser address bar, classified as Spatial. This state is therefore Sparse, Spatial, and Initial. The retrieved demonstration has the instruction “open google chrome and search for bestbuy.com” and also depicts a Costco sign-in page (Figure 12). The Image condition instead provides the screenshot of that past page, while retaining the same task and action information. Under Text mem-ory, the actor correctly taps the current address bar. Under Image memory, it outputs a typing action for bestbuy.com without first selecting the address bar. The action scores are 1 and 0, respectively, and SwitchMem selects Text.
