# Rank, Don’t Regress: A 279M Text Ranker Beats 2B and 7B VLMs on Referential Urdu GUI Grounding

## Abstract 

UI grounding asks a model to find the screen element that a user instruction refers to. Most current systems use a vision-language model (VLM) that reads a screenshot and outputs pixel coordinates. We study this task on Urdu mo-bile web pages, a setting with no published UI grounding results. Instead of regressing coor-dinates, we take the candidate elements from the page DOM and train a 279M-parameter cross-encoder (mDeBERTa-v3-base) to pick one. The click point is the centre of the picked element’s box, so it is exact whenever the right element is picked. We built a frozen test set of 304 instructions from six Urdu news sites; 149 of them (49%) are referential and never quote the full target text. Test domains were banned from training data before collection started. The ranker scores 73.4% point-in-box accuracy, against 29.6% for UI-TARS-2B and 23.7% for Qwen2.5-VL-7B, both zero-shot. On the ref-erential slice the ranker scores 65.8%, against 30.2% for a string-matching baseline that needs no training. In a controlled comparison at small scale, with training data drawn from the same pages, a coordinate-regression model of similar size scores 1.6%. Adding element geometry as input tokens gives the best variant, at 75.7%. The ranker’s errors concentrate in two places: elements that share identical text, and ordinal instructions such as “the fourth link”. 

## 1 Introduction 

A computer-use agent acts through a screen. Before it can click, it has to ground: given an instruction such as “open the sports section”, it must find the element the instruction means. The current default is a vision-language model that reads a screenshot and generates a point (Cheng et al., 2024; Qin et al., 2025; Bai et al., 2025). Grounding accuracy is the ceiling on everything the agent does next, and it is usually the weakest part of the pipeline (Zheng et al., 2024). Two facts pushed us away from that default. First, coordinate regression is fragile under layout change. In pilot runs for this project, Qwen2.5-VL-7B scored 34.1% zero-shot on an 82-item pilot set of mobile pages; the same model fine-tuned on desktop screenshots fell to 11.0%, because training and test pages laid out the same content at different widths. The readout itself is part of the problem: on COCO photos, Qwen3-VL-4B picks the correct cell 68.5% of the time when the cells are named options, and 20.0% when it must answer with pixel coordinates (Frontera Del Valle, 2026). Second, the language we care about has no grounding data at all. Public grounding benchmarks cover English and Chinese interfaces (Cheng et al., 2024; Li et al., 2025); for Urdu, a right-to-left language with tens of millions of speakers, we found no published UI grounding result, and hand-labelling click points for a new language is slow work. A web page removes the labelling problem. Its DOM lists every clickable element with its text, attributes, and bounding box. The supervision is al-ready there. The open question is the output space: should a model regress a point from pixels, or se-lect one element from the page’s own candidate list? Selection is not a new idea. MindAct (Deng et al., 2023) trains a small DeBERTa ranker over DOM candidates, but uses it as a pre-filter: the ranker shortlists elements and a large language model makes the final pick. Deng et al. report that the ranker on its own is not competitive on Mind2Web. Their pages are English desktop pages with about 1,135 candidate elements per page on average. Our pages are Urdu mobile pages with a median of 25 candidates. We test whether the con-clusion survives the change of regime: a trained ranker, alone, as the complete grounder. Our contributions are three: 1. First UI grounding results for Urdu. We arXiv:2611.20145v1 [cs.CL] 15 Nov 2026 report the first UI grounding (element local-ization) results for Urdu, measured on real mobile websites: a frozen test set of 304 instructions over six Urdu news sites, col-lected and locked before any training, with test domains excluded from training at the registrable-domain level. Half of the items are referential: the instruction describes the target without quoting its full text. 2. The ranker alone is enough on mobile web. 

A 279M cross-encoder used as the complete grounder, with no downstream model, scores 73.4% against 29.6% for UI-TARS-2B and 23.7% for Qwen2.5-VL-7B. This reverses the ranker-alone finding of Mind2Web in the mo-bile regime. 3. A controlled rank-versus-regress study at small scale. Training data for both models comes from the same pages: DOM ranking scores 73.4% and pixel coordinate regression scores 1.6%. The difference is the output space, not the data source. (Wu et al., 2026) run the VLM-scale version of this comparison in pixel space; Section 2 separates the two. Section 2 places this work against prior ground-ing systems. Section 3 defines the task and the frozen protocol. Sections 4 and 5 describe the ranker and the comparison systems. Section 6 gives results, Section 7 takes the failures apart, and Sec-tions 8 and 9 state limits and ethics. 

## 2 Related Work 

Visual grounding with VLMs. SeeClick (Cheng et al., 2024) showed that a VLM fine-tuned for grounding can drive GUI agents, and released the ScreenSpot benchmark. CogAgent (Hong et al., 2024) added a high-resolution image encoder. UGround (Gou et al., 2025) trained a grounder on large-scale web data. UI-TARS (Qin et al., 2025) trains a native agent model end to end, and Qwen2.5-VL (Bai et al., 2025) is a general VLM with strong built-in grounding. All of these systems output coordinates. Their benchmarks are desktop, English or Chinese, and screenshot-based: ScreenSpot-Pro (Li et al., 2025) targets high-resolution professional software, while OS-World (Xie et al., 2024), AndroidWorld (Rawles et al., 2024), WebArena (Zhou et al., 2024), and VisualWebArena (Koh et al., 2024) evaluate full tasks. Our zero-shot VLM baselines are UI-TARS-2B and Qwen2.5-VL-7B, the strongest open coor-dinate grounders available to us when the build ran, plus one recent mobile-focused grounder, MAI-UI-2B (Zhou et al., 2025) (Section 5). A second recent mobile grounder, Ferret-UI Lite (Yang et al., 2025b), has no released code or weights and could not be evaluated (Section 5). 

Coordinate-free and structured grounding. 

GUI-Actor (Wu et al., 2025) removes coordinate tokens and instead attends over image patches with a learned action head. It is coordinate-free, but it stays in pixel space and at VLM scale (7B). Mind2Web (Deng et al., 2023) works from the DOM: a fine-tuned DeBERTa ranker (MindAct) keeps the top candidates and an LLM picks among them. The final decision in MindAct belongs to the LLM, and the paper reports that the small ranker alone performs far below the full pipeline. Prune4Web (Zhang et al., 2025) has an LLM write small programs that prune the DOM before a down-stream model acts; again, the structured step filters and something else decides. WinDOM (Li-Chen et al., 2026) reads its training labels off the DOM for free, as we do, but spends them on a 2B re-gression grounder for a desktop web clone. Two 2026 studies set the terms for this paper. (Chen and Jacucci, 2026) recast grounded steps from Android-Control, MoTIF, and Mind2Web as same-screen ranking and showed that a fine-tuned ranker stays tied to visible labels: masking the target element’s text drops its R@1 from 0.694 to 0.151. Their rankers are diagnostics run on existing English benchmarks; none is deployed as the grounder. (Wu et al., 2026) compare output spaces under con-trol: at 7B VLM scale, on an identical 100K train-ing set, a coordinate-free attention model beats a coordinate-based one by about 3.7 points across En-glish desktop and web benchmarks. That compari-son runs in pixel space at VLM scale. Ours runs in the DOM at 279M parameters, on data drawn from the same pages, and the gap is 71.8 points. Cross-encoder ranking itself is standard in text retrieval since monoBERT (Nogueira and Cho, 2019): score each candidate against the query with full attention, take the best. We take the ranking mechanism from MindAct, credit it in full, and change its role and regime: mobile web, Urdu, roughly 25 candidates per page, and the ranker’s top-1 is the answer. 

Low-resource interfaces. Multilingual agent evaluation has reached low-resource languages, at coarser grains than element localization. LoWA-gent (Monjur et al., 2026) evaluates web agents in English, Hindi, Bengali, Urdu, and Amharic on synthetic localized websites, and reports multi-step task success. VLURes (Atuhurra et al., 2026) benchmarks grounding in Urdu, but the task there is matching long texts to natural images, not inter-face elements. macOSWorld (Yang et al., 2025a) ships genuinely mirrored Arabic right-to-left inter-faces, on desktop, scored by task success. A Per-sian vision-language-action dataset (Pourasghari et al., 2026) covers instruction-to-plan grounding over photographs, an embodied setting. None of these reports UI grounding accuracy for Urdu, and none runs on real mobile websites. The blocker for UI grounding in a new language is annotation cost: each item needs a person to read an instruction and mark a box. For web pages, the DOM gives the boxes for free, which is what makes this study possible without an annotation budget. 

## 3 Task and Data 

3.1 Task definition 

One item consists of a mobile page view (a 390 ×844 screenshot and its DOM candidate list) and one Urdu instruction. A system outputs one point. The item is a hit if the point falls inside the gold element’s box (point-in-box accuracy). For the ranker, the output point is the centre of the top-ranked candidate’s box, so a hit is the same event as ranking the gold element first. For the VLMs and the coordinate control, the output point is whatever the model generates. 

3.2 Candidate extraction 

Candidates are the visible clickable elements of the view: links, buttons, inputs, and elements with button or link roles, filtered by the same visibility rules across all items. Each candidate record holds the element text, tag, aria-label, placeholder, title, link target, an id/class snippet, the heading of the nearest ancestor section, and the bounding box. The frozen views carry a median of 25 candidates. 

3.3 The frozen protocol

The frozen set holds 160 views from six sites: Siasat (75 items), Dawn (75), Express (75), Daily Khabrain (67), Daily Mashriq (11), and Ummat (1). No site contributes more than 25% of the items. 

3.4 Instruction generators 

Instructions come from five rule-based generators, listed in Table 1. The explicit generator quotes the element’s full text (“click «X»”). The other four are referential: they describe the target without quoting its full text. Ordinal items name a position among same-tag candidates in DOM order (“the fourth link”). Partial items quote only the first three words of a long headline. Section items name the heading the element sits under. Function items refer to a control by its job (search box, menu button, login link, home link), found by deterministic attribute rules. Every referential item passes an automatic uniqueness check: exactly one candidate in the view may satisfy the description under the genera-tor’s own rule, or the item is discarded. Each item records which generator produced it. The referen-tial slice makes up 149 of 304 items (49.0%). In 64 items, some other candidate in the view carries the same text as the target; those items are the source of the duplicate failures in Section 7. 

3.5 Training pool 

Training pages come from 12 Urdu sites outside the ban list: 532 views and 4,216 positive items (2,774 explicit, 1,442 referential), produced by the same generators and the same uniqueness checks. Explicit items are capped at 16 per view so that easy quoted-text items do not swamp the pool. The pool is skewed: ARY News supplies 2,179 posi-tives (51.7%) and Urdu Wikipedia 1,049 (24.9%), with BBC Urdu (381), Jang (282), and Geo Urdu (224) behind them. Validation holds out whole sites, never random rows; the validation split has 419 positives. A separate coordinate file holds the 1,539 explicit positives for which a screenshot was stored, with their gold centres, drawn from the same pages, for the control model in Section 5. 

3.6 Independent verification 

After the build, a separate script recomputed ev-ery number in this paper from the raw files rather than from stored summaries. It recounted all items, rechecked oracle presence for all 304 items (304/304 gold boxes match their frozen candidates exactly), confirmed zero registrable-domain over-lap between training and test data and zero shared screenshot paths, and recounted every accuracy cell in Table 3 from the per-item outputs. Eight items, spread across sites and generators, were also checked by eye against their screenshots. Every check passed. 

## 4 Method 

4.1 The ranker 

The ranker is a cross-encoder. For one item, it scores every candidate in the view against the in-struction and returns the argmax. Each score comes from one forward pass over the pair (instruction, candidate string), encoded jointly by mDeBERTa-v3-base (He et al., 2023) with a single-logit classifi-cation head. The model has 278.8M parameters. It reads no pixels: the screenshot exists for the VLM baselines and for human checking, and the ranker never sees it. 

4.2 Candidate strings 

A candidate is rendered as its text followed by bracketed fields. Table 2 defines the four variants we trained. The MINDACT _TEXT variant is the MindAct-style representation: text and tag only. The FULL variant adds the attribute fields when they carry information the text does not, plus the parent section heading. FULL _NOPARENT removes the section heading. FULL _GEO adds the box as four numbers normalised by the viewport size.

4.3 Training 

For each positive item, the gold candidate gets la-bel 1 and up to eight other candidates from the same view, sampled at random, get label 0. One exception: for explicit items, a candidate whose normalised text equals the gold text is never used as a negative. It is a defensible answer to the quoted text, and punishing the model for it would teach the wrong lesson; Section 7 shows the cost of this ambiguity at test time. We train with AdamW (Loshchilov and Hutter, 2019) at learning rate 1e-5, weight decay 0.01, a linear schedule with 10% warmup, two epochs, and seed 13. The effective batch is 32 (batch 32 at max length 160; batch 16 with two accumulation steps at max length 224). One practical detail cost us two early runs: the mDeBERTa-v3 checkpoint loads in fp16 by default in our stack, and fp16 training drove the loss to NaN. All reported models are loaded and trained in fp32, with steps skipped when the loss is non-finite. 

## 5 Experiments 

5.1 Systems compared String-match heuristic. No training. The rule extracts the quoted text from the instruction, picks a candidate whose normalised text matches it exactly (ties broken by larger area), and otherwise falls back to the candidate with the highest token overlap with the quote (ties by overlap ratio, then area). For referential instructions, which carry no quote, the rule has almost nothing to work with. This baseline prices the value of the quoted text alone. 

Ranker variants. The four variants of Section 4, all trained on the same training split of the pool in Section 3.5 (validation sites held out) with the same recipe. 

UI-TARS-2B. ByteDance’s GUI-specialised VLM (Qin et al., 2025), zero-shot. It receives the screenshot and the instruction in its standard prompt format and outputs a point in 0-to-1000 coordinates. All 304 outputs parsed. 

Qwen2.5-VL-7B. Alibaba’s general VLM (Bai et al., 2025), zero-shot, outputting pixel coordinates for the 390 ×844 view. 253 of 304 outputs parsed; the other 51 produced no usable point and count as misses. 

MAI-UI-2B. The 2B grounder from Alibaba’s MAI-UI family (Zhou et al., 2025), a GUI foun-dation model line released in December 2025 and built for real-world mobile and desktop interfaces. Zero-shot. We ran it in its native grounding mode: the documented MAI-UI grounding prompt, with the final point read from the model’s answer block and its coordinates converted from the model’s doc-umented 0-to-999 grid, exactly as the official agent code normalises them. 220 of 304 outputs con-tained a usable point; the other 84 produced no coordinates at all and count as misses. 

Ferret-UI Lite. Apple’s 3B on-device GUI agent (Yang et al., 2025b) could not be evaluated: Apple has released no code and no weights for it, and no official model repository exists, so there was nothing openly available to run zero-shot. 

Coordinate control. SmolVLM-500M-Instruct (Marafioti et al., 2025) fine-tuned with LoRA (Hu et al., 2022) (rank 16, learning rate 2e-4, two epochs, effective batch 32) on the 1,539 coordinate rows from the same training pages. It reads the screenshot and generates the gold centre as text. This is the rank-versus-regress control: same pages, similar size, pixel input, coordinate output. All 304 outputs parsed.

## 6 Results 

Table 3 gives the main result. The full ranker scores 73.4% overall. UI-TARS-2B scores 29.6% and Qwen2.5-VL-7B 23.7%. The gap to the stronger VLM is 43.8 points. MAI-UI-2B, the newest VLM we tested, scores 11.8%, below both older VLMs; Section 5 gives its protocol and parse rate. One property of the test set must be stated next to these numbers. Half of the items are referential by design, and the VLMs are weakest exactly there: on ordinal items they score 4.0% and 2.0% (Table 4). On the explicit slice, where the instruction quotes the text, they reach 40.0% and 32.9%. Their low overall scores partly reflect the slice mix, and we report the slices so the reader can see that split directly. The comparison that does not depend on the mix is the control: a coordinate model trained on the same pages scores 1.6% overall and 0 of 155 on the explicit slice, where the answer is printed on the screen in the instruction itself. For scale, Wilson 95% confidence intervals on the headline numbers are [68.1, 78.0] for the full ranker overall, [24.8, 35.0] for UI-TARS-2B, and [19.3, 28.8] for Qwen2.5-VL-7B. On the referen-tial slice the full ranker sits at [57.8, 72.9] against the heuristic’s [23.4, 38.0]. None of the intervals behind the three main claims overlap. 

6.1 Where the win comes from 

The heuristic wins the explicit slice outright, 84.5% against 80.6% for the rankers. That is expected: the instruction quotes the target text, and exact matching is the right tool. The ranking claim rests on the referential slice. There, the full ranker scores 65.8% against the heuristic’s 30.2%, a gap of 35.6 points on items that never quote the full answer. On ordinal items the heuristic scores 1.0% and the ranker 49.5%. A model that had only learned to match strings could not produce these numbers; the ranker learned to use tag, attributes, section context, and position cues that the heuristic cannot read. 6.3 Latency and cost 

Table 5 lists measured per-item times, with the hard-ware stated for each row, because the rows were not measured on the same machine. On this hard-ware the full ranker, at a median of 7.44 seconds per query over 31 candidates, is slower per item than UI-TARS-2B served on a GPU (2.61 seconds). We make no wall-clock claim. What the ranker offers is 279M parameters, text-only input, training in about an hour on one GPU, and inference that runs on a CPU at all. A phone-class agent that cannot host a 2B or 7B VLM can host this ranker; whether it is fast enough there is a separate measurement we have not done. 

## 7 Analysis 

We classified all 81 failures of the full ranker from its per-item outputs. The failures fall into exactly two groups. 

Same-text duplicates (30 failures). Every ex-plicit failure picked a different element carrying the same text as the target. News navigation re-peats labels across a page (a section name appears in the top bar, the side rail, and the footer), and 64 of the 304 items have a duplicated target text. When the duplicates also share a section context, the candidate strings are near-identical and the pick is close to a coin flip. The geometry variant cuts these errors, as Section 6 shows, because position is one signal the duplicates do not share. One cata-logued case (item it0275, Express): the instruction quotes the label “Business”, and the element the ranker picked carries the identical label. Only the position is wrong. 

Ordinal confusion (51 failures). Every referen-tial failure is an ordinal item: the ranker got 50 of 101 ordinal items right and spread the other 51 over wrong positions. Partial, section, and func-tion items are error-free (48 of 48). The cause is structural. Each candidate is scored in a separate forward pass, so the model never sees the list as a list; nothing in a candidate string says “I am the fourth link”. One hard site. Express contributes 75 items and the full ranker gets 26 of them (34.7%), against 82.7% on Dawn, 85.3% on Siasat, and 95.5% on Daily Khabrain. Table 6 gives accuracy by site for every system. The site’s item mix stacks both failure modes: 40 of its 75 items are ordinal and 31 have a duplicated target text. The per-site gap is a property of the items, not a site-specific bug we found: the VLMs collapse on the same site (UI-TARS-2B 4.0%, Qwen2.5-VL-7B 0.0%). 

The control’s failure mode. The coordinate con-trol parsed cleanly (304 of 304 outputs) and still scored 1.6%. Its errors are spread points: with 1,539 training rows it did not learn where Urdu page elements sit, and its 0 of 155 on the explicit slice shows the problem is not instruction under-standing. Given the screenshot and the exact text to find, it cannot point at the text. That is the re-gression task failing on its own terms, at the same data scale where ranking reaches 73.4%. 

## 8 Limitations 

The test set covers six sites, all news. Forms, shops, banking, and government portals have different layouts and different element mixes, and we have no numbers for them. The instructions are rule-generated. Five genera-tors produce clean, unambiguous Urdu, and every referential item passed a uniqueness check by con-struction. Instructions written by people will be messier, and our accuracy on them is unmeasured. The test set is small. At 304 items, one item is worth about 0.33 points, and differences between ranker variants of under two points should be read as noise. The claims we make rest on gaps of 35 points or more. Two weaknesses are measured, not hypothetical. When two elements carry identical text and similar context, the ranker often picks the wrong copy (30 of its 81 failures). Ordinal instructions stay near 50% for the ranker and under 5% for both VLMs, because no system we tested represents list position well. The method needs the DOM. It applies to web pages rendered in a browser or webview. It does not apply to native apps, canvas interfaces, or a bare screenshot, and in those settings coordinate models remain the only option of the two. The training pool is skewed. Two sites supply 76.6% of the positives, so the ranker may be fitted to ARY News and Wikipedia layouts more than to Urdu pages in general. The frozen test sites are disjoint from training, which limits how much this can inflate the test numbers, but it can still narrow what the model learned. Latency was measured on a shared 2-core VM in fp32, with no batching, quantisation, or distillation. Those numbers describe our measurement setup, not a deployment. 

## 9 Ethics 

All pages came from public news sites, fetched without accounts or logins. The records hold page structure, element text, and boxes; they contain no personal data, no user accounts, and no tracking of any person. Ad and tracker requests were blocked during collection. The instructions are machine-generated; no human subjects took part and no annotation labour was used. Grounding models are components of web au-tomation, and automation can be misused, for ex-ample to operate accounts or submit content at scale. Our study is read-only: the systems predict points on saved pages, and no action was performed on any live site during data collection or evaluation. Page text and layout belong to the publishers. We use short element strings and bounding boxes for research evaluation, and the figures show single elements in context for the same purpose. 

## 10 Conclusion 

On a frozen Urdu mobile-web test set, a 279M text ranker used on its own scores 73.4%, against 29.6% and 23.7% for 2B and 7B VLMs. Min-dAct’s ranking mechanism is not ours; what the numbers show is that its role can change when the page carries about 25 candidates instead of about a thousand, and when the interface language is Urdu, where both VLMs score under 30%. The ranker then needs no LLM behind it and no GPU in front of a user. The controlled comparison makes the same point from the other side: at small scale, with both models trained on data from the same pages, regressing coordinates scores 1.6% where DOM ranking scores 73.4%. What is left open is clear from the failures: score candidates jointly so list po-sition exists, use local context to separate same-text duplicates, and test on human-written instructions, other genres, and a second right-to-left language.
