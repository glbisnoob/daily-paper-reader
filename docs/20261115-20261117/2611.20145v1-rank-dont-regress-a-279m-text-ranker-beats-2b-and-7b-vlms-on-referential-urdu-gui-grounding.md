## 摘要
UI 定位要求模型找到用户指令所指的屏幕元素。当前大多数系统使用视觉语言模型（VLM），读取截图并输出像素坐标。我们在乌尔都语移动网页上研究这一任务，该场景尚无已发表的 UI 定位结果。我们没有回归坐标，而是从页面 DOM 中取出候选元素，并训练一个 279M 参数的交叉编码器（mDeBERTa-v3-base）来选择一个元素。点击点是被选中元素框的中心，因此只要选对元素，点击点就是精确的。我们构建了一个冻结测试集，包含来自六个乌尔都语新闻网站的 304 条指令；其中 149 条（49%）为指代性指令，从不引用完整的目标文本。测试域名在数据收集开始前就被禁止进入训练数据。该排序器取得 73.4% 的点落在框内准确率，而 UI-TARS-2B 和 Qwen2.5-VL-7B 在零样本设置下分别为 29.6% 和 23.7%。在指代性子集上，排序器得分为 65.8%，而无需训练的字符串匹配基线为 30.2%。在小规模受控比较中，训练数据来自相同页面，规模相近的坐标回归模型仅得 1.6%。将元素几何信息作为输入 token 加入可得到最佳变体，得分为 75.7%。排序器的错误集中在两类情况：文本完全相同的元素，以及诸如“第四个链接”这样的序数指令。

## Abstract
UI grounding asks a model to find the screen element that a user instruction refers to. Most current systems use a vision-language model (VLM) that reads a screenshot and outputs pixel coordinates. We study this task on Urdu mobile web pages, a setting with no published UI grounding results. Instead of regressing coordinates, we take the candidate elements from the page DOM and train a 279M-parameter cross-encoder (mDeBERTa-v3-base) to pick one. The click point is the centre of the picked element's box, so it is exact whenever the right element is picked. We built a frozen test set of 304 instructions from six Urdu news sites; 149 of them (49%) are referential and never quote the full target text. Test domains were banned from training data before collection started. The ranker scores 73.4% point-in-box accuracy, against 29.6% for UI-TARS-2B and 23.7% for Qwen2.5-VL-7B, both zero-shot. On the referential slice the ranker scores 65.8%, against 30.2% for a string-matching baseline that needs no training. In a controlled comparison at small scale, with training data drawn from the same pages, a coordinate-regression model of similar size scores 1.6%. Adding element geometry as input tokens gives the best variant, at 75.7%. The ranker's errors concentrate in two places: elements that share identical text, and ordinal instructions such as "the fourth link".

# 论文结构化总结：《Rank, Don't Regress: A 279M Text Ranker Beats 2B and 7B VLMs on Referential Urdu GUI Grounding》

## 1. 核心问题与研究背景

- **任务定义**：UI grounding（界面元素定位）要求模型根据用户指令找到屏幕上对应的可点击元素；该任务通常是 computer-use agent 执行操作前必须先完成的步骤，其准确率直接决定后续所有动作的效果。
- **主流范式**：当前系统普遍采用视觉语言模型（VLM）读取截图并**直接回归像素坐标**（如 SeeClick、CogAgent、UGround、UI-TARS、Qwen2.5-VL 等）。
- **作者指出的两个问题**：
  - **坐标回归对布局变化非常敏感**。论文报告了一项试点结果：Qwen2.5-VL-7B 在 82 条移动页面上零样本得分为 34.1%，但用桌面截图微调后，在同样的内容、不同的页面宽度下，准确率降到 11.0%。另有研究报告称，Qwen3-VL-4B 在“命名单元格”任务上选对率是 68.5%，在“输出像素坐标”时只有 20.0%，说明“读出方式”本身就是瓶颈。
  - **低资源语言没有数据**。公开的 grounding 基准主要覆盖英文和中文桌面界面；乌尔都语（从右向左书写、有数千万使用者）没有已发表的 UI grounding 结果，而人工标注点击点成本很高。
- **论文的整体含义**：网页 DOM 已经免费提供了每个可点击元素的文本、属性与包围盒，因此监督信号无需人工标注；真正需要回答的是**输出空间的选择**——从像素回归一个点，还是从页面自带的候选列表中选一个元素。作者主张在移动网页这一新场景下，“排序”优于“回归”。

## 2. 方法论

### 2.1 核心思想
- 不做坐标回归，而是**从 DOM 抽取候选元素集合，用交叉编码器对每个候选与指令打分，取分数最高者**；点击点即被选中元素包围盒的中心，因此“选对元素”与“点对位置”等价。

### 2.2 候选抽取
- 候选包括：可见可点击元素（链接、按钮、输入框、带 button/link role 的元素），所有条目使用统一的可见性过滤规则。
- 每个候选记录包含：元素文本、tag、aria-label、placeholder、title、链接目标、id/class 片段、最近祖先 section 的标题、包围盒。
- 冻结测试视图的候选数**中位数为 25 个**（对比 Mind2Web 桌面页约 1,135 个）。

### 2.3 排序模型
- 模型为 **mDeBERTa-v3-base 交叉编码器，278.8M 参数**，带单 logit 分类头。
- 对每个（指令，候选字符串）对做一次联合前向编码并打分，取 argmax；**不读取任何像素**，截图仅用于 VLM 基线与人工核查。
- 四种候选字符串表示（见表 2）：
  - `MINDACT_TEXT`：`text [tag]`，最大长度 160（MindAct 风格）；
  - `FULL`：额外拼接 `[ARIA] [PH] [TITLE] [SEC]`（仅当字段存在且与文本不同），长度 224；
  - `FULL_NOPARENT`：去掉 `[SEC]` 父 section 标题；
  - `FULL_GEO`：在 FULL 基础上加入按视口归一化的 `[BOX xywh]` 几何 token。

### 2.4 训练流程
- 每条正样本：金标候选标 1，同一视图随机采样最多 8 个候选标 0。
- 特例：explicit 指令中，**与金标文本归一化后相同的候选不作为负样本**（因为它是引号文本的合理答案）。
- 优化：AdamW，lr=1e-5，weight decay=0.01，线性调度 + 10% warmup，2 epochs，seed=13，有效 batch=32（长度 160 时 batch 32；长度 224 时 batch 16 + 2 步梯度累积）。
- 工程细节：mDeBERTa-v3 默认以 fp16 加载会导致 loss 变为 NaN，因此所有模型均以 **fp32** 加载训练，并跳过非有限 loss 的步。
- 评估指标：**point-in-box accuracy**（输出点落在金标框内即命中）。

## 3. 实验设计

### 3.1 数据与基准
- **冻结测试集**：304 条指令、160 个页面视图，来自六个乌尔都语新闻站：Siasat 75、Dawn 75、Express 75、Daily Khabrain 67、Daily Mashriq 11、Ummat 1（单站不超过 25%）。
- **协议严格性**：测试域名在采集前即被禁用，禁用粒度是**可注册域级**（含子域与同主体站点）；截图与 DOM **同一次页面加载配对采集、一次性写入**，避免新闻首页变化导致金标失效。
- **五类指令生成器**（规则生成，均通过自动唯一性检查）：
  - explicit 155 条（51.0%，引号引用完整文本）；
  - ordinal 101 条（33.2%，如“第四个链接”）；
  - partial 31 条（10.2%，只引用长标题前三词）；
  - section 13 条（4.3%，用所在栏目标题指代）；
  - function 4 条（1.3%，按功能指代搜索框/菜单/登录等）。
  - **指代性（referential）切片共 149 条（49.0%）**，从不引用完整目标文本；其中 64 条存在同文本的其它候选。
- **训练池**：12 个非禁用乌尔都语站点，532 个视图、4,216 条正样本（2,774 explicit + 1,442 referential），explicit 每视图上限 16 条；验证集按**整站留出**，419 条正样本。
- **坐标对照数据**：同一批页面中 1,539 条带截图的 explicit 正样本及其金标中心点。

## 4. 资源与算力

- 全部实验在**单张 Tesla T4 GPU** 上作为独立作业运行：
  - 主 ranker 训练约 **1.1 小时**；
  - 两个消融变体共 **2.0 小时**；
  - 两个 VLM 评测共 **52 分钟**；

## 5. 实验数量与充分性
