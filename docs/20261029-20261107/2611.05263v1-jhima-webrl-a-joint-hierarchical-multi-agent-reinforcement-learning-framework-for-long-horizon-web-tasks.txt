## ABSTRACT 

Multimodal web agents have shown promising capabilities for interacting with websites through graphical user interfaces (GUIs), yet realistic web tasks often require long-horizon, multi-step planning that remains challenging for monolithic policies. Such agents must jointly infer high-level plans, navigate through in-termediate states, track progress over extended interaction histories, and execute visually grounded actions. Although prior work has explored modular multi-agent systems with a separate planner, the planner is typically not updated jointly with the actor. We investigate whether explicitly separating and jointly training plan-ning and execution provides a stronger inductive bias for long-horizon web navi-gation. We introduce JHiMA-WebRL, a joint hierarchical multi-agent reinforce-ment learning framework for web agents that couples a task decomposer with an actor. To train the decomposer, we use a strong teacher model to construct structured subtask supervision from multimodal GUI trajectories, and use these annotations to fine-tune both the decomposer and the subtask-conditioned actor. We then extend Group Relative Policy Optimization (GRPO) to jointly optimize the decomposer and actor in the interactive WebArena environment through hi-erarchical rollout grouping and role-specific advantages. On WebArena-Lite-v2, JHiMA-WebRL-14B, consisting of a 7B actor and a 7B decomposer, achieves an average success rate of 37.2%, compared with 24.0% for a ScaleCUA-32B agent that we fine-tune with RL on the same training tasks and evaluate under the same protocol. Ablations show that jointly updating the decomposer during RL outperforms updating the actor alone. These results suggest that jointly learned role factorization with smaller models can be a competitive alternative to scaling monolithic agents for long-horizon web tasks. Prior Web Agents

## 1 INTRODUCTION 

Multimodal web agents interact with websites by perceiving screenshots, interpreting page elements, and executing actions such as clicking, typing, scrolling, and navigating between webpages. Such agents could support workflows in online shopping, web-based administration, repository manage-ment, and information retrieval. Benchmarks such as WebArena (Zhou et al., 2024) and Visual-WebArena (Koh et al., 2024) evaluate this setting through tasks that require interactive execution across multiple steps. These tasks combine high-level planning with low-level visually grounded control: for example, to cancel an order, an agent must navigate intermediate pages, identify rele-vant interface elements, track progress over a long action history, and avoid repeated or irrelevant actions. Many web agents use a monolithic policy that maps the task, observation, and action history directly to the next action, learning planning, state tracking, visual grounding, and execution within a single model. ScaleCUA (Liu et al., 2025b) and UI-TARS (Qin et al., 2025) demonstrate the value of large-scale GUI data for training such policies, while WebAgent-R1 (Wei et al., 2025) and WebRL (Qi et al., 2025) improve web interaction through online reinforcement learning (RL). Modular systems instead introduce a separate planner: Agent S uses a manager to generate subtasks from retrieved knowledge and experience for workers to execute (Agashe et al., 2025a), and Agent S2 adds proactive replanning as execution provides new observations (Agashe et al., 2025b). Even though an explicit planner module can support long-horizon behavior, the planner’s parameters are not updated from the outcomes of action execution. Recent studies (Erdogan et al., 2025; Wu et al., 2026; Kong et al., 2026; Lu et al., 2025) focus on training modular agents for long-horizon tasks, but either train the modules separately, apply supervised learning or RL to only one module while freezing the other, or alternate updates between modules. To our knowledge, prior work has not studied simultaneous RL training of a separately parameterized planner and actor from a shared rollout batch in web environments. We therefore introduce JHiMA-WebRL, a joint hierarchical multi-agent reinforcement learning framework for long-horizon web interaction. Figure 1 presents an overview of the three stages in our framework: decomposer data generation, supervised fine-tuning, and joint hierarchical multi-agent RL. First, a strong teacher model converts multimodal GUI trajectories into ordered subtasks, supplying planning annotations that existing GUI trajectory datasets typically lack. Second, these annotations support supervised fine-tuning of two Qwen2.5-VL-7B models: a decomposer that pre-dicts subtasks from the instruction and starting screenshot, and an actor that predicts the next GUI action conditioned on those subtasks. Finally, we jointly train both modules using terminal task suc-cess rewards while interacting with web environments, so that the decomposer can adapt its plans to the actor’s capabilities while the actor adapts to executing them. We extend Group Relative Policy Optimization (GRPO) through the hierarchical rollout structure: the decomposer proposes K can-didate decompositions, and the actor performs M complete environment rollouts for each decom-position. Actor-level advantages compare executions under the same plan, while decomposer-level advantages compare plans by the average terminal reward of their executions, and both policies are updated from this shared batch without dense process rewards. We evaluate JHiMA-WebRL-14B, our instantiation with a 7B actor and a 7B decomposer, on WebArena-Lite-v2 (Liu et al., 2025b), a refined subset of WebArena tasks for purely visual agents. JHiMA-WebRL-14B achieves an average success rate of 37.2%, compared with 24.0% for a ScaleCUA-32B agent that we fine-tune with RL on the same training tasks and evaluate under the same protocol. Ablation studies further indicate that jointly updating the decomposer during RL is beneficial relative to updating the actor alone. These results suggest that joint training of role-factorized modules can be a competitive alternative to scaling monolithic agents. 

## 2 RELATED WORK 

WebArena, VisualWebArena, and WorkArena evaluate agents on web tasks requiring multi-step interaction, visual grounding, state tracking, and long-horizon planning (Zhou et al., 2024; Koh et al., 2024; Drouin et al., 2024). OSWorld, Windows Agent Arena, and MacArena study the broader setting of desktop and OS-level computer use (Xie et al., 2024; Bonatti et al., 2025; Muryn et al., 2026). Strong GUI agents such as UI-TARS and ScaleCUA train largely monolithic policies that 2Preprint map observations and histories directly to actions using large-scale GUI data (Qin et al., 2025; Liu et al., 2025b). These systems demonstrate the importance of data scale and GUI grounding, but require a single policy to learn planning, progress tracking, grounding, and execution jointly, whereas we factorize web interaction into a trainable decomposer and actor. A broad line of work studies modular or multi-agent LLM systems, including AutoGen, CAMEL, ChatDev, MetaGPT, and MAP (Wu et al., 2023; Li et al., 2023; Qian et al., 2024; Hong et al., 2024; Webb et al., 2025). In computer use, Agent S combines manager–worker decomposition with retrieved experience, and Agent S2 updates plans as subtasks are completed (Agashe et al., 2025a;b). OpAgent coordinates a planner, grounder, reflector, and summarizer, with the reflector’s feedback guiding subsequent planning (Guo et al., 2026). These mechanisms concern the organiza-tion and adaptation of inference-time behavior. Related methods such as ReAct, Reflexion, MiRA, SEAgent, and TreeCUA explore intermediate reasoning, subgoals, feedback, or structured explo-ration (Yao et al., 2023; Shinn et al., 2023; Wang et al., 2026; Sun et al., 2025; Jiang et al., 2026). JHiMA-WebRL focuses on learning the decomposition interface from annotated trajectories and jointly adapting it with the actor through task rewards. A complementary line of work studies training across planner–executor interfaces. Plan-and-Act separately fine-tunes planner and executor models using synthetic plans and action trajectories, and adds dynamic replanning at inference time (Erdogan et al., 2025). Our approach also uses trajectory-derived planning supervision, then jointly adapts both modules through RL. Navigating WebAI pairs a supervised hierarchical planner with an RL-trained controller (Thil et al., 2024). Planner Mat-ters! optimizes only the planner using trajectory rewards from a VLM judge, freezing the actor and memory manager (Wu et al., 2026). Its joint-training ablation shares parameters across roles, whereas our decomposer and actor are separate policies. In robotic manipulation, HiRoC aligns an executor with subgoals through supervised fine-tuning, then applies hierarchical GRPO to the ex-ecutor with a frozen planner, combining task-level and subgoal-level advantages (Kong et al., 2026). SWIRL instead trains both modules through alternating RL phases (Lu et al., 2025). In contrast, JHiMA-WebRL computes actor advantages within plans and decomposer advantages across plans, and updates both policies from a shared rollout batch. PPO and GRPO provide the basic optimization tools for recent LLM and agent RL, while multi-agent RL methods such as MADDPG, COMA, QMIX, and MAPPO study credit assignment across interacting policies (Schulman et al., 2017; Shao et al., 2024; Lowe et al., 2017; Foerster et al., 2018; Rashid et al., 2018; Yu et al., 2022). For web and GUI agents, WebAgent-R1, WebRL, OpenWebRL, and OpAgent apply online multi-turn RL to browser-based tasks, optimizing a single agent policy from terminal or outcome-based rewards (Wei et al., 2025; Qi et al., 2025; Yang et al., 2026a; Guo et al., 2026), while WorkForceAgent-R1 applies rule-based RL to single-step web decisions (Zhuang et al., 2025). Other works improve credit assignment with process or progress signals, including Web-Shepherd, WebArbiter, TGPO, GraphGPO, and MiRA (Chae et al., 2025; Zhang et al., 2026; Chen et al., 2025; Cheng et al., 2026; Wang et al., 2026). We instead extend GRPO’s rollout grouping and advantage computation to two jointly trained roles, using only terminal rewards and no dense process rewards. 

## 3 METHOD 

We propose JHiMA-WebRL, a joint hierarchical multi-agent reinforcement learning framework for long-horizon web navigation. Our approach factorizes interaction into two specialized but jointly optimized modules: a task decomposer and an actor. The decomposer maps the task instruction and initial screenshot into an ordered sequence of executable subtasks. The actor then conditions on the task, current observation, interaction history, and generated subtasks to produce visually grounded actions in the web interface. Below, we first describe the problem formulation, followed by the three stages of our framework: data generation for training the decomposer, supervised fine-tuning of both the decomposer and actor, and a joint hierarchical multi-agent extension of GRPO. 3.1 PROBLEM FORMULATION 

We consider an interactive web environment modeled as a partially observed sequential decision problem. Each task is specified by a natural-language instruction x. At time step t, the agent 3Preprint receives a screenshot ot of the web interface and produces an action at ∈ A , such as clicking a page element, typing, scrolling, navigating between webpages, or terminating with an answer. The environment then transitions to a new state and returns the next observation ot+1 . A trajectory is denoted by τ = ( o0, a 0, o 1, a 1, . . . , o T ), where T is the trajectory length. Each trajectory receives a terminal task reward R(τ ) ∈ { 0, 1}, where R(τ ) = 1 if the task is successfully completed and 

R(τ ) = 0 otherwise. Success is determined through environment-specific rule-based verification or an LLM judge. Our modular policy consists of a decomposer policy πD ≡ πθD and an actor policy πA ≡ πθA ,parameterized by separate models. Given a task instruction x and an initial observation o0, the decomposer samples a decomposition 

d = ( g1, g 2, . . . , g L) ∼ πD (· | x, o 0), (1) where each gℓ is a natural-language subtask and L is the number of generated subtasks. The actor then generates web-interface actions according to

Existing GUI trajectory datasets contain task instructions, screenshots, and action traces, but typi-cally do not provide explicit subtask annotations. To train a task decomposer, we construct a new decomposition dataset from trajectory annotations in ScaleCUA (Liu et al., 2025b). ScaleCUA provides large-scale multimodal GUI data across platforms, including grounding annotations and human or agent trajectories. For each trajectory, we provide a strong teacher model, GPT-5.2-Codex (OpenAI, 2025), with the original task instruction x and starting screenshot o0, together with the full sequence of user or agent actions (a0, . . . , a T −1) and corresponding screenshots (o0, . . . , o T ). A subgoal-generation guideline prompt, included in Appendix A, guides the annotation process. The teacher produces an ordered list of executable subtasks d = ( g1, . . . , g L) and optional descrip-tions of unnecessary or redundant actions in the trajectory. This process yields approximately 76 Kdecomposer training examples; dataset statistics are provided in Table 3, and qualitative examples are shown in Appendix C. The resulting automated pipeline converts low-level multimodal GUI demonstrations into high-level planning supervision, enabling us to train an open-source decom-poser rather than relying on a proprietary teacher at inference time. 3.3 SUPERVISED FINE -T UNING

## 4 EXPERIMENTS 

4.1 DATASETS 

The task decomposer was trained with supervised fine-tuning using approximately 76 K task-decomposition examples, which were generated from ScaleCUA trajectories using GPT-5.2-Codex as described in Section 3.2. The actor was fine-tuned on all ScaleCUA trajectories augmented with the teacher-annotated subtasks, along with grounding data spanning web, mobile, and desktop plat-forms, resulting in 2,535,552 training examples. Unlike standard ScaleCUA SFT, the actor thus receives a task decomposition in its context as a planning scaffold. Both modules were then jointly trained through online reinforcement learning using the training tasks associated with WebArena-Lite, following the setup of WebAgent-R1 (Wei et al., 2025). We-bArena contains 812 interactive web tasks spanning five domains—Reddit, GitLab, e-commerce administration, maps, and online shopping. WebArena-Lite (Liu et al., 2025a) selects a cleaned subset of 165 tasks for evaluation, leaving 647 tasks from the original WebArena benchmark for reinforcement-learning interaction. No WebArena-Lite evaluation task (and hence no WebArena-Lite-v2 task) is used during SFT or RL. We also employed the flexible evaluation protocol of Liu et al. (2025b), including LLM-based fuzzy matching using GPT-5.2-Codex, to compute the binary task outcome reward at the end of web interaction. For evaluation, we used WebArena-Lite-v2, introduced by ScaleCUA (Liu et al., 2025b). WebArena-Lite-v2 is a refinement of the evaluation subset of WebArena-Lite designed specifically for evaluating purely visual GUI agents; it removes 11 tasks that require multi-tab interaction and revises task instructions and evaluators. It contains 154 tasks across five website environments: Shopping, ShoppingAdmin, Reddit, GitLab, and OpenStreetMap. The benchmark includes hetero-geneous task objectives such as question answering, navigation, page-content matching, and state-changing operations, with success determined by the flexible evaluation criteria of Liu et al. (2025b). 6Preprint 4.2 BASELINES 

We compared against native agents at several model scales ranging from 7B to 72B, allowing com-parisons between our 14B modular system and both smaller and larger monolithic systems. We also compared against multi-agent systems consisting of a proprietary planner (GPT-4o) with a ground-ing module. These provide comparisons with systems that separate planning from visual grounding, but do not jointly train a learned decomposer and actor as in JHiMA-WebRL-14B. The UI-TARS and GPT-4o planner–grounder results are taken from ScaleCUA (Liu et al., 2025b) (15-step bud-get). The ScaleCUA-7B/32B SFT and GUI-Libra-8B results are taken from the re-evaluation of Yang et al. (2026b), which uses a 15-step budget, averages four runs, and replaces the GPT-4o fuzzy-match judge with GPT-5. Under its original evaluation setup, ScaleCUA reports higher scores for its own models (37.7% for ScaleCUA-7B and 44.2% for ScaleCUA-32B at 15 steps). We also trained a ScaleCUA-32B RL baseline, specifically fine-tuning the SFT model on the WebArena training set, using standard multi-turn GRPO with 7 rollouts and a maximum of 15 interaction steps. For a fair comparison with our method, we only included baselines that do not use HTML or DOM information. 4.3 EXPERIMENTAL DETAILS 

We trained the 7B decomposer and 7B actor of JHiMA-WebRL-14B in two stages: SFT, followed by joint hierarchical RL. The decomposer was initialized from Qwen2.5-VL-7B and fine-tuned on the approximately 76 K decomposition examples generated from ScaleCUA multimodal trajectories, on 8 NVIDIA H100 GPUs with 80 GB of memory each via full-parameter fine-tuning. We trained for 1 epoch with a learning rate of 1e-5 and a cosine learning-rate schedule with a warmup ratio of 0.03 . The per-device batch size was 2, with gradient accumulation over 4 steps, resulting in an effective global batch size of 64 . We used DeepSpeed (Rajbhandari et al., 2020) for distributed training with ZeRO-3, along with gradient checkpointing, bf16 mixed-precision training, gradient clipping to a maximum norm of 1, and a maximum token length of 30720 . The actor was also initialized from Qwen2.5-VL-7B and fine-tuned with the same hyperparameters as above, using released ScaleCUA trajectories augmented with generated subtasks. After SFT, both the actor and decomposer were jointly optimized through LoRA fine-tuning using GRPO, with standard-deviation and response-length normalization removed to reduce optimization bias, following Liu et al. (2025c). We used LoRA rank r = 32 and scaling factor α = 64 for both modules, with a separate adapter for each. For each task, the decomposer sampled K = 3 candidate decompositions. For every decomposition, the actor generated M = 7 complete trajectories. For both, we used 0.8 as the sampling temperature, and we allowed a maximum of 15 interaction steps per trajectory. We optimized the LoRA parameters with a learning rate of 1e-5 . The GRPO updates used clipping parameters ϵA = ϵD = 0.2 , KL coefficients βA = βD = 0 (i.e., no KL penalty), and 2 optimization steps per rollout batch. We used 32 gradient accumulation steps and trained for 

1 epoch over the 647 training tasks. We used the efficient parallel trajectory rollout generation of M-GRPO (Wei et al., 2025) for each task decomposition, with training taking approximately 720 GPU-hours on a cluster of 8 H100 GPUs with 80 GB of memory each. 

Evaluation. We report the task success rate on all 154 WebArena-Lite-v2 tasks, averaged over 4

independent evaluation runs. We sampled one decomposition at test time using a temperature of 0.0 and allowed a maximum of 15 interaction steps, consistent with the baselines. 4.4 RESULTS

4.5 ABLATION STUDY 

We analyzed the contribution of the components of JHiMA-WebRL-14B through ablations (Table 2). First, we trained only the actor with RL while keeping the SFT decomposer frozen (‘w/o decom-poser RL’), using the same number of rollouts per task ( K=3 , M =7 ) as JHiMA-WebRL-14B. This reduced the average success rate to 33.4%, a drop of 3.8 percentage points, indicating that updating the decomposer jointly with the actor matters. Second, to assess the role of the decomposer, we trained the actor alone using standard multi-turn GRPO without subtask conditioning. The actor was initialized from Qwen2.5-VL-7B and fine-tuned using supervised learning on released Scale-CUA trajectories and grounding data, without any subtasks. We trained two variants: one with the same total number of rollouts per task as JHiMA-WebRL-14B (21), and one with 7 rollouts, match-ing the per-decomposition group size of our actor. The two variants reached 34.9% and 35.2%, i.e., 2.3 and 2.0 percentage points below JHiMA-WebRL-14B. Finally, we removed RL entirely and evaluated the SFT decomposer and SFT actor together (‘w/o RL’), which reduced the average suc-cess rate by 2.1 percentage points. Notably, actor-only RL with a frozen SFT decomposer (33.4%) scored below this SFT-only system (35.1%), whereas joint RL improved on it; the SFT-only modular system also performed on par with the decomposer-free actors trained with RL (34.9% and 35.2%). 4.6 SUBGOAL QUALITY ANALYSIS

## 5 LIMITATIONS 

Our study has several limitations. (i) Train–test overlap: RL is performed on the remaining We-bArena tasks, which are disjoint from the evaluation tasks but can share intent templates and web-sites with them; results thus reflect in-environment generalization, not transfer to unseen websites. (ii) Supervision and cost: decomposition supervision is generated by a proprietary teacher (GPT-5.2-Codex) without human verification of annotation quality, and hierarchical rollouts require K×M

complete episodes per task, which is costly in live environments. (iii) Open-loop planning: the de-composer plans once from the initial observation and cannot revise the plan during execution. (iv) 

Coarse credit: terminal rewards assign the same advantage to every token of a decomposition or tra-jectory, without identifying which subtask or action caused success or failure. (v) Evaluation scope: 

we evaluate on a single benchmark of 154 tasks, and the ablation differences (2.0–3.8 percentage points) are of a size where run-to-run variance matters. 

## 6 CONCLUSION AND FUTURE DIRECTIONS 

We introduced JHiMA-WebRL, a framework for jointly training a task decomposer and a visually grounded actor. The framework generates subtask supervision from multimodal GUI trajectories to train the decomposer and extends GRPO with hierarchical rollout grouping and role-specific advantages. JHiMA-WebRL-14B achieved an average success rate of 37.2% on WebArena-Lite-9Preprint v2, 13.2 percentage points above a ScaleCUA-32B RL baseline trained and evaluated under the same protocol. In ablations, removing decomposer updates during RL, removing the decomposer together with subtask conditioning, or removing RL each lowered the average success rate, by 2.0– 3.8 percentage points. Our work suggests several future directions. First, the decomposer could be made adaptive , re-vising subtasks as execution deviates from the plan. Second, joint optimization can be combined with intermediate progress signals such as milestone rewards (Wang et al., 2026) or graph-based credit assignment (Cheng et al., 2026). Finally, jointly trained decomposer–actor systems could be extended to cross-domain and live-web settings, where online RL has recently been shown to be feasible (Yang et al., 2026a).
