# Abstract 

Autonomous agents powered by vision-language models (VLMs) show great po-tential in navigating mobile graphical user interfaces (GUIs) to complete complex tasks. However, existing paradigms face fundamental scalability bottlenecks: fine-tuning requires massive high-fidelity datasets or prohibitive training time and compute, while gradient-free approaches rely on custom static heuristics or costly trial-and-error trajectory exploration where feedback is deferred until the end of execution. To address these limitations, we introduce MAPLE ( Multimodal Agent with Playbook-Learned Experience ), a novel gradient-free multi-agent framework that enables dynamic, step-wise experience sharing and execution-time prompt evolution. Unlike traditional action-reflection architectures that depend on costly, post-hoc self-reflection, MAPLE enables agents to cross-reference and distribute runtime insights in real time at each operational step. This dynamic exchange eliminates blind trial-and-error looping and steers agents along direct, grounded interaction paths. Extensive evaluations on the AndroidWorld and MobileWorld benchmarks demonstrate that MAPLE achieves state-of-the-art performance on complex, long-horizon mobile tasks, while proving scalable and adaptable across novel environments. 

# 1 Introduction 

Despite significant advancements in intuitive interface design, mobile devices remain challenging or inaccessible to large segments of the population, particularly the elderly and individuals with visual impairments. With the rapid evolution of Vision-Language Models (VLMs) [3], GUI-based autonomous agents have emerged as a transformative paradigm to bridge this accessibility gap and democratize access to essential modern technology. By empowering users to delegate complex, multi-application tasks via natural language, these agents hold immense potential to transform digital autonomy. Consequently, substantial research has focused on deploying foundation models as interactive reasoning engines across mobile platforms [23, 4, 22, 6, 7], accompanied by comprehensive benchmarks [14, 8, 19] designed to evaluate the frontiers of agentic capabilities. However, developing autonomous agents for mobile UI navigation requires balancing generalizability, online interaction overhead, and offline data curation costs. Existing paradigms struggle to strike this balance: gradient-based reinforcement learning requires prohibitively expensive environment rollouts, while zero-shot inference frameworks remain handicapped by static prompts or brittle, text-bound memory structures that fail to capture the visual nuances of dynamic mobile interfaces. In opaque, highly dynamic mobile GUIs, purely memorizing procedural step sequences is insufficient; an agent must dynamically reverse-engineer interface mechanics through visual transitions.

To bridge this fundamental gap, we introduce the Multimodal Agent with Playbook-Learned Experi-ence (MAPLE ). Designed as a cold-start, continual learning system, MAPLE adapts the principles of step-level reflection and cross-episodic playbooks specifically for the multimodal mobile do-main. Rather than relying on massive pre-curated datasets or text-only procedural memory, MAPLE leverages explicit visual state transitions (e.g., before-and-after screenshots) to autonomously distill declarative UI rules on the fly. By decoupling intra-episodic state tracking from cross-episodic knowl-edge accumulation and grounding retrieved priors in the active visual interface, MAPLE achieves robust, cold-start generalization across unseen mobile applications. In summary, the primary contributions of this work are three-fold: • Dual-Memory Cognitive Architecture: We introduce MAPLE, a cold-start, gradient-free mobile agent architecture built around two complementary memory streams: (1) a 

bounded Working Memory instantiated as a dynamic key-value store that tracks transient, within-episode task state (e.g., extracted data and sub-goal checklists), and (2) a persistent Playbook that accumulates reusable, declarative UI mechanics across episodes. Coupled within a factorized step-level reasoning loop, these two memories coordinate short-term task execution with long-term interface priors without offline datasets or task-specific heuristics. • Self-Supervised Hindsight Distillation & Grounded Retrieval: We design a closed-loop mechanism to populate and query the Playbook entirely on the fly. By comparing post-action screenshot transitions against predicted visual outcomes, MAPLE autonomously distills and deduplicates universal action-effect facts, then retrieves them via intent masking and greedy visual anchor matching so injected guidance stays anchored to the active screen layout. • Extensive Evaluation & State-of-the-Art Performance: We evaluate MAPLE on two open-domain mobile benchmarks ( AndroidWorld [14] and MobileWorld [8]) across six Vision-Language Models spanning open-weight to frontier scales. Powered by Gemini-3-Flash, MAPLE reaches 75.9% Success Rate on AndroidWorld and 60.25% on MobileWorld (including a record 68.18% on interactive tasks), demonstrating superior navigational direct-ness and strong cross-model generalization. 

# 2 Related Work 

Developing autonomous agents for mobile UI navigation requires balancing policy generalizability, online interaction overhead, and offline curation costs. Existing literature generally bifurcates into gradient-based policy optimization and inference-only framework orchestration. 

2.1 Gradient-Based Policy Optimization in GUIs 

The first lineage leverages gradient-based reinforcement learning (RL) to cast GUI task execution as a policy optimization problem. Frameworks such as K 2-Agent [24], MobileRL [25], SoLS [12], and the GUI-R1 family [10] explicitly fine-tune foundation models via algorithms such as Group Relative Policy Optimization (GRPO) [16] or off-policy actor-critic methods with experience replay. While these approaches can discover robust interface policies, their scalability remains bottlenecked by severe sample inefficiency, as policy convergence demands extensive environmental interaction. On mobile platforms, executing rollouts over high-dimensional GUI state spaces inside live An-droid emulators incurs steep computational latency and infrastructure overhead, making large-scale, emulator-in-the-loop RL post-training prohibitively expensive. 

2.2 Gradient-Free & Static Inference-Based Agents 

To bypass gradient optimization, a second lineage focuses on gradient-free, inference-based architec-tures leveraging zero-shot foundation models. While computationally lightweight, their adaptability to unseen domains is often hindered by reliance on static priors. Early approaches depended on handcrafted prompt templates or pre-collected UI exploration graphs (e.g., AppAgent [27], Auto-Droid [23]). Recent efforts like GEPA [1] automate prompt tuning via offline genetic optimization. However, these strategies rely on mini-batch sampling, parallel environment cloning, and static state assumptions—conditions that rarely hold across dynamic, stateful mobile applications. 2Figure 1: Overview of the MAPLE framework. MAPLE integrates intra-episodic UI execution with a cross-episodic learning loop. Given a user goal, the agent retrieves visually grounded priors from a persistent Playbook and conditions on short-term Working Memory to execute actions. Post-execution reflection updates local state tracking while distilling generalizable rules back into the Playbook for continuous knowledge accumulation. 

2.3 Dynamic Memory & Continual Learning in Agents 

To eliminate offline curation, recent works explore continuous learning and dynamic memory archi-tectures that update agent logic on the fly. For instance, Agentic Context Engineering (ACE) [28] constructs a persistent, cross-session playbook to mitigate context collapse, while SCOPE [13] introduces dual-stream tactical and strategic updates to recover from mid-task failures. Despite these advances, adapting text-centric memory frameworks like ACE and SCOPE to mobile GUIs reveals a fundamental limitation: they accumulate procedural task strategies (memorizing specific action sequences) suited primarily for transparent, text-based environments. In opaque, highly dynamic visual GUIs, procedural memory generalizes poorly across UI updates and layout shifts. In contrast, MAPLE transitions from procedural memorization to causal rule distillation .By evaluating multimodal state transitions (e.g., screenshot diffs), MAPLE autonomously extracts declarative facts about UI mechanics to construct a localized, visually-grounded world model. 

# 3 Multimodal Agent with Playbook-Learned Experience (MAPLE) 

Figure 1 illustrates the overall execution and learning loop of MAPLE . We first formalize mobile GUI navigation as a dual-memory POMDP (Section 3.1), then detail intra-episodic state tracking and factorized action selection (Sections 3.2–3.3), followed by cross-episodic Playbook distillation and visually grounded retrieval (Sections 3.4–3.5). 

3.1 Problem Formulation 

We formalize mobile GUI navigation as a goal-conditioned Partially Observable Markov Decision Process (POMDP), defined by the tuple M = ⟨S , A, T , Ω, O, G, R⟩ , where S denotes the unob-servable system state space (including internal app variables and off-screen widgets), T the state transition dynamics, Ω the observation space, and G the space of natural-language user goals. At step 

t, given latent state st ∈ S , the observation process O coupled with Set-of-Marks (SoM) grounding converts the raw screen and view hierarchy into a multimodal observation ot = ( ˜It, E t) ∈ Ω, pairing the tag-annotated screenshot ˜It with the parsed set of interactable UI elements Et. Accordingly, the action space A comprises parameterized UI and dialogue operations (e.g., tap, swipe, text input, user query) indexed directly over e ∈ Et, avoiding continuous coordinate regression. Because st

is latent, a standard agent conditions its policy at ∼ π(at | ht, g ) on the sampled goal g ∈ G and 3interaction history ht = ( o0, a 0, . . . , o t) to generate an episode trajectory τ = ( s0, o 0, a 0, . . . , s T )

toward a terminal state sT satisfying g.While task completion is evaluated only at episode termination via a sparse binary reward R(sT , g ) = 

I(sT |= g) ∈ { 0, 1}, a training-free VLM agent cannot optimize π directly over full trajectories; instead, global task success depends on sequentially selecting well-grounded actions at each step 

t. Conditioning step-wise inference on the raw, append-only history ht, however, accumulates irrelevant visual clutter and compounding false premises—early misinterpretations persist in context and derail downstream decisions—while purely myopic selection from ot alone gets trapped in unfamiliar UI layouts. To make step-wise action selection reliable over horizon T without parameter updates, MAPLE reshapes the conditioning context through two complementary memory streams: (1) a persistent, cross-episodic Playbook Dℓ (initialized cold-start at D0 = ∅), updated after each episode trajectory τℓ with reusable UI transition rules distilled via self-supervised hindsight reflection; and (2) a bounded, intra-episodic Working Memory mt = Φ( mt−1, ∆mt−1) (reset each episode at m0 = ∅), where a deterministic parser Φ merges autoregressive key-value updates ∆mt−1

(insertions, modifications, or deletions) emitted at the previous step. At step t, combining mt with screen-grounded priors Pt retrieved from D forms a bounded context Ct = ⟨g, o t, m t, Pt⟩, yielding the active policy π(at | ht, g ) ≈ π(at | Ct).

3.2 Bounded Working Memory 

Rather than appending uncurated observation history, MAPLE instantiates the Working Memory ( mt)as a bounded, dynamic dictionary of semantic key-value pairs (e.g., {"clipboard": "code_1", "item_2_status": "checked"} ). Crucially, rather than relying on predefined schemas, both the keys and values (e.g., active sub-goals, runtime variables, and checklist states) are generated on-the-fly: at step t, the policy autoregressively predicts a schema update ∆mt, which the deterministic parser Φ merges into mt. This design replaces linearly growing raw screenshot histories with a compact, editable key-value state representation that remains interpretable and dynamically adapts to the active UI task. 

3.3 Autoregressive Policy Factorization 

Directly predicting actions via monolithic probability distributions P (at | Ct) frequently leads to spatial ungrounding and temporal myopia. MAPLE factorizes the policy output into an autoregressive sequence of cognitive artifacts: 

P (at, ˆot+1 , z t, ∆mt | Ct) = P (∆ mt | Ct) · P (zt | Ct, ∆mt)

· P (ˆ ot+1 | Ct, ∆mt, z t) · P (at | Ct, ∆mt, z t, ˆot+1 ) (1) Under this factorized bottleneck, the VLM generates a rigorous reasoning chain: (1) Memory Modulation ( ∆mt): The policy emits memory deltas to iteratively update the working memory state 

mt+1 = Φ( mt, ∆mt), appending, updating, or deleting semantic trackers; (2) Chain-of-Thought Rationale ( zt): Conditioned on the updated state, the policy generates a localized rationale aligning immediate visual evidence with the retrieved Playbook priors Pt; (3) Forward Dynamics Prediction (ˆot+1 ): Crucially, the policy must explicitly hypothesize the semantic visual consequence of its intended action prior to execution (e.g., predicting the appearance of a dropdown menu); and (4) 

Action Execution ( at): Only after establishing this reasoning sequence does the policy emit the final parameterized interaction at ∈ A mapped to a discrete SoM element (e.g., tap(element_14) ). By architecturally requiring forward dynamics prediction ( ˆot+1 ) and explicit state tracking ( ∆mt)before mechanical execution, MAPLE ensures that physical interactions are strictly grounded in both episodic intent and historical knowledge, reducing the risk of blind, repetitive looping behaviors commonly observed in unbottlenecked vision-language policies. 

3.4 Self-Supervised Hindsight Distillation & Playbook Consolidation

While intra-episodic Working Memory ( mt) tracks transient task variables, cross-episodic learning requires evaluating observed state transitions to extract generalizable knowledge. 3.5 Intent-Masked and Visually-Grounded Retrieval 

Prior to action execution at each decision step t, MAPLE queries the Playbook D using the goal g

and current observation ot to construct the heuristic prior Pt. Naive prior retrieval using raw text or unconstrained features causes context saturation and hallucinations. To ensure retrieved priors are physically actionable on the active screen, MAPLE filters the Playbook D through a sequential two-stage retrieval pipeline: 

1. Semantic Intent Masking: Raw user objectives g often contain volatile, instance-specific entities (e.g., names, dates) that hinder direct matching. To enable cross-task generalization, MAPLE applies an abstraction function kintent = ψ(g) that maps specific inputs to canonical placeholders (e.g., “Send ‘123’ to John” becomes “Send 〈MESSAGE 〉 to 〈RECIPIENT 〉”). Using kintent as a high-level query key, we retrieve a task-relevant candidate subset Dcand = {di ∈ D | ki = kintent }.

2. Greedy Visual Anchor Matching: To guarantee that candidates in Dcand are physically applicable to the current interface, we evaluate their structural congruence with the active screen. We extract a set of active layout anchors A(ot) = {u1, . . . , u M } from the observation ot, where each anchor represents a visible UI element uj = ⟨class , text , state ⟩. Dynamic Prior Distillation. If no candidate satisfies γanchor (e.g., at cold start), we set Pt = ∅. By coupling semantic abstraction with real-time layout verification, this pipeline ensures that injected playbook guidance remains grounded in the active visual observation. 

# 4 Experiments 

4.1 Experimental Setup Evaluation Benchmarks & Setup. We evaluate MAPLE on two standardized mobile environments: (1) AndroidWorld [14], comprising 116 programmatic tasks across 20 applications with dynamic task parameterization; and (2) MobileWorld [8], a harder suite testing multi-app orchestration (averaging 27.8 steps vs. 14.3 in AndroidWorld) and interactive ambiguity. We evaluate on MobileWorld’s 161 core tasks across its GUI-Only (117 tasks) and Agent-User Interaction (44 tasks) splits. Across both benchmarks, agents issue parameterized UI actions over Set-of-Marks grounded elements. An episode terminates upon the agent signaling completion or exhausting the step budget T , with task success I(sT |= g) verified deterministically by native benchmark evaluators auditing ground-truth system states (e.g., querying SQLite databases). 

Metrics & Protocol. An evaluation episode terminates upon the agent issuing a completion action or exhausting the pre-allocated step budget T . Following standard benchmark conventions, we evaluate performance across two primary metrics: • Task Success Rate (SR, %): The proportion of tasks deterministically completed within 

t ≤ T steps, as verified by native benchmark environment evaluators. • Average Trajectory Length (Steps): The average number of physical UI interactions required for task completion, quantifying navigational directness and the agent’s ability to reach target states without trial-and-error looping. For cold-start evaluation, the Playbook starts completely empty ( D0 = ∅) at the beginning of each benchmark suite, accumulates distilled rules sequentially across a single pass in the benchmark’s default task order (while Working Memory resets every episode, m0 = ∅), and is wiped cleanly between model backbones and ablation runs to prevent cross-run leakage. Complete implementation details—including VLM hyper-parameters, exact step budgets, and prompt templates—are provided in Appendix A.6. 

Baselines. We benchmark MAPLE against two agent categories: (1) Adapted M3A (Controlled Baseline): We adapt the M3A framework [14], which uses an Observe-Think-Act-Reflect loop similar to Reflexion [17] and Voyager [21]. To evaluate true cross-app generalization, we remove handcrafted per-task guidelines while upgrading M3A with the same structured prompting (including the Discoverability Protocol; Appendix A.2), Set-of-Marks grounding, and dialogue actions as MAPLE. Sharing the identical VLM backbone but lacking Working Memory ( mt), forward dynamics prediction ( ˆot+1 ), and the Playbook ( D), this baseline directly isolates the gains of our architecture. 

(2) Inference-Only SOTA: We compare against published leaderboard baselines, including Agent-SAMA [5] and MobileUse [9], which execute actions via static prompt contexts without dynamic memory or hindsight distillation.

The Scaffolding Paradox and Limitations. When scaled to frontier models on MobileWorld, MAPLE plateaus or slightly regresses in overall success rate (matching Claude-Opus-4.8 at 63 .35% 

and dipping from 62 .73% to 59 .63% on Gemini-3.6-Flash ), even though it continues to boost both models on deterministic AndroidWorld tasks (Appendix B.2). We attribute this saturation to the Scaffolding Paradox : frontier models possess strong intrinsic reasoning and naturally excel at exploratory recovery (“smart wandering”) under UI ambiguity. Imposing structured Playbook priors acts as an overly rigid constraint, narrowing the model’s search space and impeding opportunistic problem-solving. Crucially, MAPLE still shortens average trajectory length across both models (23 .24 → 22 .20 and 21 .70 → 20 .40 steps), confirming that it enforces a direct navigation policy; however, for frontier models, aggressively pruning exploratory rollouts removes the exact trial-and-error mechanism required to resolve complex edge cases. # 5 Conclusion and Future Work 

In this work, we presented MAPLE (Multimodal Agent with Playbook-Learned Experience), a gradient-free architecture designed for cold-start, continual experience accumulation across mobile GUIs. By decoupling intra-episodic state tracking via bounded Working Memory ( mt) from cross-episodic distillation via a persistent Playbook ( D), MAPLE transitions the mobile agent paradigm from brittle procedural memorization to the transfer of grounded, declarative UI mechanics. Compre-hensive evaluations on AndroidWorld and MobileWorld demonstrate that MAPLE achieves leading training-free success rates—including top performance on user-interactive workflows—while guiding agents along more direct and purposeful execution trajectories. Crucially, our scaling analysis reveals that MAPLE’s structured scaffolding provides disproportionate gains for lightweight and open-weight VLMs, preventing compounding failures under interactive ambiguity. Future work will explore adaptive scaffolding mechanisms to alleviate the Scaffolding Paradox on frontier models, as well as extending MAPLE’s grounded experience-accumulation framework to broader digital control domains, including web browsing and cross-platform desktop automation. 8References

# A Mobile World 

A.1 Benchmark Details 

To rigorously evaluate the generalization and multi-step reasoning capabilities of our proposed MAPLE agent, we utilize MobileWorld [8], a recently introduced, highly challenging benchmarking environment for autonomous mobile agents. While prior benchmarks like AndroidWorld have driven significant progress, their saturation (with state-of-the-art models exceeding 90% success rates) and reliance on short-horizon tasks limit their utility for evaluating production-grade autonomy. MobileWorld directly addresses these shortcomings by emphasizing long-horizon workflows and introducing interactive, ambiguity-driven task paradigms. 

Task Taxonomy and Scope MobileWorld consists of tasks spanning 20 third-party applications, authentically replicating real-world usage patterns. For our evaluation, we focus on the core subset comprising 161 tasks, which is structurally partitioned into two primary categories: • GUI-Only (117 tasks): Traditional visual navigation and interface manipulation tasks, demanding precise visual grounding, memory retention, and spatial reasoning over extended trajectories. 11 • Agent-User Interaction (44 tasks): A novel paradigm featuring deliberate instructional ambiguity. In these tasks, critical information is intentionally omitted from the initial prompt, requiring the agent to proactively trigger an ask_user action rather than failing silently or hallucinating. 

(Note: We deliberately omit the 40 MCP-Augmented hybrid API tasks, as MAPLE is fundamentally designed to optimize cross-episodic visual GUI navigation and semantic intent masking.) 

MobileWorld introduces severe cross-application complexity: approximately 62.2% of its tasks require orchestrating workflows across multiple apps. Consequently, the average trajectory length extends to 27.8 steps—nearly doubling AndroidWorld’s average. This extended horizon strictly tests an agent’s working memory capacity and resilience against cascading errors, directly motivating our introduction of the dynamic Playbook memory in MAPLE. 

Deterministic Evaluation Framework MobileWorld operates within a containerized environment with full backend state access for deterministic evaluation. Task success is verified programmatically via backend database inspection (47.3%) and local system storage analysis (36.8%), completely by-passing fragile LLM-as-a-judge heuristics and ensuring absolute reliability in multi-stage transaction outcomes. 

A.2 Ablation Study on User-Interactive Triggering: Analyzing Benchmark Sensitivity and Meta-Cognitive Boundaries 

A critical challenge in interactive mobile agent benchmarks such as MobileWorld is governing when an agent should act autonomously versus when it must solicit user clarification. In preliminary evaluations, we observed that agents confronted with ambiguous instructions or absent parameters frequently engaged in unproductive trial-and-error behaviors—such as searching on-device contacts, browsing local settings, or guessing missing values—rather than asking the user directly. To regulate this decision boundary, we introduced the Discoverability Protocol into the agent’s system prompt (detailed in Appendix A.7). The protocol explicitly forbids unprompted parameter hunting and enforces an immediate ask_user action across three mutually exclusive conditions: 1. Subjective Preferences: Vague or under-specified criteria (e.g., “clean up useless files”) requiring explicit user definition before interaction. 2. Missing Hard Data: Unspecified prerequisite credentials or identifiers (e.g., phone numbers, PINs) that must not be inferred via on-device search. 3. Execution Blocks: Hard roadblocks such as authentication walls or dead-end queries where repeated autonomous retries induce loops. Furthermore, the protocol assigns this clarification check top priority in the agent’s decision hierarchy, overriding standard navigational heuristics. A.3 Ablation Study: Cross-Architecture Robustness and Generalization 

A critical benchmark for any agentic framework is demonstrating that its performance gains are intrinsic to MAPLE’s coupled dual-memory and reflective reasoning architecture, rather than artifacts of a specific underlying Vision-Language Model’s (VLM) capabilities. To rigorously validate the architectural generalizability of MAPLE, we conduct an ablation study across a diverse spectrum of model families, encompassing both proprietary (Gemini-3-Flash, Gemini-3-Flash-Lite) and open-weight (Qwen3.6-35B, Gemma4-26B-A4B) backbones. As detailed in Table 2, integrating MAPLE consistently yields a universal performance lift across all tested architectures, strongly corroborating its model-agnostic robustness. Importantly, these improvements scale effectively across different model capacities. The framework’s impact is most profound in the highly complex User Interactive split, which heavily penalizes models lacking robust meta-cognitive policies. For the highly capable Gemini-3-Flash model, MAPLE pushes performance to state-of-the-art levels, yielding a 15.91% absolute increase in success rate. Even more compelling is MAPLE’s ability to “rescue” smaller open-weight models from compounding errors in ambiguous scenarios. When utilizing Gemma4-26B-A4B, the M3A baseline nearly collapses on interactive tasks (6.82% SR); however, the introduction of MAPLE’s dynamic priors completely stabilizes the policy, resulting in a near-quadrupling of the success rate to 29.55%. Finally, MAPLE improves task success while finding shorter, more direct interaction paths on three of the four evaluated backbones. Rather than relying on brute-force exploration, the harness helps the agent reason more effectively about UI state transitions and avoid repetitive sub-goal loops. Most strikingly, Gemma4-26B-A4B nearly doubles its overall success rate while requiring 25.4% fewer interaction steps (45.60 to 34.00). On Qwen3.6-35B, higher completion rates on complex User-Interactive workflows (20.45% to 27.27%) are achieved with a negligible shift in trajectory length (25.23 to 26.17 steps). Across backbones, these results indicate that MAPLE improves success not by taking more exploratory actions, but by steering the policy along cleaner, higher-precision decision paths. 

A.4 Ablation Study: Cognitive Bandwidth and Thinking Budget Prerequisites 

A fundamental consideration when deploying advanced agentic frameworks is the computational overhead and cognitive bandwidth required to maintain and query dynamic memory structures. To investigate the dependency of MAPLE on the underlying Vision-Language Model’s (VLM) internal reasoning capacity, we conducted an ablation study modulating the explicit “thinking budget” of the lightweight Gemini-3-Flash-Lite model on the MobileWorld benchmark. The results, detailed in Table 4, reveal a critical architectural prerequisite: MAPLE requires a sufficient internal thinking budget to effectively process its cross-episodic Playbook and multi-stage reflection pipeline. Under a Minimal thinking budget, MAPLE experiences a performance inversion, underperforming the M3A Baseline in Overall Success Rate (22.36% vs. 29.19%). This indicates that in severely compute-constrained, highly reactive settings, the additional context from intent-masked retrieval and visual grounding can overwhelm the model’s limited reasoning capacity, leading to context collapse or superficial action formulation. 13 However, this initial limitation highlights MAPLE’s distinct advantage in compute scaling. When the reasoning constraints are lifted ( High thinking budget), the M3A Baseline exhibits marginal gains, plateauing from 29.19% to 31.68%. In stark contrast, MAPLE’s architecture efficiently channels the increased cognitive bandwidth, surging to a 39.13% Overall Success Rate. This scaling is most pronounced in the complex User-Interactive split, where MAPLE jumps from 25.00% to 50.00%. Ultimately, this ablation demonstrates that while MAPLE introduces a baseline requirement for cognitive bandwidth, it fundamentally unlocks the VLM’s ability to translate increased compute into superior long-horizon planning and ambiguity resolution—capabilities where standard zero-shot baselines simply plateau. A.5 Limitations: The Scaffolding Paradox and Frontier Model Saturation 

While Section A.4 demonstrates MAPLE’s efficacy in unlocking capabilities for lightweight and mid-tier models, it is equally important to define the operational boundaries of explicit memory scaffolding. To this end, we evaluate MAPLE using true frontier models, specifically Claude-Opus-4.8 and Gemini-3.6-Flash, to investigate how state-of-the-art internal reasoning interacts with strict external memory constraints. The results, presented in Table 5, illustrate a phenomenon commonly referred to in agentic literature as the “scaffolding paradox.” For highly advanced frontier models, the explicit, rule-based constraints imposed by MAPLE’s Playbook memory yield diminishing returns and, in some cases, performance regressions. For Claude-Opus-4.8, MAPLE achieves an identical Overall Success Rate to the baseline (63.35%), with minor trade-offs between GUI-Only and User-Interactive tasks. However, for Gemini-3.6-Flash, introducing MAPLE results in a measurable regression in Overall SR (from 62.73% down to 59.63%). We attribute this saturation to the vast implicit reasoning and zero-shot exploration capabilities inherent to frontier models. These models naturally excel at “smart wandering”—utilizing dynamic, nuanced exploration to recover from UI ambiguities. By imposing strict, cross-episodic Playbook rules, MAPLE acts as an overly rigid prior, effectively over-constraining the model’s natural policy space and preventing creative, ad-hoc problem resolution. Notably, despite the success rate regression, MAPLE continues to strictly reduce the average Trajec-tory Length (e.g., dropping from 21.7 to 20.4 for Gemini-3.6-Flash). This indicates that MAPLE still successfully enforces a more direct, streamlined navigational policy; however, for frontier models, pruning exploratory steps ultimately removes the very mechanism they use to succeed in edge cases. Ultimately, this ablation defines MAPLE’s optimal deployment domain: it is not intended to augment massive, ultra-expensive frontier models. Rather, MAPLE serves as a critical bridge architecture, endowing highly efficient, on-device compatible models (like Gemini-3-Flash and Gemma) with the structured reasoning required to match or exceed baseline frontier performance.

B.1 Benchmark Details 

To establish a foundational baseline for our proposed MAPLE framework, we evaluate its perfor-mance on AndroidWorld [14], a comprehensive and highly reproducible environment designed for autonomous computer control agents. While MobileWorld (Section A) tests extreme long-horizon and ambiguous interactive capabilities, AndroidWorld serves as the standard proving ground for precise visual grounding, tool use, and parameter-driven execution within a live Android emulator. 

Task Taxonomy and Dynamic Instantiation: The benchmark consists of 116 diverse, hand-crafted tasks spanning 20 real-world applications. A defining feature of AndroidWorld is its dynamic task instantiation system. Rather than testing on static, pre-recorded scenarios, the environment generates millions of unique task variations by randomizing operational parameters (e.g., specific contact names, phone numbers, or target application settings) during initialization. This strict randomization explicitly prevents models from memorizing spatial trajectories or overfitting to static prompts, ensuring that the agent’s performance reflects genuine, generalized UI comprehension. 

Evaluation Protocol and Systemic Bottlenecks: A defining characteristic of AndroidWorld is its departure from fragile LLM-as-a-judge heuristics, relying instead on programmatic, deterministic reward signals extracted directly from the system state (e.g., verifying SQLite database entries or system logs). While this strict programmatic approach establishes a highly objective baseline, it concurrently introduces a double-edged sword: the risk of evaluation rigidity. In practice, rigid programmatic assertions can occasionally become decoupled from true task success, yielding false negatives when an agent executes a valid alternative workflow, or failing entirely due to brittle task parameterization. To provide a comprehensive understanding of the benchmark’s boundaries, we explicitly analyze these limitations in our subsequent System-Level Hard-To-Complete Mission Discussion, detailing 13 specific instances where mission design or metric alignment introduces problematic evaluation bottlenecks. 

B.2 Ablation Study: Cross-Architecture Robustness on AndroidWorld 

While Section B.1 establishes AndroidWorld as a rigorous, deterministic evaluation environment, it is crucial to demonstrate that MAPLE’s architectural benefits are not restricted to handling the long-horizon ambiguity of MobileWorld. A common concern with explicit memory frameworks is that the cognitive overhead of retrieving and processing historical rules might degrade performance or induce roundabout navigation in shorter, highly programmatic tasks. To address this, we conduct a cross-architecture ablation study on AndroidWorld. As presented in Table 7, we evaluate MAPLE against the M3A Baseline across six distinct Vision-Language Models. This diverse suite encompasses state-of-the-art frontier models (Claude-Opus-4.8, Gemini-3.6-Flash), mid-tier and lightweight proprietary models (Gemini-3-Flash, Gemini-3-Flash-Lite), and open-weight models (Qwen3.6-35B, Gemma4-26B-A4B). The empirical results confirm that MAPLE operates as a universal, model-agnostic enhancement in deterministic environments, consistently improving the Success Rate (SR) across every evaluated backbone. Unlike in highly ambiguous environments where explicit scaffolding can occasionally over-constrain frontier models, the rigid and programmatic nature of AndroidWorld tasks rewards strict rule adherence. Consequently, even highly capable frontier models like Claude-Opus-4.8 see an absolute SR improvement of +4.30% (from 77.60% to 81.90%) when augmented with MAPLE’s dynamic Playbook. Notably, this performance lift remains remarkably stable across the entire capacity spectrum, yielding absolute SR improvements ranging from +3.00% (Gemini-3.6-Flash) to +6.40% (Gemma4-26B-A4B). This consistency indicates that MAPLE’s intent-masked Playbook successfully grounds models of all sizes in universal UI paradigms, preventing catastrophic failures even in rigid, parameterized tasks. Furthermore, MAPLE simultaneously enforces navigational directness. Across all six models, the integration of MAPLE strictly reduces the Average Trajectory Length. For resource-constrained models, MAPLE trims over 1.5 steps off the average execution path, and even for frontier models, it consistently reduces step counts by eliminating unforced errors. Given AndroidWorld’s strict 22 programmatic step budgets, this universal reduction in futile exploratory loops is a primary driver of the observed success rate improvements. B.3 Ablation Study: The Impact of Step Budgets on Autonomous Recovery 

Standardized UI benchmarks fundamentally evaluate two coupled dimensions: task success capability and navigational directness. In AndroidWorld, the maximum step budget for each task is rigidly con-strained—historically scaled to an annotated difficulty score, and recently calibrated to approximately twice the average human completion time to strictly penalize brute-force exploration. While this strict 1X budget is essential for establishing an objective baseline, it conflates fundamental reasoning failures with minor navigational detours (e.g., failing to recover from a single misclick before the budget expires). To decouple reasoning capacity from strict step-horizon constraints, we conduct an ablation study relaxing the step budget to 3X the default allocation using the Gemini-3-Flash backbone. The objective is to observe whether MAPLE utilizes the extended horizon for random, unguided exploration (which would drastically inflate trajectory lengths) or for deliberate autonomous error recovery. As detailed in Table 8, relaxing the step budget unlocks a state-of-the-art Success Rate of 81.00% (a +5.10% absolute increase) entirely autonomously, without any manual guidance or human-in-the-loop intervention. Crucially, this substantial gain in task success is achieved with only a marginal increase in the Average Trajectory Length, shifting from 12.75 to 15.39 steps. If the agent were relying on stochastic guessing to exploit the larger budget, the average trajectory length would exhibit a massive proportional spike, as failed runs would exhaust the heavily extended 3X limit. The modest addition of roughly 2.6 steps indicates that MAPLE’s explicit memory mechanisms inherently govern the agent’s policy, preventing infinite loops. Instead, the agent utilizes the relaxed constraint precisely as intended: executing deliberate, multi-step self-correction pathways to recover from ambiguous UI states or unexpected application behaviors that would have otherwise triggered a premature budget timeout. Ultimately, this ablation demonstrates that while strict budgets are necessary for standardized evalua-tion, MAPLE possesses a highly robust, underlying capability for long-horizon task completion and autonomous recovery when temporal constraints are relaxed.

B.5 Hyperparameter Configurations: Benchmark-Agnostic Tuning 

To rigorously evaluate the generalization capabilities of MAPLE and ensure a fair, unbiased com-parison across fundamentally different environments, we deliberately avoided benchmark-specific hyperparameter tuning. We strictly maintained the exact same configurations utilized in the Mobile-World experiments. Consequently, all models evaluated on AndroidWorld utilize the identical generation parameters (e.g., Temperature, Top-p, explicit Thinking Budgets) and API endpoint settings detailed previously in Appendix A.6 and Table 6. The ability of MAPLE to achieve strong performance across both ambigu-ous (MobileWorld) and highly deterministic (AndroidWorld) tasks without requiring dataset-specific prompt or parameter adjustments strongly corroborates its robust, “plug-and-play” architectural design. 

B.6 Prompt Configurations: Environmental Adaptations 

While MAPLE’s hyperparameter configurations remain strictly uniform across benchmarks (Sec-tion B.5), adapting the framework from the open-ended MobileWorld to the rigid, deterministic AndroidWorld environment requires a specific modular adjustment to the prompt suite. Crucially, the core cognitive engine of MAPLE—comprising the Visual Reflection, Playbook Rule Distillation, Intent Abstraction, and Deduplication prompts detailed in Appendix A.7—remains completely identical. The framework’s ability to extract, synthesize, and retrieve rules requires zero domain-specific prompt engineering. However, a necessary adaptation is applied to the Action Proposal prompt. Because AndroidWorld is fundamentally designed as a zero-shot, non-interactive evaluation suite, the dynamic human-in-the-loop mechanisms (specifically the Discoverability Protocol and user-interactive Q&A triggers) utilized in MobileWorld are explicitly disabled. The agent is restricted to generating direct UI interactions 25 or declaring task completion/infeasibility, perfectly aligning with AndroidWorld’s programmatic constraints.
