## 摘要
GUI Web 智能体需要真实、可交互且在评估与训练期间均保持稳定的环境。对真实在线网站进行评估会受到内容变化、访问限制以及对需认证工作流覆盖有限等问题的困扰，而现有的用于训练的合成环境往往缺乏功能深度和视觉保真度。我们提出 WebHarbor，一套包含 153 个可执行且已 Docker 化的网站环境，能够在确定性控制下忠实重建真实 Web 服务的视觉界面、内容和功能工作流。我们通过任务驱动的人机协作构建 WebHarbor：随着新任务扩展环境的功能范围，环境不断演进；编码智能体实现所需更改；人类贡献者审核视觉保真度、功能正确性和任务有效性。最终得到的套件包含 3,518 个任务，涵盖多步骤和认证后工作流，而这些正是现有工作通常未能覆盖的。除可靠评估外，WebHarbor 还提供高保真合成 Web 环境，用于成本高效的强化学习（RL）。我们证明，一个在 WebHarbor 中使用 RL 训练的 Qwen 4B 级 GUI 智能体能够泛化到未见任务，并在四个基准上与领先的开源 GUI Web 智能体表现相当。代码和数据已在 https://github.com/aiming-lab/WebHarbor 公开可用。

## Abstract
GUI web agents require realistic and interactive environments that remain stable during both evaluation and training. Live website evaluation suffers from changing content, access restrictions, and limited coverage of authenticated workflows, while existing synthetic environments for training often lack functional depth and visual fidelity. We propose WebHarbor, a suite of 153 executable and dockerized website environments that faithfully reconstruct the visual interfaces, content, and functional workflows of real-world web services under deterministic control. We build WebHarbor through task-driven human-agent collaboration, where environments evolve as new tasks expand their functional scope, coding agents implement the required changes, and human contributors audit visual fidelity, functional correctness, and task validity. The resulting suite comprises 3,518 tasks spanning multi-step and post-authentication workflows, where existing works often fail to cover. Beyond reliable evaluation, WebHarbor provides high-fidelity synthetic web environments for cost-efficient reinforcement learning (RL). We demonstrate that a Qwen 4B-level GUI agent trained with RL in WebHarbor generalizes to unseen tasks and performs competitively with leading open-source GUI web agents across four benchmarks. The code and data are publicly available at https://github.com/aiming-lab/WebHarbor.

## 1. 核心问题与研究动机

- **背景**：多模态 LLM 驱动的 GUI Web 智能体需要在“可稳定复现”的环境中评测，并在“可执行状态转移、可重复重置”的环境中做强化学习（RL）。但现有环境难以同时满足这两类需求。
- **真实在线网站评测的痛点**（作者实测）：
  - 内容漂移：约 **22% 的 WebVoyager 任务**因网站改版而过时；
  - 访问限制：约 **38% 的 Online-Mind2Web 任务**被 bot 检测拦截；
  - 认证工作流覆盖极少：Online-Mind2Web 全部 300 条任务均标注“无需登录”，WebVoyager 643 条中仅 1 条明确要求登录。
- **合成训练环境的痛点**：自动生成环境往往“重生成、轻复刻”，视觉保真度低、功能浅、图片稀缺、缺少登录后状态；部分环境还存在答案泄漏、交互捷径，削弱任务有效性。
- **研究缺口**（Table 1）：已发布环境无法同时具备“广覆盖网站 + 离线执行 + 图像丰富 + 登录流程 + 可评测”。WebHarbor 的目标即是补齐这一组合，同时服务于**可靠评测**与**低成本在线 RL 训练**。

## 2. 方法论

### 2.1 核心思想：Docking（对接）

- 将真实网站“对接”为本地可执行环境：用本地资产、种子状态和受控重置替代线上依赖，同时保留**可识别的视觉外观**与**任务相关的功能行为**。
- 重建范围由“目标任务的支撑面”界定，即任务所需的页面、路由、图片、数据与状态转移，而非复刻整个商业站点（如 Amazon 全目录、YouTube 全视频库）。

### 2.2 任务驱动的作用域界定（Task-driven Docking）

- 每个任务契约规定：入口/终止页面、可观察实体与属性、所需浏览器动作、持久化状态变更。
- 起点为 WebVoyager 的 15 个网站、643 个任务；再扩展到 Online-Mind2Web 的全部网站（但弃用其原任务，因其偏信息检索）。
- 由人工识别站点核心功能区，LLM 依据常见 Web 服务知识扩展候选工作流，人工再审核功能覆盖、可行性与交互深度，最终覆盖账户管理、预订、购买、收藏等持久化操作。
- 环境保留自然导航路径与“近似干扰项”，防止智能体通过捷径或答案泄漏完成任务。

### 2.3 技能驱动的五阶段合成与演化（Skill-driven Synthesis）

编码智能体先在真实 Chromium（Playwright）中观察目标站点，记录页面层级、URL 模式、交互控件、渲染后 DOM 与解析后的图片 URL，再以 Flask + SQLAlchemy + Jinja2 + SQLite 构建自包含应用。五个阶段对应五个可复用技能提示：

1. **clone-website**：抓取真实图片与品牌资产（记录来源 URL、本地路径、SHA-256），实现后端、认证、搜索、详情页与 CRUD，冻结种子数据库，验证图片解码、响应式布局、重启后状态保持、重置后数据库字节一致。
2. **design-tasks**：为每站编写 15–20 条任务契约（JSONL），覆盖搜索筛选、浏览详情、账户管理、收藏、历史、比较、购物车/结算/预订/评论等；难度分层（2–3 步简单、4–6 步中等、≥3–5 条 5 步以上困难任务），并要求至少 2 条“真实歧义”任务（应主动澄清而非猜测）。
3. **evolve-env**：逐条在浏览器中执行任务，定位首个不支持的观察或状态转移，补路由、模板、表单处理、校验规则、数据库记录；每次修改后重置并完整重放。
4. **harden-env**：四维加固，包括答案去泄漏（清除标题/摘要/排序/计数中的答案线索）、近邻干扰项（每任务保留 1–3 个全匹配、至少 5 个仅违反一个约束的近似项，全匹配密度 ≤50%）、目录扩充（自然查询至少返回 6 条跨子类结果）、跨字段一致性（规格为唯一真源，联动更新描述、标签、变体、库存等）。
5. **seed-database**：幂等种子函数（函数级早退，避免 no-op commit 改动 SQLite 元数据）、4 个标准测试账号（`alice.j@`、`bob.c@`、`carol.d@`、`david.k@test.com`，密码 `TestPass123!`）及真实历史数据、50–200 个主实体、5–15 个类目、带停用词去除的**打分式 token 重叠检索**、资产与代码版本交叉锁定、字节级重置与重启校验。

### 2.4 人在回路迭代审核（Human-in-the-loop）

- 两类角色：**Contributor** 指定目标站点与高层功能需求并指导编码智能体；**Reviewer** 对照真实站点逐条端到端执行任务，核查可行性、交互序列、视觉与功能保真度，并将缺陷转写为可执行修改请求，直至通过。
- 每环境平均 **2–3 轮审核，每轮 1–2 小时**；审核者还编写任务专用 verifier 与 LLM-as-a-Judge / agent-as-a-Judge 评分细则。
- 动机来自试点：26 个网站中 13 个存在视觉/资产缺陷（如图文不符），14 个存在按钮无响应等浅层交互问题——这些问题编码
