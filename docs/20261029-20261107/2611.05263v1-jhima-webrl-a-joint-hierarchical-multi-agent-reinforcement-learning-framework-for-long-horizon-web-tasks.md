## 摘要
多模态网页智能体已展现出通过图形用户界面（GUI）与网站交互的前景能力，但现实网页任务往往需要长时程、多步规划，这对单体策略仍具挑战。此类智能体必须联合推断高层计划、在中间状态间导航、在长交互历史中跟踪进度，并执行基于视觉的动作。尽管先前工作探索了带有独立规划器的模块化多智能体系统，但规划器通常未与执行器联合更新。我们研究显式分离并联合训练规划与执行是否能为长时程网页导航提供更强的归纳偏置。我们提出 JHiMA-WebRL，一种面向网页智能体的联合分层多智能体强化学习框架，将任务分解器与执行器耦合。为训练分解器，我们使用强教师模型从多模态 GUI 轨迹中构建结构化子任务监督，并利用这些标注微调分解器和以子任务为条件的执行器。随后，我们扩展组相对策略优化（GRPO），通过分层 rollout 分组和角色特定优势，在交互式 WebArena 环境中联合优化分解器与执行器。在 WebArena-Lite-v2 上，由 7B 执行器和 7B 分解器组成的 JHiMA-WebRL-14B 取得 37.2% 的平均成功率，而 ScaleCUA-32B 智能体为 24%，后者由我们在相同训练任务上用 RL 微调并在相同协议下评估。消融实验表明，在 RL 期间联合更新分解器优于仅更新执行器。这些结果表明，使用较小模型联合学习角色分解，可作为扩展单体智能体以处理长时程网页任务的有竞争力替代方案。

## Abstract
Multimodal web agents have shown promising capabilities for interacting with websites through graphical user interfaces (GUIs), yet realistic web tasks often require long-horizon, multi-step planning that remains challenging for monolithic policies. Such agents must jointly infer high-level plans, navigate through intermediate states, track progress over extended interaction histories, and execute visually grounded actions. Although prior work has explored modular multi-agent systems with a separate planner, the planner is typically not updated jointly with the actor. We investigate whether explicitly separating and jointly training planning and execution provides a stronger inductive bias for long-horizon web navigation. We introduce JHiMA-WebRL, a joint hierarchical multi-agent reinforcement learning framework for web agents that couples a task decomposer with an actor. To train the decomposer, we use a strong teacher model to construct structured subtask supervision from multimodal GUI trajectories, and use these annotations to fine-tune both the decomposer and the subtask-conditioned actor. We then extend Group Relative Policy Optimization (GRPO) to jointly optimize the decomposer and actor in the interactive WebArena environment through hierarchical rollout grouping and role-specific advantages. On WebArena-Lite-v2, JHiMA-WebRL-14B, consisting of a 7B actor and a 7B decomposer, achieves an average success rate of 37.2%, compared with 24% for a ScaleCUA-32B agent that we fine-tune with RL on the same training tasks and evaluate under the same protocol. Ablations show that jointly updating the decomposer during RL outperforms updating the actor alone. These results suggest that jointly learned role factorization with smaller models can be a competitive alternative to scaling monolithic agents for long-horizon web tasks.

## 二、方法论

### 2.1 核心思想
将网页交互因子化为两个独立参数化、但**联合训练**的模块：
- **分解器（Decomposer）** $\pi_{\theta_D}$：输入任务指令 $x$ 与初始截图 $o_0$，输出有序子任务序列 $d=(g_1,\dots,g_L)$；
- **执行器（Actor）** $\pi_{\theta_A}$：输入任务、当前截图 $o_t$、动作历史 $h_t$ 与子任务序列 $d$，输出网页动作 $a_t$。

框架分**三阶段**：①教师模型生成子任务监督 → ②两个模块分别 SFT → ③分层 GRPO 联合 RL。

### 2.2 阶段一：分解器数据生成
- 以 **GPT-5.2-Codex** 为教师模型，输入 ScaleCUA 轨迹的任务指令、起始截图、完整动作序列与逐步截图，按专门 prompt（附录 A）生成有序子任务及“冗余动作”标注。
- 产出约 **76K** 分解训练样本（平台分布：Windows 5,873 / macOS 3,845 / Linux 25,122 / Android 17,245 / Web 24,311；平均 2.56 个子任务；约 1.6% 轨迹含冗余动作）。
- 目的：把低层 GUI 演示自动转化为高层规划监督，避免推理时依赖专有教师。

### 2.3 阶段二：监督微调（SFT）
- **分解器 SFT**：Qwen2.5-VL-7B 初始化，最小化
  $$\mathcal{L}^{SFT}_D=-\sum_{n=1}^{N_d}\log\pi_{\theta_D}(d^{(n)}\mid x^{(n)},o_0^{(n)})$$
- **执行器 SFT**：同样 Qwen2.5-VL-7B 初始化，在 ScaleCUA 轨迹 + 教师子任务 + grounding 数据（共 **2,535,552** 条）上训练：
  $$\mathcal{L}^{SFT}_A=-\sum_{n=1}^{N_A}\sum_{t=0}^{T_n-1}\log\pi_{\theta_A}(a_t^{(n)}\mid x^{(n)},o_t^{(n)},h_t^{(n)},d^{(n)})$$
- 关键点：执行器把子任务作为**显式规划上下文**，在 SFT 阶段就学会“按计划执行”。

### 2.4 阶段三：联合分层多智能体 GRPO
- **分层 rollout 结构**：对每个任务，分解器采样 $K$ 个候选分解 $d_i$；每个分解下执行器独立采样 $M$ 条完整交互轨迹 $\tau_{i,j}$；每条轨迹获得终端二值奖励 $R_{i,j}\in\{0,1\}$。
- **执行器层优势**（同一计划内比较）：
  $$A^A_{i,j}=\frac{R_{i,j}-\frac{1}{M}\sum_m R_{i,m}}{\mathrm{std}_m[R_{i,m}]+\delta}$$
  同一轨迹所有 token 共享该优势。
- **分解器层优势**（跨计划比较）：先聚合 $S_i=\frac{1}{M}\sum_j R_{i,j}$，再
  $$A^D_i=\frac{S_i-\frac{1}{K}\sum_{i'}S_{i'}}{\mathrm{std}_{i'}[S_{i'}]+\delta}$$
  同一分解所有 token 共享该优势。
- **目标函数**：对两个模块分别使用 GRPO 的 token 级裁剪目标（含 KL 正则），总损失
  $$\mathcal{L}_{JHiMA}=\mathcal{L}_A+\mathcal{L}_D$$
  由于 $\theta_A$ 与 $\theta_D$ 不相交，等价于用**同一 rollout 批次**分别更新两个模块。
- **实现细节**：按 Liu et al. (2025c) 去掉标准差与响应长度归一化；附录 B 证明去掉标准差归一化后，$A^D_i$ 是分解器策略梯度的**无偏（至多相差正比例因子）基线化估计**，且执行器基线以 $d_i$ 为条件，可剥离计划质量带来的奖励方差。

## 三、实验设计

### 3.1 数据集与 Benchmark
- **训练数据**：
  - 分解器 SFT：约 76K 教师生成分解样本；
  - 执行器 SFT：ScaleCUA 轨迹 + 子任务 + grounding，共 2,535,552 条；
  - RL 交互：WebArena 中排除 WebArena-Lite 后的 **647 个训练任务**（5 个站点：Reddit、GitLab、电商后台、地图、在线购物）。
- **评测 Benchmark**：**WebArena-Lite-v2**（ScaleCUA 提出），共 **154 个任务**，覆盖 Shopping、ShoppingAdmin、Reddit、GitLab、OpenStreetMap 五个环境；任务类型含问答、导航、页面内容匹配、状态变更；采用 Liu et al. (2025b) 的柔性评判（GPT-5.2-Codex 模糊匹配）。
- **严格隔离**：WebArena-Lite（及 Lite-v2）任务不参与 SFT 或 RL。

### 3.2 对比方法
- 单体/原生智能体：UI-TARS-1.5-7B、UI-TARS-72B-DPO、ScaleCUA-7B SFT、ScaleCUA-32B SFT、GUI-Libra-8B；
- **自建强基线**：ScaleCUA-32B RL（在相同 WebArena 训练任务上，用标准多轮 GRPO、7 rollouts、15 步预算微调，同协议评测）；
- 规划器—执行器系统：GPT-4o Planner + UI-TARS-1.5-7B Grounder、GPT-4o Planner + ScaleCUA-7B Grounder；
- 所有方法统一 15 步交互预算，仅纳入不使用 HTML/DOM 信息的基线。

### 3.3 消融实验
- `w/o decomposer RL`：冻结 SFT 分解器，仅 RL 训练执行器（K=3, M=7）；
- `w/o decomposer`（actor-only RL）：完全去掉子任务条件，分别用 21 rollouts 与 7 rollouts 两个变体；
- `w/o RL`：仅 SFT 分解器 + SFT 执行器；
- **子目标质量分析**：用 GPT-5.2-Codex 判定每个子目标是否完成，计算完成比例对最终成功的 AUROC 与 Kendall τ，并比较 RL 前后。

## 六、主要结论与发现

1. **主结果**：JHiMA-WebRL-14B（7B 执行器 + 7B 分解器）在 WebArena-Lite-v2 上平均成功率 **37.2%**，比同协议训练的 ScaleCUA-32B RL（24.0%）高 **13.2 个百分点**，且总参数更少；在 GitLab（47.5%）、Reddit（60.5%）、Shopping（29.0%）、ShoppingAdmin（44.3%）四个领域均为最高。
2. **联合更新分解器有效**：冻结分解器仅更新执行器时降至 33.4%（−3.8pp），说明分解器需要随执行器能力共同演化。
3. **分解器条件本身有价值**：完全去掉子任务条件的 actor-only RL 为 34.9%（21 rollouts）/ 35.2%（7 rollouts），比完整方法低 2.0–2.3pp。
4. **RL 整体有增益**：仅 SFT 的模块化系统为 35.1%，完整联合 RL 提升 2.1pp；值得注意的是“冻结分解器 + actor RL”（33.4%）反而低于纯 SFT（35.1%），说明**只训练执行器而不更新分解器可能造成计划—执行错配**。
5. **子目标是有效的过程信号**：分解器生成子目标的完成比例对最终成功的 AUROC 为 **0.838**（SFT-only 为 0.836），经验成功率随子目标完成比例单调上升（Kendall τ=0.516 vs 0.503），说明子目标可作为有意义的中间里程碑。
6. **薄弱环节**：Map 领域仅 12.5%，低于 GUI-Libra-8B（17.3%）与 ScaleCUA-7B（15.4%）；失败案例显示智能体反复切换缩放控件直至耗尽 15 步预算。
7. **总体判断**：小型模型经角色分解 + 联合 RL，可作为“扩展单体智能体”的有竞争力替代路径。

## 七、优点

- **问题定位清晰**：准确指出“有规划器但不联合训练”这一空白，并用“同一 rollout 批次同时更新两个策略”给出明确的技术

方案，概念简单、实现代价低，且与现有 GRPO 训练管线兼容。

- **分层优势估计设计合理**：执行器层在“同一计划内”做相对比较、分解器层在“跨计划”做相对比较，两层基线各自条件化，使计划质量带来的奖励方差不会污染执行器的信用分配；附录给出的无偏性论证增强了方法可信度。
- **训练数据构造有工程价值**：用强教师模型把大规模低层 GUI 轨迹（ScaleCUA）自动“反译”为高层子任务监督，避免了推理期依赖专有模型，也让执行器在 SFT 阶段就习惯以计划为上下文，缓解了 RL 冷启动困难。
- **基线的可控性较好**：自建 ScaleCUA-32B RL 基线在相同训练任务、相同 15 步预算、相同评测协议下训练，使“14B 分层 vs 32B 单体”的对比具有较强说服力；同时明确排除使用 HTML/DOM 的方法，避免信息渠道不一致带来的不公平比较。
- **过程级分析补充了结果级结论**：不仅报告成功率，还用子目标完成比例的 AUROC 与 Kendall τ 说明“子任务是有效中间信号”，为“分解器为何有用”提供了机制性证据，而非仅停留在分数提升。
- **诚实的负面结果呈现**：作者主动指出“冻结分解器 + actor RL”低于纯 SFT，并据此提出计划—执行错配的解释，这类反直觉发现对后续工作有参考价值；Map 领域的失败模式（反复操作缩放控件耗尽预算）也被如实披露。

## 八、局限与不足

- **评测覆盖面窄**：仅一个 benchmark（WebArena-Lite-v2，154 任务、5 个站点），且均为 Web 环境；论文标题与动机强调“多模态网页智能体”，但训练数据虽跨 Windows/macOS/Linux/Android/Web 五平台，评测却未涉及桌面与移动端，跨平台泛化能力未经验证。
- **增益幅度与统计可靠性**：消融各组差异仅 2.0–3.8 个百分点，作者自己承认与 run-to-run 方差同量级；未报告置信区间、标准差或显著性检验，4 次运行取平均不足以支撑对小幅度差异的强断言。主结果 +13.2pp 虽较大，但对比对象是不同规模（32B vs 14B）且由作者自行复现的基线，缺少与原文报告数字的交叉核对。
- **基线协议不完全统一**：UI-TARS-1.5-7B、UI-TARS-72B-DPO、GUI-Libra-8B 以及 GPT-4o Planner 组合使用的是各自原有的模糊匹配 judge，与本文的 GPT-5.2-Codex 柔性评判并非同一判定器；judge 差异可能系统性地影响成功率，尤其在“页面内容匹配”类任务上。
- **缺少与最接近工作的直接对比**：Plan-and-Act、Planner Matters!、HiRoC、SWIRL 等同样做规划器—执行器联合训练的方法未被纳入实验，因此“同时 RL 联合优化优于交替/部分更新”这一核心主张实际上只由内部消融（冻结分解器 vs 联合更新）支撑，缺乏外部横向证据。
- **超参与结构未做敏感性分析**：K（候选分解数）、M（每计划轨迹数）、子任务长度 L、LoRA 秩等均未扫描；K=3、M=7 使每任务 rollout 数达 21 条，计算成本与性能的权衡关系不明。RL 阶段 β=0（无 KL 惩罚）也未见消融，策略漂移风险未讨论。
- **分解器质量依赖教师模型**：约 76K 分解样本全部由 GPT-5.2-Codex 生成，教师的分辨率上限即学生的上限；论文未评估教师标注噪声（如子任务切分粒度不一致、冗余动作标注错误率约 1.6% 之外的其他错误类型），也未与人工标注子集做一致性校验。
- **奖励信号过于稀疏**：仅使用终端二值成功奖励，未利用中间进度、动作合法性或子目标完成度构造塑形奖励；尽管理论上分层结构缓解了信用分配，但对 15 步长时程任务而言，二值奖励的方差仍然很高，这可能解释了消融差异偏小的现象。
- **效率与部署成本未讨论**：推理时需先跑一次 7B 分解器再逐步跑 7B 执行器，相比单体 7B 模型增加了每任务的额外前向开销与延迟；论文报告了训练算力（约 720 GPU-hours），但未报告推理时延、token 消耗或每任务成本的对比。
- **失败分析偏定性**：Map 领域仅 12.5%，失败案例描述为“反复切换缩放控件”，但未统计各领域的失败类型分布（定位错误、计划错误、早停、循环），因此难以判断瓶颈究竟在分解器还是执行器。

## 九、启示与可拓展方向

- **角色分解 + 共享 rollout 联合 RL 是一种通用范式**：本文的核心贡献不在具体算法细节，而在“两个不相交参数集共享同一批 on-policy 轨迹、各自用自己的分层优势更新”这一简洁框架。该思路可迁移到其他需要“规划—执行”分离的具身导航、机器人操作、软件工程智能体等场景。
- **过程信号的自动挖掘**：用强教师把低层轨迹反译为高层子任务，是一种低成本获得过程监督的通用手段；后续可探索用 RL 过程中的成功/失败轨迹自我迭代生成或修正子任务标注，减少对固定教师的依赖。
- **奖励设计有待加强**：在二值终端奖励之上引入子目标完成度、动作有效性等中间奖励，或采用课程式逐步放宽步数预算，可能进一步放大分层结构的优势。
- **跨平台与跨 benchmark 验证是必要的下一步**：将评测扩展到 Android/桌面环境（如 AndroidWorld、OSWorld 类基准）以及 Web 之外的站点，检验分解器学到的“计划先验”是否真的跨域可迁移。
- **自适应分层**：当前分解器一次性输出固定长度子任务序列，执行器无条件遵循；可考虑让执行器在执行中回报进度、触发重规划（replan），形成闭环分层，从而缓解 Map 类任务中“计划错误却无法纠正”的问题。
- **与更先进的分层 RL 技术结合**：如 options framework、hierarchical advantage weighting、或对分解器使用基于执行器回报的 credit assignment 平滑（而非硬性 std 归一化），可能改善小样本下的方差问题。

## 十、总体评价

本文针对“网页智能体规划与执行耦合过重”的问题，提出将任务显式分解为 7B 分解器与 7B 执行器，并在同一批分层 rollout 上分别用分层 GRPO 优势同时更新两个模块。方法概念清晰、实现成本可控、与现有 GRPO 管线兼容，且配有较完整的三阶段训练流程（教师蒸馏 → 双模块 SFT → 联合 RL）。

实验上，14B 分层系统在 WebArena-Lite-v2 上以 37.2% 平均成功率超过同协议训练的 32B 单体 RL 基线（24.0%），并在四个领域取得最佳，为“小型模型 + 角色分解”的路线提供了有说服力的正面证据；消融也较一致地显示联合更新分解器、保留子任务条件、引入 RL 三者各自都有正贡献。子目标完成度对成功的高 AUROC（0.838）进一步支持了分层结构的合理性。

但需谨慎看待结论的强度：单一 benchmark、消融差异与运行方差同量级、缺少显著性检验与超参敏感性分析、跨源基线 judge 不一致、未与最接近的联合训练方法直接对比，这些都限制了结论的普适性；Map 领域的明显短板与推理开销的缺失也提示该方法尚未成熟到可直接部署。

总体而言，这是一篇**问题定位准确、方法简洁有效、实验基本充分但统计严谨性与外部效度有待加强**的工作。其最大价值在于提供了一个可复用、低门槛的“分层联合 RL”训练模板，并为后续在奖励设计、闭环重规划与跨平台泛化上的改进留下了清晰空间。
