## 摘要
现有的图形用户界面（GUI）基准测试主要依赖精确且无状态的用户指令。然而在日常使用中，指令往往是模糊且依赖历史的：用户会省略过去操作的确切细节，因为他们已不再记得这些细节，从而需要智能体从冗长且嘈杂的交互历史中恢复缺失的上下文。为弥合这一评估空白，我们提出 MemU-Bench，这是一个包含 118 个模糊任务的移动端基准测试，基于 29 条长程用户轨迹构建。在该基准中，智能体必须将原始交互流提炼为记忆，并按需检索缺失的上下文，任务结果则依据序列化的应用数据库进行验证。除成功率外，我们还引入交互效率（IE）和按路径长度加权的成功率（SPL），以揭示那些通过在不同应用中穷举搜索而非真正回忆历史来取得成功的智能体。评估表明，在没有用户历史的情况下，最先进的系统在此类模糊性下表现不佳：表现最佳的 Gemini-3.1-Pro 的 SPL 仅为 16.4%，端到端 GUI 智能体则低于 5%。为解决这一问题，我们进一步提出 AppMem，这是一个免训练框架，可将用户历史提炼为结构化的、以应用为中心的记忆库，跨应用切换跟踪被中断的意图，并通过目标应用推断选择性检索相关记忆。AppMem 将 GPT-5.5 的 SPL 从 15.7% 提升至 66.9%（+51.2%），比朴素摘要基线高出 9.3%，并在所评估的主干模型上带来一致增益。

## Abstract
Existing Graphical User Interface (GUI) benchmarks predominantly rely on precise and stateless user instructions. In everyday usage, however, instructions are often \emph{vague and history-dependent}: users omit the exact details of their past operations because they no longer remember them, leaving the agent to recover the missing context from long and noisy interaction histories. To bridge this evaluation gap, we introduce \textbf{MemU-Bench}, a mobile benchmark of \textbf{118 vague tasks} grounded in 29 long-horizon user trajectories, where agents must distill raw interaction streams into memory and retrieve the missing context on demand, with task outcomes verified against serialized application databases. Alongside Success Rate, we incorporate Interaction Efficiency (IE) and Success weighted by Path Length (SPL) to expose agents that succeed by exhaustively searching across different applications rather than by \emph{genuinely recalling} the history. Evaluations show that without user history, state-of-the-art systems struggle under such ambiguity: the best-performing Gemini-3.1-Pro achieves an SPL of only 16.4\%, and end-to-end GUI agents fall below 5\%. To address this, we further propose \textbf{AppMem}, a training-free framework that distills user history into a \emph{structured, app-centric} memory bank, tracks interrupted intents across application switches, and selectively retrieves relevant memories via target-app inference. AppMem raises the SPL of GPT-5.5 from 15.7\% to 66.9\% (\textbf{+51.2\%}), outperforms a naive summary baseline by 9.3\%, and delivers consistent gains across evaluated backbones.

- **对基准设计的三点要求**：
  1. 暴露**原始、长且嘈杂**的历史（而非预清洗摘要）；
  2. 保留**被跨应用切换打断的碎片化意图**；
  3. 必须区分“真正回忆”与“执行时穷举搜索”这两种成功路径。
- **整体含义**：论文主张**记忆而非执行能力**是长程 GUI 智能体的主要瓶颈，并同时提供评测基准（MemU-Bench）与解决方案（AppMem）。

## 2. 方法论

### 2.1 MemU-Bench 的三阶段任务定义

- **记忆生成**：给定历史轨迹 \(T=\{(o^H_i,a^H_i,t_i)\}_{i=1}^N\)（截图、原子动作、绝对时间，间隔从不足 1 秒到 1 天），智能体产出记忆库 \(M=f_{generate}(T)\)。
- **关键信息检索**：对模糊指令 \(\tilde I\)，检索 \(\kappa=f_{retrieve}(\tilde I,M)\)。
- **在线执行**：在 MDP 中按策略 \(a_t\sim\pi(a\mid \tilde I,o_t,h_{<t},\kappa)\) 逐步操作真实 App。
- **数据构建流程**：人工设计“意图级轨迹草图”→操作员在 Android 虚拟设备上模拟真实使用（含误触、冗余切换、数小时空档）→后台脚本以 0.3 秒间隔同步记录截图与动作→过滤连续重复截图→**冻结并序列化各应用运行时数据库（SQLite）与系统时间**，测试前恢复快照，使历史副作用（已发消息、已改日程）在后台可核验。
- **规模**：29 条轨迹、118 个任务（71 个 L1 短历史 <400 帧，47 个 L2 长历史 >700 帧），覆盖 30+ 应用、5 大类别，单条轨迹最多 179 次应用切换。
- **评测级联**：规则化数据库校验（44.9% 任务）→ 开放式文本用 LLM-as-Judge（时间戳等确定性字段仍规则校验，55.1% 任务）→ 少数数据库不可达任务用 VLM 看截图判定。
- **指标**：
  - SR \(=|C|/N\)；
  - IE \(=\frac{1}{|C|}\sum_{i\in C}\frac{S^{golden}_i}{\max(S^{agent}_i,S^{golden}_i)}\)（仅在成功任务上计算，用于识别“盲目探索式成功”）；
  - SPL \(=\frac{1}{N}\sum_{i=1}^{N}\mathbb{I}[i\in C]\cdot\frac{S^{golden}_i}{\max(S^{agent}_i,S^{golden}_i)}\)（联合衡量成功率与路径效率）。

### 2.2 AppMem（免训练框架）

**核心思想**：把原始历史流蒸馏为**以应用为中心的结构化记忆库**，通过“意图续接 + 应用引导检索”解决碎片化与精准召回问题。

**（A）记忆生成（滑窗 W=10）**——三阶段流水线：

1. **当前事件摘要**：对窗口内截图-动作对生成条目 6 元组 \(m_j=\langle app_j,e_j,d_j,t_{start,j},t_{end,j},s_j\rangle\)，其中 \(s_j\in\{\text{ongoing},\text{finished}\}\)；提示词明确要求记录“硬信息”（价格、验证码、专有名词、规格），并禁止“用户浏览了 App”这类过度概括。
2. **最新记忆抓取**：对每个新条目，在全局库中查找**同一应用最近的一条**历史条目。
3. **进行中意图续接（OIC）**：若历史条目状态为 ongoing，则合并更新 \(M\leftarrow M\setminus\{m_i\}\cup\{\text{update}(m_i,m_j)\}\)；若已 finished 或无匹配，则追加新条目。效果是跨应用切换后同一意图仍保持为一条连贯线索，且已完成事件不被覆盖。

**（B）应用引导检索**（最多 K=3 轮）：

1. **应用推断**：由 \(\tilde I\) 推断候选应用子集 \(A^*\subseteq A\)；
2. **记忆检索**：过滤出应用专属子库 \(M^*=\{m_i\in M\mid app_i\in A^*\}\)，缩小搜索空间；
3. **信息过滤**：\(\kappa=f_{filter}(M^*,\tilde I)\) 提炼任务相关信息；
4. **充分性验证**：不足则从候选集移除已探索应用 \(A\leftarrow A\setminus A^*\) 并进入下一轮，充分则开始执行。
