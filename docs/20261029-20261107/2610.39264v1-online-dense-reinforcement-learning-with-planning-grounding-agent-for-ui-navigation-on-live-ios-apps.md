## 摘要
尽管前沿视觉语言模型在用户界面（UI）导航中展现出强大能力，但其高昂的推理成本阻碍了日常使用。相反，通过监督微调（SFT）或离线强化学习训练的小型模型往往记住静态轨迹，导致执行脆弱且无法从错误中恢复。为解决这些局限，我们提出了一种新颖的在线强化学习框架，可直接在实时 iOS 应用上训练 UI 导航智能体。我们的框架将智能体解耦为两个专用组件：规划智能体和 UI 接地模型。我们依赖 LLM-as-a-Judge 提供全面的奖励信号，将用于评估中间进度的稠密步级反馈与用于整体任务完成的终端奖励相结合。为有效利用这种双重奖励结构，我们使用带有步级优势估计的近端策略优化（PPO）来优化智能体。此外，我们引入了 GiGPPO，一种新颖的邻居条件价值估计方法，通过利用并发轨迹中视觉相似状态的奖励信号来提高评论家稳定性。为大规模支持这种在线训练范式，我们引入了一种高效基础设施，可编排数百个并发虚拟 iOS 设备。在包括 UINavBench、iOSWorld 和 AndroidWorld 在内的严格基准上的评估表明，我们在线强化学习训练的智能体显著优于 SFT 和仅终端奖励的强化学习基线，同时加速了训练收敛。值得注意的是，我们的 8B 强化学习智能体在对 Android 环境的分布外泛化方面，相比 SFT 基线实现了近七倍的提升，同时在真实 iOS 应用上优于 Gemini-3.5-Flash，并与 Gemini-3.1-Pro 持平。

## Abstract
While frontier vision-language models demonstrate strong capabilities in user interface (UI) navigation, their high inference costs prohibit everyday use. Conversely, smaller models trained via supervised fine-tuning (SFT) or offline reinforcement learning often memorize static trajectories, leading to brittle execution and an inability to recover from errors. To address these limitations, we propose a novel online reinforcement learning framework that trains UI navigation agents directly on live iOS applications. Our framework decouples the agent into two specialized components: a Planning agent and a UI Grounding model. We rely on an LLM-as-a-Judge to provide comprehensive reward signals, combining dense, step-level feedback to evaluate intermediate progress with a terminal reward for overall task completion. To effectively leverage this dual reward structure, we optimize the agent using Proximal Policy Optimization (PPO) with step-level advantage estimation. Furthermore, we introduce GiGPPO, a novel neighbor-conditioned value estimation method that improves critic stability by leveraging reward signals from visually similar states across concurrent trajectories. To support this online training paradigm at scale, we introduce an efficient infrastructure that orchestrates hundreds of concurrent virtual iOS devices. Evaluations on rigorous benchmarks, including UINavBench, iOSWorld, and AndroidWorld, demonstrate that our online RL trained agents substantially outperform both SFT and terminal-only RL baselines while accelerating training convergence. Notably, our 8B RL agents achieve nearly a sevenfold improvement over the SFT baseline in out-of-distribution generalization to Android environments, while outperforming Gemini-3.5-Flash and tying with Gemini-3.1-Pro on real iOS applications.

- **论文目标**：提出一个可直接在**实时 iOS 应用**上大规模训练的在线 RL 框架，兼顾低成本推理、错误恢复与跨环境泛化。

## 2. 方法论

### 2.1 核心思想

- **规划与接地解耦**：将智能体拆分为两个专用组件——**Planning Agent**（负责开放域推理与规划）和 **UI Grounding Model**（负责将计划映射为具体动作与坐标）。
- **RL 只用于规划器**：接地被视为近似确定性的映射问题，用 SFT 即可高效解决；计算昂贵的 RL 仅用于最需要开放推理与自适应能力的规划阶段。
- **在线稠密 RL**：在真实虚拟 iOS 设备上持续采样新轨迹，用 LLM-as-a-Judge 同时提供步级稠密奖励和终端任务奖励，以 PPO 优化，并引入 GiGPPO 稳定 critic。

### 2.2 架构与动作空间

- **问题建模**：将 UI 导航视为序列决策过程。状态由当前截图 \(s_t\) 与历史动作摘要构成；动作为固定原语集合：`TAP`、`SWIPE`、`TEXT ENTRY`、`NAVIGATE HOME`、`LONG PRESS`、`ASK USER`、`TASK COMPLETE`。
- **Planning Agent**：
  - 基座为 Qwen3-VL-8B-Instruct，先经 SFT 热启动；
  - 输入任务指令、当前截图、历史步计划及其推理、上一步的剩余计划；
  - 输出带 Chain-of-Thought 的当前步计划，以及带推理的长期剩余计划。
- **Grounding Model**：
  - 内部 3B 稠密预训练模型，经人类标注数据 SFT，在留出集上坐标/动作准确率超过 90%；
  - 仅支持方向性滑动，因此所有 `SWIPE` 指令路由至 Gemini-3.5-Flash（支持基于位置的滑动）。
- **SFT 热启动数据**：两个内部 iOS 数据集（第一方与第三方应用）+ 公开 GUIOdyssey（Android，多应用轨迹）；由于原始数据缺少推理标注，使用 Gemini 生成 CoT 与剩余计划目标。
- **多应用任务合成**：用 Gemini 两阶段生成 iOS 跨应用任务（先识别逻辑应用对，再生成多样化任务），并由作者人工校验。

### 2.3 奖励设计：LLM-as-a-Judge 双通道

- **稠密奖励（每步，Gemini-3.5-Flash）**：
  - 输入任务、动作历史（含此前稠密判定）、当前计划、推理、前后截图；
  - 输出 `success` / `fail` / `overcomplete`；
  - `success` 要求前后截图体现朝总目标推进，且推理与动作均与 UI 视觉状态一致；幻觉导致的“偶然进展”判为失败；重复失败动作的无效循环受罚；任务已完成仍继续动作判为 `overcomplete`。
  - 另有独立 judge 评估 `ASK USER` 是否确实针对当前步骤下信息不足的部分。
- **终端奖励（轨迹级，Gemini-3.1-Pro）**：
  - 基于最后三张截图、完整动作历史及此前稠密判定；
  - 输出 `success` / `fail` / `blocked complete`；`blocked complete` 用于奖励在付费墙、CAPTCHA 等不可逾越外部障碍前正确完成所有可执行步骤的轨迹。
- **具体权重**：
  - 稠密通道：`+1.0` 成功；`0.0` 失败或计划不可接地；`-1.0` 空计划或生成长度截断；`-2.0` 任务完成后继续动作。
  - 终端通道：`+2.0` 完成任务并声明 `Task Complete`；`+0.5` `blocked complete`；`-0.75` 耗尽步数预算；`-1.0` 虚假完成声明；`-2.0` 不可解析或空输出。
  - 稠密回报上界为 \(1/(1-0.5)=2.0\)，与一次终端成功等值，避免任一通道主导。
- **基础设施失败掩码**：应用未渲染、安装失败、设备断连、生成超时等轨迹不进入策略梯度、critic 回归、邻居候选及优势白化统计。

### 2.4 PPO 与不对称折扣

- 价值函数目标：
  \[
  V^\pi(s_t)=\mathbb{E}_\pi\left[R_T+\sum_{k=t}^{T}\gamma^{k-t}r^{\text{dense}}_k \mid s_t\right],\quad \gamma=\tfrac12
  \]
  其中终端奖励 \(R_T\) **不折扣**，稠密奖励按 \(\gamma=1/2\) 折扣。
- 优势估计采用 GAE，令 \(\lambda=1\)，退化为蒙特卡洛估计：实际回报减去 critic 估计，避免 bootstrap 偏差但引入采样方差。
- **不对称折扣的动机**：
  - 若 \(\gamma=1\)，每步稠密奖励与即时奖励等权，智能体可通过“人为延长轨迹、每步都显得局部正确”来刷高
