## 摘要
轨迹级 GRPO 是训练多步 GUI 智能体的常用方法，但从任务根节点反复展开完整轨迹可能效率低下：任务级奖励只能对哪些中间决策需要改进提供粗粒度监督，而已经掌握的轨迹前缀在到达困难状态之前会被反复重新执行。我们提出一个两阶段自适应训练框架，联合解决在何处学习以及展开多远的问题。我们首先从成功的专家轨迹中构建可复用的中间检查点，并利用动作不一致性选择信息量大的关键点，该不一致性直接从采样得到的 GUI 动作中度量不确定性。阶段 I 在这些关键点处执行一步 RL，以改进不确定的局部决策。阶段 II 随后根据任务进展，通过自适应的 Local、Suffix 和 Root 训练逐步扩展策略责任范围。可恢复检查点使得能够从中间状态反复训练，而无需重放之前的轨迹。在 MobileGym 和 CUA-Gym-Hub 上，我们的方法相对于 Vanilla GRPO 将环境交互减少了 56%–61%，同时提升了任务性能，这表明跨状态和展开范围联合分配训练可以显著提高 GUI 智能体 RL 的效率。

## Abstract
Trajectory-level GRPO is a common approach for training multi-step GUI agents, but repeatedly rolling out complete trajectories from the task root can be inefficient: task-level rewards provide coarse supervision over which intermediate decisions require improvement, while already-mastered prefixes are repeatedly re-executed before reaching difficult states. We introduce a two-stage adaptive training framework that jointly addresses where to learn and how far to roll out. We first construct reusable intermediate checkpoints from successful expert trajectories and select informative pivots using action disagreement, which measures uncertainty directly from sampled GUI actions. Stage I performs one-step RL at these pivots to improve uncertain local decisions. Stage II then progressively expands policy responsibility through adaptive Local, Suffix, and Root training according to task progress. Recoverable checkpoints enable repeated training from intermediate states without replaying the preceding trajectory. Across MobileGym and CUA-Gym-Hub, our method reduces environment interaction by 56-61% relative to Vanilla GRPO while improving task performance, demonstrating that jointly allocating training across states and rollout ranges can substantially improve GUI-agent RL efficiency.

# 论文结构化总结：Where to Learn and How Far to Roll Out

## 1. 核心问题与研究背景

- **背景**：多步 GUI 智能体的强化学习普遍采用**轨迹级 GRPO**——从任务根节点出发，完整 rollout 整条交互轨迹，再用最终任务成败构造策略更新。这一范式简单有效，但对 GUI 场景存在结构性低效。
- **两大低效来源**：
  - **信用分配粗粒度**：任务级 0/1 结果无法指出"到底哪一步中间决策需要改进"，长轨迹上多步相互依赖，监督信号稀疏。
  - **前缀重复执行**：策略已能稳定处理的早期步骤被反复重跑，才能到达真正困难的深层状态；而每次 rollout 都要与外部环境真实交互，成本高昂。
- **核心命题**：高效 GUI 智能体训练必须**联合决定"在何处学习（where to learn）"与"展开多远（how far to roll out）"**，而非只解决其中之一。
- **与已有工作的差异**：PivotRL（局部奖励方差选点）、BPO（首 token 熵 + 沙箱快照分支）、PivoARL（失败轨迹自反思重试）、SRC（教师回滚纠错）、Tree-GRPO（随机中间分支）通常**只决定"优化哪些中间状态"或"从哪里分支"**。本文认为二者应随策略能力演化**协同自适应**。
- **GUI 环境特有挑战**：
  - 弱策略自身难以到达有价值的深层状态；
  - 奖励方差类信号会漏掉"动作分歧大但当前奖励全为 0/8"的不确定状态；
  - 通过动作回放恢复中间 GUI 状态成本高，且在异步加载、动画、时序依赖的动态界面下不可靠。

## 2. 方法论

### 2.1 核心思想
以**可复用中间检查点**为基础设施，用**动作分歧**挑选信息量最大的枢轴（pivot），再以**两阶段 + 三档 rollout 范围**的训练课程，把"局部一步决策改进"逐步扩展为"整任务端到端能力"。

### 2.2 可复用中间状态（Reusable Intermediate States）
- 对成功专家轨迹 τ = (o₀,a₀,o₁,a₁,…,o_T)，定义第 t 步检查点 **c_t = (x, h_t, o_t, e_t)**：任务实例、策略可见交互历史、当前观测、可恢复的环境状态引用。
- 检查点可**反复恢复**并生成独立 rollout 分支，无需重放前缀，从而摊薄到达深层状态的代价。
- 工程实现（附录 A.1）：Podman + CRIU 做**容器级**快照，捕获浏览器内存与 JS 堆、文件系统变更；恢复时关闭旧 TCP 连接、由健康检查与截图成功判定就绪，并做恢复前后观测/评测一致性校验。
- 实测恢复延迟：MobileGym 2.97s vs 10 步回放 15.7s（**降低 81.1%**）；CUA-Gym-Hub 3.21s vs 11.3s（**降低 71.6%**）。

### 2.3 在何处学习：动作分歧选枢轴
- 候选状态来自**成功的专家轨迹**（提供可靠的下一动作参照，并暴露初始策略难以到达的状态）。
- 对状态 c_t 采样 N=8 个策略响应，按 GUI 动作等价规则分组，第 j 类动作计数为 n_j，定义经验动作分歧：

  **D̂(c_t) = 1 − Σ_j n_j(n_j−1) / [N(N−1)]**

  即"两个采样响应产生不同 GUI 动作"的概率；当 **D̂ > τ_dis = 0.45** 时选为枢轴。
- **动作等价规则**：点击/长按/双击坐标差异 ≤ 屏幕宽高 5% 视为同一动作；滑动按离散化方向匹配；其他动作比较类型；文本输入**不论内容**视为同一类型。
- **相对 Reward Variance 的优势**：某状态可能出现 8 个样本动作各异但奖励全为 0（无奖励方差），奖励方差准则会将其丢弃，而动作分歧仍能识别"模型不知道该怎么做"的不确定性。阈值示例：6–2 分组 D̂=0.429 被过滤，6–1–1（0.464）、5–3（0.536）被保留。

### 2.4 展开多远：自适应混合训练（Local / Suffix / Root）
- 以根级成功率 **p̂(x) = 成功 rollout 数 / rollout 总数** 做初始路由：
  - **Local**（p̂ < τ_low = 0.25）：长 rollout 组常坍缩为同一失败结果，信号弱却代价高；改为在枢轴处做**一步 RL**，以专家下一动作构造即时局部奖励 **r = 1[M(a^(i), a^E)]**（M 为上述动作匹配函数）。
  - **Suffix**（τ_low ≤ p̂ ≤ τ_high = 0.75）：从**最深枢轴**开始生成后缀 rollout 直至任务终止，避开已可靠前缀；若后缀成功率 > τ_suffix，则下一轮把前沿**前移一个枢轴**，否则停留原地；直至前沿到达根节点。
  - **Root**（p̂ > τ_high）：仅用**2 条轻量根级 rollout** 探测是否仍有优化空间；若 rollout 组存在结果差异则更新，若全部成功则不更新；进入 Root 后**不再回退**到中间枢轴（单调性）。

### 2.5 两阶段训练流程
- **Stage I（局部枢轴预热）**：仅在动作分歧枢轴上做一步局部 RL，不要求完成后续任务，为多步训练提供更强初始化。
- **Stage II（自适应混合训练）**：从 Stage I 中 **Train Avg@4 最高**的检查点初始化，先跑 4 条根级 rollout 做任务路由，随后按 Algorithm 1 循环：Local 任务周期性根级重评（4 条 rollout）并可晋级；Suffix 任务用 8 条 rollout 并逐步前移前沿；Root 任务保持轻量探测。

## 6. 主要结论与发现

- **总体效率**：相对 Vanilla GRPO，环境交互减少 **56%–61%**，同时任务表现不降反升。
- **自适应 rollout 分配本身有效（Base→Hybrid vs Base→Vanilla）**：
  -

- 在 Stage I 检查点相同的前提下，仅把"始终整条轨迹 rollout"换成"Local/Suffix/Root 自适应分配"，就能在**更少的优化样本与更少的交互步**下取得持平或更好的 Train/Held-Out 表现，说明**"展开多远"本身是一个独立于"在哪里学"的有效杠杆**，而不仅是局部奖励带来的副产物。
- **两阶段课程具有累积增益（Action→Hybrid 最优）**：Local 预热（Action→Vanilla）先改善中间状态的一步决策质量，Hybrid 分配再把这些局部改进沿枢轴前沿逐步"串接"成完整任务能力；完整方案在两组 benchmark 的 Train 与 Held-Out 上均优于 Vanilla、无预热的 Hybrid 以及单步预热 + Vanilla GRPO。
- **动作分歧优于奖励方差作为选点准则**：在选点消融中，Action Disagreement 相对 All Pivots 与 Reward Variance 收敛更快、在相同样本预算下达到更高 Avg@4/Pass@4，验证了"奖励全 0 但动作分散"的状态确实是奖励方差类信号的结构性盲区。
- **相对 SFT 基线的优势**：尽管 SFT 使用了与本文相同的专家轨迹且覆盖全部轨迹步（监督信号更"密集"），RL 方案在 Held-Out 上更优，说明收益并非单纯来自专家数据暴露，而来自"在策略自身可达状态上做偏好/奖励驱动的改进"。
- **训练分配随训练自然演化**：随累计优化样本增加，Local 任务占比下降、Suffix 与 Root 占比上升，符合"策略变强→可优化前沿向根节点迁移"的设计预期；相比之下 Base→Hybrid 因缺少局部预热，早期更长时间停留在 Local，说明预热改变了课程进入节奏。
- **工程可行性的直接证据**：容器级检查点恢复相比动作回放把"到达深层状态"的代价降低 71.6%–81.1%，使"大量中间状态分支 rollout"在实际训练预算内变得可行——这是本文方法能落地的前提条件，而非单纯的实现细节。

## 7. 局限与可改进方向

- **统计严谨性不足**：缺少随机种子重复、置信区间与显著性检验；在 4 条 rollout 的评测协议下，小幅差距（如 MobileGym Held-Out 的 47.85 vs 47.66）不足以支撑"更优"的强结论，宜补多次运行并报告中位数/方差。
- **超参数缺少依据**：τ_dis=0.45、τ_low=0.25、τ_high=0.75、τ_suffix 均为手工设定且无敏感性分析；这些阈值直接决定 Local/Suffix/Root 的路由与前沿推进速度，其稳健性未知。
- **规模与泛化验证有限**：训练/评测任务量（83/128、80/60）与单一 4B 策略规模偏小，未验证在更大模型、更多任务、跨域迁移（如 Web↔移动）上的表现。
- **"在哪学"与"展开多远"的耦合未完全解耦**：虽然消融显示 Hybrid 分配单独有效，但缺少"不同选点准则 × 不同 rollout 范围"的完整交叉矩阵，无法判断两者是否存在交互效应（例如 Reward Variance 选点是否在 Suffix 模式下同样有效）。
- **基础设施依赖较重**：Podman + CRIU 的容器级快照对运行环境有较强假设，论文未量化快照存储开销、恢复失败率与就绪判定误判对训练信号的影响；也未与"动作回放"在**最终性能**上对比，仅比较了延迟。
- **与相关工作的对比不完整**：仅复现了 PivotRL/BPO 的**选点准则**，未与其完整算法（如 BPO 的分支策略、SRC 的教师回滚纠错）端到端对比，因此"优于已有方法"的结论应谨慎表述。
- **可复现性瑕疵**：正文与表格在 CUA-Gym-Hub 的样本量（3.1K vs 15.4K）与指标（55.00/65.00 vs 52.08/61.67）、τ_suffix（0.75 vs 0.5）上存在前后不一致，需作者澄清或勘误。
- **奖励设计简化**：Local 阶段使用"与专家下一动作是否匹配"的 0/1 即时奖励，隐含"专家动作唯一正确"的假设；对多解任务（多种合理操作路径）可能引入假负例，未来可考虑动作集合匹配或过程奖励模型。

## 8. 总体评价与启示

- **贡献定位**：本文的主要贡献不在于提出全新的 RL 目标函数，而在于**把"采样位置"与"展开长度"提升为一等公民的训练设计变量**，并给出可执行的协同调度方案（动作分歧选点 + Local/Suffix/Root 三档范围 + 两阶段课程）。这一视角对长程、交互昂贵、状态难以回放的智能体任务（GUI、具身、工具调用）具有较好的迁移性。
- **方法论价值**："用动作分歧替代奖励方差识别不确定状态"是一个简洁且可复用的洞察——它把"策略不知道该做什么"与"任务暂时失败"解耦，弥补了稀疏 0/1 奖励下探索信号的缺失。
- **实证强度**：在效率维度（交互步数降低 56%–61%）上的证据相对扎实且方向一致；在效果维度上的提升幅度较小且缺少统计检验，应视为"不劣于甚至略优"而非"显著更优"。
- **实践建议**：若要在自有环境中复现，优先投资"低成本可恢复中间状态"这一基础设施，其次再调选点阈值；并建议在正式使用前补齐多种子重复与阈值敏感性扫描，以避免被小样本评测噪声误导。
